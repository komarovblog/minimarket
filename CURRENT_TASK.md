## Новое целевое решение по URL от пользователя 01.11.2026
Пользователь привёл примеры с vseinstrumenti.ru и уточнил, что тип страницы должен определяться **отдельным префиксом**, а после него должны идти `alias-ID`:
- `/catalog` — витрина/корень каталога.
- `/category/{alias}-{id}` — категория.
- `/product/{alias}-{id}` — товар.
- `/bundle/{alias}-{id}` — комплект (сущность ещё НЕ реализована).
- `/filter/{alias}-{id}` — вручную созданный SEO-лендинг фильтра (сущность ещё НЕ реализована).

Без вложенности родителей и без изменения URL товара при переносе в другую категорию. ID постоянный в пределах типа; одинаковые ID у разных типов допустимы благодаря префиксу. Не генерировать миллионы индексируемых страниц динамических фильтров. При смене alias продумать canonical/301; временные адреса `/catalog/{alias}-{id}` не считать окончательным контрактом. Канонический документ — `docs/COMPONENT_ARCHITECTURE.md`.

## Следующая техническая задача — типизированный Joomla router
**Не выкатывать непроверенный redirect/роутер в уже работающую Joomla.** Спроектировать и реализовать в `development` следующим небольшим релизом (после 0.3.3) сначала **только category/product**, не добавляя пустых таблиц и MVC для будущих bundle/filter. Не просто переписать `build()`: Joomla выбирает начальный URL-сегмент по `Itemid`/menu alias. Нужен проверяемый план настройки корневых menu aliases `category` и `product` (возможны скрытые опубликованные пункты в отдельном меню) без нарушения `/catalog`; согласовать `preprocess/build/parse` и `RouteHelper/SeoHelper`, учесть технические URL и маршруты публикации.

Критерии PASS: реальные `/category/testovaa-kategoria-1`, `/product/testovyj-tovar-1`; каталог `/catalog` жив; один правильный absolute canonical у каждой страницы; работающая админка; опубликованные показываются, неопубликованные дают 404; старые `/catalog/{alias}-{id}` не становятся SEO-дублями (301 или документированный план миграции до публичного релиза); не затрагивать обычные Joomla-страницы. После теста — отдельный этап bundle и SEO-filter entities.

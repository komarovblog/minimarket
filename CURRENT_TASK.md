# 09.11.2026 — исправление ошибки Joomla prepared statements на 0.5.73

При обновлении в Joomla возникало `This command is not supported in the prepared statement protocol yet`
из-за `START TRANSACTION` в SQL-обновлении. Старт транзакции переведён в
`script.php::preflight()` через Joomla DB driver. SQL установщика
подготовлен к протоколу MySQL 8.4, тестируется через `mysqli::prepare()`.
Старый ZIP нельзя повторно использовать; после сбоя сверить версию
`#__schemas` и исходные колонки и иметь резервную копию.
Отдельный ручной SQL для phpMyAdmin не изменён; это альтернативный путь.

# Актуальная задача на 07.11.2026 — нормализация характеристик на реальном дампе

Выпущен MiniMarket **0.5.72**: в глобальных настройках появились три режима
**Физические товары / Цифровые товары / Доставка еды**. Физические товары —
умолчание; доработки цифрового режима и доставки еды пока намеренно не
реализованы. CI зелёный на PHP 8.4/8.5, MySQL 8.0/8.4, Windows ZIP.

Получен полный дамп Joomla/MySQL 8.4 от 07.11.2026, **не размещать его
в GitHub**: содержит данные системных таблиц Joomla и секреты. В 33
таблицах MiniMarket находятся 81 товар/комплект, 12 характеристик
(все value_source=legacy), 13 значений палитры и 77 ссылок на палитру,
770 scalar значений (в т. ч. 308 text presets), 111 old multi rows,
0 free_values. Пять текстовых атрибутов имеют 39 уникальных пресетов.
При локальной проверке сопоставления все 419 старых текстовых назначений
имеют существующие определения вариантов, не выявлены пропуски и дубли.
На канонической модели должно получиться **496** ссылок на значения
(77 + 308 + 111), **462** scalar number/boolean; product IDs не менять.

**Важно: окончательная чистка legacy-хранилища пока НЕ выпущена.**
Для неё необходимо одновременно перевести PHP-сервисы
AttributeSettings/AttributeTable/AttributeModel/ProductAttributes/
ProductattributesField/FacetedCatalog/BulkDeleteGuard/CatalogArchiveV2,
fresh install SQL, демоданные, импорт/экспорт и тесты на единый контракт
manual/preset. Только после MySQL 8.4 round-trip и проверки сохранности
ID/всех 496 назначений можно удалять колонку старых пресетов и
таблицу product_attribute_multi_values. Не удалять таблицы раньше
переключения всех читателей/писателей и не выдавать промежуточный
data-only SQL за финальное обновление.

В текущей беседе подготовлен **предварительный, не предназначенный
для живой БД** SQL для транзакционного переноса preset-data и отчёт
локальной проверки. В рабочую БД не импортировать до завершения
рефакторинга и испытания SQL на MySQL 8.4.

См. [docs/RELEASE_0_5_72.md](docs/RELEASE_0_5_72.md).
Работать только в `development`, не трогать main, Joomla Core и
сторонние таблицы. Для новой версии нужны отдельный ZIP компонента,
независимый ZIP toolbar, настоящий SQL schema-update и тесты.

## Обнаруженное противоречие настройки основного Itemid — к ближайшему связанному релизу

Пользователь проверил, что текущий per-menu флаг `shop_primary_route=1` допускает `Да` в двух и более обычных пунктах MiniMarket. Сейчас Router при конфликте выбирает пункт с наименьшим ID — детерминированно, но неочевидно администратору. **Это UX-дефект, не ограничение количества публичных пунктов.** Предложенное упрощение: оставить сколько угодно обычных menu items, но заменить множественные независимые флаги **одной глобальной настройкой выбора Itemid** в MiniMarket Options: «Автоматически» (MiniMarket home → минимальный ID) либо один опубликованный обычный пункт MiniMarket. При удалении/снятии с публикации ранее выбранного пункта — безопасный fallback в Auto; не создавать скрытые меню, не писать в `#__menu` при сохранении других пунктов, не менять ядро Joomla. Существующие `shop_primary_route` надо учитывать при переходе, чтобы случайно не сломать прежние URL, и проверить SEO/canonical. **Предложение ещё не реализовано в коде; не менять сейчас версию/ZIP только ради этого.** Объединить исправление с ближайшим маршрутизационным выпуском после smoke 0.3.8.

## Новое решение 01.11.2026 — ровно один включённый флажок, без глобального списка

**Пользователь выбрал вариант UX:** оставить **переключатель прямо в каждом обычном пункте Joomla MiniMarket** — «Использовать этот пункт для ссылок на товары и категории». При сохранении опубликованного пункта MiniMarket с **Да** автоматически ставить **Нет** у остальных обычных пунктов MiniMarket; никаких ограничений на количество пунктов (хоть 100). Менять **только** этот параметр, не трогать другие настройки, алиасы, публикацию, привязанные модули и пользователей. Если везде Нет, используется прежний fallback: MiniMarket на главной, затем пункт с минимальным ID. Нельзя позволять новому неопубликованному пункту, созданному через «Сохранить как копию», незаметно вытеснять действующий основной пункт.

**Технически это отдельная будущая задача, не реализованная в 0.3.8:** пункты меню сохраняет штатный Joomla `com_menus`, поэтому для синхронизации нужны его события сохранения (`com_menus.item` / `onContentAfterSave`) и безопасное обновление только параметров других MiniMarket пунктов без изменения ядра Joomla. Изучить совместимость с установкой одним ZIP, кэшем меню, неопубликованными пунктами и повторными сохранениями. Не выдавать переключение как уже рабочее, пока не проверено в Joomla. **Предыдущее предложение о новом глобальном выпадающем списке ОТМЕНЕНО.** Следующую реализацию объединить с близкой по смыслу итерацией настроек/маршрутизации, не выпускать отдельный ZIP только ради переключателя.

# MiniMarket — согласованная модель характеристик, опций и SKU (04.11.2026)

## Источник требований и границы

Требования: скриншоты категории, характеристик, карточки товара, матрицы SKU, галереи, связей и стартовой страницы Joomla 6.2.0. Рабочая ветка development; main и ядро Joomla не менять.

В 0.5.44 внесены исправления ссылок и стартовой страницы; таблицы категорий, матрица с закреплёнными колонками, выбор изображения по SKU, вкладка «Опции», отдельное сохранение связи и выбор цвета/изображения уже были реализованы в development 0.5.43. Переделывать их без причин не нужно.

**Универсальный механизм характеристик ниже — согласованное техническое требование, НЕ завершённая реализация 0.5.44.** Старые схемы таблиц и типы хранимых значений нельзя переинтерпретировать без миграции/тестов.

## 1. Единый порядок редактора характеристик

1. Заголовок и уникальный код характеристики.
2. **Тип значения**: Текст; Число; Редактор HTML; Файл/документ; Цвет; Да/Нет. У существующих характеристик допустимые устаревшие типы остаются читаемыми.
3. **Источник значения** (кроме Да/Нет): «Ручной ввод» или «Выбор из заданных значений». Это независимое поле, а не текущая смесь input_mode с селектом/радио/флажками.
4. **Выбор значений в товаре**: «Одно значение» / «Несколько значений». Сохранение проверяется на сервере. Для числа — одно число; для Да/Нет — отдельный выбор состояния. При выборе из справочника одиночный ввод показывается нативным выпадающим списком, множественный — флажками. Не нужно ещё одно поле «Способ показа» с радиокнопками и селектом, способ следует из настройки кратности.
5. **Справочник значений**, если выбран соответствующий источник: Joomla repeatable с «+», сортировкой и удалением. В строке: текстовое название, стабильный код, необязательная фотография, необязательный HEX-цвет и статус. Для HTML/документа кроме названия требуется типизированная нагрузка (HTML или путь к документу), не смешивать её с обычной строкой VARCHAR(255).
6. **Настройки типа**, ниже общего блока: число — единица, min, max, шаг; цвет — показ «название и кружок» или «только кружок», а ручной ввод — доступный HEX color picker в карточке товара; HTML — редактор со строгой очисткой; документ — поле Joomla Media для файлов.
7. **Фильтры и публикация** — отдельный смысловой блок. Параметры фильтра не должны подменять настройки редактора товара.

## 2. Заполнение товара

- В товаре выводить только характеристики выбранной категории с наследованием; обязательность брать из категорий. Невалидные сочетания значений не сохранять.
- Ручной ввод: текст → input; число → number с min/max/step; HTML → безопасный Joomla editor; документ → Joomla Media; цвет → выбор HEX через color input, с возможностью оставить значение пустым; Да/Нет → три состояния пусто/да/нет (пусто запрещено для обязательного).
- Заданные значения: **одиночное** — выпадающий список; **множественное** — флажки. При наличии фото выводить маленькое превью; при HEX показывать цветовой свотч. Для типа Цвет учесть отдельную настройку режима «кружок»/«кружок и текст».
- Атрибуты информационные, не создают SKU. Только **опции** создают сочетания SKU, поэтому выбор значений характеристики не меняет остатки.

## 3. Миграция без потери данных — обязательные этапы

1. Новый независимый `value_source = legacy/manual/preset` либо эквивалентное поле, без принудительной смены старого `input_mode`. Старые характеристики работают по старой логике до явной безопасной конверсии. `is_multiple` сохраняет выбранную кратность.
2. Для универсальных значений добавить typed `value_payload` (HTML, путь документа или число), не помещать длинный HTML в `title`; существующие `value_id`, `code`, `sample_image`, `color_hex` не изменяются. Код остаётся уникальным в пределах характеристики.
3. Ручной цвет хранить типизированной scalar-строкой с проверкой `#RRGGBB`; значение из справочника хранить ссылкой на `attribute_values.id`, не текстовой копией.
4. Сохранение вариантов характеристик: переиспользовать существующие `product_attribute_options` для одиночного/множественного выбора по ID. Для ручного HTML/файла валидировать MediaPath, HTML и размер и сохранять scalar. Обязательность и допустимую категорию перепроверять на сервере.
5. Перевод уже используемой характеристики между источниками или из нескольких значений в одно — только после проверки текущих товаров; при несовместимости — ошибка с перечислением, не автоудаление.
6. Storefront: отображение строки, картинки, цвета, HTML и ссылки на файл; адаптация фильтров. Микроразметка/фиды должны брать отображаемое значение, а не внутренний ID.
7. PHP 8.4/8.5, MySQL 8 upgrade + fresh install, корректность старых product IDs и category mappings, тесты обратной миграции, браузерная приёмка.

## 4. Независимая матрица опций

У товара сначала выводится перечень назначенных категории опций и кнопка открыть категорию/назначение. Ниже — компактная матрица:

| Цвет | Размер | Артикул | Остаток | Активно |
|---|---|---|---:|---|
| Синий | S | ART-1 | 3 | Да |
| Синий | M | ART-2 | 0 | Нет |

При большом количестве опций горизонтальный scroll допускается **только внутри блока матрицы**. Справа закреплены три колонки «Артикул», «Остаток», «Активно». Цена — единая у товара. Одной строке соответствует один физический SKU, даже если поле артикула пустое.

## 5. Галерея

После каждой дополнительной фотографии блок «Показывать: всем / выбранным SKU»; при ограничении — перечень **активных** артикулов с галочками. Следующий отдельный блок «Главная для SKU» с галочками. Сервер не допускает два главных изображения для одного SKU. Назначения сохраняются по ID варианта, не по тексту SKU; общая обложка товара остаётся fallback.

## 6. Визуальные правила

- Переход по названию характеристики, опции, категории и товара — именно в соответствующий редактор сущности; роутинг Joomla через task=entity.edit. При необходимости нововкладочности — явно указать target=_blank, а не открывать страницу компонента.
- Панели и таблицы — одинаковые аккуратные рамки; код маленькой строкой **под** названием; публикация — отдельным столбцом; нет горизонтального скролла за пределами матрицы SKU.
- Кнопки с заливкой: зелёная «Добавить/Сохранить», красная «Удалить», синяя «Открыть/Поиск». В «Связях» явно разделять «Добавить товар», «Сохранить» и «Отменить».
- Стартовый экран MiniMarket: заголовок, короткое описание, разделы вертикальным списком, внизу заметная синяя кнопка «Открыть каталог», ведущая на site view=catalog.

## 7. Приёмка релиза 0.5.44

0.5.44 — только безопасные адресные корректировки и UI/документирование, не миграция характеристик. Сборка в `dist`: `com_minimarket-0.5.44.zip` и отдельный `minimarket_toys_rich_import.sql`. Во время обычного обновления **не импортировать** demo SQL, т.к. он заменяет данные MiniMarket. После установки Joomla Ctrl+F5; проверь ссылки и кнопку каталога, а также регрессионно матрицу, галерею и связи. Реальный браузерный тест не заменяется CI.

## Правила нумерации и статусов

- **Этап `1`** — крупный результат; **шаг `1.2`** — самостоятельная задача; **подшаг `1.2.1`** — проверяемое действие. Номера не переиспользуем и не меняем без отдельного решения. Номер ZIP (`0.3.11`, `0.4.0`) **не равен** номеру задачи.
- **Подтверждено** = проверено в реальной Joomla пользователем; **Частично** = есть ограниченная реализация/подтверждение; **CI PASS, Joomla не проверено** = код и автоматические проверки есть, но установка/работа в Joomla не подтверждены; **Не начато** = нет проверенного результата.
- **Критерий готовности** после каждого шага — условие, по которому он закрывается. Наличие файла или документа само по себе недостаточно.
- Если у шага несколько подшагов, они выполняются последовательно либо фиксируется причина изменения порядка. **Никаких непроверенных промежуточных ZIP**. После каждого связанного выпуска — GitHub CI и отдельный Joomla smoke с записью результата.
- Все данные и цены проверяются **на сервере**. Скрытые/черновые позиции не индексируются и не участвуют в заказах. **Никаких изменений ядра Joomla**; максимум штатные компоненты, модули и стандартные Joomla API.
- **Ранняя атрибутная миграция 0.4.0 ИЗОЛИРОВАНА:** код и тесты сохранены в `feature/attributes-stage6`, из устанавливаемого `development` удалены. ## Сквозные бизнес-решения, которые нельзя потерять

1. **Товар:** один product_id и canonical URL, простой товар после migration превращается в один default variant; цвет/размер — варианты, а не отдельные публичные товары. Фото точного SKU → фото цвета → общие.
2. **Комплект:** самостоятельный товарный объект с собственными ID/ценой/URL и списанием конкретных составляющих; не путать с подборками/«с этим покупают». [BUNDLES.md](BUNDLES.md).
3. **Маршруты:** плоские `/category/alias-id` и `/product/alias-id`; можно создавать сколько угодно обычных Shop menu items; одно глобальное поле в Options выбирает основной для генерируемых ссылок.
4. **Joomla:** users/ACL/media/роутинг/переводы — штатные механизмы; компонент не зависит от одного шаблона. Нет отдельного обязательного плагина ради стандартного выбора Itemid.
5. **Вход и checkout:** email — **только уведомления**, вход — телефон с кодом MAX/SMS или подтверждённые ID МТС/Сбер/Яндекс/VK; гость оформляет заказ с телефоном и подтверждением, авторизованный без повторных полей.
6. **SEO:** базовый Schema.org JSON-LD/OG на этапе 5, ProductGroup и продаваемый комплект — после этапов 7–8. «AI Schema» не существует как отдельная обязательная SEO-технология; `llms.txt` необязателен. [SEO_ANALYTICS_AI.md](SEO_ANALYTICS_AI.md).
7. **Аналитика:** единый server-driven dataLayer, адаптеры GA4 и Яндекс Метрики, purchase/refund без дублей, без PII, сумма реального заказа ≡ данные аналитики.
8. **Интеграции:** импорт/экспорт, Яндекс Товары/YML, опционально Merchant Center; платёжные операции и реальные сообщения только после согласованного безопасного тестирования.
9. **Ограничения:** `development` — единственная рабочая ветка; `main` не менять. Локальный `.osp/project.ini` пользователя не сбрасывать, Joomla core, действующую базу и персональные данные не коммитить; не выполнять `git clean/reset` ради сборки.
10. **Статус:** готовность исходников, CI и Joomla runtime — разные состояния. Ни один этап не закрывать без пользовательской проверки.

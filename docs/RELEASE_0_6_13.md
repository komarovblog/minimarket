# MiniMarket 0.6.13 — условные настройки в нативном интерфейсе Joomla

**Источник:** `komarovblog/minimarket`, `development`. Изменения не затрагивают таблицы, учётные записи и ядро Joomla. Установочный `com_minimarket-0.6.13.zip` собирается штатным `scripts/release-to-desktop.ps1`. Результат CI и реальной проверки в админке Joomla фиксировать отдельно — наличие коммита не равнозначно принятию в браузере.

## Что исправлено

- При выборе гостевой покупки `checkout_auth_mode=guest` настройка `checkout_verification_method` скрывается штатным `showon`; для `guests` и `all` появляется сразу при смене режима. Информационный блок уже работал по такому же условию.
- В настройках checkout скрываются описания отключённых шагов; при выключении блока данных покупателя скрываются его поля, а при выборе «Скрыто» для телефона — его маска. Видимость кнопки входа остаётся независимой настройкой.
- Отзывы: при выключении раздела зависимые настройки скрыты. Сетка категорий и товара: настройки колонок скрываются при выключенном списке/режиме «Список». Опции дочерних товаров/комплектов видимы только при соответствующем показе; индивидуальная категория учитывает вариант «Наследовать».
- Товар/комплект: скидка от суммы показывает только процент; флажки показывают настройки отображения/сроков только в активном состоянии. При смене цены комплекта несовместимые флаги Sale и Benefit скрываются, как и раньше обнуляются только при смене на несовместимый тип цены. Вес/объём доступны физическим товарам.
- Характеристики: значения выбора нельзя открыть у логического типа. Дополнительные поля checkout показывают маску только для text/tel, варианты только для select; сервер игнорирует сохранённые значения параметров, которые не относятся к новому типу поля.
- SKU-варианты: описания и видео появляются только при явном выборе собственных, не при наследовании.
- Специальные редакторы: в тарифе зоны доставки ставка за единицу показывается только при тарифе по весу/объёму, а в настройках email-уведомлений события появляются только при активном канале. Для таких HTML-форм применяется минимальный JS без собственного дизайна; ранее сохранённые значения остаются.

В витрине `CategoryDisplayOptions::resolve` также нормализует эффективные значения: отключённое отображение товаров/комплектов не может включить скрытую настройку потомков, а фильтр остатков не работает при глобально выключенном учёте склада. Сохранённые значения не стираются.

Для стандартных форм используются только штатные `showon` и `renderField()/renderFieldset()`. Специальные редакторы SEO/фидов и защита складских остатков продолжают использовать специализированные механизмы из-за отличающегося поведения; см. `docs/SETTINGS_REGISTRY.md`.

## Проверки

`php scripts/test-0-6-13-conditional-settings.php` — валидность XML, условия, нормализация маски/вариантов, манипуляции с флажками и миграция без DDL. Проверка запускается в GitHub Actions. После установки вручную проверить переключения без перезагрузки в стандартном Atum (RU/EN, светлая/тёмная темы), сохранение существующих значений, случай старых записей и форма дополнительных полей.

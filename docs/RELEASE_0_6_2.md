# MiniMarket 0.6.2 — SEO-страницы с трёхсостояниями фильтров

**Основание:** MiniMarket 0.6.1, `development`. Реализация НЕ меняет ядро Joomla, Blank, checkout, товары, остатки и существующие тексты/URL SEO-страниц. Отдельная миграция `admin/sql/updates/mysql/0.6.2.sql` добавляет nullable `conditions_json`. Публикуется самостоятельный `mod_minimarket_toolbar` 0.6.2. Для обновления использовать **обычный ZIP компонента и бэкап БД**.

## Правило выбора

Каждая SEO-страница принадлежит **одной опубликованной категории**. Для каждого фильтра из характеристик/опций этой категории и применимых системных фильтров доступны 3 состояния:

1. **Не использовался (unused)** — фильтр не должен присутствовать среди реально выбранных в каталоге. Состояние по умолчанию, в JSON не записывается.
2. **Не имеет значения (any)** — фильтр **обязательно должен быть применён** пользователем, но допускается любое значение и несколько значений, если фасет разрешает множественный выбор. Отсутствующий фильтр НЕ подходит.
3. **Конкретное значение (exact)** — фильтр применён и выбрано **ровно одно** значение. Для числового фильтра — один фиксированный диапазон min/max; для текстового — одна строка. Одна страница обязана иметь хотя бы один exact.

`conditions_json` хранит только `any/exact` (неиспользованные отсутствуют), например:
```json
{"a10":{"mode":"exact","value":"v:101"},"s20":{"mode":"any"}}
```
Это означает: категория + атрибут a10 равен v:101 + опция s20 применена с любым значением; **все остальные фильтры отсутствуют**. Нельзя сохранять два значения цвета как один exact.

Сортировка, отображение список/плитка, pagination и количество товаров на странице **не являются условиями**. Логика сравнивает нормализованную сервером `FacetedCatalog::selection` по тем же SKU-совместимым правилам, что и обычная витрина.

## Специфичность и пересечения

Сначала выбирается совпадающая страница с **наибольшим числом exact**. `any` ниже exact. Сайт не выбирает страницу по ID/дате. При сохранении опубликованной страницы и при отдельном действии «Опубликовать» проверяются страницы **этой категории**. Если два правила могут совпасть на одной фильтрации **с одинаковым числом exact**, публикация блокируется с понятным сообщением. Например:
- a10=Красный, s20=любое значение;
- a10=любое значение, s20=M.
Оба совпали бы на «Красный + M» с одним exact. Нужно изменить условия. Более частное «Красный + M» (два exact) законно и имеет преимущество.

Блокировка проверяется под транзакционной блокировкой строки категории, поэтому две параллельные публикации не должны обходить проверку. **Проверяются три пути:** сохранение опубликованной страницы, публикация одной страницы и массовая публикация нескольких страниц; массовый обработчик проверяет конфликты и внутри выделенной группы до общего обновления.

## Витрина, URL, canonical и wildcard

Новый редактор сохраняет `conditions_json` (правило), а `filters_json` — **точные фильтры для прямого URL страницы**, то есть без `any`. Это позволяет одному красивому URL быть базовой страницей для «Красные футболки любого размера», а фильтрация «Красный + размер M» ведёт на этот URL с mmf-параметрами для размера. Такие уточнённые варианты всегда `noindex,follow`, canonical ведёт на чистый URL SEO-страницы. Непосредственное открытие чистого URL показывает точные фильтры и все размеры, не подставляя фиктивный размер. Если подходящая фильтрация относится к более точной странице, браузер/GET переходит на её URL.

Обычная категория без совпавшей SEO-страницы сохраняет прежний фильтрованный GET и `noindex,follow`. AJAX обновляет всю страницу при смене маршрута, чтобы H1, Title и canonical не оставались от предыдущей страницы. При изменении фильтров на SEO-странице форма ведёт в категорию и заново выполняет подбор подходящего landing.

## Совместимость с 0.6.1

Старые `filters_json`, тексты, publication и URL **не меняются**. Их `conditions_json` после миграции = NULL, поэтому они открываются как раньше, но **не подключаются автоматически к сопоставлению новых правил**. При редактировании прежние одиночные значения превращаются в exact для отображения. Если было несколько значений одного фильтра, редактор предупреждает и требует от администратора осознанно выбрать новое правило; ни одно значение не выбирается молча. После сохранения новая страница использует трёхсостоянийную модель. Старые SEO-страницы не удаляются и не деиндексируются миграцией.

## Предохранители

- Сервер повторно валидирует правила, категории и доступные им значения. Нельзя привязать чужой атрибут/опцию или произвольную строку URL.
- Только опубликованные категории/товары и доступные активные SKU участвуют в выдаче. Когда точные фильтры больше не доступны, SEO-страница становится `noindex`.
- У редактора ровно один выбор для exact, а не чекбоксы множественных значений. Системные диапазоны `price`, наличие `stock` и SKU имеют те же три состояния. Числовые и текстовые характеристики поддерживают фиксированное значение/диапазон.
- Отдельная автоматическая стратегия ссылок, sitemap-рекомендаций, редиректы для старых URL, внешняя проверка индексации и массовая генерация SEO-страниц **не добавлялись**. Не представлять это как реализованное.
- Важно проверить на локальной Joomla 6 RU/EN, светлую и тёмную тему, новые/старые страницы, опцию Цвет и SKU-совместимость, пересечение любых/конкретных правил, AJAX переходы, robots/canonical; автоматический CI не заменяет браузерную приёмку.

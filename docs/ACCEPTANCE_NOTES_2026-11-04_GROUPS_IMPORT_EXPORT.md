**Дата:** 04.11.2026. **Статус:** утверждённые пользовательские замечания и требования к будущей разработке. **Ничего из пунктов ниже не реализовано этим документом.**

Пользователь сообщил: «Остальное вообще хорошо». **Сохранить без изменений** существующие поля, навигацию на сущности, матрицу SKU, изображения/галерею, характеристики/опции, категории, состав связей, цены, остатки и интерфейс остальных разделов. Нельзя начинать другие доработки, рефакторинг, миграции, перевёрстку, создание ZIP/релиза или запуск обновления без новой прямой команды пользователя. Работа только в `development`, `main` и ядро Joomla не трогать.

## 1. Явная кнопка «Развернуть / Свернуть» у каждой связи товара

По приложенному скриншоту вкладки **Товар → Связи товаров** сейчас видна свёрнутая строка «Настенные механизмы (#909), 6 · Товары в связи», а действие раскрытия недостаточно очевидно.

**Требование на будущий этап:**
- В каждой строке связи — **отдельная, видимая** кнопка «Развернуть» / «Свернуть» с chevron/иконкой и корректной подписью; по состоянию меняется надпись и `aria-expanded` (возможна нативная Joomla-кнопка или `details` с доступным управлением).
- Нажатие на **название связи** по-прежнему должно открывать редактор самой связи, а не разворачивать строку и не вести на dashboard. Раскрытие — отдельное действие без конфликта кликов.
- В свёрнутой строке оставить название, ID и количество товаров; в раскрытой — существующие элементы редактирования и кнопки без изменения логики сохранения.
- Не изменять порядок связей, их ID, состав товаров, существующие кнопки «Добавить связь» / «Добавить существующую связь», серверное сохранение и удаление.
- Должно работать с мышью, клавиатурой и в мобильной адаптации; RU/EN.
- **Критерий приёмки:** из свёрнутой строки очевидно как раскрыть; после раскрытия видно как свернуть; название отдельно открывает реальную сущность.

## 2. Импорт — понятный интерфейс и Excel

**Факт текущей реализации (проверено в исходниках 0.5.46):**
- Админка `MiniMarket → Импорт`: только **JSON-пакет v1** (`accept=.json,application/json`, сервер требует расширение .json; максимум 3 МиБ), сценарий загрузка → предпросмотр/проверка → подтверждение применить либо отменить.
- Частично поддержаны категории, характеристики, опции, простые товары, связи и назначения сущностей категориям. Не реализована загрузка всех данных SKU/медиа и других будущих сущностей.
- **XLSX/CSV не поддерживаются**, **экспорта нет**.
- Текущая ссылка «Пример» ведёт на GitHub (`examples/import-catalog-v1.json`) — пользователь просит убрать эту зависимость из админки.

**Требование на будущий этап:**
- Поддержать **Excel .xlsx** как основной удобный табличный формат; добавить CSV и оставить JSON для автоматического обмена.
- Предоставить **понятную пошаговую инструкцию прямо на странице**: что можно загрузить, допустимые форматы, что означают столбцы, как устроены связи категорий/опций/значений/SKU и что будет при повторном импорте.
- **Все примеры и шаблоны скачиваются непосредственно из установленного компонента**: без переходов на GitHub, без внешних сервисов и без необходимости смотреть исходники. Это относится к JSON, Excel и CSV, включая заполненные образцы и пустой шаблон.
- Предусмотреть вкладки или отдельные логические блоки: «Импорт», «Экспорт», «Примеры и инструкция»; финальный UX уточнить на этапе реализации, не вводить лишних экранов. Отобразить только реально поддержанные форматы.
- Для Excel предусмотреть понятную модель нескольких листов: сущности/значения/назначения, стабильные ключи внешних записей, сохранение русских текстов, ID-связей, чисел, цен и ведущих нулей в SKU. Схему согласовать перед реализацией.
- Сохранить безопасный двухшаговый импорт **предпросмотр → применить** с наглядными числами создания/изменения/связывания, причинами ошибок, транзакцией/откатом, сохранением текущих данных. Никогда не уничтожать неприсутствующие строки «по умолчанию» и не переопределять чужие связи/SKU.
- Реализовывать поддержку новых разделов каталога одновременно с их импортом, не выдавая неполный импорт за поддержку всего каталога.

## 3. Экспорт — полноценный парный механизм

**Пока не реализовано.** Требование на будущий этап:
- Отдельный раздел **«Экспорт»** в MiniMarket и явные действия «Экспортировать» и «Скачать файл», с указанием доступных форматов **Excel (.xlsx), CSV, JSON**.
- По возможности общий экспорт каталога и экспорт выбранных разделов (категории, товары, характеристики, опции, связи и др.), с фильтрацией/статусом публикации; точный набор выбирается после согласования UI.
- Формат экспорта и импорта должен быть **совместимым и воспроизводимым** (round-trip). Сохранять устойчивые ключи и отношения, реальные ID где это необходимо, типы значений, единицы, SKU, остатки, цены, публикацию; не терять связи при переносе.
- На витрине и в экспорте не смешивать **характеристики** (информационные данные) с **опциями** (выбор и SKU).
- Для изображений, файлов и видео отдельно определить правила экспорта ссылок/путей и вложенных файлов; не обещать перенос медиа, пока не будет отдельно реализован и проверен.
- Безопасность: права доступа, защита выгрузки, валидация форматов, отсутствие уязвимых формул Excel/CSV, ограничения размера и потоковая работа при больших каталогах, RU/EN.
- Тесты: пример внутри компонента доступен без интернета, импорт XLSX/CSV/JSON, проверка ошибок, повторная загрузка без дублирования и экспорт → импорт в чистую БД (проверить взаимосвязи и отсутствие потери SKU).

3. Добавить Excel/CSV импорт и расширить полноту импорта по сущностям; обеспечить безопасный preview/rollback.

# MiniMarket 0.5.90 — единые нативные списки Joomla 6

**Эталон:** стандартные «Материалы» и «Категории» Joomla 6, не самодельная имитация.

## Область изменений

**Только страницы списков сущностей.** Карточки редактирования, оформление заказа, тарифы и схема БД в эту итерацию не входят.

| Нативные списки на Joomla ListModel | Списки, переведённые на штатные Joomla SearchTools |
|---|---|
| Категории, Товары, Комплекты | Заказы, Доставки, Отзывы |
| Характеристики, Значения, Опции | Промокоды, SEO-страницы, Зоны доставки |
| Бренды, Коллекции | Фиды, Интеграции |
| Связи товаров, Связи комплектов | Способы доставки, Способы оплаты |

**Всего: 20 списков.** В десяти списках на ListModel уже используется `joomla.searchtools.default`; в остальных десяти используется адаптер `NativeListTools`, создающий нативную форму Joomla с полями фильтра и сортировки и отображающий **тот же core layout**, а не отдельную вёрстку MiniMarket.

## Единый контракт

1. Заголовок страницы и действия — стандартная Toolbar Joomla сверху, без повторного заголовка внутри списка.
2. Поиск и «Параметры поиска» — `joomla.searchtools.default`. Дополнительные фильтры зависят от сущности и реально влияют на выборку в её серверном представлении/модели.
3. Сортировка и размер страницы — поля штатной формы Joomla; десять списков с собственной выборкой используют совместимость `NativeListTools::importRequest()` для принятия `filter[...]` и `list[...]`.
4. Таблица — `table table-striped`, `thead/th`, без `colspan` и `tfoot`, со штатным `table.columns` и `multiselect`; в таблицах с массовыми действиями сохранены стандартные `cid[]`, `boxchecked`, `task`, CSRF и серверные ACL.
5. Пагинация — `Pagination::getListFooter()`, не отдельный блок с «Вперёд/Назад». Иерархический список категорий может показывать дерево целиком без страницы.
6. Ширина страницы не меняется от длинной таблицы: прокрутка остаётся внутри `.mm-native-list-viewport`. Удалена последняя прежняя CSS-рамка `#adminForm .mm-admin-list`, которая принудительно добавляла толстые контуры, скругление и `border-collapse: separate`.
7. Старые самостоятельные JS-переключатели столбцов и панели поиска не загружаются. Удалены CSS-правила для этих собственных элементов. Сохраняется только функциональность самой сущности, не дублирующая Joomla.

## Контроль изменений

- `scripts/verify-admin-lists.ps1`: проверяет все 20 экранов, стандартные формы, общие файлы, массивные действия, PHP lint при доступном PHP.
- `scripts/verify-0.5.90.ps1`: защищает от возврата собственных панелей поиска, нестандартных пагинаций, CSS-рамок, режимов карточек вместо таблиц, нестандартного JS колонок; проверяет состав форм и связи.
- `scripts/release-to-desktop.ps1` запускает эти проверки **до** сборки и проверки ZIP. GitHub Actions не запускаются.
- Для фактической браузерной приёмки требуется открыть каждый из 20 списков в Joomla 6.2, проверить RU/EN, светлую/тёмную тему, 90/100/125/150%, поисковые фильтры, сортировку, переключение столбцов, страницу 2 и стандартную верхнюю панель. Статическая проверка исходников сама по себе не доказывает визуальное совпадение.

## Не изменено

- В этой версии нет новых SQL-миграций. Последняя миграция схемы — 0.5.87.
- SQL-файл для локального демокаталога необязателен, импортировать его для исправления интерфейса **не нужно**.
- Отдельная ошибка Joomla Database Maintenance остаётся открытым вопросом, не нажимать «Исправить» без backup.

## Сборка из CMD (одна строка)

В каталоге `C:\OSPanel\home\minimarket.local`:

```cmd
git pull --ff-only origin development && powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\release-to-desktop.ps1 -SkipPull
```

Ожидаются `com_minimarket-0.5.90.zip`, `mod_minimarket_toolbar-0.5.90.zip` и опциональный SQL для версии 0.5.90. Установка и визуальное сравнение с нативными материалами/категориями пока не подтверждены.

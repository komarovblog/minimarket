# MiniMarket — системное ревью соответствия кода требованиям, 0.5.60

Дата: 06.11.2026. Проверен `development` на Joomla 6 / PHP 8.4–8.5 / MySQL 8.0 и 8.4.

## Метод и область

- Инвентаризация репозитория: **439 файлов** на момент старта, 32 таблицы MiniMarket для полного JSON-архива, ~29 административных XML-форм, 20 PHP-шаблонов администратора.
- Контрактный автоматический анализ `scripts/audit-component-wiring.php`: **14 статических ссылок task**, 9 медиа-подключений и 6 буквальных HTML-кнопок в шаблонах. Большинство кнопок/переключателей создаются *динамически* сервисами/JavaScript/классами Joomla; эти числа **не отражают все фактические кнопки**.
- `scripts/test-0-5-59-audit.php` и `scripts/test-0-5-60-wiring.php`: настройки ↔ форма категории ↔ сервис разрешения ↔ SQL, флаги ↔ сохранение ↔ выборка ↔ публичный рендер, промовидео, SKU, импорт/экспорт.
- CI: PHP 8.4/8.5 (isolated tests), MySQL 8.0 (upgrades), MySQL 8.4 (full catalog + repeated SQL + real SKU option assignments + JSON v2), Windows ZIP.
- **Браузерное тестирование живой Joomla 6.2 и ручной клик по каждой кнопке НЕ выполнялись** — проект не имеет в CI развернутой браузерной Joomla. Этот уровень нельзя подменять static code checks.

## Найденные расхождения и изменения

1. **Promo click**: требовалось разворачивание нажатием самого видео, а код 0.5.59 слушал только отдельную кнопку. **FIXED 0.5.60**, добавлены фокусировка и Enter/Space.
2. **Badge defaults**: код проверял отсутствие свойства через `??`, но затем читал несуществующее поле напрямую — предупреждения на старых данных/тестовых объектах. **FIXED 0.5.60**, покрыто строгим PHP-test.
3. **Демо media**: 0.5.59/0.5.60 SQL ссылается на `images/minimarket/sample-01.png`…`sample-20.png` и `demo-promo.mp4`, но файлы физически не создаются SQL. **EXTERNAL STEP**, создан отдельный ZIP из 20 тестовых иллюстраций и короткого MP4 (без изменения файлов Joomla). Распаковывать в корень сайта, не перезаписывать свои фотографии.
4. **Фронтенд SKU**: JS-переключатели wired, SQL-данные согласованы с product-local variants; **реальный браузерный симптом пользователя ещё не воспроизведён**. При браузерной ошибке нужны URL товара, скриншот и консоль браузера.
5. **Купить** в промо и карточке: пока отсутствует backend корзины/заказа, поэтому disabled преднамеренно. **OPEN, новая подсистема**, не подменять фальшивой кнопкой.
6. **Импорт/экспорт 100% магазина**: JSON v2 действительно передаёт все 32 SQL-таблицы с SEO/SKU/связями, но изображения/MP4 не включены, разная схема/идентичность отклоняется ради сохранения данных. **PARTIAL**, перенос медиа и версионная миграция формата отдельно.
7. **Сквозной E2E**: CI тестирует обработчики/данные и packaging, но не выполняет клики на Joomla с авторизацией. **OPEN** — предусмотреть Playwright с отдельной Joomla и тестовой DB, затем регрессии на mobile/tablet/desktop, диалоги, ввод и сохранение.

## Режим поставки

`development` only. Версия `0.5.60`. `scripts/release-to-desktop.ps1` кладёт ZIP и SQL на рабочий стол. SQL применяют после установки ZIP (он не обновляет схему; миграции применяет Joomla). Медиа ZIP загружается отдельно; Joomla Media не изменяется скриптом автоматически. Никогда не запускать CI миграции против рабочей БД. Схема/данные не удаляются.

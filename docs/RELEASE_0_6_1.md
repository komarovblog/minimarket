# MiniMarket 0.6.1 — безусловный пропуск шагов и текст согласия

**База:** 0.6.0 (commit `d0c67dfb5cc234d5845185c51aa8a9042af3cef8`), `development`. Обновляются `com_minimarket` и самостоятельный `mod_minimarket_toolbar` до 0.6.1. **SQL-миграция не нужна:** параметры Joomla и существующие VARCHAR-поля заказа позволяют хранить новые состояния.

## Правила, принятые пользователем

- **Каждый из четырёх шагов оформления** (Покупатель, Доставка, Оплата, Цифровая выдача) можно отключить **безусловно**, без принудительного требования заполнить другие данные или выбрать способ. Администратор принимает риск неполного заказа.
- Если данные покупателя отключены, гость может оформить заказ с пустыми именем/телефоном/email/дополнительными полями. Никаких поддельных персональных данных. При включённом шаге прежние правила ввода и серверной валидации сохраняются.
- При отключении физической доставки `delivery_method='pending'`, `delivery_fee_cents=0` (ещё **не рассчитано**, а не подтверждённая бесплатная доставка), тариф отсутствует. При отключении оплаты `payment_method='pending'`, `payment_status='unpaid'` без фиктивной оплаты «при получении»/«переводом». Полностью цифровая корзина не требует физической доставки.
- Выключенный шаг не рисуется и не обрабатывается по подделанным параметрам POST. При включённом шаге выбор/адрес/оплата продолжают проверяться. При отсутствии email цифровая выдача ждёт решения менеджера; заказ не получает статус оплаченного от одного клика «Оформить».
- **Подтверждение покупки кодом не является настраиваемым шагом.** Настраивается только `checkout_auth_mode=guest/guests/all`. Для `all` ввод OTP отображается независимо от состояния всех четырёх шагов. Регистрация/способ подтверждения — в разделе «Регистрация». Не путать подтверждение личности с оплатой.
- В нижнем итоговом блоке, непосредственно **перед кнопкой «Оформить заказ»**, добавлено `checkout_consent_text`: встроенный HTML-редактор Joomla с гиперссылками на правила, договор и политику. **Без отдельного шага «Подтверждение заказа» и без чекбокса.** Поле сохраняется как параметры компонента и безопасно фильтруется Joomla. Для ранее введённого `checkout_confirmation_description` предусмотрен fallback, сохранённые настройки не уничтожаются. Устаревшие `checkout_require_terms` и `checkout_terms_itemid` удалены из видимой формы и больше не применяются.

## Сквозные связи

`admin/config.xml` → параметры `com_minimarket` → `CheckoutSettings::step` / `CheckoutDelivery::checkoutQuote` / `CheckoutData::normalize` → `CheckoutController::preview/submit` → `OrderStorage` → запись `pending` / `unpaid` → карточка заказа. Согласие: `checkout_consent_text` → `View/Checkout/HtmlView` → `site/tmpl/checkout/default.php`. Код покупки: только `CheckoutSettings::requiresPurchaseCode`, не отключается вместе со шагами.

## Обновление

Перед обновлением резервная копия БД. Команда пользователя едина и работает из любой директории CMD/PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

После выполнения установить `com_minimarket-0.6.1.zip` через Joomla; ZIP toolbar устанавливать отдельно по необходимости. DEMO SQL не импортировать в рабочую БД.

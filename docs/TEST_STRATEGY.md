# MiniMarket — автоматизированное тестирование

Зафиксировано 06.11.2026. Цель: покрывать **критические сценарии**, а не только проверять наличие файлов. Каждая итерация добавляет регрессионные тесты и завершается успешным CI на `development`.

## Уже действующие уровни

1. **Модульные и контрактные проверки PHP 8.4 / 8.5**: модели категорий, публикация, SKU, атрибуты, редакторы, комплекты, импорт/экспорт, параметры отображения и наследование. Выполняются в GitHub Actions на двух версиях PHP.
2. **JavaScript**: синтаксис `node --check`, функции зависимостей SKU; сейчас проверяется в т.ч. новый редактор состава комплекта. **Синтаксис не доказывает корректный внешний вид!**
3. **MySQL 8.0 и 8.4**: создание и обновление схемы, сохранность старых данных, целостность связей, цена/остатки комплектов, повторный импорт одного накопительного файла, отсутствие дублей. Тесты запускаются только в изолированных CI БД.
4. **Windows PowerShell**: `build.ps1` создаёт установочный ZIP; `inspect-package.ps1` проверяет содержимое, имена файлов и Joomla manifest. SQL выгружается *рядом* с компонентом, но не внутри него.

## Что внедряем дальше: обязательные настоящие E2E

В CI добавить самостоятельную установку Joomla 6 с временной MySQL 8.4 БД, тестового пользователя и Playwright. Автотесты выполняются в браузерах Chromium и WebKit (позже Firefox), на desktop/tablet/mobile.

Критические сценарии:
- Сохранение и повторное открытие глобальных `Общие`/`Категории`; восстановление глобальных значений и локальное переопределение одной категории.
- Вложенные категории глубиной >= 3; выключенные родительские/дочерние категории; разные комбинации видимости собственных товаров, комплектов и вложенных товаров; отсутствие дублирования.
- Режим `Список`/`Плитка`; 1–6 карточек на экранах 375/768/1024/1440 пикселей; без переполнения и со снимками экрана.
- Комплекты: таблица с выровненными колонками, добавление/удаление компонента, смена количества, сумма и процент скидки; сверка вкладок Основное/Состав, сохранение/перезагрузка.
- SKU: доступность сочетаний, фото, суммы, фильтры, навигация, ссылки и URL.
- Импорт/экспорт: полный round-trip и повторный импорт без дублей (временно только поддерживаемые поля v1; **полный v2 ещё не готов**).
- Отсутствие доступа к неопубликованным товарам, защита от XSS/CSRF, ACL административных действий.
- Обновление компонента на БД предыдущей версии, контроль сохранности данных.

E2E **пока не реализованы и не должны обозначаться PASS**. Скриншоты пользователя, PHP-моки и Windows ZIP не заменяют реальный браузер.

## Приёмочные критерии

- Каждая новая функция: unit + интеграционный тест на MySQL (если меняет данные), JS тест (если есть интерактивность), позднее E2E.
- CI полный, `main` не менять, стабильность PHP8.4/8.5 + MySQL8.4.
- UI на Joomla 6.2: проверка вручную до внедрения E2E.
- Новые/изменённые поля: тест миграции с уже заполненными данными и тест чистой установки.
- Выпуск: `com_minimarket-X.Y.Z.zip` и `minimarket_mysql84_nnop3_update_X_Y_Z.sql` на рабочий стол через `scripts/release-to-desktop.ps1`, SQL импортируется только вручную.
- Для 100%-го покрытия всех сценариев потребуются отдельные тесты внешних интеграций и браузера; текущие автоматизированные тесты частичные. Процент покрытия не утверждать без отчёта инструмента покрытия.

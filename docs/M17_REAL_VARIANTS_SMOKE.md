# MiniMarket 0.5.17 — реальные SKU-варианты

Статус: код в ветке `development`. PHP/Windows/MySQL CI — отдельная автоматическая проверка; реальное тестирование Joomla подтверждает пользователь после установки.

## Модель

- Один товар и один SEF URL независимо от цвета, размера, варианта.
- На вкладке «Характеристики» есть общий набор свойств, например «Материал: Металл + Камень». Это **не** отдельные SKU.
- У свойств `Цвет`, старого `List` или `Текст → готовые значения` можно включить «Различает варианты товара». Так можно создать новый размер S/M/L даже после отказа от отдельного типа List.
- В карточке товара вкладка «Варианты»: нативная Joomla Subform с перетаскиванием, плюс/минус строк; для каждого SKU выбирается по одному значению всех активных вариантных осей, собственная цена, остаток (0 допустим), главное фото, дополнительные фото, описание фото, публикация.
- Два новых отношения `product_variants` и `product_variant_images`, миграция `0.5.17.sql` без изменения продуктов, галереи, старых характеристик и URL. Каждая комбинация имеет SHA-256 подпись и UNIQUE на (`product_id`,`signature`); SKU не повторяются внутри товара. При редактировании существующего варианта сохраняется его ID. Физические файлы Joomla Media никогда не удаляются.
- Публичная карточка показывает только опубликованные комбинации с опубликованными характеристиками и допустимыми значениями; выбор существующего варианта меняет SKU, цену, остаток и фото в DOM без навигации. Нет заказа/корзины на этом этапе. Не более 4 осей и 200 комбинаций на товар.

## Ручной Joomla smoke

1. Создать опубликованный «Цвет» (красный, синий) + «Размер» типа **Текст → готовые значения** (S, M, L); у обоих включить «Различает варианты» и назначить категорию.
2. Создать товар, сохранить базовые поля (SKU, цену, остаток, главное фото). Вкладка «Варианты»: Add (красный + S, SKU RED-S, цена 1590, остаток 5, фото); второй Add (красный + M, SKU RED-M, цена 1790, остаток 10); третий Add (красный + L, SKU RED-L, остаток 0). Добавить хотя бы два фото к одному варианту.
3. Сохранить и открыть снова: комбинации, цены, количества, фотографии и порядок должны остаться. На сайте выбрать M/L: SKU/цена/остаток/фотографии меняются, URL остаётся тем же. L показывает «Нет в наличии». Выбор несуществующих комбинаций не создаёт SKU.
4. Попробовать повторить комбинацию или SKU, подменить значение справочника, отправить отрицательную цену/остаток, опасный путь фото — сохранение должно быть заблокировано без потери старых данных.
5. Проверить товар без вариантов и обычные многозначные характеристики «Металл + Камень»: прежняя витрина сохраняется.
6. Если редактировать оси, к которым уже привязаны SKU, убедиться, что не происходит молчаливой потери вариантов. Тест RU/EN. Резервную копию БД делать до установки обновления.

Замечание: товарные атрибуты и SKU-варианты пока независимые разделы редактора. Автоматический расчёт остатков всего товара из SKU и матрица генерации всех возможных комбинаций — дальнейший шаг; основным источником доступности конкретного SKU уже служит остаток варианта.

# MiniMarket 0.5.10 — значения List как повторяемое поле

**02.11.2026.** По новому уточнению пользователя общее управление значениями списка **упрощено**: вместо трёх вкладок, отдельного экрана и числового порядка — такое же стандартное Joomla Subform, как в галерее. **Реальное Joomla UI NOT RUN, пока пользователь не подтвердил установку.** Исходники и автоматические PHP/MySQL/Windows ZIP checks — отдельно в GitHub Actions.

## Реализация

**MiniMarket → Attributes → Цвет** — основная вкладка **Attribute**. В её нижней части при **Value type = List** находится одно повторяемое поле «Значения». Каждая строка: **Название**, **Код** (необязательно, создаётся автоматически при первом сохранении), **Статус опубликовано/снято**. Кнопки стандартной Joomla Subform — **+ Добавить**, **− Удалить**, **переместить строку за маркер**; порядок строк = \`sort_order\` в справочнике.

- **Без переходов** в отдельный список, отсутствует отдельная вкладка Values/Значения. В общем списке характеристик убрана отдельная колонка Edit values: пользователь просто открывает характеристику по названию.
- Новый List можно создать вместе с первыми значениями **одним Save**, без промежуточного сохранения характеристики.
- Значения из старого словаря \`#__minimarket_attribute_values\` загружаются в поля **со своими существующими ID**. При редактировании ID сохраняется. Название, код и публикация меняются в той же записи; при перетаскивании обновляется \`sort_order\`, физически значения не дублируются.
- Если код не задан, при первом сохранении система создаёт стабильный slug из названия посредством Joomla transliteration, иначе безопасный ASCII-код из детерминированного хеша. При следующем редактировании уже сохранённый код остаётся; существующие коды не переписываются без явного изменения.
- Удалённая строка удаляет запись **только если она не привязана к товарам**. Если связана с хотя бы одним товаром, сохранение **отклоняется и откатывается**, чтобы не обнулить выборы цветов/размеров. Другие характеристики и списки не затрагиваются. В исключительных случаях DB FK — дополнительная защита.
- Список не связан с SKU-комбинациями пока не реализован этап 7. Общий словарь цветов/размеров остаётся ID-based, без копирования данных на товар.
- При **Text, Number, Yes/No** повторяемое поле скрыто и новых значений справочника у этих типов нет. Их значения вводятся непосредственно у товара, как прежде.
- Категории, товары, SKU, цена, остаток, путь изображения и прочие поля не меняются. Новых SQL-миграций и изменений Joomla core **нет**.
- RU/EN поля и ошибки. Внутренний устаревший standalone Values экран остаётся для обратной совместимости старых URL, но основной путь из MiniMarket до него больше не ведёт.

## Обновление

**Сделать резервную копию БД Joomla.** Не удалять MiniMarket, не запускать SQL вручную. В Windows CMD:

```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-attribute-value-rows.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидаемый результат: **\`PACKAGE_OK: 0.5.10 (com_minimarket-0.5.10.zip)\`**. Установить \`dist\\com_minimarket-0.5.10.zip\` через Joomla → System → Install → Extensions поверх текущей версии.

## Browser smoke в настоящей Joomla

1. Открыть **MiniMarket → Attributes → Цвет**. Должна быть основная вкладка Attribute, там — строки с уже имеющимися значениями. **Не должно быть старой вкладки Values**, кнопки Edit values и отдельного экрана.
2. Проверить сохранённое прежнее «Жёлтый»: его код/ID должны остаться прежними, даже если код был ошибочно введён. Чтобы его изменить — поправить поле Code **в этой же строке**.
3. Нажать **+**, добавить **Красный** (код пустой) и **Синий** (код \`blue\`), состояния опубликовано. **Перетащить** «Синий» вверх маркером строки. Нажать обычный Save/Apply. **Переоткрыть**: оба значения, автоматически заполненный код Красного, статусы и порядок сохранены.
4. У существующего значения поменять Title и Status, нажать Save, открыть заново. Проверить, что **ID прежний** и выбранные значения в тестовом товаре остались привязаны.
5. Удалить **только специально созданную, неиспользуемую** строку через −, сохранить. Она удалена из справочника; другие значения не меняются.
6. Попытаться удалить через − значение, выбранное у тестового товара. Save должен **отклонить удаление**, не меняя ни значения, ни остальные строки, ни сам атрибут.
7. В Text, Number, Yes/No не должно быть блока повторяемых значений. Переключение обратно в List не должно потерять старые значения.
8. Существующий TEST-001, его URL, SKU, цена, остаток, категория и фото не меняются.

**Внимание:** полноценная browser acceptance подтверждается отдельно; автоматические тесты не запускают настоящую Joomla Subform.

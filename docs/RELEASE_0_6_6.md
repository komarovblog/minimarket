# MiniMarket 0.6.6 — единый интерфейс Atum, таблицы, заказы и независимый модуль 1.0.0

Ветка `development`. Без изменения ядра Joomla/Atum, без вмешательства в Blank, **без SQL-миграции**. База интерфейса и роутинг каталога остаются 0.6.5. Подробная инвентаризация: [ADMIN_UI_AUDIT_0_6_6.md](ADMIN_UI_AUDIT_0_6_6.md).

## Изменения

1. В редактировании категории на вкладке **Отображение** инфоблок «Сетка подкатегорий» отделён от нового блока **«Сетка товаров»**. Используются штатные `type=note` / `alert-info`, переводы RU/EN.
2. В категориях на вкладках **Опции / Характеристики** таблицы распределяют ширину между всеми четырьмя столбцами (32/30/20/18), используют отдельный `table-responsive`, не превращают заголовок «Опубликовано» в вертикальный столбик. Поле видимости в списке переведено на native select «Показывать / Скрывать»; данные записываются прежними значениями `v<ID>`, миграция не нужна.
3. В создании заказа кнопка удаления позиции стала компактной с родной иконкой Joomla, `aria-label` и отдельным местом в строке. Верхнее сохранение — единственная кнопка сохранения. JS добавления новых строк клонирует исправленный шаблон.
4. У специальных редакторов (доставка, отзыв, SEO, промокод, зона, фид, способы и плагины) унифицированы верхние панели кнопок: `btn-toolbar`, штатный `btn-success` Save, `btn-outline-secondary` Cancel; красный — только для деструктивных действий. Ряд редакторов на родном `FormController` продолжает использовать `ToolbarHelper`.
5. **Обязательные отмечаемые строки в списках:** обычные CRUD-разделы уже содержали `grid.checkall/grid.id`; фиды и зоны доставки получили реальные массовые publish/unpublish (у фидов также delete). Все мутации проверяют POST, CSRF, права и строго положительные ID с лимитом. У способов доставки/оплаты/регистрации — строка выбора и **только открытие одного метода** через безопасно проверенный серверный route (встроенный / реальный plugin); массовое удаление способов не существует.
6. **`mod_minimarket_toolbar` получил самостоятельную версию 1.0.0.** Это стабильный one-time module, уже установленный модуль продолжит работать без немедленной переустановки. Отдельный сборщик не зависит от версии компонента и не вызывается стандартной командой выпуска компонента.

## Команды Windows

Обычная поставка компонента после локального `git pull`, командой из корня проекта или любого каталога:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

Вывод: `com_minimarket-0.6.6.zip` и отдельный **необязательный** demo SQL `minimarket_mysql84_nnop3_update_0_6_6.sql` (не импортировать для обновления UI).

**Самостоятельный пакет модуля 1.0.0, только при первом формировании или явном выпуске:**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\build-toolbar-package.ps1"
```

Вывод: `dist/mod_minimarket_toolbar-1.0.0.zip` и копия того же ZIP на рабочем столе. Модуль устанавливается через стандартный менеджер расширений Joomla. Скрипт не вызывается при релизах 0.6.x компонента.

## Проверки

`scripts/test-0-6-6-native-admin-ui.php` — статический контракт списков, выделения, ToolbarHelper, SearchTools, редакторов, RU/EN и независимой версии toolbar. Сохранены предыдущие тесты всех версий, PHP 8.4/8.5, MySQL 8.4 и Windows release ZIP. Перед обновлением сделать резервную копию БД, хотя схема этой версии не изменяется.

**Ручная приёмка:** обязательно установить компонент локально и проверить экраны в светлой/тёмной Joomla, RU/EN, XS–XXL. Особенно скролл таблиц в категориях и сохранение выпадающих селектов; в списках фидов/зон пробовать массовые действия **на тестовых данных**; у методов выбрать одну строку и Edit. Нельзя считать UI проверенным в браузере только по зелёному CI.

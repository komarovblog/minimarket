# MiniMarket 0.5.57 — накопительное обновление демонстрационного каталога

Дата: 2026-11-06. Ветка: `development`.

## Изменения

- Новый `sample-data/minimarket_mysql84_nnop3_update_0_5_57.sql`: **единый повторно исполнимый SQL** для каталога в БД `minimarket` с префиксом `nnop3_`. Содержит категории, товары, атрибуты, словари, фотографии-ссылки, сочетания SKU, связи, бренды/коллекции, комплекты и флаги из накопительного сценария 0.5.50–0.5.56.
- На повторном запуске существующие поля/ручные правки не перезаписываются; добавляются пропущенные демонстрационные записи и связи. Предыдущие целевые демо-примеры скидок и выгод применяются только при безопасных условиях.
- До изменения записей проверяются ID и естественные ключи известных демонстрационных сущностей. При конфликте с чужой записью импорт прерывается с защитной ошибкой, а не удаляет данные.
- Новый `scripts/release-to-desktop.ps1`: `git pull`, сборка ZIP, проверка и копирование ZIP вместе с актуальным SQL на рабочий стол.
- `scripts/build.ps1` теперь требует новую версионированную накопительную SQL-поставку для каждой следующей версии. Windows CI публикует SQL рядом с компонентом.

## Запуск

Из любого PowerShell:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

Первый раз после обновления скрипт должен быть получен через `git pull --ff-only origin development`. После исполнения на рабочем столе два файла: `com_minimarket-0.5.57.zip`, `minimarket_mysql84_nnop3_update_0_5_57.sql`.

Установить ZIP поверх MiniMarket, затем сделать резервную копию БД и при необходимости импортировать SQL в phpMyAdmin. Импорт демонстрационных данных **не запускается автоматически**. Пути `sample-01.png` … `sample-10.png` в SQL не создают реальные картинки.

Файл `minimarket_mysql84_nnop3_full_0_5_56.sql` остаётся историческим fresh-only сценарием и **не подходит** для существующего каталога. Накопительный SQL не является резервной копией сайта и не предназначен для чужих ID/параметров префикса БД.

## Проверки

- Статические проверки целостности/защитного условия.
- MySQL 8.4 CI: старый демокаталог, затем импорт нового накопительного файла дважды; число сущностей не растёт, пропущенная связь восстанавливается, вручную изменённая цена сохраняется.
- Windows CI: собирается установочный ZIP и рядом публикуется версионированный SQL.
- Проверка в реальном Joomla 6 и phpMyAdmin остаётся ручной.

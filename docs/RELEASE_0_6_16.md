# MiniMarket 0.6.16 — совместимость оплаты / доставки, события и проблемы доставки

**Ветка:** development. Принятые направления C04 и C05: [COMMERCE_EXPANSION_2026_11_13.md](COMMERCE_EXPANSION_2026_11_13.md). Другие 8 направлений остаются в плане.

## Изменения

### C04. Одна матрица, в методе оплаты

- Настройки → Способы оплаты → встроенная «При получении» или «Банковский перевод» → **Совместимость**, штатная вкладка Joomla. Чекбоксы разрешённых способов доставки: Самовывоз, Курьер, а для банковского перевода также Цифровой товар.
- Совместимость сохранена непосредственно в Joomla component params: `payment_on_receipt_allowed_deliveries` и `payment_bank_transfer_allowed_deliveries`. Значение — перечисление кодов через запятую, пустое значение запрещает все сочетания для данного способа. Отсутствующий ключ после обновления использует прежние допустимые сочетания — действующие магазины не ломаются.
- У выключенного способа блок «Совместимость» скрывается, но предыдущее значение остаётся в параметрах.
- CheckoutDelivery::quote() проверяет каждую физическую / цифровую пару на сервере, а не доверяет JS. И при ручном создании заказа, и при оформлении на витрине используется ровно один серверный источник истины. JS скрывает недопустимые варианты и корректирует выбранные радио, но не определяет безопасность.
- `pending` при явно пропущенном шаге остаётся допустимым техническим состоянием; никаких фиктивных платежей/доставок не возникает.
- Плагины методов, ещё не имеющие работающего rate/payment adapter, не становятся автоматически доступными покупателю. Для них нужна отдельная подключаемая интеграция.

### C05. Факты перевозки, проблемы

- Управление → Доставки → карточка отправления → вкладка «События и проблемы доставки».
- Запись события и его даты UTC. События: передано перевозчику, прибыло в ПВЗ, вручено, неудачная попытка, истёк срок хранения, возвращено перевозчиком, проблема открыта/решена, заметка.
- Статус отправления обновляется **только** когда данное событие означает разрешённый переход. Проблема (delay/lost/damaged/address/recipient/other) имеет **собственный** статус `none/open/resolved` и не подменяет общий жизненный цикл заказа.
- Запись: серверная ACL `core.edit.state`, CSRF, строго валидированный тип, дата, комментарий, nonce, транзакция InnoDB, `FOR UPDATE`, журнал истории заказа и отдельный неизменяемый event с источником/автором. Повтор nonce для того же факта не создаёт дубля. События нового интерфейса не претендуют на ретроспективное восстановление старой истории.
- Список «Доставки» теперь содержит столбец «Проблема» и штатный фильтр SearchTools по открытым/решённым проблемам.
- НЕТ API СДЭК: ручной источник события помечен `manual`. Нет автоматического заказа перевозчику, рестока или выплаты при неудачной доставке.

## SQL и совместимость

Аддитивная миграция `0.6.16.sql`: `#__minimarket_shipments.problem_status/problem_code` и таблица `#__minimarket_shipment_events` с двумя уникальными ключами для идемпотентности. Исторические доставки остаются в прежнем состоянии; старые события не придумываются. `install.mysql.sql` обновлён для fresh install. Demo SQL, даже с названием 0.6.16, **НЕ импортировать** для обновления компонента.

## Установка

Сделать резервную копию БД. Одна стандартная команда:
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"`

Установить `com_minimarket-0.6.16.zip`. Joomla выполняет SQL upgrade, дополнительные demo SQL не нужны.

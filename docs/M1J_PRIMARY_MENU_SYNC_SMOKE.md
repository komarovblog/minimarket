# MiniMarket 0.3.9 — единый пакет компонента и синхронизации основного пункта меню

**Дата:** 01.11.2026. **Статус:** исходники опубликованы в GitHub `development`; **PHP lint + автотесты + Windows ZIP CI PASS** на `7b11e440`. Реальный Joomla 6.2/OpenServer runtime **NOT RUN**.

## Новый согласованный интерфейс
Администратор может создать **сколько угодно обычных опубликованных** пунктов `MiniMarket → Магазин`. В настройках одного из них включает **«Использовать этот пункт для ссылок на товары и категории» = Да**. При сохранении Joomla автоматически снимет этот флажок с других пунктов MiniMarket; **не** изменит их alias, публикацию, настройки категорий/товаров/модулей/сортировки и не затронет пункты других компонентов.

Если администратор снимает флаг с единственного активного пункта, другие пункты не включаются автоматически: роутер использует предусмотренный fallback (MiniMarket на главной → пункт с наименьшим ID). **Не ограничивать число пунктов меню.**

## Почему нужен небольшой плагин
Joomla сохраняет пункты через **штатный** `com_menus`, а не `com_minimarket`. Добавлен малый `content`-плагин `plg_content_minimarketmenu`, подписанный на Joomla 6 событие `onContentAfterSave` / контекст `com_menus.item`. Он срабатывает только при сохранении **опубликованного** обычного `MiniMarket → Магазин` с флагом **Да**; обновляет исключительно `params.shop_primary_route` других Menu Items того же компонента, используя их `component_id`. Изменяются только JSON-параметры пунктов Joomla (их сущностей); **не SQL-схема, не Joomla core, не товары/заказы**. Через `Table::store()` остальных пунктов не проходит, поэтому нет рекурсивного вызова события. Если `Save as Copy` создаёт неопубликованный пункт, он не перехватывает основной URL.

Служебный плагин устанавливается как отдельное расширение Joomla внутри **одного пакета**, и его нужно **один раз включить** в Joomla после первой установки. Если отключить — старое детерминированное поведение роутера остаётся, но автоматическое снятие других флажков **не будет работать**. Плагин не создаёт никаких скрытых menu anchors и не меняет Joomla core.

**Ограничение версии 0.3.9:** автоматическая синхронизация вызывается при обычном **сохранении** menu item с Да. Отдельное действие «Опубликовать» для ранее созданного неопубликованного пункта без повторного сохранения его формы не проверено и в этом выпуске не гарантируется; при таком сценарии открыть пункт и сохранить с Да. Работа в мультиязычном режиме и при конкурентном сохранении двух администраторов тоже требует отдельного реального smoke.

## Состав одного ZIP
- `dist/pkg_minimarket.zip` — **устанавливать этот файл**. Пакет включает `com_minimarket.zip` (компонент 0.3.9) и `plg_content_minimarketmenu.zip` (плагин 0.3.9). Ранее установленный компонент обновляется поверх предыдущей версии, **не удалять** старый компонент.
- `dist/com_minimarket.zip` — отдельный компонент только для диагностики/восстановления, **сам по себе не устанавливает плагин**.
- `dist/plg_content_minimarketmenu.zip` — отдельный плагин, в обычном сценарии не устанавливать отдельно.

Ранее работающий MiniMarket 0.3.8, выборка всех товаров, базовые URL/canonical и все пользовательские данные сохраняются. В 0.3.9 нет миграций БД товара/вариантов и нет 301 legacy URL.

## Подготовка и установка — один цикл

В CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-router.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-catalog.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-menu-sync.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-package.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package-bundle.ps1
```

Ожидаем `ROUTER_TEST_OK`, `CATALOG_TEST_OK`, `MENU_SYNC_TEST_OK`, `PACKAGE_OK: 0.3.9`, `BUNDLE_OK: 0.3.9`. В GitHub Actions на Windows и PHP 8.4/8.5 эти проверки уже PASS. Если локально хотя бы одна ошибка — **не устанавливать ZIP**. Известный локальный `.osp/project.ini` не сбрасывать и не делать `git reset` / `git clean`.

1. В Joomla **Система → Установка → Расширения** загрузить **`dist/pkg_minimarket.zip`** поверх текущего MiniMarket, **не** `dist/com_minimarket.zip`. Никакого удаления компонента/пункта меню/БД.
2. Проверить наличие **Content — MiniMarket — primary shop menu** (русская подпись «MiniMarket — основной пункт меню») в **Система → Управление → Плагины**. **Включить плагин**, если после первого пакетного обновления он выключен по умолчанию.
3. Проверить, что и `/`, и `/catalog` могут быть обычными опубликованными пунктами MiniMarket одновременно, и оба работают.
4. Включить **Да** у «Каталог» (`/catalog`), сохранить. Вернуться к пункту «Главная» и проверить, что там теперь **Нет**. Ссылки категории и товара должны стать `/catalog/category/testovaa-kategoria-1` и `/catalog/product/testovyj-tovar-1` (включая canonical).
5. Теперь включить **Да** у «Главная», сохранить; в «Каталог» флажок должен самостоятельно стать **Нет**. Ссылки `/category/testovaa-kategoria-1` и `/product/testovyj-tovar-1` (canonical — туда же). Другие настройки пункта «Каталог» не меняются.
6. Выключить **Да** на главной (везде Нет). Магазин не ломается, ссылки сохраняют документированный fallback на MiniMarket-home.
7. Проверить, что обычные Joomla пункты статей/категорий не изменены; карточка товара `TEST-001` с прежними значениями, панель категорий, вывод товаров и редактирование работают.
8. Если по каким-то причинам установка пакета вызывает ошибку Joomla: остановиться, передать короткий текст и/или скриншот. Не удалять расширение и не очищать базу.

**Критерии PASS:** пакет устанавливается поверх компонента без потери данных, плагин виден/включён, переключение в обе стороны снимает флаг с остальных, все прочие параметры и адреса сохраняются, никаких ошибок на страницах `/`, `/catalog`, категориях и товарах.

# MiniMarket 0.5.42 — единое оформление форм, поиск связей и привязка опций к категориям

Дата: 04.11.2026. Рабочая ветка `development`, Joomla 6; ядро и `main` не менять.

## Изменения

1. **Кнопки создания и подключения связей — внизу общего списка.** Если нажать «Добавить связь», создаётся **первая** раскрытая строка, а фокус переводится на заголовок новой связи. Если нажать «Добавить существующую связь», поиск (название или ID) появляется **сверху**; поиск оформлен как добавление товаров (строка поиска, синяя кнопка «Поиск», результаты отдельными строками, зелёная «Добавить связь»). После выбора существующая связь перемещается первой строкой, её состав отображается сразу.
2. **Добавление товара в существующую связь.** Кнопка находится под составом связи; по нажатию поиск по названию/SKU и категориям раскрывается **над участниками**, а не внизу списка. Новый выбранный товар появляется **первым** в составе связи. Списки товаров не загружаются целиком — серверный поиск выдаёт максимум 25 строк.
3. **Стандартные контрастные кнопки Joomla:** зелёные заполненные для добавления, красные — удаления, синие — поиска, отмены удаления и прочих нейтральных действий. В редакторе связей больше нет слабоконтрастных кнопок `btn-outline-*`.
4. **Единые рамки:** все шесть редакторов MiniMarket (товары, категории, характеристики, опции, связи товаров, значения) используют `card card-body mm-admin-panel`. У таблиц правил категорий/атрибутов/опций, SKU и списков — единая тонкая рамка, отступы и скругление. Сохраняются нативные цветовые переменные и светлая/тёмная темы Joomla; на узком экране поля не должны порождать горизонтальные скроллы.
5. **Редактор опции → вкладка «Категории».** Форма уже имела `fieldset=categories` с полем `Optioncategories`, а `OrderoptionModel` уже загружал и транзакционно сохранял связи через `CategoryOrderOptions`. Ошибка была в шаблоне `admin/tmpl/orderoption/edit.php`, который показывал только «Опция заказа» и «Значения». Теперь вкладка видима, работает идентично обратной привязке у характеристик. Никакого второго набора данных/таблиц и SQL миграции не добавлено.

## Принципы работы связей (сохраняем 0.5.41)

- Один товар может состоять в нескольких связях, каждая показана отдельно и раскрывается по клику.
- Название товара внутри связи — ссылка на карточку товара в новой вкладке.
- «Убрать товар» исключает только этого участника; **сама связь остаётся** в списке связей и у остальных товаров. Даже полностью пустая связь остаётся до явного удаления.
- Удаление всей связи — отдельная красная кнопка и подтверждение. Сохранение и проверка прав остаются серверными.
- Никаких огромных рядов чекбоксов ни для товаров, ни для связей.

## Приёмка на локальной Joomla

1. Создать резервную копию базы `minimarket`. Выполнить `git pull --ff-only origin development`, `scripts/build.ps1` и `scripts/inspect-package.ps1`.
2. В `dist` два отдельные файла: `com_minimarket-0.5.42.zip` и `minimarket_toys_rich_import.sql`. **Установить только ZIP**. Демо SQL заменяет данные MiniMarket и для обновления не нужен.
3. Открыть товар с большим количеством связей. Кнопки добавления должны быть снизу; при создании связь появляется первой, заголовок сразу доступен.
4. Открыть «Добавить существующую связь»: поиск должен выглядеть аналогично поиску товаров, новая выбранная связь — первой сверху.
5. Раскрыть связь с несколькими товарами, нажать «Добавить товар»: поиск появляется перед списком участников, новый товар после выбора становится первым. Проверить, что ни одна кнопка на тёмной теме не выглядит пустым контуром.
6. В «Опции» открыть опцию и перейти во вкладку «Категории». Изменить правило для конкретной категории, сохранить, затем открыть категорию → «Опции» — правило должно совпадать. Проверить наследование и обязательность; открыть опцию повторно.
7. В карточках товара, категории, характеристики, опции, связи и значения убедиться, что табы и таблицы оформлены рамками, поля не налезают. Проверить на узком окне.
8. Проверить отдельный сценарий 0.5.41: исключение текущего товара из связи не удаляет связь и остальных участников.
9. Обновить кеш браузера Ctrl+F5. GitHub CI тестирует PHP 8.4/8.5, MySQL 8, Windows ZIP и синтаксис JS, но **не заменяет реальный браузерный smoke Joomla**.

## Дальнейшие задачи

После реальной проверки — улучшить массовое назначение участников при больших каталогах, динамический выбор категорий с поиском по дереву и перейти к следующему разделу дорожной карты MiniMarket. Ведём единое визуальное оформление будущих сущностей и не добавляем контурные кнопки для действий добавления/удаления.

# MiniMarket 0.3.6 — исправление ссылки меню и общий routing smoke

**Дата:** 01.11.2026. **Статус:** исправление опубликовано в `development`, **Windows/Joomla runtime NOT RUN**. Это замена следующей инструкции для 0.3.5; не переустанавливать старые версии по одному патчу.

## Подтверждённая причина FAIL 0.3.5

После обновления 0.3.5 пользователь сообщил: пункт «Каталог» перестал вести на `/catalog`, при наведении ссылка указывает на главную. Сборка ZIP/установка завершились, но **frontend menu smoke FAIL**.

Код `Router::getShopItems()` проверял `$item->published ?? 0`. **SiteMenu Joomla 6.2 в SQL выбирает только опубликованные записи (`m.published = 1`), но не включает поле `m.published` в результат `MenuItem`.** Поэтому все правильные пункты ошибочно отфильтровывались и `preprocess()` бросал исключение `requires exactly one published Shop menu item; found 0`. `Joomla\CMS\Router\Route::_()` в Joomla 6 перехватывает `RuntimeException` и возвращает `null`, что согласуется с пустым `href`/переходом на главную и возможным SEF-перенаправлением.

**Исправление:** больше не проверяем отсутствующий `published` в элементах, уже полученных из `SiteMenu::getItems('component','com_minimarket')`. Проверяем только явный `view=catalog`, количество пунктов по-прежнему ровно 1. Это обычный опубликованный пункт меню владельца, **никаких скрытых пунктов, автосоздания и fallback на главную**.

Официальный код Joomla: `libraries/src/Menu/SiteMenu.php` и `libraries/src/Router/Route.php` в ветке `6.2-dev`; также https://manual.joomla.org/docs/next/general-concepts/routing/build/ .

## Что входит в 0.3.6

- Исправление `getShopItems()` — небольшое изменение только логики проверки меню.
- Сохраняется введённая в 0.3.5 типизация `category/{alias}-{id}` / `product/{alias}-{id}`, обратная совместимость старых `catalog/{alias}-{id}` и один штатный пункт магазина.
- **Добавлен изолированный тест `scripts/test-router.php`** с объектами меню именно как у Joomla 6 (**без** поля `published`); проверяет поиск меню, ссылки каталога, замену чужого Itemid, build/parse категорий и товаров, legacy URL, 404, home item, отсутствие/дубликат пунктов, совпадение alias-ID между категорией и товаром.
- Версия манифеста: **0.3.6**.
- **Без изменения** Joomla core, SQL, .htaccess, .osp/project.ini, товаров/вариантов, настроек меню. **301 legacy URL ещё не реализован** — не применять на индексируемом публичном сайте как законченную SEO-миграцию.

## Одна консолидированная локальная проверка

В CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-router.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидаются `ROUTER_TEST_OK: 23 cases` и `PACKAGE_OK: 0.3.6`. Если `git status --short` показывает только известный локальный `.osp/project.ini`, не трогать его; при других неожиданных правках сначала разобраться. При FAIL отдельного роутер-теста **не устанавливать** ZIP. PHP 8.5 путь тот же, что использовался в других проектах OpenServer; если путь отсутствует, использовать доступный `php.exe` текущего профиля, без изменений Joomla.

После PASS штатно установить `dist/com_minimarket.zip` через менеджер расширений **поверх** 0.3.5, не удаляя компонент, БД или меню. **Не менять текущий alias `catalog`.**

Проверить всё одним заходом:
1. Ссылка пункта «Каталог» при наведении **`/catalog`**, а не `/`. Клик открывает страницу каталога.
2. Ссылка на категорию в каталоге ведёт на `/catalog/category/testovaa-kategoria-1` и открывается.
3. Товар из категории открывает `/catalog/product/testovyj-tovar-1`. Значения: SKU `TEST-001`, цена `1990.50`, остаток `2`.
4. Старые `/catalog/testovaa-kategoria-1` и `/catalog/testovyj-tovar-1` **временно открываются**. У них canonical на новые typed URL; 301 пока нет.
5. Проверить отрицательные URL: `/catalog/product/testovaa-kategoria-1` и `/catalog/product/missing-999999` дают HTTP 404.
6. Админские Save категории/товара и переключатель «Показывать категории» Да→Нет→Да остались исправны.
7. При доступе к исходнику HTML: один `rel=canonical` на правильный typed-путь; никакого сайта-корня вместо URL магазина.

**При ошибке:** остановиться, сообщить коротко симптом и адрес, при необходимости скриншот. Не очищать базу, не пересоздавать меню, не менять SEO настройки и .htaccess. Сырые логи/консоль в чат не публиковать.

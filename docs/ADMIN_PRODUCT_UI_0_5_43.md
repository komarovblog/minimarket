# MiniMarket 0.5.43 — UI категорий, SKU, галереи и опций

Дата: 04.11.2026. `development`, Joomla 6. Не менять ядро Joomla и `main`.

## Реализовано

1. Ссылки на характеристики и опции из категории теперь ведут прямо на `view=attribute&layout=edit&id=...` / `view=orderoption&layout=edit&id=...`. Ссылки не вложены в label, который может перехватывать нажатие.
2. Главная административная страница MiniMarket: заголовок, пояснение, вертикальный список разделов и одна синяя залитая кнопка открытия каталога; старые разноцветные контурные кнопки удалены.
3. В списке назначений категории для характеристик и опций — три колонки: название со вторым рядом кода, правило и отдельный столбец статуса публикации. Единый стиль и границы таблиц. Статус не затрагивает наследуемый режим.
4. Вкладка товара `Опции заказа` названа **`Опции`** на RU и EN. Сверху отображается пояснение и список назначенных категории опций с доступными значениями; кнопка `Добавить опцию в категорию` открывает соответствующую карточку категории в новой вкладке. Сами SKU при смене категории не стираются.
5. Матрица SKU снова компактная настоящая таблица, не карточки. В ней внутри одного ограниченного контейнера прокручиваются только колонки значений опций. Артикул, остаток и активность закреплены справа, в том числе на узком экране. На каждый набор опций одна строка, стоимость по-прежнему общая цена товара. Скрытие остатка в режиме общей массы сохраняется.
6. В редакторе связей отдельные **Сохранить** и **Отменить создание** сгруппированы под списком участников, не смешаны с `Добавить товар`. Сохранение вызывает штатный apply родительской формы Joomla (product/group).
7. Галерея товара: два блока под каждым дополнительным фото. Первый `Показывать всем / только выбранным SKU` с чекбоксами; второй `Главная фотография для SKU` с чекбоксами. Список активных сочетаний берётся из текущей матрицы. Существующие неактивные SKU, которым было назначено фото, не теряются при обычном открытии. Второй cover того же SKU недоступен в UI и дополнительно запрещён сервисом ProductGallery на сервере; для ограниченных фото главная автоматически включается в видимость.
8. В каждом значении глобальной опции можно независимо добавить цвет HEX (текст + нативная палитра, с очисткой) и/или изображение Joomla Media. Добавлена **только аддитивная** SQL-миграция `0.5.43.sql`: `sample_image` в таблицу `#__minimarket_order_option_values`, с пустым значением для всех старых строк. ID/коды/цвета/связи с SKU не меняются. Свежий `install.mysql.sql` обновлён.

## Принятая модель для универсальных характеристик (отдельный структурный этап)

Сейчас характеристики сохраняют исторические схемы ввода (текстовые и числовые предустановки, справочник ID для цвета/списков). Переключение их без миграции поломало бы существующие товары. Следующий структурный этап:

- Тип данных: Текст, Число, HTML редактор, Файл, Цвет, Да/Нет.
- Сразу после типа для всех, кроме Да/Нет: `Ручной ввод` или `Выбор из готовых значений`. Отдельно настройка `Одно / несколько` (не смешивать с отображением на витрине).
- Для готовых значений — единый справочник значений с ID, названием, кодом, цветом HEX, примером-изображением и при необходимости типовым содержимым HTML или ссылкой на файл. Множественные выборы сохраняются ссылками на ID значений, а не строками свободного текста.
- Для ручного цвета — палитра HEX в карточке товара; для чисел — диапазон и шаг ниже общих настроек; для цвета — режим показа текста, кружка или обоих.
- Сохранить старые значения и SKU. Миграция текстовых/числовых пресетов должна учитывать уже заполненные товары и старые ID. Нельзя внезапно переписать существующие характеристики.
- Не путать признаки характеристики с опциями, которые создают физические SKU. Информационная характеристика никогда сама не создаёт артикул.

## Проверка в установленной Joomla

Резервная копия базы перед обновлением. `git pull --ff-only origin development`, `scripts/build.ps1`, `scripts/inspect-package.ps1`, установить ZIP 0.5.43. Отдельный SQL не импортировать.

После Ctrl+F5 проверить навигацию из категории, главную страницу компонента, три колонки характеристик/опций, вкладку товара `Опции` и фиксированную матрицу, сохранение связи и назначение разных фотографий SKU, изображения и цвет значений глобальных опций. При ошибке сохранить полный текст и не выполнять DROP/UPDATE вручную без диагностики.

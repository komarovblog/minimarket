## Доставлено

1. **Переводы:** устранена показанная на скриншоте утечка `COM_MINIMARKET_CHECKOUT_JOOMLA_LOGIN` в checkout, поскольку ключ отсутствовал в **site** языковых файлах. RU/EN добавлены. Проведена проверка всех **явных** `COM_MINIMARKET_*` references в site/admin PHP/XML, закрыты прежние 37 unresolved usages, добавлены новые подписи рекомендаций. `scripts/verify-translations.ps1 -Strict` теперь обязательный Windows CI и возвращает `LANG_AUDIT ... missing=0`. Проверка составных/динамических языковых ключей и экранов в живой Joomla остаётся отдельной задачей приёмки.
2. **Три согласованных навигации:** единый порядок и иконки на главной панели, в Joomla sidebar submenu и component preset:
   - Управление: **Очередь задач → Заказы → Доставки → Возвраты → Платежи → Покупатели → Обращения → Документы**;
   - Отчёты: **Показатели бизнеса → Продажи → Остатки → Возвраты → План-факт**;
   - Магазин: Категории → Товары → Комплекты → Связи товаров → Связи комплектов → Бренды → Коллекции → Характеристики → Опции;
   - Маркетинг: **Акции и скидки → Промокоды → Рекомендации → Отзывы → SEO-страницы**;
   - Инструменты: Импорт/экспорт → Фиды;
   - Настройки: Способы доставки → Способы оплаты → Способы регистрации → Способы уведомлений → **Фискализация → Настройки**.
   - Отдельная `com_config` ссылка **сохранена**; все реальные пункты и маршруты проверяются тестом. Иконки Joomla/Atum используются на dashboard/menu/preset; без собственных цветовых тем.
3. **Отчёт «Остатки» = остатки + ABC + XYZ.** ABC по действующей прямой выручке из оплаченных/вручённых продаж за выбранные 30/90 дней. XYZ независимо считает количество действительно списанных в исполнение товаров за **три 30-дневных окна** последних 90 дней: коэффициент вариации спроса X ≤10%, Y ≤25%, Z >25%. Отсутствие спроса → нет класса, а не фиктивный X. Добавлены нативный столбец и фильтр `filter_xyz`. Без отдельного «движения запасов», без выдуманного прогноза и без учёта недоказанной прибыли.
4. **Категория → «Похожие товары» и «Сопутствующие товары».** Каждый тип отдельно: `inherit` (предок), `own` (текущая категория), `selected` (конкретный набор категорий). Для похожих можно выбрать **только характеристики, применимые к категории**, и совпадающие значения поднимают кандидатов вверх. Наследование динамическое и не размножает настройки в дочерних категориях; отсутствие настройки → своя категория. Новые `#__minimarket_category_recommendations` и `CategoryRecommendationRules`, аддитивная миграция, сохранение внутри существующей транзакции категории, проверка фактических category IDs и attribute IDs. Режим «selected» требует хотя бы одну категорию.
5. **Товар/Комплект → две вкладки рекомендаций**: `inherit` (правила категории), `auto`, `manual`, `hybrid`. Ручные товары выбираются **существующим штатным поисковым picker**; он скрыт, если выбран не ручной/смешанный режим. Валидируются сущности, собственный товар и дубликаты, максимум 30, сохранение в общей транзакции товара через `RecommendationSettings`; старый раздел «Маркетинг → Рекомендации» остаётся единым списком по товарам, редактирует **те же записи**, не отдельную копию.
6. **Сопутствующие на витрине** по-прежнему учитывают только подтверждённую совместную покупку из оплаченного доставленного заказа и отсекают возвраты и недоступные товары. Источники ограничиваются категориями-правилами, ручной подбор имеет приоритет. Похожие выбираются из заданных категорий и ранжируются по реально сохранённым значениям характеристик.
7. **Пояснения UI:** под блоком «Отчёты» на панели объяснено отличие пяти отчётов, в маркетинге объяснены роль центрального списка рекомендаций и вкладок категорий/товаров. «Документы» — общий поиск коммерческих счетов, которые формируются и хранятся в **заказе**; «Фискализация» — отдельно операции кассового провайдера, если и когда он реально появится. Сейчас реестр read-only и чеков не создаёт.

## Границы

- Никаких изменений ядра Joomla/Atum, темы Blank, `main`, резервирования, остатков, оплаты/возвратов/стоимости, нескольких складов или журнала складских движений.
- Нет фактической интеграции онлайн-кассы, SMS, перевозчика или провайдера оплаты. Не называть коммерческий счёт фискальным чеком.
- XYZ 90 дней — классификация фактической нестабильности спроса, **не статистически обоснованный прогноз** на будущий период. Нулевая реализация классификации не получает. Неподтверждённые деньги и товарные движения не включать.
- Существующие рекомендации/товары/категории миграция не перезаписывает. Для рекомендаций без сохранённого override действует наследование категории; ранее сохранённые ручной/смешанный режимы остаются.
- Реальная Atum light/dark, мобильная ширина, RU/EN, frontend checkout и сохранение через UI **должны быть проверены вручную**. CI PASS не заменяет это доказательство.

### Ручная приёмка

1. На сайте открыть оформление гостевого заказа: вместо `COM_MINIMARKET_CHECKOUT_JOOMLA_LOGIN` должна быть «Войти в аккаунт»; проверить RU/EN и доступность входа.
2. На админке проверить Dashboard + Joomla sidebar + preset — точный порядок, наличие иконок, отсутствие `undefined`/битых ссылок, в том числе настройка `com_config`.
3. Категории: сначала родительская с `selected` источниками и применимыми атрибутами, затем дочерняя с `inherit`. После изменения родителя дочерняя должна отражать правило, а переопределённая дочерняя — сохранять своё.
4. Товар: вкладки похожих/сопутствующих, `manual` и `hybrid` с поиском, `inherit`, сохранение/повторное открытие; на витрине изменения действительно отражаются. Удалённые/неопубликованные цели не показываются. Сопутствующие автоматом — только по доставленным оплаченным заказам без возврата.
5. Отчёты → Остатки: ABC и XYZ, при отсутствии спроса прочерк, фильтр XYZ, 30/90 дней ABC, XYZ всегда по 90 дням. Отчёт не должен менять фактический склад.
6. Проверить «Документы» (счёт в заказе и общий реестр), «Фискализация» перед «Настройками», оба языка и темы Joomla.

# MiniMarket 0.5.9 — простой список значений и сортировка Joomla

**02.11.2026.** Пользователь сообщил, что в 0.5.8 путь «Редактировать значения» из карточки цвета создавал лишний промежуточный экран и «Назад» вёл к общему списку характеристик. Требование — **одна таблица значений**, которую можно просматривать по алфавиту или в ручном порядке Joomla, без лишней навигации.

## Реализовано

- Редактор MiniMarket → Attributes → **Цвет** (`color`) → вкладка **Values** показывает **одну таблицу** значений (например, Красный, Жёлтый). Лишняя кнопка **Edit values / Редактировать значения** удалена.
- Кнопка **Add value / Добавить значение** остаётся. Название каждой строки — ссылка редактирования самой записи (название, код, статус, порядок), а после **Save & Close** или **Cancel** Joomla возвращает **к характеристике «Цвет»**. Имеющийся числовой \`attribute_id\` переносится при создании нового значения.
- Над таблицей есть сортировка **Joomla ordering**, **Title: A–Z / А–Я**, **Title: Z–A / Я–А**. Алфавитная сортировка меняет только **отображение**, не затрагивает хранимый ручной порядок. Она работает локально в браузере, без запросов к MySQL.
- В последней колонке у каждого значения есть **порядок** (от 0). Изменение числа и нажатие обычного **Save / Apply** карточки характеристики обновляет \`sort_order\`. Запись ограничена только значениями этой характеристики; сервер не принимает чужие ID, неверные или неполные номера. Все изменения сохраняются в одной транзакции с изменениями характеристики.
- Для старого отдельного списка Values (доступного по старым ссылкам и из карточки товара) доступны сортируемые заголовки Название / Порядок. Если список отфильтрован по характеристике, **Back to attribute** возвращает именно к ней, а не на список всех характеристик.
- Никаких SQL-миграций, дублирующих справочников, изменений товара/SKU/цен/остатков/галерей или Joomla core. Оба языка RU/EN.

## Установка

Сначала **резервная копия БД Joomla**. Обновить исходники в CMD:

```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-attribute-value-ordering.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидается \`PACKAGE_OK: 0.5.9 (com_minimarket-0.5.9.zip)\`; установить **\`dist\\com_minimarket-0.5.9.zip\`** через Joomla → System → Install → Extensions поверх текущего компонента.

## Короткая проверка в Joomla (runtime до установки NOT RUN)

1. MiniMarket → Attributes → Цвет → Values. Должны быть таблица и **одна** кнопка Add value. Другой кнопки Edit values быть не должно.
2. Если значений нет, добавить **Красный** с кодом \`red\` и **Жёлтый** с кодом \`yellow\`. Если строка «Жёлтый» уже есть с ошибкой \`eelow\`, **исправить код через редактор значения**: установка нового компонента не изменяет введённые данные автоматически.
3. Нажать сортировку **Title A–Z**, затем **Z–A**: порядок строк изменится на экране. Вернуть Joomla ordering: показывается хранимый порядок.
4. Указать вручную «Красный» — 20, «Жёлтый» — 10 и сохранить характеристику. Открыть снова → Joomla ordering → сначала «Жёлтый», затем «Красный». Заголовки и статус записей не меняются.
5. Открыть название «Жёлтый», затем нажать Cancel: возвращаемся к **Цвет**. Проверить аналогично Save & Close после изменения только тестового значения.
6. В товаре из разрешённой категории значения продолжают отображаться и сохраняться, существующие TEST-001 и другие товары не меняются.
7. В админке на английском — английские подписи, на русском — русские. Оценить сортировку на кириллических именах, а не только на латинице.

**Автоматические тесты — не гарантия Joomla runtime.** PHP + JS syntax, ZIP inspector, MySQL CI; после установки нужно реальное подтверждение UI и возврата после Save & Close.

# MiniMarket 0.5.61 — фиды и административный дашборд

Дата: 2026-11-06. Ветка `development`, ядро Joomla и `main` не менялись.

## 1. Что реализовано

- В админ-меню рядом с **Импорт / Экспорт** добавлен **Фиды**.
- Фид — отдельная запись с названием, компанией, типом/площадкой, состоянием, 20-байтным случайным ключом URL.
- Редактор: список опубликованных категорий, опция включения подкатегорий, список опубликованных товаров/комплектов с поиском и чекбоксами. По умолчанию при создании выбраны все опубликованные категории и все доступные товары.
- Режим **Автоматически** включает все актуальные опубликованные товары выбранных категорий. Снятые вручную галочки сохраняются как исключения; добавленные товары вне категорий — как исключения из правила в обратную сторону (явные включения). Новые товары подходящих категорий автоматически появляются при следующем запросе.
- Режим **Вручную** включает только явно отмеченные товары. Кнопки **Выбрать все** / **Снять все** переключают на ручной режим. Сохранённые настройки можно редактировать.
- Родительские неопубликованные категории, неопубликованные товары и удалённые сущности не попадают в фид, даже если сохранены в его правилах.
- После публикации фид доступен по URL `/index.php?option=com_minimarket&task=feed.xml&id=ID&key=SECRET`. Секретный ключ проверяется через `hash_equals()`, черновики всегда дают 404. Не передавать URL посторонним.
- Текущий генератор отдаёт **базовый YML/XML**: название и компания, валюта RUR, категории, товары, URL, цены и старая цена, изображение, бренд, артикул, остаток, описание. При SKU-матрице предложения формируются на каждый опубликованный SKU и имеют стабильные `sku-ID`; родительский товар без вариантов — `p-ID`. Цена для комплекта рассчитывается через существующий `CatalogRepository`.
- Количество отобранных родительских товаров на один запрос ограничено 5000; больший объём отклоняется (не обрезается молча). Передача публичного URL требует **доступного для робота сайта**; `minimarket.local` годится только для тестирования.
- В меню появляется встроенный Joomla-dashboard значок для MiniMarket; при установке добавляется `mod_submenu` в штатную позицию `cpanel-minimarket` с безопасной повторной проверкой, а собственная главная страница `view=dashboard` показывает Bootstrap-карточки статистики и ссылки. Блок Заказы отмечен как функциональность будущих версий, без фиктивных чисел.

## 2. Площадки и ограничения готовности

Провайдеры в интерфейсе: Яндекс Директ / Яндекс Товары, Яндекс Маркет, Яндекс Бизнес, VK Реклама — **пока один базовый YML-адаптер с небольшим различием формата даты**. Это полезная отправная точка, но **не подтверждает полное соответствие требованиям каждого приёмника**. Проверить доставка/самовывоз, таксономия, цена, фото, наличие и иные обязательные атрибуты в валидаторе площадки до подключения.

- [Yandex Direct YML](https://yandex.ru/support/direct/ru/feeds/requirements-yml)
- [Yandex Market YML](https://yandex.com/support/marketplace/ru/assortment/auto/yml)
- [Яндекс Бизнес YML](https://yandex.ru/support/business-priority/ru/manage/price-list)
- [VK каталоги по Yandex/YML](https://ads.vk.ru/help/articles/ecomm_catalog_y_goods)
- [Google Merchant Center XML](https://support.google.com/merchants/answer/15624855?hl=ru) — отдельный Google RSS/XML/TSV-адаптер нужен.
- **Авито** — отдельные XML-шаблоны автозагрузки по категориям, с маппингом обязательных полей. Предлагать универсальный YML как готовую интеграцию нельзя.
- Следом: динамические маркетплейс-API **Ozon**, **Wildberries** — это отдельные интеграции, не общий фид; для услуг/локального магазина полезны Yandex Business и 2ГИС при подтверждении формата подключения.

**Нет** отправки фида в API, автоматической проверки площадкой, истории загрузок, расписания обновления, платформенных таксономий и XML-валидаторов. Публичный URL строится при каждом запросе из актуальной БД, поэтому отдельный CRON для него сейчас не нужен. На большом каталоге нужна оптимизация/кэширование.

## 3. Как пользователь настраивает

1. Компоненты → MiniMarket → **Фиды** → Новый. Задать название, компанию, формат, публикацию.
2. Галочками выбрать категории; по умолчанию все опубликованные. При необходимости выключить дочерние или комплекты.
3. В правом списке товаров снять конкретные галочки — они попадут в исключения, либо выбрать **Снять все** для ручной выборки с нуля. В таком случае категории служат ориентиром, а не ограничением выбора.
4. Сохранить. У опубликованного фида в списке появится URL с секретным ключом, его можно открыть как XML и затем передать площадке.
5. Проверить пример `TOY-1012` и комплекты. Секретный URL нельзя случайно индексировать, помещать в публичную HTML-страницу или аналитические UTM-параметры.
6. При изменении цены, остатка, публикации и попадания товара в категорию XML обновляется на следующем запросе.

## 4. Дашборд и быстрый доступ

- Левая навигация Joomla не изменена. Под «Компоненты → MiniMarket» есть пункт **Главная** и все прежние разделы, в том числе новые **Фиды**.
- Штатный Joomla dashboard: `<dashboards>`, `<params><dashboard>minimarket</dashboard></params>`, preset + `mod_submenu` в `cpanel-minimarket`. Это штатный API Joomla 6.
- Внутри MiniMarket `index.php?option=com_minimarket&view=dashboard` — отдельная главная с виджетами (категории/товары/комплекты/фиды, справочники, импорт/экспорт, будущие заказы).
- Если нужна **отдельная кнопка в самой верхней панели на всех страницах Joomla**, используйте **Содержимое → Модули (панель управления) → Создать → Произвольный**. Позиция: `customtop` (над шапкой) или `status` (справа в шапке Atum — зависит от chrome), название «MiniMarket», ссылка `index.php?option=com_minimarket&view=dashboard`, иконка `icon-cart`; доступ только для администраторов. Мы не создаём такой глобальный модуль автоматически, чтобы не навязывать кнопку всем администраторам и не дублировать существующий top-bar.
- Переход на альтернативный шаблон Joomla возможен без изменения логики и БД.

## 5. Схема / поставка

- Новая таблица `#__minimarket_feeds`, миграция `admin/sql/updates/mysql/0.5.61.sql` — отдельная аддитивная `CREATE TABLE IF NOT EXISTS`, не меняет товары или категории.
- **Full JSON v2 сохраняет 32 исторические таблицы каталога, но конфигурации фидов в него не включены.** Это зафиксированное ограничение, в будущем нужен совместимый v3 и отдельный экспорт конфигураций. Нельзя обещать, что full v2 сохраняет всё.
- Демоданные: `sample-data/minimarket_mysql84_nnop3_update_0_5_61.sql` — новая накопительная копия прежнего демокаталога, без принудительного добавления фидов и без перезаписи пользовательских правил фидов.
- Сборка: `scripts/release-to-desktop.ps1` → ZIP + накопительный SQL на рабочий стол. SQL импортируется после установки ZIP только по желанию, с резервной копией.

## 6. Тесты

В CI: PHP8.4/8.5 статические маршруты/настройки, FeedSelection для автоматических/ручных списков, отсеивание неопубликованного, YML escaping и поля, Node DOM режимы выбора/галочки/массовые кнопки, MySQL8.4 сохранение и обновление feed-конфигурации поверх заполненного каталога + удаление только тестовой записи, MySQL8.0 сохранность предыдущих миграций, Windows ZIP/manifest. **На настоящей Joomla административные формы и YML URL вручную ещё не пройдены**.

### Ручная приемка

1. Установка поверх 0.5.60: нет потерь SKU, картинок, категорий, прежних меню.
2. Проверка native dashboard icon, `cpanel-minimarket`, кнопок виджета, отсутствии дублей `mod_submenu` после повторной установки.
3. Создать черновик фида, убедиться что нет URL. Опубликовать, сохранить, проверить URL XML, затем заменить ключ или снять публикацию → 404.
4. Выбрать одну категорию + вложенные, исключить товар, добавить вручную товар другой категории, сохранить, проверить XML. «Снять все», выбрать два товара, сохранить и проверить XML.
5. Проверить, что неопубликованный товар и товары скрытого родителя не попадают в XML даже при явном включении.
6. Открыть фид через валидатор конкретной площадки; обязательные атрибуты могут требовать отдельный профиль.

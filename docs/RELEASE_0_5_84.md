# MiniMarket 0.5.84 — доставка, заказы, интеграции, промокоды и интерфейс Joomla

**Дата:** 10 ноября 2026. **Ветка:** `development`. **Проверка:** GitHub Actions, PHP 8.4/8.5, MySQL 8.0/8.4, Windows ZIP — PASS.

## Настройки и оформление

- Вкладки **«Доставка и получение»** и **«Оплата»** перенесены внутрь **«Оформление заказа»**. Разделы данных покупателя, доставки, оплаты представлены штатными неподвижными `note`/Bootstrap `alert-info` с пояснениями, без раскрывающихся аккордеонов. Значения существующих параметров сохранены.
- Режимы подписаны **«Возможность гостевого заказа»**, **«Обязательное подтверждение по SMS»**, **«Обязательное подтверждение по email»**. В гостевом режиме заказ доступен и гостю, и уже вошедшему пользователю Joomla. Для SMS и email новый покупатель должен пройти проверку, которой пока нет — гостевой заказ в этих режимах **блокируется**, а уже вошедший пользователь не проверяет контакт повторно. Проверка провайдеров не имитируется.
- Тарифы собственного курьера: одна строка **`Город|Стоимость|БесплатноОт`**, например `Москва|500|5000`: стоимость доставки 500 ₽, а при стоимости товаров от 5000 ₽ — бесплатно. Третий параметр необязателен, старый `Тверь|250` продолжает работать. Сервер рассчитывает плату по актуальной сумме товаров и не доверяет присланной из браузера цене. Самовывоз всегда бесплатен. По весу/объёму и тарифным зонам требуется отдельное проектирование данных товара, сейчас не заявлено как готовое.
- Для блоков отображения, команд offcanvas, регистрации и отзывов добавлены нативные информационные пояснения RU/EN.

## Администрирование

- Переключатель столбцов компактный, без дополнительной тёмной рамки; список заказов, доставок, отзывов и SEO-фильтров использует единый прямоугольный стиль таблиц Joomla.
- **Удаление заказа — через защищённую корзину**: сначала статус «Отменён», затем «В корзину заказов». Отдельный просмотр корзины и «Восстановить». Требуются ACL `core.delete`, POST и Joomla CSRF. Физического удаления заказа и его товарных/финансовых строк **нет**. К рабочему счётчику скрытые записи не относятся.
- **Доставка — отдельная сущность** `#__minimarket_shipments`: создаётся из курьерского заказа или через «+» у доставок; одна доставка на заказ (первый этап). Выбор своего курьера, СДЭК (ручной учёт) или другой службы, поле трек-номера, комментарий, независимые статусы «Создана», «В пути», «Доставлена», «Отменена». Трек вводится с внешнего ресурса перевозчика; собственный API СДЭК пока не вызывается. После создания связь видна в заказе.
- Исправлен шаблон редактора SEO-фильтра (открытие с default layout, без ошибки 500).
- **«Интеграции»** — отдельный пункт меню и карточка рядом с настройками, с SVG-иконкой. Категории: платёжные службы, доставка, SMS, email/уведомления, Яндекс/Сбер/МТС/VK ID, Telegram, CRM/склад, аналитика, маркетплейсы, webhooks. Состояние активных/неактивных плагинов группы Joomla `minimarket` отображается через реестр Joomla; статус «включён» означает лишь состояние плагина, **не** успешное подключение внешнего API. Секреты в этот экран не копируются.
- **«Промокоды»** — отдельный раздел меню и карточка инструментов. Код из латинских букв/цифр/дефиса, значение скидки в рублях и признак активности, хранится в `#__minimarket_promo_codes`. В корзине/заказе скидка пока **не применяется**; ограничения сроков, количества применений, сочетания скидок и минимальной суммы будут согласованы отдельно.

## Схема БД и безопасность

- Миграция `admin/sql/updates/mysql/0.5.84.sql` только аддитивная: `orders.deleted_at`, таблица `#__minimarket_shipments` (FK `order_id`), `#__minimarket_promo_codes`. Не изменяет структуру базовых таблиц Joomla; прежние заказы и товары сохраняются.
- Важное историческое предупреждение Joomla о старых миграциях характеристик (0.5.12/0.5.14/0.5.73) **не решается этим релизом**. Не нажимать Joomla «Исправить» вслепую, не повторять старые SQL. Для безопасной диагностики выполнить только SELECT из [RELEASE_0_5_83.md](RELEASE_0_5_83.md), предварительно сохранив дамп.
- Нет самопроизвольной отправки SMS, выдачи чека, оплаты, вызова CDEK или автоматического списания складских остатков.

## CI, локальная проверка и дистрибутивы

- Проверки: `scripts/test-0-5-84-features.php` (опции/безопасность/маршруты/тарифы), `scripts/test-0-5-84-schema-mysql84.php` (отдельная MySQL 8.4 тестовая схема), исторические регрессии 0.5.64–0.5.83, PHP syntax и Node JS syntax, Windows ZIP. **Реальная браузерная проверка установленной Joomla 6.2 пользователем ещё нужна.**
- Создать ZIP на рабочем столе, выполнив в CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development && powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\release-to-desktop.ps1" -SkipPull
```

- `com_minimarket-0.5.84.zip`, `mod_minimarket_toolbar-0.5.84.zip`, необязательный `minimarket_demo_gallery_filters_0_5_84.sql`. Последний **не импортировать** при обычном обновлении. ZIP компонента устанавливать через установщик Joomla 6, модуль — отдельно.
- Перед установкой сделать резервную копию БД и файлов, при невозможности восстановить из бэкапа обновление не проводить.

# MiniMarket 0.3.8 — единый smoke: несколько витрин + общий каталог товаров

**Дата:** 2026-11-01. **Статус:** изменения исходников опубликованы в GitHub `development`, **не установлены и не проверены в Joomla 6.2.0**. Это одна консолидированная итерация поверх ранее работавшей версии; **не нужно отдельно переустанавливать 0.3.7**, поскольку 0.3.8 включает все её изменения. Данные, меню, Joomla core и SQL автоматически не меняются.

## Что нового
- Продолжается исправление 0.3.7: разрешены сколько угодно **обычных опубликованных** пунктов `MiniMarket → Магазин`; `/`, `/catalog`, `/shop` — независимые страницы, **без скрытых пунктов меню**. Необязательное поле «Использовать этот пункт для ссылок на товары и категории» задаёт предпочтительный URL категорий/товаров, не ограничивая страницы.
- **Новый работающий параметр пункта «Магазин»: «Показывать все товары» = Нет по умолчанию.** Если включить, под категориями выводится общий ассортимент **из всех опубликованных категорий**. Можно выключить категории, но оставить товары, или наоборот; оба поля настраиваются **для каждого** пункта меню независимо.
- При включённых товарах доступны настройки: `12/24/48` на страницу и сортировка по дате добавления (точнее по ID), названию, цене по возрастанию/убыванию.
- Серверный запрос использует `LIMIT/OFFSET`, обе таблицы фильтруются по `state=1` и связь с категорией обязательна. Никаких скрытых/неопубликованных товаров.
- Переходы между страницами каталога используют query-параметр `mm_page` и сохраняют **конкретный Joomla Itemid этой страницы**, а не перескакивают на основной пункт магазина. Canonical страницы 2 содержит `mm_page=2`; страница 1 не получает лишнего параметра. Товар/категория при открытии из любого блока используют предпочтительный Itemid магазина.
- **Это НЕ модули популярных, новинок, подборок или фильтров.** Они будут отдельными Joomla Modules после появления данных, как согласовано. В текущем выпуске нет вариантов товара/новых БД/новой корзины/301.

## Один объединённый Joomla smoke

**А. Роутинг/меню:**
1. Опубликовать **два обычных** пункта MiniMarket: один — Главная `/`, второй — Каталог `/catalog` (если они уже существуют, не пересоздавать). Оба должны открываться одновременно и иметь правильные hover href/без 404.
2. В параметрах главной: `Показывать категории = Да`, `Показывать все товары = Нет`. В параметрах `/catalog`: `Показывать категории = Да`, `Показывать все товары = Да`. Проверить, что их содержимое отличается.
3. С `/catalog` открыть тестовую категорию `/category/testovaa-kategoria-1` и товар `/product/testovyj-tovar-1`. Вариант с обычным пунктом `/shop` при желании проверить отдельным сценарием, **не нужно создавать новые пункты специально**.
4. Приоритет ссылки товаров/категорий: по умолчанию MiniMarket на главной; при `Да` в параметре «Использовать этот пункт для ссылок на товары и категории» пункта `/catalog` ссылки должны поменяться на `/catalog/category/...` и `/catalog/product/...`. После проверки вернуть `Нет` (или оставить желаемый основной пункт). Все страницы остаются открываемыми.
5. Canonical страницы `/` ссылается на `/`, а страницы `/catalog` — на `/catalog`; товар/категория — на выбранный основной типизированный адрес. Старые одно-сегментные пути `/catalog/{alias}-{id}` временно поддерживаются, **автоматический 301 ещё НЕ реализован**. Дубли этих двух магазинных страниц, если контент одинаковый, относятся к редакторским/SEO настройкам владельца.

**Б. Список товаров:**
1. На `/catalog` появились категории **и под ними список опубликованных товаров**. Проверить тестовый `TEST-001`, цену `1990.50`, переход из каталога в товар и обратно; данные не менялись.
2. Переключить только на `/catalog`: `Показывать категории = Нет`, `Показывать все товары = Да` → список остаётся, категории исчезают. На главной изменения не должны отражаться. Затем вернуть нужные настройки.
3. Поменять порядок сортировки и лимит — сохранить настройки пункта меню; с одной тестовой записью визуальная сортировка почти не заметна, но не должна вызывать 500/ошибку.
4. Если опубликовано **больше 12 товаров**, выбрать 12 на страницу и проверить `/catalog?mm_page=2`: следующая/предыдущая страницы не повторяют товары, не переключают пункт меню, canonical второй страницы содержит параметр. Если пока есть только `TEST-001`, **не создавать 13 фиктивных товаров**: этот runtime-тест пометить `NOT RUN`, отдельно от `CATALOG_TEST_OK` на mock DB.
5. Для неопубликованного товара и товара неопубликованной категории убедиться, что они не входят в общий список. Если таких тестовых записей нет — **не менять существующие данные ради smoke**; тест SQL-условий выполняет `scripts/test-catalog.php`.

**В. Регрессия:** админское Save Category/Product и `show_categories` Да/Нет; старые ссылки на категорию/товар; видимый параметр основного пункта. SQL/категории/товары не пересоздавать. При любом 404/500 остановиться и прислать URL + текст ошибки.

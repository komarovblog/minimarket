# MiniMarket — единый стандарт интерфейса администратора Joomla 6

**Статус: обязательное продуктовое правило (03.11.2026).** Интерфейсы MiniMarket должны выглядеть и работать как стандартный администратор Joomla. Никаких отдельных дизайн-систем, псевдотаблиц, нестандартных шрифтов и кнопок для обычных CRUD-операций.

## Основные принципы

- **Списки:** стандартная Joomla Toolbar, SearchTools, форма `adminForm`, нативная `table table-striped`, checkbox/select-all, публикация через `PublishedButton`, компактные отступы. Сортировка/фильтры и массовые действия используют MVC Joomla.
- **Иерархии:** показывать дочерние категории сразу, с отступами и тире (как в Articles → Categories). **Без специальных кнопок сворачивания**, скрывающих ветки и усложняющих поиск.
- **Повторяющиеся значения:** использовать стандартную Joomla `Subform` с кнопками **+ / удалить / переместить**, как у галереи. Примеры: значения цвета/размера, фотографии, видео, список других объектов. Не рисовать второй независимый список кастомным JavaScript.
- **Таблицы:** `table table-striped` и штатная `joomla.form.field.subform.repeatable-table` для редактируемых строк. Избегать больших карточек, когда заполняется несколько однотипных записей; большие медиаполя могут быть вложены по необходимости.
- **Карточки:** стандартные вкладки и подписи, Joomla Media / Editor / Select / Number / Text, без нестандартных обложек, цветных «дизайнерских» блоков. Настройки не требуют скрытых пунктов меню.
- **Характеристики категории:** компактные две колонки: название/метаданные наследования и правило. Все состояния видны, включая неопубликованные, чтобы не стереть старые назначения.
- **Варианты товара:** внутри одной карточки на вкладке «Варианты» — параметры со значениями через те же +, затем таблица предварительного просмотра комбинаций, затем штатная таблица SKU с ценой, остатком и фото. Создание не требует предварительного назначения глобальных характеристик категории.
- **Везде RU/EN**, используя языковые константы; веб-активы подключать через Joomla WebAssetManager. Не менять ядро, не создавать ловушек `MutationObserver`, не дублировать источники данных.
- **Media:** сохранять путь `images/...` без Joomla-технического фрагмента `#joomlaImage://...`; проверять на сервере, даже если интерфейс его очистил.
- **Тестирование:** в каждом релизе проверять PHP/MySQL/ZIP, JS синтаксис и регрессию UI на наличие нативных контролов. Настоящий Browser Smoke на Joomla 6, включая тёмную тему, отдельно подтверждает пользователь.

## Чек-лист для новых разделов

Перед добавлением комплектов, заказов, фидов, складских остатков, импорта проверить, можно ли повторить UI стандартного компонента Joomla или уже реализованного раздела MiniMarket. Если есть список нескольких однотипных значений — нативный Subform (+/−/move); если это список записей — Joomla SearchTools + table + Toolbar, не самописный интерфейс. Новые паттерны вводить только если нативного недостаточно.

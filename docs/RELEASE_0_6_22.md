# MiniMarket 0.6.22 — План-факт по подтверждённым заказам

Направление C12: в разделе **Отчёты → План-факт** добавлен управленческий отчёт с ручным планом в рублях для каждого календарного месяца UTC и фактом по заказам.

**Факт:** сумма товаров после скидки для заказов `status=completed`, `payment_status=paid`, `currency=RUB`, `deleted_at IS NULL`, попавших в выбранный месяц **по дате создания заказа** (UTC). Источник тот же, что в существующей управленческой аналитике, чтобы не смешивать показатели. Без доставки, реальных возвратных выплат, рекламы, налогов. При изменении подтверждения оплаты факт прошлых месяцев может изменяться — это явно отмечено на экране; не считать показатель бухгалтерской выручкой.

**План:** отдельная таблица `#__minimarket_sales_plans` и аудит `#__minimarket_sales_plan_revisions`. План не задан → NULL/«Не задан», не фиктивный ноль. Денежные операции — строго копейки, ввод проверяется сервером; повторное сохранение одинакового значения не создаёт новую историю. Контроллер использует POST, CSRF и `core.admin`. Никаких складских движений или фиктивных финансовых транзакций.

**Навигация:** синхронно подключены все три места — левое меню Joomla, preset меню компонента, кликабельная карточка на главной панели в секции «Отчёты». Приоритет нативных классов Joomla и адаптива Bootstrap; RU/EN.

**Миграция:** `admin/sql/updates/mysql/0.6.22.sql` (аддитивные новые таблицы, без backfill); fresh install и cumulative demo SQL обновлены. Demo SQL вручную не импортировать. Резервная копия перед обновлением.

**Проверки:** `scripts/test-0-6-22-planfact.php`, `scripts/test-0-6-22-planfact-mysql84.php`, PHP 8.4/8.5, MySQL 8.4, Windows ZIP. Браузерная Joomla 6/Atum RU/EN, два оформления, обе темы остаётся отдельной приёмкой.

**Не реализовано:** доходы после возвратов, маркетинговая атрибуция, ROMI, бюджеты по кампаниям, фискальные чеки. Для C11 нужны настоящие кассовые провайдеры и выбор налоговой юрисдикции.

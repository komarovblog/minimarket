# MiniMarket 0.5.71 — Bootstrap 5: шесть режимов сетки

Дата: 07.11.2026. Рабочая ветка `development`.

## Сетка и настройки

В глобальных настройках MiniMarket, вкладка «Категории», и в каждой категории,
вкладка «Отображение», теперь одинаковые шесть переключателей количества карточек:

| Режим | Ширина окна | Макс. ширина Bootstrap-контейнера |
| --- | --- | --- |
| XS | 0–575 px | 100% |
| SM | 576–767 px | 540 px |
| MD | 768–991 px | 720 px |
| LG | 992–1199 px | 960 px |
| XL | 1200–1399 px | 1140 px |
| XXL | ≥1400 px | 1320 px |

Точки переключения соответствуют Bootstrap 5, не ширинам контейнера.
В каждой настройке приведены пояснения на русском и английском, с примерами
типичных устройств. Можно выбрать от 1 до 6 карточек на строку.

При глобальном «Список» настройки количества колонок видны, но
визуально и функционально отключены. В отдельной категории настройки
неактивны при «Список» и «По умолчанию»; они становятся доступны при
явном выборе «Плитка». При отключении значения сохраняются через скрытые
синхронизированные поля и снова доступны после переключения режима.

«По умолчанию» наследует **и тип представления, и размеры плитки**
из настроек магазина. Плитка категории позволяет переопределить любой
из шести размеров, оставив остальные в состоянии «Наследовать».

## Миграция без потери существующей настройки

- Старая БД: `cards_mobile→cards_xs`, `cards_tablet→cards_md`,
  `cards_desktop→cards_lg`, `cards_wide→cards_xl`.
- Колонки `cards_sm` и `cards_xxl` добавляются с `-1` (наследование).
- Глобальные параметры из Joomla `#__extensions.params` при обновлении
  переносятся в новые ключи. SM принимает старое значение Mobile, XXL —
  Wide. Прочие глобальные параметры не изменяются. Повторное
  выполнение не создаёт дубликатов.
- Старые четыре колонки категории переименовываются, не удаляются вместе
  со значениями и не создаются заново. После миграции их старых имён нет.
- Новый компонент содержит исходную шестиколоночную схему сразу.
- SQL `admin/sql/updates/mysql/0.5.71.sql` выполняется установщиком
  Joomla при обновлении. Ручной запуск SQL при обычном обновлении не требуется.

## Проверка

Тесты PHP 8.4/8.5, отдельные тесты наследования и фильтров витрины,
JavaScript-симуляция отключения и сохранения полей, MySQL 8.0 на
заполненной старой таблице, MySQL 8.4 с отдельной тестовой таблицей,
контракт сборки ZIP для Windows.

## Что ещё остаётся по общей задаче

**Полная ликвидация старых хранилищ характеристик не входит в 0.5.71.**
Для безопасного переноса нужны актуальные структуры и значения базы
`nnop3_minimarket_*`, чтобы составить однозначное сопоставление
пресетов, справочников, значений товаров, SKU и ссылок.
Не выполнять неподтверждённую деструктивную миграцию.
Потребуется отдельный проверенный SQL миграции, а затем полные
сквозные тесты на копии БД и в Joomla.

## Выгрузка для локальной установки

На Windows:

```powershell
Set-Location 'C:\OSPanel\home\minimarket.local'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release-to-desktop.ps1
```

Демонстрационный файл `minimarket_mysql84_nnop3_update_0_5_71.sql`
**не является миграцией схемы**: он содержит отдельные тестовые
демоданные. Не импортировать его повторно в рабочий магазин без необходимости.

# MiniMarket 0.4.1 — проверка дерева и редактора категорий

**01.11.2026 · Этапы ROADMAP 1.2–1.4 и 1.6 (частично) · Joomla runtime пока НЕ ПРОВЕРЕН.**

## Состав выпуска

- **Единственный ZIP:** `dist/com_minimarket.zip` — обычный компонент Joomla; **плагинов нет**. Текущая версия в манифесте **0.4.1**.
- Ветка `development` больше **не содержит** раннюю 0.4.0 миграцию характеристик: она и всё связанное с ней сохранены отдельно в **`feature/attributes-stage6`**, для этапа 6. В установку **не входят таблицы характеристик**, не требуется их запускать и нет пункта «Характеристики».
- Миграция `admin/sql/updates/mysql/0.4.1.sql` добавляет **только шесть полей в уже существующую** `#__minimarket_categories`: `introtext`, `sort_order`, `image`, `image_alt`, `show_children`, `show_products`. Старые поля, ID, alias, parent_id, все товары и их цены/остатки не переписываются. Для чистой установки те же поля в `install.mysql.sql`. SQL выполнять только штатным установщиком Joomla, не через phpMyAdmin.
- В редакторе категории: название/alias/родитель/статус, порядок, краткое описание, полное описание в штатном Joomla editor, выбор изображения через Joomla Media, alt, флаги показа дочерних категорий/товаров (**Наследовать/Да/Нет**).
- В Joomla **MiniMarket → Options** добавлены значения показа дочерних/товаров по умолчанию (Да). На витрине сохраняются плоские URL `/category/alias-id`. Дочерние категории сортируются по `sort_order` и названию. Непубликованные предки скрывают все дочерние страницы и товары.
- **Не готово:** полноценное административное дерево с отступами (1.6.2), гарантированное массовое управление порядком, полный SEO-редактор (этап 5), галереи товаров (этап 3), финальная семантическая вёрстка (этап 4). Эти пункты не маркируются выполненными.

## Подготовка перед установкой

1. Сохранить **резервную копию БД Joomla** (phpMyAdmin Export) — новая миграция добавляет колонки.
2. В CMD из `C:\OSPanel\home\minimarket.local` проверить статус и подтянуть `development`, не сбрасывая локальный `.osp/project.ini`:

```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-router.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-catalog.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-category-tree.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

3. Ожидаем `ROUTER_TEST_OK`, `CATALOG_TEST_OK`, `CATEGORY_TREE_TEST_OK` и **`PACKAGE_OK: 0.4.1`**. При FAIL **не устанавливать** ZIP и сообщить первый симптом. Тест `scripts/test-category-schema.php` в пользовательской БД **не запускать**: он специально ограничен одноразовой CI MySQL.
4. Установить **только `dist/com_minimarket.zip`** в Joomla Система → Установка → Расширения поверх существующего компонента. **Не удалять MiniMarket**, Joomla, старые товары и обычные пункты меню.

## Проверка в Joomla

1. MiniMarket → Категории: открыть существующую категорию. Новые поля должны отображаться, старые название/alias/описание/статус — сохраниться. Не менять чужие данные без причины.
2. Создать дополнительную тестовую категорию **«Аксессуары»** (alias `aksessuary`), родитель — одна из действующих опубликованных категорий, статус опубликован, порядок `5`; сохранить и повторно открыть. Родитель и порядок не должны сбрасываться.
3. Вставить краткое и полное описание, выбрать **изображение из Joomla Media** и alt, сохранить. Повторно открыть и проверить путь, alt и описания; на сайте изображение и текст должны отображаться, если файл доступен.
4. На странице родительской категории ссылка на «Аксессуары» должна появиться; адрес **`/category/aksessuary-{id}`**, без имени родителя. На главной витрине новая подкатегория отдельным корневым пунктом **не** появляется.
5. В категории «Аксессуары» поставить «Показывать товары» = **Нет**; сохранить. Убедиться, что страница не говорит «Нет товаров», если блок намеренно выключен. Вернуть «Наследовать».
6. Проверить запрет сделать категорию родителем самой себя или выбрать её потомка, а также доступность существующих категорий при публикации и снятии с публикации — без порчи действующих товаров. Операции с публикацией проводите **на созданных тестовых категориях**, не на рабочих.
7. В MiniMarket → Options проверить настройки дочерних категорий и товаров «по умолчанию» и их влияние только на категории со значением «Наследовать».
8. Открыть существующий товар `TEST-001`, убедиться, что **его ID, SKU, цена, остаток, URL не поменялись**; глобальная настройка основного пункта меню осталась.
9. Если были ошибки, приложить адрес страницы и скриншот/краткий текст; вручную БД не менять и компонент не удалять.

**PASS:** Joomla сохранила вложенную категорию, изображение/alt, порядок и видимость, а тестовый товар и маршруты не изменились. После пользовательского PASS обновить [ROADMAP.md](ROADMAP.md), [../CURRENT_TASK.md](../CURRENT_TASK.md), [PROJECT_PROGRESS.md](PROJECT_PROGRESS.md).

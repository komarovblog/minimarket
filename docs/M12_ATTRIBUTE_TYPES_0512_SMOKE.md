# MiniMarket 0.5.12 — тип данных, заполнение товара и вид фильтра

**02.11.2026. Разработка в development, GitHub CI проверяется; работа в реальной Joomla ещё не подтверждена.** Не путать с работающим фасетным фильтром: сейчас сохраняются его настройки, само пользовательское фильтрование по каталогу будет реализовано на следующем этапе.

## Три независимых параметра

В карточке характеристики:
- **Тип значения** (семь): `List` (Список), `Text` (Текст), `Number` (Число), `Textarea` (Многострочный), `Date` (Дата), `Boolean` (Да/Нет), `URL` (Ссылка).
- **Заполнение в товаре:** для списка — automatic / dropdown / radio (одно) / checkboxes (несколько); для числа — ручной ввод или **выбор из заданных чисел**, остальные типы имеют собственные стандартные контролы. В списковом редакторе по-прежнему работает одно Joomla Subform со значениями +/−/перетаскивание, прежние ID сохраняются. У Number значения `1000,1500,2000` хранятся **как число**, не как отдельные текстовые ID.
- **Фильтр каталога:** независимый `is_filterable` и совместимый `filter_mode`; при необходимости `filter_multiple`. Доступно: List — checkboxes/radio/dropdown, Text — поиск/фактические значения, Number — range/slider/checkboxes/dropdown, Date — date_range, Boolean — Boolean. URL и Textarea не фасетятся. Checkboxes всегда означает множественный выбор в фильтре, Radio — одиночный; Dropdown может быть одним или несколькими. Если товар хранит один материал, в публичном фильтре всё равно может быть выбран набор материалов.

Флаг **«Различает варианты SKU»** независим от обеих настроек. Реальные SKU-комбинации, цены/остатки по вариантам, публичные фильтры **НЕ реализованы** в 0.5.12.

## Безопасность данных

Миграция `0.5.12.sql` добавляет только колонки метаданных в attributes и расширяет `product_attribute_scalars.value_text` до `TEXT` для многострочного текста; не меняет товары, SKU, цены, остатки, изображения, категории и выбранные value_id. Уже разрешённые списковые фильтры получают совместимый режим Checkbox, чтобы не сбросить intent. Сохранение формы проверяет тип/способ ввода/фильтр, числовой диапазон/шаг/предустановки и запрещает менять тип при несовместимых сохранённых значениях. Для числовых списков в товаре нет дублирования таблицы словаря.

Ограничения: максимальная длина Text/URL 1024, Textarea 10 000 символов, Number до четырёх знаков после десятичной точки, Date — YYYY-MM-DD, URL — только http/https. Числовая таблица поддерживает min/max/step/единицу и список допустимых чисел через запятую. При выборе «из списка» сервер проверяет, что сохранённое число присутствует в preset-наборе.

## Установка Joomla

1. **Сначала резервная копия БД Joomla**; текущий MiniMarket **не удалять**, SQL руками не выполнять.
2. Windows CMD:
```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-attribute-presentation.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```
3. Ожидается `PACKAGE_OK: 0.5.12 (com_minimarket-0.5.12.zip)`. Установить **`dist\com_minimarket-0.5.12.zip`** через Joomla → System → Install → Extensions поверх установленного компонента.

## Короткая браузерная приёмка

1. Открыть уже существующий «Цвет». `List`, все его старые значения и **ID** должны остаться. Способ заполнения — автоматический / dropdown / radio / checkboxes; при radio можно только одно значение, при checkboxes несколько. Сохранить и проверить старый тестовый товар: значения должны остаться.
2. Создать в тестовой категории атрибут **Мощность** (`power`), тип Number, единица Вт, способ ввода **Выбор заданного числа**, варианты `1000, 1500, 2000`. Установить фильтр=Да, вид=**Ползунок**. Сохранить. В тестовом товаре выбрать 1500, сохранить и переоткрыть. Должно сохраняться как число `1500`.
3. Поменять у «Мощность» **только вид фильтра** на Checkboxes, сохранить. В товаре по-прежнему выбирается число из списка; настройки фильтра не должны менять заполнение товара.
4. Создать отдельные тестовые Textarea, Date (валидная дата, например 2026-11-02), URL (https://example.org) и Boolean; проверить сохранение и повторное открытие. URL и Textarea не могут быть фильтрами.
5. Попробовать невалидный диапазон min>max, нечисловые presets или Number с видом фильтра Radio: сервер должен отклонить данные. Проверить, что TEST-001, его старые SKU/цена/остаток, URL, галерея и атрибуты не меняются.
6. Проверить текст интерфейса в выбранном языке Joomla (RU/EN). В публичном каталоге **пока не появится** работающий фильтр — это следующий выпуск, а не ошибка установки.

**Границы принятия:** автоматические PHP/MySQL/ZIP проверки не заменяют проверку в живой Joomla, особенно зависимые поля формы и взаимодействие с Joomla Showon. Если форма не обновляется как ожидается — прислать краткий текст или скриншот, без БД/логов в чате.

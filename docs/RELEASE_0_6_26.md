# MiniMarket 0.6.26 — брошенные корзины, администраторские уведомления, касса и полезные счётчики

**База:** Joomla 6, PHP 8.4/8.5, MySQL 8.4. **Ветка:** `development`. Эта версия расширяет архитектуру магазина, но **не** подключает автоматические рассылки, фискальный провайдер или клиентские сообщения.

## Новая архитектура меню

- **Управление:** Очередь задач → Уведомления → Заказы → Доставки → Возвраты → Платежи → **Касса** → Покупатели → Обращения → Документы.
- **Отчёты:** Показатели бизнеса → Продажи → Остатки (ABC/XYZ) → Возвраты → План-факт.
- **Магазин:** Категории → Товары → Комплекты → Связи товаров → Связи комплектов → Бренды → Коллекции → Характеристики → Опции.
- **Маркетинг:** Акции и скидки → Промокоды → Рекомендации → **Брошенные корзины** → Отзывы → SEO-страницы.
- **Инструменты:** Импорт/экспорт → Фиды.
- **Настройки:** Способы доставки → Способы оплаты → Способы регистрации → Способы уведомлений → **События уведомлений** → **Операторы фискализации** → Настройки.

Тот же порядок и пункты внедрены в Joomla manifest submenu, component preset и главной панели. Всего **39 действующих карточек**. Новые страницы находятся в allowlist административного DisplayController и AdminEntityLinks. Все карточки используют inline SVG-иконки: отсутствие глифа Joomla в установленной теме больше не оставляет пустое место.

## 1. Брошенные корзины — реальный учёт, но пока НЕ рассылка

- Реальное событие: пользователь меняет корзину через CSRF-проверенный POST; `AbandonedCartStore::record` best-effort сохраняет ограниченные товар/вариант/количество и проверенный Joomla user_id (если есть). Гостевой сеанс представлен случайным 256-битным токеном, в БД хранится только SHA-256. Контакты, email, IP, цены не сохраняются.
- После **успешного** `OrderStorage::create` `AbandonedCartStore::converted` помечает именно этот токен завершённым. Не создавать заказ и не менять остатки ради аналитики.
- Брошенной в списке считается **неизменявшаяся минимум 60 минут** активная непустая корзина за последние **30 дней**. Очистка старых записей происходит opportunistic пачками по 100 после части мутаций корзины; пока нет гарантированного cron на точное время удаления.
- Раздел Marketing → Abandoned carts: нативные SearchTools, список реальных товарных ID и количеств, проверенный ID Joomla-покупателя либо «Гость», даты UTC; поиск только по действительному ID. Сумма не фиксируется и не используется как окончательная стоимость.
- **Пока нет:** восстановления корзины по ссылке, автоматических email/SMS напоминаний, зарегистрированного согласия на маркетинг и верифицированной связи гостевой корзины с человеком. Это следующий отдельный этап, причём отправлять клиентам без доказанного права/подключённого канала **нельзя**.
- `0.6.26.sql` и fresh install создают `#__minimarket_cart_snapshots`. Никакого журнала движений запасов.

## 2. Административные уведомления и единая событийная матрица

- В Управлении → **Уведомления** показаны личные **непрочитанные** текущие события из **той же** Workqueue (оплаты, проблемы доставки, активные возвраты, обращения), с общей персональной отметкой read/unread. Не создаётся второе независимое хранилище исходных бизнес-фактов. Статусы закрываются только в исходных карточках. Показываются первые 100 текущих записей в каждой категории; полный список открывать в исходном разделе.
- В Настройки → **События уведомлений** две группы: **клиенты** и **администраторы**. В строках — события, в столбцах — встроенный email и обнаруженные каналы от установленных notification-плагинов; можно назначить несколько каналов каждому событию. Customer matrix использует те же `notification_email_events`/`notification_plugin_events`, что и редактор способов уведомлений. Для администратора добавлены `notification_admin_email_events`/`notification_admin_plugin_events` в **тот же** список допустимых component settings. Сохранение — POST/CSRF, `core.options/core.admin`, строгая проверка channel ID/event code.
- Новые admin events: новый заказ, ожидание оплаты, проблема доставки, новый возврат, обращение, фискальная ошибка, брошенная корзина. Это **настройка списка событий**, не фактически отправленные сотрудникам письма: пока нет получателей/шаблонов/transport sender для admin и нет гарантий отправки. Действующий `NotificationSender` покупателей не переопределялся.

## 3. Касса и фискальные операторы

- **Управление → Касса** = ранее созданный защищённый read-only `view=fiscalization` с будущим журналом реальных операций продажи/возврата, их ID/ошибок/чеков; новый заголовок и новое положение в меню. Нет реального кассового провайдера, реальные чеки не выпускаются.
- **Настройки → Операторы фискализации** = реестр установленных Joomla-плагинов `minimarket` с префиксом `fiscal_*`; при достаточных правах — ссылка на нативную карточку Joomla Plugins. Само включение произвольного плагина не превращает его в поддерживаемый адаптер; для подключения потребуются конкретный провайдер, юрисдикция и подтверждённые операции.
- **Документы** остаются внутри заказа + общим реестром коммерческих счетов. **Документы ≠ ERP:** B2B счёт сам по себе не вводит закупки, поставщиков, бухгалтерские регистры и взаиморасчёты.

## 4. Значимые счётчики и иконки

- Badge для **Управления**: Очередь задач = все реально незакрытые; Уведомления = личные непрочитанные; Заказы = новые; Доставки = новые или с проблемой; Возвраты = новые; Платежи = требующие внимания; Касса = pending/failed операции; Обращения = новые.
- Badge «Брошенные корзины» = реальные активные корзины без изменений ≥60 минут. «Отзывы» = ожидающие модерации.
- У других пунктов (категории, справочники, отчёты, способы, настройки, документы без действий) **значок числа скрыт**. Ноль у любой задачи скрыт, а не вводит в заблуждение прочерком. Слишком большие выборки событий уведомлений подсчитываются с ограничением: панель обозначает нижнюю границу/неполные данные, а не выдумывает число.
- Все dashboard cards получают SVG с реальной графикой: не зависят от библиотеки отсутствующих Joomla font icons. Стили адаптивности Atum не менялись.

## Пока предлагаем только ПРЕДУСМОТРЕТЬ — не добавлять пустые меню

1. **Маркетинг:** полноценные сценарии восстановления брошенной корзины, разрешённые отправки по событиям/окнам, частотные лимиты, отписка, результаты и продажи после возврата; программа лояльности/бонусы/подарочные сертификаты — после приоритизации.
2. **Управление:** настоящая доставка администраторских уведомлений с адресатами, журнал доставки/ошибок и retries, полная клиентская поддержка по подтверждённым каналам; настоящие refund и безопасный отдельный restock без складского журнала; подключённые доставщики.
3. **B2B внутри заказов/покупателей:** юридические лица, реквизиты, плательщик/получатель, счета, накладные/УПД, статусы подписания, печать/PDF и интеграция с внешней бухгалтерией. Название «ERP» не использовать до реальной закупочной/учётной функциональности.
4. **Касса:** правовая юрисдикция, реальный фискальный провайдер и его настройки, подтверждение, возмещения, чеки с внешним ID/ссылкой, webhook, идемпотентность, сверка, retry.
5. **Витрина:** избранное/сравнение и личный кабинет покупателя; маркетинговые/аналитические отчёты по воронке — только после достоверного учета событий и согласий.
6. **Финансы:** документированные комиссии, фактические возвраты, расходы/налоги; не называть неполную выручку «чистой прибылью».

## Безопасность и ограничения

- Ни одна новая маркетинговая запись не служит основанием для отправки клиенту письма. Контакты гостя нельзя выводить из cart_key, и лог нельзя считать согласием.
- Реальные деньги, остатки, статусы заказов, работа фискального провайдера, ядро Joomla, шаблон Blank и ветка `main` **не менялись**.
- На очередях/уведомлениях сохраняется серверная ACL проверка, единственный базовый источник состояний и персональный read state.
- CI не доказывает корректность реальных Joomla/Atum экранов; требуются RU/EN, светлая/тёмная тема, responsive, маршруты submenu/preset, guest/login checkout и ручная приёмка.

### Приёмка

- Гостевая и авторизованная корзина: добавить/обновить/удалить товар; через 60 минут без изменений увидеть запись в маркетинге; после успешного checkout корзина не должна числиться брошенной. Гость остаётся гостем без контактов и напоминания. Выход/логин, новые сессии не должны смешивать корзины.
- Проверить четыре новых раздела, все три меню и все 39 реальных карточек; иконка есть у каждой. Ни один справочник не показывает «число всех записей» без практической причины; новый заказ поднимает badge заказа, изменение статуса снимает его.
- Два администратора: личная непрочитанная очередь, отметить прочитанным, восстановить unread при новом событии. Проверить рабочее сохранение отдельных customer/admin событий и единство способов; **не ожидать отправки** admin email.
- «Касса» должна показать пустой read-only журнал, «Операторы фискализации» — список обнаруженных плагинов или отсутствие плагинов без ложной «готовой кассы».

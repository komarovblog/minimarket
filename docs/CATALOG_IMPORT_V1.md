# MiniMarket — единый импорт данных (обязательный стандарт всех разделов)

**Решение 03.11.2026.** После установки новой версии магазина пользователь должен иметь возможность быстро загрузить **свои** категории, товары, характеристики, опции и связи без ручного ввода. Каждый следующий раздел (бренды, коллекции, рекомендации, фиды, комплекты и др.) принимается в разработку вместе с форматом импорта, экспортом и автоматическими проверками. Импорт не является отдельной «опцией на будущее».

## Что реально умеет версия 0.5.35

- В админке **MiniMarket → Импорт** загружается единый JSON-пакет с зависимостями по стабильным внешним ключам: `source` + `key`.
- В текущем пакете поддержаны: **categories, attributes, options, products, links, category_attributes, category_options**.
- Можно загрузить категории с иерархией (порядок категорий в файле не важен), информационные характеристики `text/number/editor/boolean/document/color`, цветовые значения характеристики, глобальные опции со значениями, простые товары с базовым SKU/ценой/остатком, несколько связей товаров и назначения характеристик/опций категориям.
- Операции выполняются в порядке зависимостей. **Предпросмотр** проверяет запись в транзакции и откатывает её; пользователь видит количество новых и обновляемых записей и назначений. После подтверждения импортируется **точно тот же пакет из административной сессии**. Ошибка прерывает всю транзакцию.
- Повторная загрузка с тем же `source` и `key` обновляет уже существующие сущности. Схема `#__minimarket_import_entity_keys` хранит соответствие `source + kind + external_key → local_id`; при первой загрузке совпадающий уникальный `code/alias/title` **по умолчанию приводит к отказу**, чтобы случайно не перезаписать вручную созданный или импортированный из другой системы объект. Для осознанной привязки к существующим объектам можно добавить на верхнем уровне `"adopt_existing": true`; после этого явного разрешения запись привязывается по уникальному коду и далее обновляется по стабильному внешнему ключу. Проверить такой предпросмотр особенно внимательно.
- Импорт **не удаляет** пропущенные категории, значения, товары, опции, галереи, SKU, ручные связи или назначения. В режимах назначения категорий явное `inherit` отменяет только одно правило.
- Формат до 3 МиБ; максимум 2500 строк верхнего уровня в одном пакете и 250 значений на одну опцию или характеристику. Для больших каталогов — разбиение на несколько пакетов с одинаковым `source`.
- Никакой работы напрямую с `.env`/PHP/SQL для пользователя, загрузка из Joomla. CSV/Excel (XLSX) и экспорт будут добавлены в общий интерфейс следующими итерациями. Пока JSON подходит для подготовки из любого источника через скрипт или табличную конвертацию.

**Не готово в 0.5.35:** импорт вариативных SKU и комбинаций, фото/видео файлов, значений характеристик товаров, фидов, брендов и коллекций (сами разделы ещё не реализованы), Excel/CSV и экспорт. Простому товару пока **обязателен базовый `sku`**, поскольку действующий редактор товара требует его; необязательный SKU варианта относится к будущему A2. Сама загрузка ещё должна пройти ручную приёмку в локальной Joomla, даже если PHP/MySQL CI PASS.

## Файл и поля

Пример: [examples/import-catalog-v1.json](../examples/import-catalog-v1.json). `version:1`, `source: "my-supplier"`, необязательный флаг `adopt_existing: false` (по умолчанию), секции-списки. Неизвестные секции и поля запрещены, чтобы импорт не игнорировал опечатки.

Каждая сущность получает **внешний `key`** (латинский ключ с цифрами, точкой, дефисом, двоеточием или подчёркиванием, до 128 символов). Его нельзя менять между загрузками. Если нужно изменить название, поменяйте `title`, а `key` сохраните. `source` отличает разные системы поставщиков.

| Секция | Поля | Ссылки |
| --- | --- | --- |
| categories | key, title, alias, parent, state | parent — ключ родительской категории либо null, отсутствие parent сохраняет старую связь |
| attributes | key, title, code, type, state, values (только color) | values: code, title, state, необязательный color_hex |
| options | key, title, code, state, values | values: code, title, state, необязательный color_hex |
| products | key, title, alias, sku, price (строка, точность 2), stock, stock_mode (0 общий, 1 по SKU), category, state | category — ключ категории того же source |
| links | key, title, members, state | members — список ключей товаров того же source; пополняет связи, не заменяет весь старый состав |
| category_attributes | key, category, attribute, mode | ключи категории/характеристики; режим disabled / optional / required / inherit |
| category_options | key, category, option, mode | ключи категории/опции; режим disabled / optional / required / inherit |

Требования к `alias/code`: латинские строчные буквы, цифры, дефисы/нижнее подчёркивание, начало — буква. `title` — обычное название, поддерживает русский язык. `state` — 0 либо 1, без него новые записи по умолчанию неопубликованы. Цена — **строка**, например `"64990.00"`; не использовать дробные числа JSON, чтобы не потерять копейки.

При импорте характеристик уже заполненного магазина **тип характеристики менять нельзя**: сохранённые значения нельзя переинтерпретировать. Иерархия категорий проверяется на циклы. Одинаковый URL категории и товара запрещён. Каждая комбинация источника, сущности и ключа уникальна. Ссылки на отсутствующие категории/товары/опции приводят к откату всего пакета, а не к частичному импорту.

Файлы изображений нужно загружать в Joomla Media отдельно; импорт внешних URL изображений или скачивание из сети пока не реализовано. Это исключает SSRF, неожиданные файлы и изменение медиа без контроля.

## Контрольный пример рабочего процесса

1. Сделать backup MySQL `minimarket`, установить компонент после PASS GitHub Actions.
2. Открыть MiniMarket → Импорт, скачать пример JSON из репозитория. При необходимости изменить `source`, категории, имена/коды/цены.
3. Загрузить файл, нажать «Проверить файл». Сверить созданные/обновлённые записи и связи.
4. Нажать «Применить импорт» — сервер использует проверенный файл из сессии, без повторного выбора.
5. Открыть Категории, Товары, Характеристики, Опции, Связи товаров: проверить данные и связи, RU/EN, тёмную/светлую тему.
6. Повторить загрузку того же файла: **новых записей 0**, изменения обновляют уже созданные ID. Изменить цену одного товара, импортировать снова: цена меняется, SKU/галерея/URL других товаров не затрагиваются.
7. Испытать неправильный parent или ссылку на несуществующий product: предпросмотр отклонён, частичных изменений нет.
8. Проверить отдельный импорт, содержащий только `options` и `category_options`, с тем же `source`: уже загруженные категории распознаются по mapping.

## Обязательный контракт для нового раздела

Новый раздел считается **завершённым** только после следующих пунктов:

- Рабочий список и форма Joomla, RU/EN.
- Import vN: поля, стабильный внешний ключ, разрешённые зависимости и режим обновления, пример файла для уже существующего источника.
- Export с теми же логическими кодами/ключами (этап развития Import v1): round-trip (экспорт → чистая установка → импорт) должен сохранять ссылки, цены, параметры. До появления экспорта не заявлять полный round-trip.
- **Preview + Apply**, строгая валидация, отсутствие молчаливого удаления, transaction rollback, ACL/CSRF, понятный отчёт без технических логов.
- Тесты: fresh/upgrade схемы, первый импорт, повторный импорт без дублей, изменение нескольких значений, ошибки связей/rollback, сохранение SKU/остатков/галереи.
- Пример + пользовательская инструкция прямо в разделе/документации. Не добавлять раздел как «пустую кнопку, которую заполним потом».

Приоритет после 0.5.35: (1) SKU и значения характеристик товара, (2) CSV и экспорт, (3) импорт новых брендов/коллекций в момент реализации их CRUD, (4) правила рекомендаций категории, (5) фиды/комплекты по мере разработки. **Импорт не должен отставать от появления разделов.**

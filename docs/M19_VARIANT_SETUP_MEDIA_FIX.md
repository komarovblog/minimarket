# MiniMarket 0.5.19 — варианты SKU и метаданные Joomla Media

## Инцидент

Открытие товара уже исправлено в 0.5.18, но при добавлении строки `TEST-002` без назначенных для категории **характеристик вариантов** сохранение отклонялось общей ошибкой `COM_MINIMARKET_VARIANTS_INVALID`. По скриншоту категория не содержала опубликованных атрибутов с `is_variant=1` и готовыми вариантами. Это не ошибка изображения: серверный `MediaPath::normalize()` очищал суффикс Joomla Media, но клиентский селектор `clean-media.js` охватывал только фото товара и базовую галерею, пропуская вложенную галерею и обложку SKU.

## Изменение

- При отсутствии подходящей характеристики в выбранной категории рядом с вкладкой «Варианты» показывается инструкция (RU/EN) и переход к **MiniMarket → Характеристики**, а кнопка `+` добавления варианта блокируется. У вложенных фото кнопка `+` не затрагивается.
- При выборе категории с готовыми осями кнопка активируется. На сервере даже обход JS выдаёт `COM_MINIMARKET_VARIANTS_NO_AXES` вместо общей ошибки. Ненужных SKU и значений в БД не создаём.
- Для variant `image` и `photos[].path` расширен `clean-media.js`: в интерфейсе оставляем `images/...` без `#joomlaImage://...`; серверный MediaPath всё равно валидирует и очищает вход.
- В карточке **Характеристики** уточнено «Различает варианты товара»: это применимо для Color, Text/Preset (Size), legacy List, позволяет отдельные SKU/остатки/цены/фото при одном URL.
- Никаких миграций БД. Ветки `main` не меняем.

## Проверка в Joomla

1. В товаре без назначенной вариантной характеристики вкладка «Варианты» должна показывать инструкцию, `+` заблокирован; обычный товар сохраняется без SKU-вариантов.
2. MiniMarket → Характеристики: создать «Размер», Тип «Текст», Ввод «Готовые значения», S, M, L; включить «Различает варианты товара», опубликовать; на вкладке «Категории» назначить категорию товара. Открыть товар заново.
3. Варианты: `+` активна; новая строка показывает селект «Размер». Выбрать S, SKU `TEST-S`, цена `22`, остаток `3`, фото. Сохранить, переоткрыть товар и проверить фото/значения на сайте.
4. Проверить выбор медиа в обложке варианта и дополнительных фото: текстовое поле не показывает `#joomlaImage://...`, в БД значения без служебных метаданных.
5. Случайный ввод без выбранного размера отклоняется конкретной ошибкой, старый товар/URL/галерея не изменяются.

GitHub CI проверяет синтаксис PHP/JS, нативный ZIP, MySQL миграции и регрессии. Работа реальной Joomla подтверждается только ручной проверкой после установки.

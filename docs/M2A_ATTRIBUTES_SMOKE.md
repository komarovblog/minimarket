# MiniMarket 0.4.0 — первый этап характеристик, безопасный smoke

**Дата:** 01.11.2026. **GitHub `development`**. Первое подтверждение пользовательской Joomla версии **0.4.0 пока NOT RUN**. В предыдущей версии пользователь подтвердил работу Options и одного выбранного основного пункта меню.

## Что это и что пока не готово

**Реализован только независимый справочник характеристик и значений.** Характеристики могут быть следующих типов: **Список**, **Текст**, **Число**, **Да / Нет**; у каждой есть понятное название, уникальный латинский код, статус, порядок, флажок «Использовать в фильтрах» (подготовка) и «Различает варианты товара» (**только для типа Список**). Значения списков (например, цвет → красный, жёлтый) — отдельные записи со стабильным ID, кодом, статусом, порядком; код значения уникален в пределах своей характеристики. Можно редактировать значения по ссылке из списка характеристик.

**Не реализованы ещё:** назначение характеристик товару, создание нескольких вариантов SKU, отдельные цены/остатки вариантов, фотографии по цвету, фильтры товаров, cart/checkout с variant_id. Флажки готовят модель данных, но **сами ничего не выводят на витрине**. Не обещать пользователю работу этих функций, пока нет кода и runtime PASS.

**Данные и схема:** миграция `admin/sql/updates/mysql/0.4.0.sql` **только создаёт** `#__minimarket_attributes` и `#__minimarket_attribute_values`. Текущую `#__minimarket_products` и `#__minimarket_categories` не изменяет, не удаляет и не переписывает. `install.mysql.sql` для чистых установок создаёт обе новые таблицы вместе с исходными. На уровне БД уникальные индексы по `attribute.code` и `(attribute_id, value.code)`, FK значения → характеристики (ON DELETE RESTRICT), индексы state/order. Товар `TEST-001`, его `product_id`, alias, SKU, цена, остаток и URL не мигрируют; перенос в единый вариант запланирован отдельной итерацией после проверки этой основы.

## Проверки перед установкой

**Сначала сделайте резервную копию БД** через phpMyAdmin или другую привычную процедуру. Даже добавление таблиц должно быть обратимым до установки. Не выполняйте SQL вручную и не удаляйте предыдущий компонент.

В CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-router.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-shopmenu.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-catalog.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-attributes.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидается `ROUTER_TEST_OK`, `SHOPMENU_TEST_OK`, `CATALOG_TEST_OK`, `ATTRIBUTES_TEST_OK`, `PACKAGE_OK: 0.4.0`. Скрипт `scripts/test-attribute-schema.php` **локально НЕ запускать**: это тест только в одноразовой CI MySQL базе и он принудительно проверяет её имя.

При FAIL — ZIP не устанавливать. Сохранять собственный `.osp/project.ini`, не делать `git clean/reset`; конфиденциальные логи и пароли не публиковать. Проверку CI смотреть в Actions — PHP 8.4/8.5, Windows ZIP, тест временной MySQL 8, включая сохранность старой строки товара.

## Один Joomla smoke после обновления

1. Joomla → Система → Установка расширений → установить **`dist/com_minimarket.zip` 0.4.0** поверх работающего MiniMarket. Ничего не удалять; **НЕ** `pkg_minimarket.zip` и не плагин.
2. В админке MiniMarket открыть новый раздел «Характеристики». Если пункт в левом подменю не появился при обновлении, можно открыть MiniMarket Dashboard и перейти по ссылке «Характеристики» или напрямую: `/administrator/index.php?option=com_minimarket&view=attributes`. Это не требует ручной правки меню Joomla.
3. Создать характеристику **Цвет**: код `color`, тип `Список`, «Различает варианты» = Да, «Использовать в фильтрах» = Да, статус Опубликовано, сохранить.
4. В её строке нажать «Редактировать значения», создать **Красный** (`red`) и **Жёлтый** (`yellow`), оба опубликованы. Проверить, что в списке значение связано именно с «Цвет».
5. Создать **Размер** (код `size`, тип `Список`, «Различает варианты» = Да) и значения **S** (`s`), **M** (`m`), **L** (`l`).
6. Попробовать повторно создать значение `red` внутри «Цвет» — должно быть сообщение о дубле, не новая запись. Значение `red` внутри другой характеристики теоретически допустимо. Попробовать поменять тип «Цвет» с `Список` на `Число` — должно отказать, пока у цвета есть значения; вернуть тип Список. Прежние значения не должны исчезнуть.
7. Проверить регрессию: пункты `/` и `/catalog` продолжают открываться, **Options** выбирает основной пункт для ссылок. Товар `TEST-001` в «Товары» должен остаться с теми же параметрами, которые были перед установкой (последний пользовательский скриншот: цена `1990.50`, остаток `3`), URL продукта не меняется. **Не создавать фиктивные товары и не менять остатки ради проверки.**
8. После успешного smoke сообщить «Характеристики 0.4.0 — PASS» или прислать краткий симптом и скриншот ошибки. Не менять таблицы вручную при FAIL.

## Следующая итерация после PASS

Связать характеристику с реальным товаром; реализовать только допустимые комбинации варианта с уникальными SKU, основной вариант, цены и остатки; мигрировать каждый старый продукт **в один default variant** в транзакционно безопасной и проверяемой логике, не меняя текущие product_id, alias, URL. Затем фотографии общие/по значению/по точному SKU. Не допускать двух независимых источников цены/остатка.

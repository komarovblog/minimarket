# MiniMarket — разработка, сборка и установка на чистую Joomla 6

Обновлено: 30.10.2026. Только `komarovblog/minimarket`, ветка `development`; Symfony Shop и `main` не трогать.

## Главное правило

**Работающая Joomla — только тестовый стенд.** Код наших расширений живёт в GitHub `src/`, скрипты сборки в `scripts/`. Нельзя разрабатывать вручную в `public_html/components`, `public_html/administrator/components`, `public_html/plugins` или изменять Joomla core и чужой активный шаблон. Установленный сайт и БД не отправляются в GitHub.

Результат разработки — **самостоятельный Joomla ZIP**, который устанавливается на любую **совместимую Joomla 6** через System → Install → Extensions, без переноса нашего локального SQL-дампа или файлов ядра. Конечные дистрибутивы: `pkg_minimarket_articles.zip` и `pkg_minimarket_catalog.zip`. Пока они **не созданы**.

## Процесс одной итерации

1. Правим **только** свои исходники в `src/`, коммитим в GitHub `development` (или локально с контролируемым push). Никаких ручных изменений уже установленной копии как источника кода.
2. Локально проверяем `git status`, затем безопасно получаем обновления `git pull --ff-only origin development`; при конфликте остановиться без `reset --hard`.
3. Запускаем будущую проверенную команду `scripts/build.ps1`. Она собирает ZIP со штатными XML-манифестами Joomla, PHP, JS/CSS и собственными SQL-миграциями в локальную **игнорируемую Git** папку `dist/`. Скрипт ещё **не реализован**.
4. Устанавливаем или обновляем ZIP через **штатный менеджер расширений Joomla** на `minimarket.local`. Joomla копирует файлы в нужные каталоги и выполняет install/update scripts.
5. Проверяем фронт, админку, работу выбора товарных категорий, стандартные Joomla URL, цену, безопасность, Schema.org и dataLayer. Ошибку исправляем в `src`, пересобираем ZIP.
6. Для доказательства **переносимости** тот же ZIP устанавливаем на **вторую чистую Joomla с отдельной БД** и проверяем установку, обновление, удаление. Никаких файлов/полей/дампов из первой Joomla не копируем. Не утверждать успешность без фактической проверки.

Официальная документация: https://manual.joomla.org/docs/next/building-extensions/install-update/installation/package/ ; https://manual.joomla.org/docs/next/building-extensions/install-update/installation/manifest/ ; https://manual.joomla.org/docs/next/building-extensions/install-update/installation/install-process/ .

## Что будет внутри пакета

Начиная с малого, затем при необходимости добавляем:
- **`com_minimarket`**: меню админки, настройки категорий Joomla, корзина, заказы, checkout и общая торговая логика.
- **Content plugin**: интеграция товаров на материалах и с нужными событиями `com_content`; не затрагивает обычные статьи.
- **System plugin**: общая интеграция маршрутизации/Schema.org/dataLayer по контексту и с учётом Joomla schema/consent.
- **Модуль корзины**: счётчик/мини-корзина, если потребуется.
- **Макеты/отдельный устанавливаемый шаблон**: для полноценного вида карточек и категорий.

Joomla поддерживает один `package`, включающий component, plugin, module и template. Пакетный манифест и подчинённые ZIP упаковываются вместе. Первая версия может быть простым `com_minimarket.zip`, но цель — единая установка полнофункционального `pkg_minimarket_articles.zip` и отдельного `pkg_minimarket_catalog.zip`.

## Переносимые товарные категории и Custom Fields

В `MiniMarket → Настройки` администратор выбирает **существующие category IDs Joomla**, материалы которых считаются товарами. Есть отдельная опция включения дочерних категорий. Список пуст по умолчанию: чужие статьи не превращаются в товары.

Установщик/поддерживаемый код конфигурации **идемпотентно создаёт собственные технические группы и поля** (SKU, price, stock и т.п.) средствами Joomla API и назначает их на выбранные категории. При обновлении нельзя создавать дубликаты, перезаписывать чужие поля или удалять данные. Категории и материалы являются **контентом владельца сайта** — пакет не пересылает их из локальной Joomla.

Собственные защищённые таблицы заказов/платежей создаются только штатными миграциями расширения, используя общую с Joomla БД и префикс `#__`. При удалении согласовать политику сохранения реальных заказов и данные никогда не очищать молча.

## Полные переопределения article/category

Template overrides `com_content` обычно принадлежат активному шаблону. Копировать их в произвольный шаблон при установке небезопасно: они могут конфликтовать с пользовательскими изменениями. Поэтому:
- Торговые блоки поставляем в **своих layout/ресурсах и совместимых событийных плагинах** для выбранных категорий.
- Полноценную товарную страницу и категорию при необходимости поставляем как **отдельный устанавливаемый шаблон/дочерний шаблон Joomla** либо безопасно подключаемые альтернативные макеты. Администратор назначает этот стиль/макет там, где нужно; пакет не заменяет текущую тему самовольно.
- Проверяем поддержку разных шаблонов; не обещаем идентичное оформление на всех сторонних темах.

**M1:** идемпотентные товарные поля Joomla, вывод карточки и категории, кнопка корзины; затем Schema.org Product/Offer, dataLayer и SEO-фильтр. **Далее** общая корзина/checkout/заказы и второй вариант Catalog с собственными таблицами и плоскими URL.

**Готовность** не определяется тем, что мы что-то настроили в админке тестовой Joomla: решает воспроизводимый ZIP и тест чистой установки.

# MiniMarket 0.5.54 — 12 UI уточнений каталога, комплектов и импорта

**Дата:** 06.11.2026. **Ветка:** `development`. Обновление поверх 0.5.53, без удаления данных и переделки Joomla.

## Зафиксированные решения

1. **Категория → «Отображение»:** отдельно от «Показывать товары» добавлено **«Показывать комплекты»**, выбор наследовать / да / нет. Для старых категорий `show_bundles=-1`; родительские настройки меню не переписываются. На витрине категория фильтрует обычные товары и комплекты независимо.
2. **«Метки» переименованы в «Флаги» (RU) / «Flags» (EN).** «Скидка» отображается всегда, но без старой цены checkbox недоступен, рядом пояснение. При вводе старой цены он активируется. Никаких исчезающих контролов.
3. **Бренд — один, поиск как у коллекций.** «Добавить бренд», поиск по названию или alias; выбранный бренд показывается ссылкой в редактор и кнопкой «−». Удаление выбора отправляет `brand_id=0`; данные бренда не удаляются. AJAX endpoint ограничен 25 и защищён ACL/CSRF.
4. **Единые кнопки:** самостоятельные действия вне списков — подробный текст («Добавить бренд», «Добавить товар», «Добавить комплект», «Добавить в коллекцию», «Добавить категорию»). Внутри списков/выдачи поиска — **только «+» для добавления и «−» для исключения**, обязательно `aria-label` с названием сущности и локализованным действием. Функция «Удалить» из самой БД — всегда отдельное подтверждаемое действие, НЕ заменяется минусом.
5. **Характеристики в товаре:** единая ссылка **«Редактировать характеристику»** прямо на редактор сущности для *каждого типа*, включая число, текст, HTML, цвет, файл, да/нет; исчезает особый линк «Редактировать значения» только у цвета.
6. **Товар:** вкладка «Состав комплекта» скрыта; SKU и опции товара остаются. **Комплект:** вкладка «Опции» (SKU матрица) скрыта, «Связи товаров» обозначена «Связи комплектов».
7. **Связи комплектов:** кнопки и подписи о комплекте, фильтрация по типу с сервера, сохранены существующие группы. В выдаче поиска плюс, у участников минус.
8. **Способ цены комплекта перенесён в «Основное»:** «Фиксированная цена» либо «Скидка от суммы компонентов» и поле %. При скидочном способе вручную введённую цену не показывать, не стирать базовую цену в БД; публичная цена автоматически считается из цен компонентов и вложенных комплектов.
9. **«Состав комплекта»:** только компонент/SKU, количество, единичная цена, сумма строки, снизу **сумма компонентов и цена итого**. JS предварительно пересчитывает при добавлении, исключении, изменении количества и способа цены. Сервер пересчитывает при каждом открытии каталога.
10. **Дополнительный флаг «Выгода»:** только у комплекта с процентной скидкой от суммы, checkbox включается на вкладке «Флаги». Публичная надпись «Выгода 123.00 ₽» (Savings в EN) считается из суммы компонентов минус фактическая цена. При нулевой выгоде или фиксированной цене метка не показывается.
11. **Флаг «Скидка» на сайте:** теперь **процент и денежная разница старой и текущей цены**, например «Скидка −26% · 500.00 ₽». Если старая цена равна или ниже актуальной — флаг скрывается. У комплектов используется их **вычисленная** итоговая цена, так что экономия обновляется по изменению компонентов.
12. **Импорт/экспорт:** форма загрузки и кнопка «Проверить файл» перенесены внутрь верхнего единого блока импорта, экспорт остаётся отдельным блоком ниже. Контроллеры, формат и ограничения импорта на данном этапе не меняются.

## Изменения БД

Аддитивная автоматическая миграция `admin/sql/updates/mysql/0.5.54.sql`:
- `#__minimarket_categories.show_bundles TINYINT NOT NULL DEFAULT -1`;
- `#__minimarket_products.badge_benefit TINYINT UNSIGNED NOT NULL DEFAULT 0`.

Те же поля — в `install.mysql.sql` для чистых установок. Никаких удалений, пересоздания товаров/коллекций/комплектов, потери SKU и картинок. **Встроенная миграция нужна всегда, но вручную в phpMyAdmin её импортировать не надо.**

Отдельный необязательный `sample-data/minimarket_ui_benefit_demo_0_5_54.sql` для пользовательского демо каталога MySQL 8.4 с префиксом `nnop3_`: категория #101 показывает комплекты, а скидочные комплекты #1091/1092 получают флаг выгоды **только если их режим цены уже discount**. SQL не стирает данные, повторно исполним, не делает DROP/DELETE/ALTER; не предназначен для реальных товаров без проверки.

## Приёмка

1. Сделать копию БД, установить **`com_minimarket-0.5.54.zip` поверх 0.5.53** через Joomla. Не запускать заново полную демо загрузку.
2. Проверить настройку отображения комплектов в категории: да/нет/наследовать независимо от товаров.
3. В обычном товаре: вкладки «Флаги» и «Бренд и коллекции»; «Состав комплекта» отсутствует. Без старой цены чекбокс скидки виден, но выключен; после ввода цены доступен.
4. Проверить бренд: выбрать по поиску, сохранить/переоткрыть, исключить через «−» и убедиться, что запись бренда не удалена.
5. В каждой характеристике (текст, число, цвет, HTML, файл) одинаковая ссылка «Редактировать характеристику».
6. В комплекте: есть вкладка «Состав комплекта» и «Связи комплектов», нет вкладки SKU/опций. На «Основное» два режима цены, на «Состав» цена каждой позиции и итоги, изменение количества пересчитывает сумму.
7. Включить флаг «Выгода» у скидочного комплекта; при изменении цен товаров на сайте должны пересчитаться и стоимость комплекта, и денежная выгода. Для фиксированного комплекта флаг недоступен.
8. Публичный каталог, категория и карточка: «Скидка −N% · N ₽», «Выгода N ₽», «Новинка» и «Популярное», RU/EN. Проверить действительность временных меток и старой цены.
9. Открыть «Импорт и экспорт», проверить, что выбор файла и «Проверить файл» входят в первый блок.
10. Для образца бонусов после установки можно вручную импортировать **только** `minimarket_ui_benefit_demo_0_5_54.sql`, если в базе уже есть прежние демо-комплекты.

## Правило интерфейса (приоритет для новых чатов)

**Кнопки отдельно от списков пишутся словами с объектом действия; кнопки внутри списков — плюс/минус и доступные подписи.** Все селекторы добавления в каталог используют поиск; для товара/SKU — поиск по имени/артикулу и фильтр категории; для одиночного бренда — поиск по имени/коду. Не возвращать огромные списки чекбоксов/селектов. Не менять принятые матрицу SKU, галерею и маршруты сущностей без команды.

Порядок далее: приёмка исправлений → **полный импорт/экспорт v2** (включая `show_bundles`, флаги и состав комплектов) → фильтры/SEO лендинги → корзина/заказы/ЛК → рекомендации → публичная полировка.

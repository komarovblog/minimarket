# MiniMarket 0.5.7 — характеристики непосредственно в товаре

**02.11.2026.** После замечания пользователя («в товаре по-прежнему нет атрибута») реализован этап 6.3: вкладка **Attributes / Характеристики** в редакторе товара, RU/EN. **Автоматические тесты ≠ реальная Joomla.** После установки проверить всё в браузере. Эта версия ещё **НЕ СОЗДАЁТ реальные SKU-комбинации** и **НЕ ВКЛЮЧАЕТ публичные фасетные фильтры**.

## Что меняется

- Товар получает только свойства своей выбранной категории, включая разрешённые предком и исключённые потомком (с учётом inheritance из 0.5.5/0.5.6). Глобальные чужие свойства не показываются, а их заполненные значения сервер отклоняет.
- Вкладка автоматически обновляет видимые поля при выборе другой категории, без сохранения промежуточного товара. Если свойство больше недоступно, но в нём есть значение, оно остаётся видимым с предупреждением до **явной очистки**. Старые значения не удаляются молча при смене категории.
- **Тип List + «Различает варианты»:** можно выбрать несколько значений, например Цвет: Красный + Жёлтый, Размер: S + M. Это *доступные значения у товара*, ещё **НЕ готовые комбинации SKU**. Нет автоматических вариантов «Красный/S, Красный/M» без явного создания реальных SKU в следующей версии.
- **Тип List без признака вариантов:** ровно одно значение из опубликованного/неопубликованного справочника. **Text:** одна строка до 1024 символов; **Number:** десятичное число точности до 4 знаков; **Yes/No:** Да, Нет либо не заполнено.
- Неопубликованные свойства и значения тоже можно редактировать **в админке**, с соответствующей пометкой. Для будущей публичной выдачи и фильтров доступны будут только опубликованные свойства/значения; их публикация отдельно не нужна для настройки черновой карточки товара.
- Данные сохраняются в двух нормализованных таблицах: `#__minimarket_product_attribute_scalars` — ровно одно типизированное значение на товар+атрибут; `#__minimarket_product_attribute_options` — связи товар+атрибут+значение списка. Используются ID справочников, не копируется текст названий. У обоих типов каскад удаления только **связанных строк при удалении самого товара**. Удаление справочника с используемыми значениями блокируют FK; физические фото не трогаются.
- Сохранение основной карточки, галереи и всех характеристик — в **одной транзакции**. Не меняются legacy `products.sku`, `products.price`, `products.stock`, URL, ID, категория и старые картинки. Миграция 0.5.7 только создаёт две таблицы, не переносит коммерческие поля.
- RU и EN локализация для поля, описаний, предупреждений и валидации. Без изменения Joomla core. JS управляет отображением, но сервер проверяет данные независимо от JS.

## Установка

**Сделать backup БД Joomla до обновления.** Не удалять существующий MiniMarket, не запускать ручной SQL. CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-product-attributes.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидаемый результат: `PACKAGE_OK: 0.5.7 (com_minimarket-0.5.7.zip)`. Установить **`dist\com_minimarket-0.5.7.zip`** поверх существующего расширения Joomla → System → Install → Extensions.

## Короткая реальная проверка

1. MiniMarket → **Attributes**: создать/проверить атрибут **Цвет/color** (List, Distinguishes variants — Yes), значения Красный/red, Жёлтый/yellow. Атрибут может быть даже черновиком — для админки он виден. Аналогично Размер/size с S, M. Проверить в **категории** на вкладке Attributes, что они **Enable** напрямую или унаследованы.
2. Открыть существующий **тестовый** товар именно из этой категории (не изменять TEST-001 ради проверки); должна быть вкладка **Attributes**. Там Цвет и Размер — с чекбоксами. Выбрать Красный, Жёлтый и S, M; сохранить/применить и **переоткрыть** — выборы сохранились.
3. Добавить категории разрешённые обычные Text, Number и Yes/No. Заполнить у тестового товара; проверить сохранение текстового значения, числа `12.5` и отрицательного «Нет» (boolean 0). Проверить, что **Unpublished** атрибут может быть редактирован в admin.
4. Переключить категорию товара на другую тестовую категорию: поля должны сразу пересчитаться. Если часть прежних свойств больше не разрешена, они остаются видимыми с предупреждением; пока не очистили несовместимые значения, сервер должен не принимать сохранение. Не допускать бесшумной потери значений.
5. Зайти в товар из категории без назначенных свойств — вкладка сообщает, что категорию нужно выбрать/настроить. При выборе категории с назначениями поля появляются сразу.
6. Проверить, что TEST-001, его старый SKU, цена, остаток, URL, обложка и галерея не изменились. Отдельных цен и остатков по цветам/размерам в 0.5.7 ещё **нет**.
7. Проверить английский и русский перевод в зависимости от языка выбранной административной панели Joomla.

Если поле не появилось, **сначала убедиться, что у товарной категории есть разрешённая характеристика**, а товар действительно принадлежит ей. Если вкладки нет совсем — проверить версию компонента в Joomla Extensions: она должна быть **0.5.7**.

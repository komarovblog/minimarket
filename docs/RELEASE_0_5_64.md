# MiniMarket 0.5.64 — горизонтальный дашборд и удаление старой кнопки

Дата: 2026-11-06. Ветка `development`. Joomla core, Atum и `main` не изменяются.

## Дизайн главной компонента

Переработан не в узкие карточки с вертикальными меню, а в **три полноширинные горизонтальные полосы**:

1. **Управление** — пока единственная плитка **Заказы** слева (25% строки при ширине >= 992 px). Заказы ещё не реализованы: плитка помечена `Скоро`, не ведёт на несуществующий URL.
2. **Товары** — отдельная полноширинная полоса с кнопками-плитками **Категории, Товары, Комплекты, Бренды, Коллекции, Связи товаров, Связи комплектов, Характеристики, Опции**. Кнопки располагаются в ряд, при переполнении переносятся на новые ряды. У каждой иконка **слева от названия**, у ключевых разделов — небольшой счётчик записей.
3. **Инструменты** — полноширинная полоса с двумя плитками **Импорт / Экспорт** и **Фиды**, тоже по 25% строки.

Сетка на широком экране Bootstrap `col-lg-3` (4 плитки в строке, каждая 25%); на среднем `col-sm-6` (2 в ряд), на узком `col-12` (1 в ряд). **Полоса занимает всю ширину**, четверть — это **ширина каждой кнопки**, а не самой полосы. Штатная левая навигация Joomla сохранена. Кнопка **«Открыть страницу каталога»** остаётся залитой `btn-primary`.

## Удаление старой кнопки 0.5.62–0.5.63

В версии 0.5.62 компонент автоматически устанавливал админ-модуль `mod_minimarket_quicklink`. В 0.5.63 его установка была прекращена, но ранее созданный экземпляр **оставался** на сайте.

В версии 0.5.64, при установке/обновлении **компонента**, `src/com_minimarket/script.php` ищет исключительно расширение с:
- `type = module`;
- `element = mod_minimarket_quicklink`;
- `client_id = 1` (административный модуль).

Если расширение найдено, вызывается **стандартный Joomla Installer::uninstall('module', extension_id)**. Joomla удаляет старое расширение и его экземпляры стандартным механизмом. Запрос не трогает другие модули (`mod_custom`, `mod_version` и т. д.) и не выполняет SQL DELETE напрямую. Если удаление Joomla вернёт ошибку, обновление каталога продолжается с предупреждением; прежний модуль необходимо удалить вручную в Система → Управление → Расширения / Модули панели управления.

**Важно:** автоматически распознать старую **произвольную HTML-кнопку (`mod_custom`)** невозможно без риска удалить чужой модуль. Если пользователь ранее вручную создал HTML-модуль с кнопкой MiniMarket, его нужно **отдельно** отключить/удалить через «Модули панели управления» по названию/типу. Этот старый пользовательский модуль не удаляется автоматически.

## Новая кнопка — отдельное расширение

Чтобы старый идентификатор не конфликтовал с новым, новый отдельный ZIP называется **`mod_minimarket_toolbar-0.5.64.zip`**. Код компонента его **никогда не устанавливает и не меняет**.

- Отдельная установка через Joomla → Система → Установить → Расширения.
- Новый Joomla administrator module `mod_minimarket_toolbar` при первой установке публикуется в позиции `status` и получает порядок непосредственно слева от штатного `mod_version`.
- Шаблон использует нативные классы `header-item-content`, `header-item-icon`, `header-item-text`, права `core.manage`. Прежний Bootstrap `btn-outline-primary` в шапке не используется.
- Пользователь может менять текст, значок, состояние и позицию; при повторном обновлении модуля параметры сохраняются.
- Если кнопка больше вообще не нужна, **отдельный ZIP не устанавливать**. Компонент без неё полноценно работает.

## Поставка

Скрипт `scripts/release-to-desktop.ps1` копирует на рабочий стол:
- `com_minimarket-0.5.64.zip` — компонент и очистка старого модуля при обновлении;
- `mod_minimarket_toolbar-0.5.64.zip` — новая отдельная кнопка (не входит в ZIP компонента);
- `minimarket_mysql84_nnop3_update_0_5_64.sql` — накопительный демокаталог (для этих изменений импортировать не нужно).

Обязательно **сначала установить компонент**, чтобы Joomla удалила старый `mod_minimarket_quicklink`; после этого при желании отдельно установить новую кнопку. Не устанавливать старый `mod_minimarket_quicklink-0.5.63.zip` повторно — иначе он вновь появится.

## Автотесты / ограничения

- PHP8.4/8.5: module render ACL, XSS, RU/EN, нативные классы, работа самостоятельного installer и размещение перед `mod_version`, retired module cleanup с точным ID и проверкой отсутствия удаления другого расширения.
- PHP render регрессия: **ровно 3 полноширинные секции, 12 плиток (1+9+2)**, порядок, ширина 25%, отсутствие вертикальных меню, ссылки на действующие представления, залитая кнопка каталога.
- MySQL8.0/8.4: установка схемы и накопительный демокаталог без удаления данных.
- Windows: два независимых ZIP и накопительный SQL; инспектор следит, чтобы код модуля не оказался внутри ZIP компонента.

Реальная Joomla на OpenServer не доступна из GitHub CI — ни действительное удаление старого экземпляра, ни расположение новой кнопки в Atum **пока не подтверждены живым браузером**.

## Ручная приёмка

1. Создать резервную копию БД и обновить компонент из `com_minimarket-0.5.64.zip`.
2. Проверить шапку: старого `mod_minimarket_quicklink` нет. Если осталась вручную созданная HTML-кнопка (`mod_custom`), удалить/отключить только её через модули Joomla.
3. Открыть MiniMarket → Главная. Полосы `Управление`, `Товары`, `Инструменты` занимают всю ширину; «Заказы» ровно одна четвертная плитка; товары идут в несколько рядов по 4 на ПК, инструменты — 2 плитки. Ссылки открывают нужный раздел.
4. Если верхняя кнопка по-прежнему нужна — **отдельно** установить `mod_minimarket_toolbar-0.5.64.zip` и проверить положение слева от версии Joomla.
5. Повторно обновить компонент: модуль новой кнопки не изменяется. Повторно обновить сам модуль: выбранные публикация/позиция/текст остаются.

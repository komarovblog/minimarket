# MiniMarket 0.6.10 — жизненный цикл заказа, резервы и уведомления

**Ветка:** development. **CI 6/6 PASS:** https://github.com/komarovblog/minimarket/actions/runs/43391385579 (PHP 8.4/8.5, MySQL 8.4 fresh/upgrade/demo, Windows ZIP). **Приёмка в реальной Joomla 6/Atum ещё не выполнена.**

## Реализовано

- Четыре основных статуса: Новый / В работе / Завершён / Отменён; отдельно отображаются оплаты и семь состояний исполнения. Создание доставки само по себе не означает «В пути» и не принимает заказ в работу. Ручное принятие, отмена с обязательной причиной, допуск отмены уже оплаченного заказа **до физической передачи**; возвращённые деньги не объявляются полученными без отдельной проверенной операции.
- В общем реестре заказов отдельные колонки и фильтры статуса заказа, оплаты и получения. Быстрые переключатели: Все, Новые, до конца резерва N дней, до конца 1 день, Просроченные, Неоплаченные резервы, Оплаченные не получены. Настраиваемые значения порогов вместо жёстких дат. Резерв до — реальная дата только при действительном резерве, исторические заказы без него не маркируются резервом.
- Начиная с 0.6.10 при сохранении физического заказа свободный запас SKU/варианта/компонента набора уменьшается **в одной транзакции** с созданием заказа и записью строки allocation. Условное обновление с проверкой остатка исключает двойную продажу последней единицы при двух конкурентных **созданиях заказа**. При разрешённой отмене запас возвращается ровно один раз, выдача/передача фиксирует расход. Включённый магазин без учёта остатков не создаёт фиктивного резерва.
- В общих настройках: 3 дня для неоплаченного самовывоза (изменяется), 7 дней для оплаченного до проверки (изменяется), сроки напоминаний по умолчанию 3 и 1 день, автоотмена просроченного неоплаченного самовывоза по умолчанию выключена. После перехода «Готов к выдаче» срок пересчитывается, а оплаченный заказ не отменяется автоматически.
- Раздел «Способы уведомлений»: встроенный email и обнаружение установленных MiniMarket notification-плагинов, матрица событие × разрешённый канал. Зарегистрированный покупатель Joomla может выбрать разрешённые события/каналы на `index.php?option=com_minimarket&view=notificationpreferences`. Для email работает встроенная Joomla Mail с точной проверкой user_id, пользовательским выбором, записью попытки и защитой от повторной отправки одинакового события. Требуется реальный почтовый транспорт и действующая активация email в Joomla.
- `ReservationMonitor::run` имеет безопасную логику проверки сроков, очередных напоминаний и опциональной отмены только неоплаченного, готового к выдаче самовывоза после повторной транзакционной проверки.

## Чего ещё нет

- **Фоновый запуск ReservationMonitor не подключён:** самостоятельный сервис не является настроенным Joomla Scheduled Task. Без task-плагина и включённого расписания напоминания/автоотмена не будут срабатывать автоматически. Не считать эту настройку работающей в фоне.
- Никаких реальных интеграций ЮKassa, СДЭК, Яндекс ID, MAX/Telegram в составе компонента. Установка notification-плагина и выбор канала не гарантируют доставки сообщения, пока не реализован и не проверен его транспорт; реально работает только встроенный Email.
- Настоящая онлайн-оплата и короткое удержание **до обращения** к её провайдеру ещё не реализованы. При подключении ЮKassa обязательно проверять и атомарно занимать SKU до создания платежа, а повторные webhook обрабатывать идемпотентно; иначе двух покупателей можно списать за одну единицу товара.
- Пользователи магазина по-прежнему являются пользователями Joomla. Для будущих Яндекс ID и OTP использовать отдельные плагины аутентификации и записи внешнего проверенного идентификатора, без изменения ядра.
- Внешние финансовые события пока не ведутся в полноценных таблицах PaymentAttempt/PaymentTransaction/RefundTransaction; ручное подтверждение требует документ/идентификатор. Эти таблицы и API — следующий отдельный этап.

## Как проверить

1. Создать резервную копию БД — обновление содержит миграцию `0.6.10.sql`.
2. Единственная команда получения ZIP:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
   ```

3. Установить только `com_minimarket-0.6.10.zip` через Joomla; отдельный SQL демоданных не импортировать. Модуль тулбара остаётся отдельным и не требует обновления.
4. Проверить два заказа на один оставшийся SKU, статусы/колонки, готовность самовывоза, изменение срока после оплаты, фильтры 3/1 день, ручное принятие и отмену с причиной, возврат количества один раз; email для согласившегося реального Joomla-аккаунта, RU/EN, тёмная/светлая Atum.
5. Следующая итерация: установка и запуск Scheduled Tasks адаптера, а затем платёжный/логистический API-шлюз, проверяемые транзакции и OAuth/OTP-плагины.

## Отдельный планировщик напоминаний и автоотмены

В версии 0.6.10 подготовлен **отдельный** плагин Joomla Scheduled Tasks `plg_task_minimarketreserves` (не включён в компонентный архив). Команда `scripts/release-to-desktop.ps1` теперь выдаёт на рабочий стол три файла: `com_minimarket-0.6.10.zip`, `plg_task_minimarketreserves-0.6.10.zip` и необязательный `minimarket_mysql84_nnop3_update_0_6_10.sql` (не импортировать при штатном обновлении). Самостоятельный модуль тулбара v1.0.0 не переустанавливается.

**После установки компонента:** установить ZIP плагина через Joomla, включить группу Task/плагин MiniMarket и создать/активировать в «Система → Запланированные задачи» задачу **MiniMarket pickup reservation monitor**. Задать периодичность и обеспечить запуск штатного планировщика (в том числе cron при выбранном режиме Joomla). Пока задача не создана/не работает, автоматические напоминания/автоотмена не выполняются. Верификация фактического запуска и доставки email на локальном Joomla ещё не проведена.

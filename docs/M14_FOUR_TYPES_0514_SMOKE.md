# MiniMarket 0.5.14 — четыре типа данных

**02.11.2026.** Принято пользователем: для новых характеристик нужны только **Текст**, **Число**, **Редактор HTML**, **Да/Нет**. Выбор из списка не является типом данных, а относится к способу заполнения. Ранее созданные ID-based List и legacy Textarea/Date/URL должны остаться доступными для редактирования и сохранения существующих товаров: данные нельзя удалять при упрощении интерфейса.

## Редактор характеристики

- **Текст**: по умолчанию свободная строка; при Product input = **Choose preset number / Выбор из значений** на самом деле используется список **текстовых** строк, добавляемых + / − / перемещением внутри Joomla Subform. Значения сохраняются как текст и не получают отдельного словарного ID.
- **Число**: ручной ввод или список чисел с Add/Remove/Move (сделано в 0.5.13); единица измерения, минимум, максимум, шаг. Сохранение в товаре числовое.
- **Редактор HTML**: настоящий редактор Joomla, поддерживающий текст, списки и ссылки. Не нужно отдельного типа URL или многострочного текста. Разрешать только доверенный/очищенный HTML, не исполнять JavaScript.
- **Да/Нет**: стандартный селект с незаполненным, Да и Нет.
- Режим ввода в товаре независим от настроек *будущего* фильтра; вид публичного фасетного фильтра в 0.5.14 ещё не активирован.
- Тип **List** остаётся для уже созданных характеристик с выбранными value_id и связями товаров. Новые характеристики с таким типом сервер блокирует. Переход типов с заполненными продуктами/словочными значениями блокирует, чтобы не удалить данные.

## Важная граница

0.5.14 сохраняет существующие поля `number_options` и `is_multiple` для совместимости. Добавлена только колонка `text_options` (JSON-строки по порядку). Сам текст/редактор хранится в существующей `#__minimarket_product_attribute_scalars.value_text`. **Без** изменения ID товаров, SKU, цен, остатков, галереи, категорий или ID старых List-значений. Публичный фильтр и реальные SKU-варианты — отдельные этапы.

## Обновление и ручная проверка Joomla

1. Backup БД. Не удалять компонент и не запускать SQL вручную. Рабочая ветка — `development`.
2. В CMD:
```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-attribute-four-types.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```
3. Ожидается `PACKAGE_OK: 0.5.14 (com_minimarket-0.5.14.zip)`. Установить `dist\com_minimarket-0.5.14.zip` поверх компонента Joomla через System → Install → Extensions.
4. Новая характеристика **Текст** / код `material`: Product input = выбор из заданных значений, добавить в повторяемой форме «Джинс» и «Хлопок», сохранить. Привязать к тестовой категории; в товаре выбрать «Джинс», сохранить и повторно открыть.
5. Новая характеристика **Число** / `power`: задать несколько допустимых чисел через «+», проверить сохранение и выбор в товаре.
6. Новая характеристика **Редактор HTML** / `features`: редактор Joomla с текстом, списком и ссылкой; сохранить и повторно открыть продукт. Проверить, что форматирование/ссылка остаются и в исходных данных нет исполняемого скрипта.
7. Новая характеристика **Да/Нет**: сохранить оба значения и проверить три состояния.
8. Открыть старый **Цвет (List)**: он должен оставаться доступен и не терять значения и привязки. TEST-001 не редактировать ради smoke, SKU/цена/остаток/URL/медиа не меняются.

**Joomla runtime не подтверждён автоматическими тестами**, поэтому после установки нужен реальный browser smoke. Реализованный интерфейс может отличаться от ожиданий, пока пользователь не проверит.

# MiniMarket 0.5.99 — единые настройки, изображения и цифровые товары

**Разработка:** `development`, база 0.5.98. **CI: 6/6 PASS, GitHub Actions #43189149240** ([проверки и установочный ZIP](https://github.com/komarovblog/minimarket/actions/runs/43189149240)). Отдельный MySQL 8.4 прогон новой миграции: `MM99_SCHEMA_MYSQL84_PASS: 6 checks`. Обновление схемы: `admin/sql/updates/mysql/0.5.99.sql` (только ADD COLUMN/CREATE TABLE, без потери данных). Joomla 6, MySQL 8.0/8.4, PHP 8.4/8.5. ZIP компонента и отдельного toolbar как прежде. Браузерная приёмка на локальной Joomla должна быть отдельной.

## Реализовано

1. Удалена глобальная настройка «Тип магазина». Отдельное поле `delivery_type` в карточке простого товара: физический / цифровой. Уже сохранённые физические товары остаются физическими, прежний глобальный параметр больше не влияет на их продажи. Комплекты пока остаются физическими. Доставка еды реализуется как физические позиции и отдельные способы доставки — никакого нового глобального типа.
2. В «Отображение → Карточка товара» добавлен выбор `lightbox` / `zoom`; лёгкая собственная модальная галерея с Escape и стрелками, zoom при наведении с desktop pointer; для touch — модальная галерея. Сохраняются изображения SKU и обычная ссылка при отключённом JS.
3. Удалены дубли: дополнительное управление отзывами в «Отображении» (управление осталось в «Отзывах»); четыре лишние настройки пагинации (ссылки на страницы и предыдущие/следующие всегда доступны); ручные «Пропустить шаг» checkout. Покупатель пропускается только при достаточных данных Joomla; доставка/оплата — только когда выбор действительно однозначный. Настройка учёта остатков сохранена, чтобы не нарушить существующие товары.
4. В checkout добавлены описание шага подтверждения, необязательная ссылка на существующий пункт меню Joomla и серверно проверяемое согласие с условиями покупки. Оформление без согласия при включённом требовании блокируется.
5. Цифровые файлы загружаются в закрытый каталог вне Joomla webroot: `dirname(dirname(JPATH_ROOT))/minimarket-private-files` — для `C:\OSPanel\home\minimarket.local` это `C:\OSPanel\minimarket-private-files`. Разрешены PDF/ZIP/EPUB/MP3/MP4/TXT, максимум 50 МиБ с дополнительным PHP лимитом. Условие безопасности: PHP должен иметь право создать и записать каталог, иначе загрузка отклоняется. Файл нельзя выбирать в публичном медиа-менеджере. Старые версии файлов сохраняются для ранее оформленных заказов.
6. Цифровой заказ требует зарегистрированного Joomla-пользователя и реального загруженного файла. Цифровая корзина не содержит физической доставки, цифровой-only поддерживает банковский перевод (не «при получении»); смешанная корзина сохраняет физическую доставку. Неавторизованная выдача блокируется.
7. Заказы дополнены `payment_status` (unpaid/paid/refunded), `paid_at`, `fulfillment_status` (pending/shipped/delivered), `fulfilled_at`, снимками ссылок на приватные файлы в каждой позиции, журналом событий и правами скачивания. В карточке заказа оператор с Joomla ACL `core.edit.state` вручную подтверждает полученный платёж; это **не проводит банковский платёж**, не гарантирует получение средств и требует фактической проверки. При подтверждении — уникальные HMAC-ссылки (30 дней, до 10 загрузок), письмо на адрес привязанного покупателя; владелец должен авторизоваться для скачивания. При неудаче письма статус оплаты остаётся `paid`, оператор может повторить отправку. Только цифровой заказ автоматически завершается после успешной отправки. Для смешанного физическое исполнение остаётся отдельным.
8. «С этим товаром покупают» теперь учитывает лишь действительно оплаченные заказы. Промовидео не запускается автоматически и не зацикливается.

## Сохранённые ограничения и недоделки

- **Онлайн-оплаты нет:** действие «Оплачено» — ручное, после подтверждения по банку. Банковский webhook, чарджбэк и возврат денег являются задачами интеграции с провайдером. Статус «Возвращено» — лишь запись уже совершённого возврата.
- **Резервирование/списание физического склада пока отсутствует.** Не вводить клиенту ложное утверждение об автоматическом резерве; до реального подключения складской транзакции оператор подтверждает наличие вручную.
- Валюта RUB пока является единственной рабочей: нельзя добавлять интерфейс выбора валюты без сквозного изменения сумм, заказов и отчётов. Налоги/чеки зависят от страны и фискальной интеграции, не представлены фиктивными глобальными переключателями.
- Пока не реализованы цифровые комплекты, гостевые цифровые скачивания, пополнение инвентаря кодами/ключами, личный кабинет скачиваний и внешние онлайн-платежи; существующие физические сценарии сохранены.
- Проверять file permission и работу почты Joomla до включения цифровых товаров. Скачивания запрещены для неоплаченных, отменённых, возвращённых, удалённых заказов и после истечения срока.
- Нельзя запускать демонстрационный SQL для обновления схемы. Joomla применит миграцию компонента при установке ZIP поверх предыдущей версии.

## Обязательные проверки

- `php scripts/test-0-5-99.php` и прежние regression scripts, PHP lint, node --check JS.
- Fresh и upgrade MySQL 8.0/8.4, отдельные Windows ZIP (CI).
- Локальная Joomla 6: native UI светлый/тёмный, переключение рус/англ, галерея/zoom/touch/variant pictures, checkout с единственным/несколькими способами, отсутствие дублей; физический/цифровой/смешанный заказ; отказ выдачи до оплачено; отправка email и повторная отправка, аннулирование доступа после возврата, скачивание только авторизованным владельцем, ограничение 10/30 дней, ручной заказ/комплекты/остатки.

# MiniMarket 0.5.89 — штатные формы Joomla, фильтры, настройки способов

**11.11.2026 · `development` · Joomla 6.2, PHP 8.5, MySQL 8.4.**

## Что изменено

### 1. Единообразие списков Joomla

- Убран отдельный дублирующий бордер вокруг таблиц MiniMarket. Вёрстка списков опирается на штатные классы `table table-striped` и контейнер `table-responsive` Joomla/Bootstrap.
- Уменьшены промежутки от строки поиска до фильтров, селектора столбцов и таблицы. Самостоятельное цветное обрамление дополнительных фильтров снято.
- Название кнопки `JSEARCH_FILTER_OPTIONS` заменено на собственный корректно переведённый ключ «Параметры поиска» / «Search Tools».
- **Интеграции:** глобальная кнопка «Открыть плагины Joomla» убрана. У каждого реально установленного плагина остаётся персональная ссылка «Настройки».
- Фильтры работают на сервере: интеграции — назначение и состояние; фиды — площадка и публикация; SEO — категория и публикация; промокоды — вид скидки и состояние; доставки — перевозчик и статус; отзывы — оценка и модерация; зоны — тариф и публикация.

### 2. Нативные вкладки и поиск внутренних сущностей

- SEO-страницы, промокоды и карточки зон переведены с неработающих `data-bs-toggle="tab"` на нативный Joomla `HTMLHelper::_('uitab...')`, как в товарах.
- Убрана дополнительная внешняя рамка вокруг вкладок; содержимое использует такие же карточки Joomla, как карточка товара.
- Исправлено сырое `JSAVEANDCLOSE` — теперь «Сохранить и закрыть» / «Save & Close».
- Поисковик внутренних сущностей в SEO, промокодах и доставках одинаково отображает результаты/выбранные записи. У одиночного выбора (например, категория SEO) найденное значение видно сразу над панелью поиска, поиск закрывается после выбора.
- Старое предупреждение в редакторе промокода, будто скидки не применяются, заменено на актуальное описание серверной проверки при оформлении.

### 3. Импорт и экспорт

- Удалён отдельный экранный блок **«Полный обмен каталогом — JSON v2»** и связанная форма загрузки/выгрузки. Прочие доступные форматы и обычный импорт/экспорт каталога не изменены.
- Закрытые API-функции полного JSON не удалялись физически из контроллера, чтобы не ломать уже существующие процессы. Они не выводятся в интерфейсе и требуют своих прав.

### 4. Доставка и оплата — теперь в настройках

- «Зоны доставки» убраны из главного блока «Управление» и из верхней группы меню. Управление зонами доступно внутри `Настройки → Способы доставки → Собственный курьер`.
- В блок и меню настроек MiniMarket добавлены самостоятельные разделы:
  - **Способы доставки** — встроенные «Самовывоз», «Собственный курьер» с включением/отключением, адресом самовывоза, тарифами по городам либо переходом к полноценным зонам; установленные плагины доставки с переходом в Joomla Plugin Settings.
  - **Способы оплаты** — встроенные «При получении» и «Банковский перевод» с включением/отключением и инструкциями; установленные плагины оплаты с переходом в настройки плагина.
- Все настройки встроенных способов остаются в **параметрах существующего компонента** `#__extensions.params`. Нет второй независимой БД настроек, нет новых SQL-миграций. Сохранение выполняется с `core.options`/admin ACL, токеном CSRF, валидацией входных значений и транзакцией.
- В Joomla `Настройки` поля доставки и оплаты вынесены из общей вкладки «Оформление заказа» в отдельные вкладки «Способы доставки» и «Способы оплаты». В Checkout остаются поля данных покупателя и ссылка-пояснение.
- Для банковского перевода инструкция показывается на странице завершения заказа **только при подтверждённом для текущей сессии заказе** с указанным способом оплаты.
- Не подключён реальный API СДЭК/эквайринга; включённые плагины пока не считаются действующими адаптерами Checkout автоматически. Не отображаются демонстрационные/несуществующие службы.

## Проверки и ограничения

- `scripts/verify-0.5.89.ps1` проверяет структуру, XML манифеста/настроек, native tabs, фильтры, новые страницы методов и отсутствие JSON-v2 UI, затем запускает PHP lint и `scripts/verify-method-settings.php`, если PHP доступен.
- Ранее действующие проверки 0.5.87/0.5.88 и штатные проверки списков/переводов продолжают работать.
- Полная проверка RU/EN *по наличию ключей*: admin 1141/1141, sys 40/40, storefront 181/181, без дубликатов и расхождений при чтении репозитория. Отображение переводов в браузере Joomla ещё требуется проверить.
- Последний SQL-файл схемы — **0.5.87.sql**, в 0.5.89 таблицы не изменяются. Файл `minimarket_mysql84_nnop3_update_0_5_89.sql` рядом с ZIP — **только необязательный демокаталог**, не импортировать его для обновления интерфейса.
- Ошибка обслуживания БД Joomla около `AND 'null' = 'NO'` остаётся отдельной задачей. Не нажимать автоматическое «Исправить» до резервирования и исследования.
- **Ещё не подтверждено в локальной установке:** сборка Windows ZIP, открытие новых страниц, переходы вкладок, SQL/CRUD и адаптивная вёрстка 90–150%.

## Сборка на компьютере пользователя (CMD, одна строка)

В каталоге `C:\OSPanel\home\minimarket.local`:

```cmd
git pull --ff-only origin development && powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\release-to-desktop.ps1 -SkipPull
```

Ожидаемые три файла на рабочем столе: `com_minimarket-0.5.89.zip`, `mod_minimarket_toolbar-0.5.89.zip`, `minimarket_mysql84_nnop3_update_0_5_89.sql`.

## Приёмка

1. Проверить `Интеграции` и `Фиды`: корректные RU/EN названия поиска; фильтры назначений/площадок; отсутствие лишней глобальной кнопки; ссылки настройки только у фактических плагинов.
2. Проверить `SEO-страница`, `Промокод`, `Зона`: переключение штатных вкладок без переполнения; сохранение с каждой вкладки; видимый и корректно сохраняемый выбор категории или товара.
3. Проверить `Товары, Комплекты, Категории` при 90%, 100%, 125%, 150%; нет второй толстой рамки, горизонтальное переполнение только внутри таблицы, отступы идентичны нативному Joomla.
4. Убедиться, что JSON-v2 полного обмена нет на экране «Импорт/Экспорт»; обычный CSV/XLSX/JSON по-прежнему работает.
5. Проверить новый раздел «Способы доставки»: настройки самовывоза, курьера, тарифа по городу, переход к зонам. Сохранить, перезагрузить, проверить значение в Checkout.
6. Проверить новый раздел «Способы оплаты»: отключение/включение методов, инструкции банковского перевода, показ текста после заказа с банковским переводом.
7. Проверить локальные права: редактор без `core.options` видит способы, но не может их менять.

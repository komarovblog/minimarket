# MiniMarket 0.5.25 — архитектура SKU v3 и расширенные свойства товарной позиции

**Дата:** 03.11.2026. **Ветка:** development. **Статус:** B2.2 (базовое хранение/редактирование/витрина); реальная Joomla browser-приёмка **не выполнялась**. Установка только после резервной копии БД. Документ-источник: [PRODUCT_SKU_ARCHITECTURE_V3.md](PRODUCT_SKU_ARCHITECTURE_V3.md).

## Что изменено

- Товар-модель сохраняет один URL/SEO, SKU сохраняет свой стабильный ID, цену, остаток, публикацию, обложку и фотогалерею.
- В существующем редакторе SKU появились «Описание товарной позиции: как у модели / своё», отдельные краткое/полное описания (Joomla safe HTML), «Видео: как у модели / своё / без видео», нативная повторяемая галерея видео. Это переходный интерфейс, полноценную отдельную карточку SKU с компактным списком делаем в B2.3.
- У каждого локального значения параметра (например, Красный) — одна повторяемая галерея с кнопками Joomla «+ / удалить / переместить». Размеры S/M/L наследуют фото цвета, пока SKU не назначена собственная галерея. Файлы не копируются и не удаляются.
- При переключении SKU на сайте обновляются SKU, цена, остаток, фото, краткое/полное описание, видео. HTML описаний проходит Joomla InputFilter на сервере, видео выводится лишь из разрешённых источников, URL/SEO/canonical неизменны.
- «Наследовать/без видео» скрывает индивидуальные видео, но **не удаляет сохранённые ссылки**. Аналогично уже введённые тексты SKU не теряются при переключении на наследование.
- Только аддитивная миграция 0.5.25: description_mode, introtext_override, description_override, video_mode в product_variants; product_variant_videos и variant_value_images. Старые товары, SKU/ID, цены, остатки, SEO и медиа не меняются. Нет нового EAV или дублей products.

## Ручная приёмка Joomla 6

1. Создать обычный товар без вариантов; открыть/сохранить. Базовая цена, SKU, фото и видео не должны измениться.
2. Открыть товар с локальными параметрами Цвет: Красный/Синий и Размер: S/M/L. Добавить SKU Красный/S и Красный/M. Для Красного загрузить в поле значения **две фотографии**. У SKU оставить индивидуальные фото пустыми. Сохранить/открыть снова.
3. На сайте оба красных размера показывают одинаковую красную галерею. Для Красный/M назначить свою обложку и галерею → только M показывает собственную, а S по-прежнему использует красную. Изменение цвета на Синий с собственной галереей переключает синие снимки.
4. У Красный/M выставить описание «Своё», заполнить краткое и полное описание HTML, добавить собственное видео YouTube/MP4 через Joomla Media. Проверить на сайте смену описаний и видео без изменения URL. Красный/S продолжает наследовать описание и видео модели.
5. Для M выбрать видео «Без видео», сохранить: модельные и индивидуальные видео не показываются. Переключить на «Своё»: прежние ссылки видео остаются и снова работают. Аналогично переключение описания на «Как у модели» должно сохранить ранее введённый собственный текст.
6. Попробовать ввести в видео javascript:/http:/неподдерживаемый адрес, фото с path traversal, дубли одного пути, слишком длинный HTML — сервер отклоняет и не сохраняет транзакцию.
7. Старый SKU 0.5.17–0.5.19 не переносится автоматически в локальные параметры, сохраняет ID, цену, остаток, путь и адрес товара. Простой товар без SKU живёт в legacy торговых полях до этапа C.
8. Протестировать RU/EN, тёмную тему, Joomla Media без #joomlaImage://, отсутствие зависания и сохранение обязательных характеристик в категориях.

## Тесты и известные границы

- CI: PHP 8.4/8.5 с test-sku-v3-media.php, test-public-variants.php, MySQL 8 upgrade/fresh install, Windows ZIP/inspect; успешные CI не заменяют браузер Joomla.
- Не готовы: полноценная **отдельная** карточка редактирования SKU с собственными характеристиками, копирование всех переопределений, более удобная таблица SKU (B2.3); одна реальная SKU для простого товара вместо legacy полей (C); склад/заказы/комплекты (D); импорт/фиды/AND-фильтры (E).
- Приложение не должно заявлять, что B2.3–E реализованы. Для будущего импорта использовать стабильные variant_id и (source_key,external_sku_id).

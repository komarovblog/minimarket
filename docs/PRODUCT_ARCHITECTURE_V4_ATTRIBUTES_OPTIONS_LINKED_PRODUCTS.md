# MiniMarket — архитектура v4: атрибуты, опции заказа и связанные товары

**Утверждено 03.11.2026.** Заменяет модель терминов из [v3](PRODUCT_SKU_ARCHITECTURE_V3.md), но **не удаляет** старые таблицы или SKU. Цель: понятный ввод, фильтры, остатки, импорт и собственные URL только у самостоятельных товаров.

## Три разных понятия

| Сущность | Для чего | Свой URL | Влияет на выбор заказа |
|---|---|---|---|
| **Товар** (`products`) | Самостоятельная карточка, описание, SEO, фото/видео, базовый артикул | Да | Продаётся |
| **Атрибут** (`attributes`) | Информация о товаре: материал, мощность, вес | Нет | Нет |
| **Опция заказа** (`variant_dimensions`, существующее имя таблицы) | Выбор внутри товара: размер, цвет, комплектация | Нет | Да |
| **Сочетание опций / SKU** (`product_variants`) | Конкретная продаваемая конфигурация; уникальные SKU и при необходимости цены/остатки | Нет | Да |
| **Связанная группа** (`product_groups`) | Перелинковка *самостоятельных* товаров с разными URL | Нет собственного URL | Нет |

Например, футболка может быть **одним товаром** (URL /classic-1001), с опциями Цвет Красный/Синий и Размер S/M/L, шестью уникальными SKU. Выбор цвета/размера не меняет основной URL (допустим параметр `?variant=<id>` для точного выбора в фиде). Фильтр по красному и S должен находить товар, только если такой SKU существует, и сразу выбирать RED-S.

Другой сценарий: красная футболка (`/red-1001`) и синяя (`/blue-1002`) — **два товара**, каждый со своим артикулом, SEO, галереей и собственными опциями размеров. Оба находятся в группе «Футболка Classic» и перелинкованы на страницах. **Группа не продаётся** и не дублирует товары.

Смена фото/видео/материала сама по себе **не обязывает** создавать другой товар: администратор решает, нужна ли отдельная SEO-страница. Если нужен самостоятельный URL и отдельная карточка — создаём связанный товар. Если выбираем внутри единой карточки — опция/SKU с возможностью отдельных фото и других данных.

## SKU и остатки

**Для каждой физически различимой комбинации, продаваемой как вариант, нужен уникальный SKU**, включая красную и синюю, даже если они выбираются внутри одного URL. SKU задаётся в сохранённой строке, не генерируется из количества или названия как единственный идентификатор. Постоянный `variant_id` защищает заказы/импорт при переименовании SKU.

Настройка товара `option_stock_mode`:
- **0 = общий остаток**. Все опции тратят один запас `products.stock`. *Матрицу остатков не заполняем*, но SKU для доступных сочетаний всё равно существуют — нужно знать, что именно выбрано и заказано. Сохранённые `product_variants.stock` **не удалять**: при обратном переключении они восстановятся; в витрине считать наличие по `products.stock`.
- **1 = отдельно для сочетаний**. Остаток/наличие каждого SKU берётся из `product_variants.stock`. Матрица SKU может редактироваться массово. Не объединять остатки разных физических цветов/размеров по ошибке.

В старой модели 0.5.25 отдельный запас существующих SKU был активен. **Миграция 0.5.26 устанавливает 1 для товаров, у которых уже есть SKU**, не трогая числовые остатки и ID. Новые товары по умолчанию имеют общий запас (0). Переход 0 ↔ 1 не удаляет строки/артикулы или их сохранённое количество. Цена SKU может отличаться независимо от режима остатков.

## Структура БД (без дублирования данных)

| Таблица | Назначение |
|---|---|
| `categories` | Категория с собственным URL |
| `attributes`, `attribute_values`, `category_attributes` | Информационные характеристики и связь категорий |
| `products` | Самостоятельный товар с URL, SEO, галереей и `option_stock_mode` |
| `variant_dimensions`, `variant_dimension_values` | **Опции** и значения, локальные для товара; старые имена таблиц сохранены во избежание деструктивного переименования |
| `product_variants` и `variant_value_assignments` | Уникальная продаваемая SKU-комбинация и её выбранные значения |
| `product_groups`, `product_group_members` | Не продаваемые группы связанных товаров (каждый product_id максимум в одной группе) |
| `import_product_keys`, `import_sku_keys` | Внешние ID источников для импорта, независимые от изменяемых артикулов |

Существующие поля `products.sku/price/stock` пока остаются для простых товаров и совместимости. Полное выравнивание SKU как единственной складской позиции — **отдельный этап C**, с проверкой существующих записей и резервной копией. Не удалять их автоматически и не создавать базовый SKU сверх уже существующих вариантов. Не придумывать параллельную систему «товаров-цветов» для связанных групп.

## Интерфейс Joomla

- Вкладка **«Характеристики»** — информационные поля, как сейчас.
- Вкладка **«Опции заказа»** — значения (Цвет, Размер и т.п.) через штатные `+`, выбор отдельных SKU, дополнительная генерация комбинаций. У каждого доступного сочетания свой SKU.
- Радиопереключатель на товаре **«Общий остаток / Отдельно для каждого сочетания»**. При общем режиме редактируем общий остаток и не показываем индивидуальные поля количества SKU. При раздельном — компактная обычная таблица.
- Вкладка **«Связанные товары»** — выбрать существующую группу или создать новую; другие товары включаются через тот же селектор. На сайте у каждого товара свой URL и ссылки на остальные товары группы.
- Все списки: checkbox → публикация **слева** → название; стандартный Joomla SearchTools, таблицы и формполя, RU/EN.

## Импорт, фильтры и комплекты

- Атрибуты и опции участвуют в фильтрах. Атрибут — пересечение на уровне товара, опции с AND — пересечение **внутри одного существующего SKU**. Если пользователь выбрал S и Красный, выдаётся товар с доступным RED-S, а не S одного SKU + Красный другого.
- Источник поставщика сопоставляем по `source_key + external_product_id` и `source_key + external_sku_id`. Не склеиваем по одному цвету, названию или цене. Связанные товары могут передавать одинаковый внешний model/group ID, но независимые product_id.
- Фид: одна запись на физический SKU при наличии опций, свой offer ID, общий URL товара с `?variant=id`, status/price/availability по выбранному режиму остатков; связанные товары имеют **разные основные URL**.
- Фиксированный комплект состоит из конкретных SKU; конфигурируемый — разрешает выбрать SKU. Списываем либо компоненты, либо готовый складской комплект, но не оба запаса одновременно.

## Реализовано в 0.5.26 и границы

Аддитивная SQL-схема с режимом остатков и группами; штатные поля выбора группы/создания группы внутри карточки; перелинковка опубликованных товаров; общий/индивидуальный остаток в публичном выборе SKU; скрытие индивидуальных полей остатков при общем режиме; RU/EN; автоматические тесты. **Проверка в установленной Joomla должна быть отдельной**.

**Ещё не выполнено:** новый полноценный раздел каталога «Опции» с глобальными справочниками и привязкой к категориям (пока локальны для товара), ERP-импорт/экспорт, корзина/резервирование, AND-фильтры сайта, окончательное выравнивание старых простых товаров в таблицу SKU, полноценная таблица управления группами. Ничего из этого нельзя объявлять готовым только потому, что миграция создана.

Работа исключительно в ветке `development`; `main` и ядро Joomla не меняем.

# MiniMarket — типы характеристик, ввод в товаре и отображение в фильтрах

**02.11.2026. СТАТУС: DRAFT / предложение для согласования с пользователем. Никаких новых типов, настроек фильтров или фронтенд-фильтров этот документ не внедряет.** Текущий релиз 0.5.11 содержит только базовые `list/text/number/boolean`, независимый `is_multiple` для списков в **товаре** и флаг `is_filterable` без реализации фильтра.

Исходная идея пользователя: «Тип» должен означать **как заполняется значение в товаре** (включая Checkboxes, а не просто переключатель multiple), а **отдельная настройка** — как эта характеристика отображается в покупательском фильтре и разрешено ли там выбирать несколько вариантов.

## 1. Что предлагает Joomla

Официальный Joomla User Guide: [Fields](https://guide.joomla.org/user-guide/fields) и [Checkboxes](https://guide.joomla.org/user-guide/fields/fields-adding-custom-fields-checkboxes-field).

В актуальном списке Joomla 18 основных разновидностей custom fields: Calendar, Checkboxes, Colour, Editor, Integer, List, List of Images, Media, Note, Number, Radio, SQL, Subform, Text, Textarea, URL, User, Usergroup. **Не копировать весь набор** в MiniMarket: SQL, User, Usergroup, Note — служебные/системные поля Joomla, не каталожные характеристики; Editor — для отдельного описания товара; Media и Subform уже используются для фотографий и повторяемых блоков; URL и произвольный WYSIWYG как технические фасеты не нужны.

Разделяем три слоя:
1. **Хранимые данные** (технически): ID словарного значения, строка, число, bool, дата. Сохраняем проверку типов, не меняем ID значений. Разделение на `integer/decimal` — режим точности числового значения, не обязательно отдельная таблица. Цвет с несколькими оттенками — ID значения в общем справочнике с будущим `hex` или визуальным образцом, **не** свободный HEX у каждого товара.
2. **Тип поля при заполнении товара** (то, что видит менеджер): Text, Textarea, Number, Yes/No, Date, List, Radio, Checkboxes, Colour swatches. Здесь UI называется **«Тип поля в товаре»**, а не двусмысленное «Value type».
3. **Отображение в публичном фильтре**: Checkboxes, Radio, Dropdown (single/multiple), Colour swatches, Yes/No/Only Yes, Number range, Date range (позже). Параметры фильтра имеют собственные вид, число одновременно выбранных значений и правила применимости.

`is_variant` отвечает только за будущие реальные комбинации SKU и **не влияет** на тип управляющего элемента товара или фильтра. `is_filterable` разрешает участие в фильтрах и показывает настройки соответствующей секции.

## 2. Рекомендуемый набор типов заполнения товара

| Имя в UI | Что хранит | Сколько значений в товаре | Нужно? | Пример |
| --- | --- | --- | --- | --- |
| **Список** (Dropdown) | список ID | один, опционально multiselect | **Да** | Материал, производитель ткани |
| **Переключатели** (Radio) | один ID | всегда одно | **Да** | Класс энергопотребления |
| **Флажки** (Checkboxes) | несколько ID | несколько (0..N) | **Да** | Совместимые устройства, поддерживаемые интерфейсы |
| **Цветные образцы** (Swatches) | ID списка + цвет/образец | один или несколько, настройка | **Да, после настройки визуальных значений** | Цвет товара |
| **Текст** (Text) | строка | одно | **Да, готово** | Заводской артикул, артикул производителя |
| **Многострочный текст** (Textarea) | длинная строка | одно | **Да, добавить** | Особенности, техническое описание (не путать с общим Description) |
| **Число** (Number) | число (целое/дробное) | одно | **Да, готово частично** | Вес/мощность; min, max, шаг, единица измерения добавить |
| **Да / Нет** (Boolean) | true / false / пусто | одно | **Да, готово** | Поддержка Bluetooth, влагозащита |
| **Дата** (Calendar) | дата ISO | одно | **Можно вторым этапом** | Дата выпуска, срок гарантии до |
| URL | строка URL | одно | Пока нет | Тех. документация лучше как файл/ссылка товара |
| Media, List of Images, Editor, Subform, SQL, User, Usergroup, Note | смешанные | — | **Не добавлять в характеристики** | Есть галерея, контент, отдельные сущности |

**Checkboxes** — выбранный пользователем тип **поля товара**; технически это ID-based list и **не требует собственной копии словаря или таблицы**. Тип `boolean` отличается: единичное «Да/Нет» (включая «не заполнено»), а не группа флажков. Joomla List с Multiple тоже поддерживается, но визуально это другое поле, поэтому не нужно сводить разные формы ввода к одной галочке.

**Что делать с 0.5.11:** ранее сохранённые `input_type=list + is_multiple=1` корректно показывать как Checkboxes / Multiselect, `is_multiple=0` — Dropdown/Radio по новому предпочтению; мигрировать только настройки отображения, не сами значения у продуктов. Не включать отложенный тип `swatch` как отдельную семантику хранения.

## 3. Рекомендуемые виды фильтра (совсем отдельно от типа товара)

| Хранимое значение | Варианты публичного фильтра | Поведение |
| --- | --- | --- |
| Список ID | **Флажки** — по умолчанию; Radio; Dropdown | Флажки: можно несколько; Radio: одно; Dropdown — отдельная настройка single/multiple |
| Список цветов | **Цветные образцы** (с подписью), опционально чекбоксы | Мультивыбор возможен даже если у конкретного SKU один цвет |
| Булево | Да/Нет/Любое; опционально только «Да» | Не путать отсутствие данных с «Нет» |
| Число | **Диапазон от–до**; также готовые интервалы (позже) | Единица измерения и нормализация, использовать реальные числовые значения |
| Дата | Диапазон дат (позже) | Дата хранится отдельно от оформления календаря |
| Свободный Text/Textarea | **Не использовать как фасет по умолчанию** | При необходимости — общий полнотекстовый поиск, а не миллионы уникальных фильтров |

### Независимая множественность

- В **товаре** Материал = Dropdown **одно** значение; в **фильтре** Материал = Checkboxes **несколько** (Джинс OR Хлопок).
- В **товаре** Цвет = Checkboxes/Swatches **несколько** допустимых цветов; в **фильтре** Цвет = Swatches **несколько**.
- В **товаре** Класс = Radio **одно**; в **фильтре** Класс = Radio **одно**.
- В **товаре** Совместимость = Checkboxes **несколько**, флаг **is_variant=No**; в **фильтре** выбирается несколько совместимостей через Checkboxes.
- В **товаре** Водонепроницаемый = Boolean (Да/Нет/не заполнено); в фильтре отдельный Boolean без пустого как ложного.
- **Выбор нескольких фильтров в одной группе** = OR; **между группами** = AND; внутри SKU-вариантов условия совместимы в **одном** реально существующем SKU.

## 4. Предлагаемый редактор характеристики MiniMarket (Joomla RU + EN)

**Основное:** Title, Code (уникальный стабильный), Status, Ordering; применимость категориям через уже реализованную вкладку Categories.

**Заполнение в товаре:**
- «Тип поля в товаре» со списком из §2.
- Только для `Список` — отдельное «Разрешить несколько» (для Dropdown как допустимый альтернативный режим); для `Флажки` множественный выбор **уже зафиксирован типом**, для `Радиокнопки` одиночный. Никаких дублирующих противоречивых переключателей.
- Для списковых типов — **тот же** встроенный повторяемый Joomla Subform значений (+/−/drag), заголовок, уникальный стабильный код, публикация; в будущем optional HEX/образец изображения. Значения общие для характеристики.
- Для числа — «Целое/Дробное», единица измерения, ограничения/шаг; для даты календарь; для text max length; не показывать несовместимые настройки.
- «Различает варианты товара (SKU)» = отдельный независимый флаг, только на допустимых списковых типах.

**Фильтр каталога:**
- «Использовать в фильтре» = Да/Нет (уже есть флаг `is_filterable`, но **нет реализации**).
- Только при Да: «Отображение» = Флажки, Переключатели, Выпадающий список, Цветные образцы, Диапазон, Да/Нет **с учётом типа данных**.
- «Сколько значений можно выбрать в фильтре?» = Одно / Несколько **только если выбранный вид поддерживает оба варианта**; при Radio всегда одно, при Checkboxes всегда несколько. Не связывать с количеством значений в товаре.
- Опционально: показывать счётчики товаров, сортировать значения по порядку Joomla / алфавиту / числу товаров, свернуть длинную группу; последнее — дизайн будущего фильтра, не источник данных.
- Вкладка значений не меняет свои stable ID при смене вида поля или фильтра. Валидация непротиворечивых комбинаций и ограничение перехода Multiple→Single при имеющихся нескольких выбранных значениях в товарах — сервером.

## 5. Категории, отключение значений и скорость — уже согласованные требования

Родительская категория объединяет характеристики **реальных опубликованных товаров и SKU** всех видимых в каталоге подкатегорий. В дочерней — только реально видимые товары дочерней ветки. Фильтр **не показывает** значения, которые есть лишь в глобальном словаре, но **не назначены** товару подходящего scope. После выбора недоступные значения/целые группы **disabled, а не hidden**. В одной группе OR, между группами AND. В variant-фильтрах все условия применяются в одном реальном variant_id.

Для динамических фасетов — один серверный запрос на выбор фильтра, групповые SQL-агрегации, индексы, кэш с инвалидацией при изменении товара/варианта; **без** N запросов на N значений. Скорость подтверждать тестом на реальном каталоге, не обещать число миллисекунд.

## 6. Граница реализации

- В 0.5.11 **реально есть только** List/Text/Number/Boolean и настройка `is_multiple` для заполнения товара, скопированная при миграции со старого `is_variant` для сохранения поведения. Joomla browser smoke не подтверждён.
- **Нет** Radio/Checkboxes как самостоятельных видимых типов поля в форме атрибута, выборов presentation для фильтра, numeric ranges, swatches с цветами, Date/textarea-полей в характеристиках, фасетного endpoint, фронтенд-фильтра или реальных variant SKU.
- Не начинать необратимые SQL-миграции и не выкатывать ZIP под этот проект UX, пока пользователь не согласует матрицу.

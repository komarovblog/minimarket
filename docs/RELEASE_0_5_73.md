# MiniMarket 0.5.73 — окончательная нормализация характеристик

## Исправление установщика (09.11.2026)

Если Joomla показала `This command is not supported in the prepared statement protocol yet`,
причиной была команда `START TRANSACTION` внутри
`admin/sql/updates/mysql/0.5.73.sql`. Установщик Joomla запускает
SQL через подготовленные запросы MySQL 8.4, которые не поддерживают
эту команду. Теперь транзакцию начинает PHP в `script.php::preflight()`,
а `COMMIT` и проверки сохранности остаются в installer SQL.
Тест MySQL 8.4 воспроизводит выполнение через `mysqli::prepare()`.
Старый ZIP 0.5.73 требуется пересобрать перед повторной установкой.

Файл ручной миграции `releases/minimarket_mysql84_nnop3_upgrade_0_5_73.sql`
по-прежнему содержит `START TRANSACTION`: он предназначен только
для phpMyAdmin/обычного SQL и применяется вместо автоматической
миграции Joomla после резервного копирования. Не использовать оба
способа. Если установка уже была прервана, проверить `#__schemas` и
старые колонки перед повтором; браузерные тесты Joomla остаются необходимыми.

Дата: 09.11.2026. Ветка `development`.

## Что сделано

Реально удалена поддержка старого `legacy`-хранилища и типы
`list, textarea, date, url`. Единая модель характеристик использует только
типы `text`, `number`, `editor`, `boolean`, `document`, `color` и
источники `manual` / `preset`. Публикация и порядок находятся в
самостоятельной вкладке. Настройки витринного фильтра — в отдельной вкладке.

- Перенесены старые текстовые пресеты из JSON `text_options` в
  `#__minimarket_attribute_values` с устойчивыми ID.
- Старые одиночные и множественные выборы теперь связаны через
  `#__minimarket_product_attribute_options`.
- Сохранены числовые, логические и свободно введённые значения через
  `#__minimarket_product_attribute_scalars` и
  `#__minimarket_product_attribute_free_values`.
- Старый тип `list` в БД превращается в `text` + `preset` с теми же ID
  словаря.
- Окончательно удалены колонки `input_mode`, `text_options`,
  `number_options` и таблица
  `#__minimarket_product_attribute_multi_values`.
- Переключены редакторы, валидаторы, фильтры витрины, импорт/экспорт
  полного JSON-архива и новые установочные схемы; удалены старые
  сервисы `TextPresetRows`, `NumericPresetRows` и неиспользуемые
  формы их ввода.
- Глобальный тип магазина по-прежнему имеет варианты
  «Физические товары / Цифровые товары / Доставка еды».
  Специальные сценарии цифрового магазина и доставки еды ещё не реализованы.

## Проверка данных присланного дампа

Дамп MySQL 8.4 от 07.11.2026 содержал 12 характеристик.
Контрольное соответствие после миграции: 52 записи словаря,
496 связей товаров со справочниками, 462 числовых/логических значения.
Существующие ID товаров и старых значений цветов сохраняются.
Цифры относятся к **снимку 07.11.2026**: на более поздней базе могут отличаться.

В CI проверены PHP 8.4/8.5, JavaScript, новый MySQL 8.4 каталог,
повторный импорт демонстрационных данных, фактическое обновление
заполненной старой схемы MySQL 8.4 (включая удаление колонок/таблицы),
установка обновлённых форм и сборка Windows ZIP.
Тест MySQL 8.4 выполняется на отдельной фикстуре, не на приватной БД.
Браузерная проверка установленной Joomla остаётся отдельным этапом.

## Как обновить существующую Joomla

**Рекомендуемый вариант:** сделать полную резервную копию MySQL,
затем установить `com_minimarket-0.5.73.zip` поверх текущей версии
в штатном установщике Joomla. Он сам применит
`admin/sql/updates/mysql/0.5.73.sql`. Никакой ручной SQL после
этого **не нужен**.

**Альтернативный ручной импорт:** если требуется сперва импортировать
финальный SQL в phpMyAdmin, после полного бэкапа использовать
`releases/minimarket_mysql84_nnop3_upgrade_0_5_73.sql` на
той же БД с префиксом `nnop3_`, затем установить ZIP 0.5.73.
В конце ручной SQL отмечает запись в `nnop3_schemas`, чтобы Joomla
не пыталась второй раз удалить уже удалённые колонки и таблицу.

**Не делать оба способа одновременно.** MySQL DDL делает
неявный COMMIT; при сбое схемной миграции восстановление из резервной
копии может быть обязательным. Для рабочей установки сначала проверить
процедуру на копии БД. Текущий приватный дамп не публикуется в GitHub.

Накопительный `sample-data/minimarket_mysql84_nnop3_update_0_5_73.sql`
является отдельной **демонстрационной загрузкой**, а НЕ миграцией
твоей рабочей БД. Не запускать его ради очистки характеристик.

## Архивы

Выпуск:`com_minimarket-0.5.73.zip` и
`mod_minimarket_toolbar-0.5.73.zip` (модуль отдельно устанавливается).
Команда для Windows:

```powershell
Set-Location 'C:\OSPanel\home\minimarket.local'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release-to-desktop.ps1
```

На Desktop появится ZIP компонента, отдельный ZIP модуля,
демонстрационный SQL и дополнительно финальная ручная миграция SQL.

# MiniMarket 0.5.3 — проверка галереи товара в Joomla

**Статус:** исходники в GitHub development; полный CI проверять по последнему коммиту; **реальный Joomla smoke NOT RUN**, пока пользователь не подтвердит. Рабочий компонент 0.5.2 обновляется штатным ZIP.

## Что вошло

- В существующей вкладке товара «Изображения» осталась **главная обложка** (`image` + `image_alt`). Она считается основным фото, используется в списках, OG fallback и первым фото на карточке. **Выбрать главную можно через это поле**.
- Ниже — повторяемая форма Joomla **«Дополнительные фотографии»**. «Добавить» выбирает фото через штатный Media Manager и отдельный alt; «Переместить» меняет порядок; «Удалить» удаляет связь с товаром, **НЕ файл в Joomla Media**.
- Путь в каждой строке только `images/filename.ext`, без `#joomlaImage://`, ширины и высоты. Повтор одной фотографии, включая совпадение с обложкой, запрещён.
- Дополнительные записи лежат в таблице `#__minimarket_product_images`: product_id, path, alt, sort_order. Физические файлы нигде не копируются. Единственная обложка хранится по-старому в products.image; SKU/price/stock/URL не меняются.
- При Save/Apply изменения товара и галереи записываются одной транзакцией. Ошибка галереи не должна приводить к частичной записи; при удалении последнего ряда удаляются только связи.
- Публичная карточка: первое фото крупно, дополнительные превью с клавиатурным переключением, исходный файл открывается по ссылке. На маленьком экране блок адаптивный; при отключённом JS фото по-прежнему можно открыть.
- Цвета, SKU-specific галереи, автоматическая смена картинок при выборе варианта и bundles **не реализованы**, будут следующим связанным этапом. Нельзя показывать несуществующие привязки.

## Единственный порядок установки

1. Перед миграцией создать **backup БД Joomla**. Не удалять компонент, файлы Joomla или TEST-001.
2. После **PASS всех работ GitHub Actions** выполнить в CMD из `C:\OSPanel\home\minimarket.local`:
```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-product-gallery.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-product-editor.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```
3. Ожидается `PACKAGE_OK: 0.5.3 (com_minimarket-0.5.3.zip)`. Обновить Joomla через **Система → Установка → Расширения**, установить **только** `dist\com_minimarket-0.5.3.zip`. SQL вручную не выполнять; scripts/test-category-schema.php в пользовательской базе не запускать.

## Точечный smoke в существующей Joomla

- Открыть отдельный тестовый товар (НЕ менять TEST-001). На вкладке «Изображения» выбрать обложку и 3 дополнительные фотографии с alt.
- После выбора в поле виден **только** путь `images/...`, без служебных фрагментов Joomla.
- Сохранить/Применить и открыть снова. Проверить 3 ряда, alt и порядок; поменять порядок, Save, открыть снова.
- Удалить из повторяемой формы **среднюю** фотографию; Save. Другие фото остались, файл доступен в Joomla Media Manager. Затем удалить все дополнительные фото; Save — галерея пустая, обложка остаётся.
- Попытаться добавить два одинаковых файла или тот же файл, что обложка — сервер должен отклонить сохранение без потери уже сохранённой галереи.
- На публичной карточке проверить крупную обложку, превью, изменение выбранного изображения кнопкой, открытие исходника, навигацию клавиатурой и мобильную ширину. При одной обложке дополнительных превью нет.
- Проверить существующий TEST-001: ID, URL, SKU, цена, остаток, категория и обложка без изменений. Варианты и фиды в этом выпуске не должны появиться.
- При ошибке указать номер шага и короткий симптом/скриншот. Не править рабочую БД и не удалять расширение.

**Автоматический CI не подтверждает работу повторяемого Joomla Subform в конкретном браузере: это отдельная реальная приёмка.**

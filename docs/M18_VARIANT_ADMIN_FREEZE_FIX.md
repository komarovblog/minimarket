# MiniMarket 0.5.18 — исправление зависания редактора товара

**Инцидент:** после обновления 0.5.17 при открытии товара Joomla отрисовывала часть административной формы, но вкладка браузера продолжала показывать загрузку и интерфейс не завершал отрисовку.

**Причина:** новый скрипт `media/js/variants-admin.js` наблюдал за **всем** `#adminForm` через `MutationObserver`, вызывал `redraw()` на каждое изменение DOM и при каждом вызове повторно устанавливал `warning.textContent`. Даже если текст предупреждения совпадал, изменение DOM повторно вызывало observer. Для категорий без осей вариантов постоянный ненулевой текст предупреждения создавал самоподдерживающийся цикл браузерных microtasks, блокируя отрисовку страницы.

**Исправление:** предупреждение изменяется только при изменении его текста; observer реагирует только на добавление Joomla Subform-строки с полем `variants[...][selection]`, игнорируя собственные узлы и изменения других компонентов. Логика выбора SKU и сохранения данных не меняется. Новая регрессия `scripts/test-variant-admin-observer.js` воспроизводит синтетический цикл `MutationObserver`, проверяет отсутствие повторных вызовов и реакцию на новые строки/смену категории. Тест запускается в PHP CI job через Node, отдельно от `node --check`.

**Установка и проверка:** резервная копия БД перед обновлением, установка `com_minimarket-0.5.18.zip` поверх версии 0.5.17, затем Joomla System → Clear Cache и принудительное обновление страницы `Ctrl+F5` (браузер мог кешировать прежний JS). Проверить открытие существующего товара и добавление строки «Варианты». Если симптомы сохраняются, проверить ответ PHP и доступность JS через браузерные DevTools; не объявлять live Joomla smoke успешным без подтверждения пользователя.

Миграций SQL в 0.5.18 нет; схема 0.5.17 сохраняется.

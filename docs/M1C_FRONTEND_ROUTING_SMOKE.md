# MiniMarket 0.3.0 — первый frontend каталог, категория, карточка и SEF

Дата: 2026-10-31. Репозиторий `komarovblog/minimarket`, рабочая ветка `development`, Joomla 6.0–6.2 по проектному окружению (точную локальную версию сверить в Joomla). **Реальный тест на компьютере пользователя ещё не выполнен.**

## Реализовано в исходниках

- `com_minimarket` версия `0.3.0`, **без изменений SQL-схемы**. Действующие категории/товары 0.2.1 должны сохраниться.
- Один штатный Joomla RouterFactory/RouterService + собственный `Site\Service\Router` для **одного сегмента `alias-id` на сущность**; не строит иерархию категорий в URL.
- `catalog` выводит только опубликованные категории; `category` выводит только опубликованные товары категории; `product` показывает только опубликованный товар из опубликованной категории.
- Публичные данные читаются через `CatalogRepository`. Публичные шаблоны экранируют значения; никакой кнопки «Купить», SEO-фильтра, Product JSON-LD и dataLayer **ещё нет** — эти вещи не считать готовыми.
- Заголовок документа берётся из конкретной категории или товара. Ссылки строятся штатным `Joomla\CMS\Router\Route`, а не конкатенацией внешнего домена.
- Товары/категории теперь не могут получать одинаковые aliases между типами через стандартные формы; старые неоднозначные строки (если были созданы до 0.3.0) дают 404, чтобы не показывать неправильную сущность.

## Особенность Joomla: Itemid и ожидаемый URL

**SEF-маршрутизация зависит от меню Joomla.** Рекомендуется создать один опубликованный пункт меню с типом **MiniMarket Catalog**, например «Каталог» с alias `catalog`:
- Каталог: `http://minimarket.local/catalog`
- Категория: `http://minimarket.local/catalog/<alias>-<ID>`
- Товар: `http://minimarket.local/catalog/<alias>-<ID>`

Сегмент `catalog` — это **пункт меню сайта**, а не родительская категория магазина. Если страницу каталога назначить главной сайта, вложенный каталоговый префикс может исчезнуть, и URL станут `/<alias>-<ID>`. Без корректного menu item Joomla может сгенерировать системную ссылку `/component/minimarket/...`; это не показатель вложенности категорий и не итоговый SEO-URL.

**Здесь не нужно** создавать пункт меню для каждого товара: собственный router использует ID/alias из своих таблиц. **Точный URL следует брать из реально открытой страницы, а не предполагать ID/aliases.**

## Как безопасно обновить 0.2.1 → 0.3.0

1. На всякий случай сохранить приватный SQL-экспорт БД `minimarket` до обновления, особенно если уже есть тестовые данные. SQL-миграций в 0.3.0 нет; backup не загружать в GitHub.
2. Открыть **PowerShell**:
```powershell
Set-Location 'C:\OSPanel\home\minimarket.local'
git status --short
git pull --ff-only origin development
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```
   При неожиданных изменениях `git status` или ошибке pull **остановиться**, не выполнять reset/force.
3. Joomla админка → **Система → Установка → Расширения** → загрузить `C:\OSPanel\home\minimarket.local\dist\com_minimarket.zip` поверх установленной версии. Старую версию не удалять.
4. Убедиться в Joomla Extensions, что версия компонента `0.3.0`. Админские формы создания/редактирования товара и категории должны остаться рабочими.

## Ручной smoke-test

1. Убедиться, что в MiniMarket опубликованы тестовая категория и тестовый товар `TEST-001` (из M1b), товар относится именно к этой категории.
2. В Joomla **Меню → Главное меню → Создать** добавить пункт меню типа **MiniMarket — Каталог** с alias `catalog` (если он ещё не существует). Пункт меню должен быть опубликован.
3. Открыть страницу каталога по пункту меню, нажать ссылку категории, затем ссылку тестового товара. Обратите внимание на **конечные URL**: у категории и товара должен быть один сегмент `alias-ID` после `/catalog/`, без `index.php` (при включенном Joomla URL rewriting), без цепочки категорий и без параметров `?view=...`.
4. В карточке должны отображаться название, SKU `TEST-001`, цена и обновлённый остаток M1b (например 2). Название товара и цена не должны быть HTML-кодом.
5. Проверить прямой технический URL `index.php?option=com_minimarket&view=product&id=<real-id>` — он должен открывать тот же опубликованный товар; альтернативный вид технического URL пока может существовать, это не значит, что уже реализованы canonical/strict SEO redirects.
6. Временно снять публикацию товара через админку: старый публичный SEF URL **должен вернуть 404** (а не страницу с данными товара). Переопубликовать товар и проверить восстановление URL.
7. Временно снять публикацию категории: весь список и карточки её товаров должны стать недоступными (404). Сразу вернуть категорию в опубликованный статус.
8. Проверить, что обычная Joomla, админка MiniMarket и другие пункты меню продолжают работать.

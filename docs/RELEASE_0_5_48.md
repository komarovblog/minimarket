# MiniMarket 0.5.48 — Excel/CSV/JSON импорт и базовый экспорт

Дата 04.11.2026. Ветка `development`. Поверх версии 0.5.47, без SQL миграции, ядро Joomla, матрица SKU/галерея не изменены.

## Реализация

- **Импорт** файлов `.xlsx`, `.csv`, `.json` через прежний двухэтапный безопасный механизм. Таблицы преобразуются к JSON-пакету v1, затем вызывается неизменённый `CatalogImport::decode` и `CatalogImport::run(...,false)` для предпросмотра и `run(...,true)` при подтверждении. Клиентский формат конвертируется в канонический документ в сеансе — повторно файл не читается. Ошибки транзакции откатываются.
- **Excel XLSX**: лист `meta` (version, source, adopt_existing), затем отдельные листы `categories`, `attributes`, `options`, `products`, `links`, `category_attributes`, `category_options`. Первая строка — английские технические названия колонок, стабильные внешние `key`. Поля `values` и `members` хранят JSON-массивы внутри одной ячейки (это ограничение формата v1); в будущей версии их можно сделать отдельными листами. Все ячейки в генерируемом XLSX текстовые: SKU с начальными нулями остаются без изменений. Файлы Excel, которые пересохраняются Microsoft Excel, читаются с shared strings и numeric values; формулы и внешние связи отвергаются.
- **CSV**: один UTF-8 файл с BOM и колонками `section,source,adopt_existing` + поля разделов; первая строка meta хранит `source` и `adopt_existing`. У всех остальных строк указан `section`, сложные значения — JSON-массивы. Никаких нестандартных локальных Excel разделителей по умолчанию (разделитель запятая).
- **JSON**: исходный базовый формат v1, полностью сохранён.
- **Шаблоны** пустой/заполненный для каждого формата скачиваются прямо в MiniMarket из проверенного локального примера, без GitHub. Защита CSRF и ACL, whitelist имён и форматов.
- **Экспорт** базового каталога в Excel XLSX, CSV и JSON. `CatalogExportV1` формирует JSON-сущности по внутренним ID и связям, затем тот же файл может быть загружен импортом в чистую установку при совместимых исходных данных. Экспортный источник `minimarket-export`; ключи `category-ID`, `attribute-ID`, `option-ID`, `product-ID`, `link-ID` стабильны внутри этой установки. Механизм проверяет совместимость с импортом v1 и **отказывается** создавать «полную» выгрузку, если есть неподдерживаемая структура (например, нет базового SKU у товара, используемого только через варианты).
- Допустимые загрузки до 3 МиБ, не больше 2500 строк пакета. ZIP XLSX имеет лимиты размера после распаковки и количества файлов/строк, формулы отвергаются. PHP расширения `zip`, `dom`, `mbstring` требуются для Excel.
- UI: один раздел **«Импорт и экспорт»** с шагами, таблицей из 6 образцов и кнопками выгрузки. RU/EN.

## Принципиальное ограничение — это НЕ полный экспорт магазина

Совместимый базовый v1 переносит название, код/alias, состояние, иерархию, глобальные значения опций, характеристики (для которых поддерживается тип), простые товары с базовым SKU, цену, базовый остаток, связи и назначения к категориям.

**Не переносит (и не должен быть выдан за резервную копию):** матрицы сочетаний SKU, остатки конкретных SKU, фото и видео, SEO/OG, информационные значения характеристик конкретных товаров, подробные описания, дополнительные поля и ряд исторических справочников. При несовместимой записи вместо молчаливого пропуска экспорта — ошибка. Сначала делайте backup базы MySQL, и **не удаляйте исходную базу на основании базового экспорта v1**.

Цель следующего этапа — полноценный v2 экспорт/импорт с отдельными листами для вариантов, значений, галереи, описаний, SEO и связей, с тестом round-trip на чистой БД. Отдельно фасетные фильтры каталога и корзина/заказы.

## Приёмка

1. Сделайте резервную копию `minimarket`.
2. Установите `com_minimarket-0.5.48.zip` поверх предыдущей версии, без отдельного demo SQL.
3. В MiniMarket → Импорт и экспорт скачайте каждый из 6 шаблонов, убедитесь, что они открываются локально и нет ссылок на GitHub.
4. В Excel откройте заполненный XLSX, проверьте листы и SKU, загрузите → проверьте → примените. Повторный импорт должен обновлять, но не дублировать записи.
5. Повторите загрузку CSV и JSON (для одного `source` повтор не должен создавать дубли).
6. На тестовой БД проверьте экспорт базового каталога и импорт обратно в чистую БД. На реальной базе при несовместимости получите объяснение и используйте MySQL backup.
7. Проверьте что кнопка Развернуть / Свернуть работает, ссылка на связь открывает редактор, остальные ранее принятые элементы не изменились.
8. PHP + MySQL + Windows packaging CI должны быть PASS.

Артефакт `minimarket_toys_rich_import.sql` из dist — отдельный демонстрационный SQL и **не должен запускаться при обновлении**.

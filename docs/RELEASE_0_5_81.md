# MiniMarket 0.5.81 — глобальные настройки оформления заказа, доставки и оплаты

**Дата:** 10.11.2026. **Ветка:** `development`.

## Новые вкладки в глобальных настройках MiniMarket

### Оформление заказа

- `checkout_auth_mode`: **«Гостевое оформление без регистрации» (по умолчанию)** или **«Регистрация при оформлении (SMS)»**. Второй режим заранее подготовлен, но **реальная SMS-регистрация и авторизация ещё НЕ реализованы**: сервер не создаёт заказ, если выбран этот режим, и показывает понятное предупреждение. Временный код или обход проверки отсутствует.
- Для **Имени**, **Телефона**, **Email** и **Комментария** отдельные варианты: **«Не показывать», «Необязательное», «Обязательное»**. Начальное состояние — имя/телефон обязательны, email/комментарий необязательны. Сервер игнорирует скрытые поля даже при ручной подмене POST.
- При оформлении обязателен хотя бы один действительный канал связи: телефон или email. Если оба скрыты, оформление блокируется понятной ошибкой конфигурации. Если оба необязательны, но не заполнены, отправка не допускается. Контакт может быть изменён без изменения профиля Joomla.

### Доставка и получение

- `delivery_pickup_enabled=1`: самовывоз, **всегда бесплатно**. Необязательный адрес точки из общих настроек сохраняется в снимке заказа.
- `delivery_courier_enabled=0`: доставка по адресу (выключена по умолчанию).
- `delivery_rate_source`: **справочник городов** или **СДЭК**. Для справочника в глобальной настройке `delivery_city_rates` вводятся строки `Город|ЦенаРуб`, например `Москва|500`, `Тверь|250,50`. Город выбирается из заполненных записей, требуется полный адрес. Компонент использует точную цену сервера и блокирует неизвестный город, неправильные/повторные строки, отсутствие адреса и попытки подменить стоимость в POST.
- СДЭК пока **только зарезервированный вариант настройки**. Если он выбран, доставка по СДЭК не показывается как рабочая; требуется последующая интеграция API и доступы. Не подставляем фиктивную сумму.
- В корзине и checkout товарная сумма всегда серверная. На странице оформление стоимость по выбранному городу отображается сразу, но сервер пересчитывает цену на POST.

### Оплата

- `payment_on_receipt_enabled=1`: **при получении**, без онлайн-списания.
- `payment_bank_transfer_enabled=0`: **перевод по реквизитам**, вручную согласовывается сотрудником.
- Можно включать оба варианта либо только один. Если ни один не активен, checkout не принимает заявки. Онлайн-оплата/ЮKassa появится в отдельной итерации и не подменяется фиктивным подтверждением.

## Форма, заказы и миграция

- Одна страница с блоками «Покупатель → Получение → Оплата» и итогом справа на компьютере; адаптивная вертикальная компоновка на телефоне. Только активные способы.
- Новая миграция `admin/sql/updates/mysql/0.5.81.sql` добавляет в `#__minimarket_orders` поля `delivery_method`, `delivery_city`, `delivery_address`, `delivery_rate_source`, `delivery_fee_cents`, `payment_method`, `items_total_cents`. Для исторических заказов исходная общая сумма сохраняется как `items_total_cents`, стоимость доставки = 0. Заказы не удаляются.
- Новые заказы сохраняют итог в копейках = **товары + доставка**, снимки адреса, тарифной системы и способа оплаты. Исторические цены товаров/SKU сохраняются отдельно. Заявки не оплачены, остатки не резервируются/не списываются.
- В админке заказа показаны способ получения, город/адрес, оплата, сумма товаров, доставка и итог.
- Тесты: `scripts/test-0-5-81-checkout.php`, `scripts/test-0-5-81-orders-mysql84.php`, PHP lint, MySQL 8.0/8.4, Windows ZIP, RU/EN.

## Ограничения и дальнейшие шаги

- **Нет** реального SMS, внешних ID, авторизации по телефону, СДЭК API и ЮKassa — это интеграции после окончательной приёмки сценариев.
- Пока в настройках один адрес самовывоза и локальный текстовый справочник «Город|Стоимость», без управления несколькими пунктами, регионами и тарифными зонами. Это стартовый вариант: более развитый справочник и ПВЗ можно обсудить отдельно.
- Не выдавать успешный CI за проверку в установленной Joomla; перед использованием нужен браузерный smoke обоих режимов полей, самовывоза и доставки на тестовой копии.
- Перед установкой — резервная копия базы и файлов, проверка восстановления. Не импортировать demo SQL при обновлении расширения.

## Доставка на локальный Windows

```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release-to-desktop.ps1 -SkipPull
```

Файлы на рабочем столе: `com_minimarket-0.5.81.zip`, `mod_minimarket_toolbar-0.5.81.zip`, необязательный `minimarket_demo_gallery_filters_0_5_81.sql`. Модуль устанавливается отдельно. При обновлении через Joomla применяется только `0.5.81.sql`.

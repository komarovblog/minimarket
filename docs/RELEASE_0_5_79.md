# MiniMarket 0.5.79 — защита заказов и фундамент телефонной авторизации

**Дата:** 10.11.2026. **Ветка:** `development`. **Статус:** подготовительный технический выпуск; реальная SMS-регистрация и внешние ID **ещё не работают**.

## Изменения в коде

- `OrderStorage::create` отказывает в создании заказа при `user_id < 1`. Контроллер `checkout.submit` также запрещает прямые POST от неавторизованных и заблокированных пользователей.
- В оформлении неавторизованному показывается предупреждение вместо формы отправки. Анонимная корзина сохраняется; **гостевых заказов нет**.
- Страница завершения заказа показывает его номер только пользователю-владельцу из той же Joomla-сессии, проверяя сохранённый `orders.user_id` по БД.
- `PhoneIdentity` нормализует международные номера в E.164, отклоняет неоднозначные формы.
- `PhoneOtp` содержит криптостойкую генерацию 6-значных кодов и проверку HMAC с привязкой к телефону, действию, сессии и nonce; TTL 5 минут и лимит 5 попыток. **Это только чистые функции**: нет публичного endpoint, реальной отправки SMS, аккаунтов и механизма авторизации. Лимиты выдачи/попыток должны быть обеспечены транзакционно в будущем сервисе БД.
- Аддитивная миграция `0.5.79.sql` и fresh install добавляют `#__minimarket_user_phones` и `#__minimarket_phone_challenges`. Таблицы готовят идентификатор телефона, HMAC/TTL/счётчики; пока не используются при оформлении.
- Заказы, созданные в предыдущей версии с `user_id=0`, не удаляются и не переписываются. Для новых заказов обязательна авторизация.
- Добавлен `scripts/test-0-5-79-auth.php`, обновлены версии regression, сборка ZIP компонента, отдельный toolbar и накопительный/демонстрационный SQL.

## Принципиальное ограничение

**НЕ считать 0.5.79 завершённым внедрением бизнес-сценария из `docs/CHECKOUT_UX_SPEC.md`.** Вход и предварительная регистрация по МТС ID, Сбер ID, Яндекс ID, VK ID; регистрация/вход после SMS; привязка к Joomla Users и личный кабинет не реализованы. Никаких реальных кодов, ключей, заглушек с успешно пройденной проверкой или автоматического появления учётных записей нет.

Для неавторизованного покупателя новый checkout закрыт. **Не устанавливать на действующий магазин, которому необходимо принимать заказы от новых клиентов, до завершения безопасного SMS/ID-потока и браузерной приёмки Joomla.**

## Следующий обязательный этап

1. Подключить официальный SMS-сервис с тестовым/производственным режимом; проверить фактическую доставку, цены, ошибки и защиту от перебора/спама. MAX — только после проверки официальной возможности отправки кода.
2. Транзакционный сервис выдачи/проверки SMS-попыток с ограничениями по номеру/IP/сессии, одноразовым погашением и независимой аудит-записью, не раскрывающей код.
3. Через штатные API Joomla 6 реализовать создание или поиск пользователя по **подтверждённому** телефону и установление авторизованной сессии через официальный механизм аутентификации; не обходить Joomla login/ACL/плагины и не менять ядро.
4. Подключить checkout к SMS-регистрации/входу; до создания заказа повторно проверять корзину, цены и остатки, записывать owner user_id, исключать дубли.
5. Публичная предварительная регистрация по SMS и через проверенные OAuth/OIDC МТС/Сбер/Яндекс/VK, отдельный тест связки external provider+subject и защиты от ошибочного объединения аккаунтов.
6. Проверить полный путь на настоящей Joomla с тестовыми SMS и оплатой, прежде чем снимать предупреждение.

## Сборка и установка на стенд

Перед любым обновлением — полный бэкап БД и файлов и проверка восстановления. Ставить пока только в локальный/изолированный тестовый магазин.

В CMD:
```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release-to-desktop.ps1 -SkipPull
```

На рабочем столе появятся `com_minimarket-0.5.79.zip`, `mod_minimarket_toolbar-0.5.79.zip` и `minimarket_demo_gallery_filters_0_5_79.sql`. Модуль устанавливается отдельно. SQL демоданных **не является миграцией** и при обычном обновлении не нужен; `0.5.79.sql` применяет Joomla installer.

## Проверка

PHP 8.4/8.5, MySQL 8.0/8.4, Windows ZIP и Desktop-3-files проверяются GitHub Actions. Они не доказывают работающий вход, SMS, OAuth и браузерную приёмку. Перед реальным включением обязательны внешняя интеграция и E2E.

# MiniMarket 0.5.96 — редакторы способов и самостоятельные системные атрибуты

## Готово в исходниках

**Доставка, оплата и регистрация.** Способ открывается по названию из соответствующего списка MiniMarket. У штатных способов редактирование остаётся внутри карточки, без дополнительного раздела «Настройки плагинов». Для курьерской доставки действующие зоны редактируются во вкладке «Зоны» карточки «Курьер». У самовывоза сохраняются стоимость, адрес, график и безопасная HTTPS-ссылка на карту. У оплаты наличными/при получении и банковским переводом — отдельные рабочие настройки; у email-регистрации — существующая отметка «Использовать для подтверждения заказа» с проверкой, что регистрация пользователей Joomla действительно включена.

**Подключённые плагины.** Параметры плагина из его штатного XML уже редактируются внутри карточки соответствующего способа; теперь там же можно **включить/выключить** сам плагин. Поле доступно только при `core.edit.state` или `core.admin` для `com_plugins`. Изменение записывается в `#__extensions.enabled` вместе с параметрами атомарно; никакого собственного хранения, отдельного второго редактора или новой модели интеграции. Информационная ссылка ведёт на штатную карточку плагина Joomla. Для не подключённых провайдеров входа, доставки или оплаты **не заявлена работа** самого API только из-за публикации плагина.

**Глобальные системные атрибуты.** В «Основных» настройках сгруппированы независимо:
- Цена: тип фильтрации (нет/диапазон/ползунок) + место отображения;
- Артикул: фильтрация текстовым поиском (или нет) + место отображения;
- Наличие: использовать в фильтре или нет + место отображения.

Эти поля уже читались магазином индивидуально; теперь и интерфейс показывает их попарно, а не два несвязанных списка. Значения, сохранённые ранее, не меняются. Цена в карточке категории не скрывается самопроизвольно. Добавленные характеристики и опции **не наследуют** параметры системных атрибутов: атрибуты и новые опции по умолчанию показываются только на полной странице товара; для каждой отдельной сущности можно задать своё место отображения. Явный режим «По настройке магазина» для старых опций сохранён и по текущей логике ведёт на страницу товара.

## SEO-страницы: проверенный текущий контракт

Редактор из версии 0.5.95 уже содержит **первую вкладку «Общая»** с названием, URL (alias), H1, изображением, кратким и полным описанием; **вторую «Условия»** с категорией, а затем AJAX-подгрузкой только связанных с ней опубликованных характеристик/опций и значений; далее SEO (title/meta/OG/robots) и «Публикация». Сервер `SeoCategoryChoices::validate` отклоняет значения, не привязанные к выбранной категории. Старую проверку, ожидавшую статические галочки в HTML, заменили проверкой действующего AJAX-сценария.

**Ограничение:** сейчас у SEO-страницы одна базовая категория (`#__minimarket_seo_filters.category_id`). Если требуется **несколько категорий одновременно для одной SEO-страницы**, это отдельное решение по URL, объединению товаров и доступным значениям. Не добавлять фиктивный multiselect, который не меняет выдачу на витрине.

## Не менять

Ветка `development` только, `main` не трогать, шаблон Blank отложен. Не создавать отдельные модули/плагины и не копировать параметры из `#__extensions` в таблицы MiniMarket. Сохранить действующие серверные тарифы и статусы заказов.

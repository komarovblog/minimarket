# MiniMarket 0.5.55 — карточки комплектов, формат товара, цены и импорт/экспорт

Дата: **06.11.2026**. Ветка: `development`. Установка поверх 0.5.54 без потери каталога.

## Реализованные замечания

1. **«Комплекты»:** внутреннее `product_type=bundle` выбирается ссылкой «Комплекты → +», а не выпадающим списком в карточке. У обычного товара `product_type=simple`; структурный тип скрыт в форме, но сохраняется в базе и передаётся при сохранении. Разделы видят только соответствующие поля.
2. **Обычный товар:** добавлено поле **«Формат товара»**: «Физический» либо «Цифровой» (`delivery_type`). Не вводить глобальное ограничение типа магазина: продавать оба вида в одном каталоге. Для старых записей — physical. Комплект может содержать товары разных типов; отдельную оплату, доставку цифрового файла, активацию ссылок и смешанное оформление заказа реализовать **позже**, на этапе корзины/заказов/ЛК. До того цифровой тестовый продукт остаётся неопубликованным.
3. **Заголовок администратора:** «MiniMarket: комплект» при открытии комплекта, «MiniMarket: товар» при обычном товаре. Корректное поведение при создании по меню и редактировании по ID.
4. **Комплект → Основное:** сразу после артикула выбирается расчёт цены: фиксированная цена либо процентная скидка от суммы компонентов. При фиксированной цене — поля **Цена**, **Старая цена**. При процентной скидке — **Процент скидки**; цену автоматически вычислять по текущей стоимости товаров/SKU и вложенных комплектов. При переключении режима старая введённая фиксированная цена не стирается из БД. Состав остаётся только для выбора компонентов/количества/просмотра текущих итогов. Расчёт доступного остатка по компонентам не меняется.
5. **Флаги:** у комплекта порядок **Выгода → Скидка → Новинка → Популярное**; у товара **Скидка → Новинка → Популярное**. Все подписи начинается с «Показывать флаг». У комплекта в режиме скидки доступна «Выгода» (денежная сумма), а «Скидка» по старой цене выключена; в режиме фиксированной цены наоборот. Для включения скидки требуется старая цена выше текущей. Сервер проверяет ограничения, не полагаясь только на JS. На публичке для комплектов с расчётной ценой **не отображать устаревшую ручную старую цену** и соответствующую метку — вместо неё «Выгода».
6. **Состав комплекта:** исправлена причина, почему поиск не выдавал ни одного результата. Контроллер возвращал не те строки: `BundlePrice::snapshot()` выполнял новую `setQuery()` до вызова `loadAssocList()` для списка кандидатов. Теперь кандидаты считываются **до** снимка цен. Работает поисковая строка, фильтр категории и начальная выдача без поискового запроса. Оставлена защита ACL/CSRF, лимит 25 результатов, запрет добавления текущего комплекта.
7. **Меню:** «Импорт / Экспорт» (и RU/EN-заголовок страницы).
8. **Импорт/экспорт:** без отдельного повторяющего заголовка вне карточки. В первом компактном блоке «Импорт» — текст о проверке и обновлении записей, два варианта шаблона (заполненный и пустой), каждый в **XLSX, CSV, JSON** с одинаковой шириной кнопок. Загрузка и проверка внутри этого же блока. Далее отдельная карточка «Экспорт», кнопки «Экспортировать XLSX / CSV / JSON». Отображение предупреждений о границах базового обмена сохранено; сами данные и действующая логика импорта/экспорта не изменены.

## Миграция и демонстрационный SQL

`admin/sql/updates/mysql/0.5.55.sql`: **только добавить** `#__minimarket_products.delivery_type VARCHAR(12) NOT NULL DEFAULT 'physical'`. Те же поля в `install.mysql.sql` для чистой установки. Старые товары, комплекты, SKU, цены, остатки, изображения, связи, бренды/коллекции и SEO не перезаписываются.

Необязательный файл `sample-data/minimarket_digital_demo_0_5_55.sql` для MySQL 8.4 / база `minimarket` / префикс `nnop3_`: добавляет **один неопубликованный** цифровой тестовый товар `DIGITAL-STEM-1200` (id 1200, категория 104 «Конструкторы») **только если** категория и свободные ID/alias/SKU найдены. Можно запускать повторно. Скрипт не содержит DROP/DELETE/TRUNCATE/ALTER. Автоматически не запускается установщиком Joomla; **импортируй только если нужен пример**. Нет новой покупки/выдачи цифрового контента в 0.5.55.

## Приёмка

1. Резервная копия БД. Установить `com_minimarket-0.5.55.zip` поверх 0.5.54 через Joomla. Не переимпортировать старый весь каталог.
2. «Товары → +»: страница «MiniMarket: товар», без селектора «Товар/Комплект»; **формат «Физический / Цифровой»** доступен. Сохранить и повторно открыть.
3. «Комплекты → +»: страница «MiniMarket: комплект», без структурного типа; после артикула выбрать способ цены. Проверить оба режима и видимые поля; «Состав комплекта» отдельно.
4. На вкладке «Флаги»: у комплекта «Выгода, Скидка, Новинка, Популярное»; у обычного товара только 3 флага. Везде одна формулировка «Показывать флаг». Дни действия без изменений.
5. При пустой старой цене «Скидка» остаётся видимой, но недоступна, с пояснением. В процентном режиме у комплекта доступна «Выгода», а «Скидка» отключена. При возврате к фиксированной цене обратное.
6. «Состав комплекта → Добавить товар или SKU»: с пустым запросом появляются 25 первых позиций, ввод названия / SKU выдаёт результаты, фильтр категории ограничивает выдачу. Добавить товар/вариант, указать количество, проверить сумму строки и итог.
7. Сравнить итоговую цену комплекта с `BundlePrice::calculate` при изменении цен его компонентов. Проверить, что «Выгода» показывает денежную разницу, а скидка по старой цене работает только для фиксированной.
8. Импорт / Экспорт: заголовок один, первый блок содержит шаблоны XLSX/CSV/JSON, поле загрузки и кнопку проверки; второй блок — экспорт с правильными названиями. Протестировать без фактической загрузки полного каталога.
9. Проверить, что существующие бренды, связи, галереи, матрицы SKU, цены и изображения сохранены.

## Правила архитектуры для последующих задач

- `product_type` — технический тип позиции: обычный товар / комплект; выбирается разделом создания и не редактируется в карточке.
- `delivery_type` — формат **обычного** товара: физический / цифровой, не глобальная настройка «тип магазина». Комплекты могут иметь смешанный состав; правила отгрузки по компонентам — задача оформления заказа.
- В комплекте два взаимно исключающих способа цены: фиксированная → старая цена/Скидка, либо процент от суммы → Выгода. Не смешивать на UI и сервере.
- Административные списки кнопок остаются по регламенту: отдельное действие с названием сущности, внутри списков плюс/минус и доступная подпись. Не менять ядро Joomla.
- Каждая итерация включает ZIP, при изменении демонстрационных данных — отдельный готовый SQL. Не менять старые SKU, позиции и галереи без согласования.

После приёмки — **полный импорт/экспорт v2**, включая SKU, комплектующие, digital/physical, флаги, SEO и медиа.

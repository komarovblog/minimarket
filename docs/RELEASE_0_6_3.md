# MiniMarket 0.6.3 — SEO-информеры, порядок Настроек, двухколоночный редактор фидов

**Основание:** 0.6.2, ветка `development`, Joomla 6 / PHP 8.5 / MySQL 8.4. Только нативные HTML/Bootstrap/Atum, без изменения ядра Joomla и репозитория Blank. **SQL-миграций нет.** Обновление — стандартным компонентным ZIP; модуль верхней панели выпускается отдельным ZIP.

## Изменения

1. SEO-фильтры: текст нижнего `alert-secondary` перенесён **в начало верхнего синего `alert-info`** на вкладке условий. Нижний информер удалён. Добавлена отсутствовавшая RU/EN локализация `COM_MINIMARKET_FILTER_PRICE` («Цена» / «Price»); проверены ключи обоих редакторов.
2. Меню компонента: в штатном `minimarket.xml` пункт «Настройки» расположен **последним после способов регистрации**. В дашборде последний элемент последней группы — плитка «Настройки»; остальные плитки и счётчики сохранены. Изменения в пользовательских/внешних меню вне компонента не выполняются.
3. Фиды: первыми полями общих сведений идут **Название фида (поле `title`)**, **URL фида** (read-only, виден после сохранения, до публикации есть пояснение), **Тип фида**. Поле «Название компании» сохранено: генератор YML отдельно использует его, поэтому удаление уничтожило бы данные. Флаг включения комплектов перенесён под общие сведения.
4. Поле «Способ отбора» из UI удалено. Используется существующий `selection_mode=auto` и серверное хранение включений/исключений товаров. **Ни схема БД, ни XML-сервисы фида, ни формат YML не изменены.**
5. Категории и товары стоят **в двух равных Bootstrap `col-lg-6` колонках**. В обоих блоках один порядок: заголовок со счётчиком выбранных записей, поиск одинаковой высоты, «Выбрать все / Снять все», прокручиваемый список. Категории выбираются слева; справа показываются только товары выбранных категорий, а тип «комплект» по-прежнему учитывает свой чекбокс.
6. Справа от поиска товаров — многокатегорийный фильтр **только по выбранным слева категориям**. Любое количество значений фильтра объединяется по OR, с поиском товаров — по AND. Фильтрация меняет видимость строк и **никогда не изменяет галочки**. Массовые действия действуют только по видимым строкам. Исключения отдельных товаров сохраняются при смене категорий/поиска до отправки формы; после сохранения — прежним серверным механизмом.

## Приёмочный сценарий в Joomla

- Сделать backup БД. Стандартно собрать и установить `com_minimarket-0.6.3.zip` (без импорта demo SQL). Модуль `mod_minimarket_toolbar-0.6.3.zip` устанавливается отдельно при необходимости.
- Проверить русскую и английскую панели, тёмную и светлую темы. SEO: «Цена» переводится, верхний синий информер содержит обе части пояснений, нижнего тёмного больше нет.
- Проверить штатный левый раздел MiniMarket: «Настройки» после способов регистрации; в дашборде эта плитка последняя. Если на сайте есть вручную созданные пункты меню сторонних расширений, их порядок настраивается отдельно.
- Создать новый фид: до первого сохранения URL пустой с пояснением; после сохранения выводится ссылка, при черновике она недоступна, после публикации работает с ключом.
- Слева отметить несколько категорий, найти категорию, не потерять остальные галочки. Справа увидеть только соответствующие товары; выбрать несколько категорий в правом фильтре и применить поиск. Проверить select all/none только по видимым строкам, снятие одного товара, выключение/включение категории, сохранение/повторное открытие.
- Проверить старый фид после обновления. Если раньше использовалась ручная выборка товаров из **неотмеченных категорий**, при первом сохранении через новый редактор они не попадут в новую область отбора; перед сохранением следует отметить их категории слева. Старый фид до редактирования не переписывается.

## Автотесты и риски

- `scripts/test-0-6-3-ui.php`: структура, порядок меню/формы, оба языка, URL, отсутствие тёмного SEO-информера.
- `scripts/test-0-5-61-feeds-editor.js`: отдельная DOM-модель для выбора категорий, сохранения исключений, фильтра категорий справа, поиска и массовых действий.
- Сохранены существующие серверные `scripts/test-0-5-61-feeds.php`, `scripts/test-0-5-61-feeds-db.php`, Windows ZIP и PHP 8.4/8.5 CI. **GitHub CI и браузерная приёмка фиксируются раздельно.**
- Никакие внешние интеграции Авито/Google, API-платежей или SMS этой итерацией не реализованы.

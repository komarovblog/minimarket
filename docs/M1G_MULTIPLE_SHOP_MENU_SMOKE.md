# MiniMarket 0.3.7 — два обычных пункта магазина + канонические маршруты

**Дата:** 01.11.2026. **Статус:** код опубликован в GitHub `development`; Windows/Joomla 6.2.0 runtime **NOT RUN**. Пользователь сообщил, что 0.3.6 работает, пока опубликован один пункт «Каталог», но при одновременном назначении второго пункта MiniMarket главной появлялась ошибка `MiniMarket canonical URL is not absolute`. Это регрессионный FAIL при **двух** пунктах.

## Исправление и новый открытый контракт

- Разрешены несколько обычных опубликованных пунктов меню Joomla типа `MiniMarket → Магазин`. **Никаких скрытых/служебных пунктов, автосоздания и изменений ядра**.
- Каждый пункт имеет свой адрес и свои обычные Joomla параметры (`show_categories` и т. д.). Пункт «Каталог» и пункт «Главная» могут сосуществовать, один из них не нужно выключать.
- В параметрах каждого пункта меню теперь есть **«Использовать этот пункт для ссылок на товары и категории»** (`shop_primary_route`, по умолчанию Нет). Один выбранный основной пункт задаёт адрес **категорий и товаров** в ссылках из карточек/модулей и `rel=canonical`. **Отмечать «Да» нужно не более чем у одного пункта; остальные «Нет».**
- Если никто не отмечен «Да», приоритет: **пункт MiniMarket, назначенный главной** (если есть) → **обычный опубликованный пункт MiniMarket с минимальным ID**. Это явное документированное правило без неявной зависимости от порядка обхода массива Joomla. Если «Да» ошибочно стоят у нескольких пунктов, выбирается самый маленький ID среди отмеченных; администратору следует оставить один. При явно выбранном пункте он имеет приоритет над главной.
- **Страницы самих пунктов меню** имеют отдельные адреса и canonical на себя: `/` и `/catalog` могут содержать разные блоки и быть разными страницами. Категория/товар всегда имеют один основной URL, даже при переходе из альтернативного пункта.
- Если после назначения главной MiniMarket одновременно опубликован `/catalog`, типизированные пути категории/товара по умолчанию `/category/{alias}-{id}` и `/product/{alias}-{id}`. Если основной пункт — обычный `/shop`, то `/shop/category/{alias}-{id}` / `/shop/product/{alias}-{id}`.
- Старые односегментные пути `/catalog/{alias}-{id}` и альтернативные пути категорий остаются временно распознаваемыми (при опубликованном `/catalog`); `rel=canonical` товаров/категорий указывает на единый выбранный основной путь. **301 редиректов пока нет**. Перед публикацией на индексируемый сайт нужен отдельный redirect smoke.
- В 0.3.7 нет изменений данных, SQL, .htaccess, Joomla core и модели вариантов товара. Joomla 0.3.7 runtime NOT RUN.

1. `/` — главная MiniMarket без ошибки 404/canonical.
2. `/catalog` — отдельный пункт «Каталог», при наведении действительно ссылка `/catalog`, при клике остаётся доступен.
3. Категория `/category/testovaa-kategoria-1` и товар `/product/testovyj-tovar-1` открываются с корректными данными и **единственным абсолютным canonical** именно на эти typed URL. Ссылки из `/catalog` на товар и категорию также должны использовать `/category` / `/product` (главную MiniMarket как первичную).
4. `/catalog` и `/` имеют **каждая свой** absolute canonical, если их содержимое действительно отличается назначенными блоками. Для полностью одинакового содержимого перед запуском публичного сайта рекомендуется оставить один индексируемый адрес/переработать состав блоков.
5. `/catalog/category/testovaa-kategoria-1` и `/catalog/product/testovyj-tovar-1` могут открываться как альтернативные пути, но canonical должен быть на **главный** `/category...` / `/product...`.
6. Настройки `show_categories` Да/Нет различаются для двух пунктов: изменения в одном пункте не должны менять другой.
7. Дополнительно проверить в параметрах пункта «Каталог» **«Использовать этот пункт для ссылок на товары и категории» = Да**; после сохранения новые ссылки товаров/категорий должны получать базу `/catalog/`. Затем вернуть **Нет**, чтобы главная снова была основным путём.
8. Не создавать скрытых пунктов, не менять .htaccess/SQL. Если что-то не работает — сообщить адрес и короткий симптом.

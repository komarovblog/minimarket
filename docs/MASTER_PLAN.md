## Неделимые правила продукта

1. Один самостоятельный `com_minimarket`; товары и категории — его собственные, не Joomla `com_content`. Ядро Joomla, шаблоны сторонних разработчиков, `main`, приватные данные и рабочую БД без согласованной миграции не изменять.
2. Админ-интерфейс строится из настоящих Joomla 6 Atum, Toolbar, SearchTools, PublishedButton, Subform, WebAssetManager и Bootstrap 5; пользовательские цвета/карточки не подменяют нативные элементы.
3. Каждая настройка имеет смысл, хранилище, чтение в рабочем сервисе, наблюдаемый результат, тест, RU/EN и документированное наследование; переключатель без потребителя — **не готов**.
4. Без дублирующих сущностей, сервисов, таблиц, модулей и плагинов. Перед добавлением проверять карту расширений и существующий сервис; расширение создается лишь при доказанной невозможности решить задачу внутри имеющегося компонента.
5. Списки — единые для всех сущностей; карточки — единые нативные вкладки и контролы. Специфичная функциональность только в необходимом месте; светлая/темная темы и RU/EN обязательны.
6. Информационная характеристика имеет одно значение у товара; множественный выбор существует в фильтре. Опции заказа — отдельный механизм и основа SKU-комбинаций; цена товара общая, если нет отдельного принятого решения.
7. Согласованное поведение не менять «попутно». Каждая итерация ведется по `docs/ITERATION_RULES.md`.

**Приёмка внешнего вида:** шапка с поиском и категориями, баннер категории/хлебные крошки, карточки дочерних категорий, фильтр слева или offcanvas на мобильном, сетка, сортировка, красивые карточки с выбором цвета и действиями. Сохраняется работающая фильтрация и актуальные параметры `category_cards_xs..xxl`, цена и наличие на сервере. Выбор фильтра в URL, например `filter_color=beige&query_type_color=or`, — образец поведения Blocksy, а **не** новый URL-контракт MiniMarket: собственный роутер и state менять только по отдельному принятому решению.

Для статей: штатные `com_content` и Joomla template overrides в Blank (`html/com_content/article`, `html/com_content/category`), не дублирующие хранение контента. Для магазина: нативные шаблоны MiniMarket + ограниченные overrides Blank/токены, без вмешательства в серверные запросы/JS, которые рассчитывают состояние. По умолчанию базовые представления MiniMarket должны работать и с Cassiopeia.

**Интеграционный барьер:** проверить Blank + MiniMarket на одном Joomla-сайте отдельно от тестов двух репозиториев, включая Bootstrap grid classes/зависимости, все брейкпоинты XS..XXL, язык RU/EN, светлую/тёмную тему, материалы и магазин в одном меню. См. `komarovblog/blank/docs/integrations/minimarket.md`. Не переписывать MiniMarket под шаблон, не переносить колонки товаров в настройки Blank.

## Режим чистовой пересборки без изменения логики

- В первую очередь исправлять **старые/несогласованные проверки и выпуск**. Действующие услуги заказа/скидок/остатков/фильтрации не переписывать ради оформления.
- Любое изменение PHP бизнес-логики требует отдельного обоснования, списка затронутых функций, тестов до/после и доказанного воспроизведения дефекта.
- При изменении визуального шаблона — не менять DOM-контракты `data-mm-*`, конечные точки, цены, SKU, URL, таблицы и настройки без отдельной задачи.
- Прежде чем создавать финальный архив: CI PASS для одного SHA; релиз на чистой Joomla и обновление с сохранением данных; функциональные браузерные проверки; отдельная приёмка владельцем проекта.
- Текущий статус: «документирован/запланирован» ≠ «реализовано/прошло тесты». Спроектированная авторизация и адаптеры Blank не объявляются готовыми.

## Решение 11.11.2026 — фактическое внедрение 0.5.91

- Раздел «Интеграции» убран из MiniMarket: вместо него «Способы регистрации». Плагины остаются самостоятельными провайдерскими адаптерами, но сам факт установки ещё не подтверждает готовность OAuth/SMS. Сама идентичность — Joomla Users.
- Встроенные доставка и оплата сохраняются в своих редакторах; вкладки-копии удалены из глобальных настроек.
- Редактор YML-фидов: отмеченные категории управляют составом, вложенные не добавляются автоматически; поиск по категориям/товарам и фильтр просмотра товаров независимы от фактического выбора для экспорта.
- Поле Title SEO-фильтра находится во вкладке SEO, последняя — Публикация; в промокодах Публикация тоже последняя. Для остальных сущностей с индексируемым URL правило: «Основная → логичные предметные вкладки → SEO → Публикация». Не добавлять пустой SEO для неиндексируемых справочников.
- Глобальное «Отображение»: категория → товары в категории и grid/list → вид карточки в списке; системные атрибуты — в «Основные». Только реально подключённые настройки включены; сложные per-attribute и per-category visibility требуют самостоятельных БД/серверных тестов.
- Существующий export v1 сохраняет сущность «товар» одной строкой и **не является полным экспортом SKU**. Для следующего `export/import v2`: одна строка на SKU; общие поля товара повторяются, атрибуты в `attr.<code>`, опции в `option.<code>`, системные значения в отдельных колонках, комплекты в отдельной таблице/листе, сохранять ведущие нули SKU и стабильные ключи для повторного импорта. Реализовать только как новый версионированный контракт, не меняя v1 молча.
- Для Sitemap: отдельный XML-режим в разделе «Фиды» или проверенная Joomla sitemap-интеграция; объединить публичные URL MiniMarket с опубликованными, доступными анонимному посетителю `com_content` материалами; учесть Joomla SEF, канонические URL, права, даты публикации, многоязычность, отсутствие дубликатов. Не смешивать с коммерческим YML.
- Принятая главная панель администратора сохраняет четыре полосы и 20 плиток; три типа методов имеют свои иконки. Blank не меняется.
- Отдельные невыполненные требования перечислены в `docs/RELEASE_0_5_91.md`; ничего не считать выполненным до сквозной проверки.

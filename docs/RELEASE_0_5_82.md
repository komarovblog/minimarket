## Безопасность, БД, миграция

- Администратор создаёт заказ с `core.create` ACL и POST Joomla CSRF. Цены, SKU, остатки, доставка вычисляются из каталога и настроек; цена от браузера не принимается. Источник заказа `manual`. Дальнейшая интеграция может использовать `integration`, но внешнего endpoint нет.
- Сохраняются снимки товаров/цены/доставки. **Ручной и гостевой заказ пока остаются неоплаченными заявками, склад не резервируется и не списывается.**
- `admin/sql/updates/mysql/0.5.82.sql` **только добавляет** `order_source` в заказы и `display_location` в характеристики/опции. Исторические записи не меняет. Полная установка имеет те же поля. В MySQL CI проверяется сохранение старых строк.
- Для `0.5.82` обязательна установка ZIP компонента через Joomla, чтобы применить SQL-миграцию. Без миграции новый код может читать несуществующие столбцы.
- Режимы SMS/email/ID, СДЭК, банковские платежи не работают и не имитируются.

## Проверки

CI: PHP 8.4 и 8.5, MySQL 8.0/8.4, сборка Windows ZIP, статический контракт UI `scripts/test-0-5-82-ui.php`, MySQL миграция `scripts/test-0-5-82-schema-mysql84.php`, проверки JavaScript синтаксиса. **CI не подтверждает браузерное поведение в установленной Joomla.** Отдельно проверить вручную меню, все вкладки, сохранение новых полей и ручной заказ на локальной Joomla.

## Получить три файла на рабочем столе

В командной строке CMD, находясь в папке `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development && powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\release-to-desktop.ps1" -SkipPull
```

Команда формирует `com_minimarket-0.5.82.zip`, `mod_minimarket_toolbar-0.5.82.zip`, `minimarket_demo_gallery_filters_0_5_82.sql`; модуль отдельно. **Не импортировать необязательный SQL при обычном обновлении.** До установки рекомендуется резервная копия БД и файлов.

# MiniMarket 0.5.5 — характеристика применяется к категории

**Статус:** source + CI; **реальная Joomla NOT RUN**, пока пользователь не подтвердит. Новая таблица назначений не изменяет товары, цены, SKU, галереи и категории.

## Логика

Вкладка «Характеристики» в редакторе категории содержит все глобальные характеристики из справочника MiniMarket, в обоих языках административного интерфейса Joomla (RU/EN). Для каждой характеристики выбирается **один из трёх режимов**:

- **Наследовать (Inherit)** — у категории нет своего правила; получить настройку родителя. У корневой категории по умолчанию свойства отсутствуют, пока она не включит их.
- **Включить (Enable)** — характеристика явно разрешена в этой категории и наследуется её потомками.
- **Исключить (Exclude)** — явно блокирует характеристику от родителя только в этой ветке. В следующей дочерней категории можно снова включить свойство.

Вкладка показывает, включено ли свойство через текущего родителя, и ID категории-источника. Когда меняется родитель категории, после сохранения нужно **переоткрыть** карточку для обновления подсказки наследования. Система вычисляет действующие свойства из цепочки родителей, не дублирует связи во всех потомках.

Таблица `#__minimarket_category_attributes` хранит только прямые правила (category_id, attribute_id, enabled=1/0). Отсутствие строки = inherit. Изменение/сброс правил не удаляет саму характеристику и её глобальные значения. SQL обновление 0.5.5 добавляет таблицу, не меняет старые данные.

**Ограничение:** это этап **6.2**. Поля характеристик в редакторе **товара ещё не появляются** — это этап 6.3. Публичные динамические фильтры и настоящие комбинации SKU также ещё не готовы. Реальная Joomla UI-проверка обязательна.

## Установка

Перед изменением SQL через Joomla ZIP **создать резервную копию БД**. Никогда не удалять MiniMarket и не запускать вручную SQL-миграции.

CMD из `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-category-attributes.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидаем: `PACKAGE_OK: 0.5.5 (com_minimarket-0.5.5.zip)`. Установить только `dist\com_minimarket-0.5.5.zip` через Joomla → Система → Установка → Расширения поверх существующего компонента.

## Один сценарий в Joomla (создаём только тестовые правила)

1. Проверить, что глобальные «Цвет» и «Размер» уже созданы. Если нет — создать в MiniMarket → Характеристики.
2. Открыть существующую тестовую **родительскую категорию** → вкладка **Характеристики**: «Цвет» — **Включить**, «Размер» — **Включить**. Сохранить.
3. Открыть **дочернюю** категорию: напротив «Цвет»/«Размер» должна показываться подсказка «Включено категорией №...» (ID родителя); оба правила — **Наследовать**.
4. В дочерней категории указать для «Размер» **Исключить**. Сохранить, переоткрыть — «Цвет» наследуется, «Размер» явно исключён.
5. Если есть третья ступень, открыть **внучатую** категорию, явно включить «Размер» — оно опять должно быть разрешено в этой ветке.
6. У дочерней категории изменить «Исключить» обратно на «Наследовать»: правила родителя должны действовать. У несвязанной корневой категории «Цвет» не появляется в эффективных настройках автоматически.
7. Проверить перевод вкладки/режимов в выбранном языке Joomla (английский UI должен быть по-английски).
8. Проверить старый товар TEST-001 и галерею: SKU, цена, остаток, URL, категория, фото и статусы остались прежними.

Не принимать отсутствие вкладки «Характеристики» в товаре за ошибку релиза 0.5.5: этот релиз **только категории**. Если при Save произошла ошибка — короткий текст ошибки/скриншот без дампов БД и секретов.

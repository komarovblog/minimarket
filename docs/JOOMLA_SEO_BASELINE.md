# Joomla 6 — первоначальная настройка SEF и защита от дублей

Дата: 2026-10-30. Проект `komarovblog/minimarket`, ветка `development`.
Локальная Joomla (установлена и работает по подтверждению пользователя):
`C:\OSPanel\home\minimarket.local\public_html` / `http://minimarket.local/`.
Apache 2.4.66, PHP 8.5.4, MySQL 8.0.45 в OSP 6.5.1.
**Это инструкция, а не отчёт о фактически применённых настройках.** Из GitHub нельзя менять настройки установленной Joomla: пользователь делает изменения в админке/Проводнике, затем подтверждает результат.

## A. Базовый SEF — сделать до создания товаров

1. Проверить в корне `public_html`, существует ли `.htaccess`. Если уже существует — **не заменять/не перезаписывать**; проверить, что там правила Joomla и поддержка Rewrite. Если файла нет, переименовать **штатный оригинальный** `public_html\htaccess.txt` в `public_html\.htaccess`. Важно: только в MiniMarket, не в `C:\OSPanel\home\phpmyadmin`/Shop/Bidder, не править ядро.
2. Joomla admin → **System → Global Configuration → Site → SEO Settings**:
   - Search Engine Friendly URLs: **Yes**.
   - Use URL Rewriting: **Yes** (после создания .htaccess и при Apache с AllowOverride/mod_rewrite).
   - Add Suffix to URL: **No** (не добавлять `.html`).
   - Unicode Aliases: **No** (транслитерация в латиницу, единая политика; aliases проверять вручную).
   - Site Name in Page Titles: по необходимости, не связано с SEF-дублями.
   - `Force HTTPS`: **не включать ради SEF в локальной среде**, пока нет настроенного доверенного локального сертификата.
3. Сохранить и проверить `http://minimarket.local/`, `http://minimarket.local/administrator/`. Админка и ссылки должны открываться без `index.php` в SEF-адресе. При 404/500 не менять конфиги вслепую — проверить `.htaccess`, mod_rewrite/AllowOverride, журналы Apache; при необходимости вернуть URL Rewriting = No до устранения проблемы.
4. Не создавать тестовые товары/категории ради одного SEO-переключателя, не редактировать файлы Joomla core, не добавлять Joomla в GitHub.

Документация: https://guide.joomla.org/user-guide/seo/seo-search-engine-friendly-urls ; https://guide.joomla.org/user-guide/seo/seo-sef-urls-on-apache ; https://guide.joomla.org/help-pages-references/site/site-global-configuration .

## B. Зафиксировать маршруты материалов (после базового SEF)

- **Content → Articles → Options → Integration → Routing → Remove IDs from URLs = Yes**, потому что пользователь выбрал **штатные Joomla URL** для Articles. Не путать с Variant B, где собственные плоские адреса `/{alias}-{id}`.
- Выбирать один основной пункт меню для каталожного корня и каждой индексируемой категории, не создавать одновременно несколько индексируемых Itemid/пунктов меню, ведущих на один и тот же список/товар. Сайт Joomla может дать разные пути к одному article при разных меню. Планировать menu/category aliases до добавления контента.
- Если нужно несколько пунктов меню на ту же страницу, используйте **menu alias к основному** или явное постоянное перенаправление, а не две независимые индексируемые страницы.
- Перемещение категории/смена alias после публикации — 301 со старого URL на канонический; контроль 404. Не обещать, что Joomla сама исправит все старые URL.

Документация: https://guide.joomla.org/help-pages-references/articles/articles-options ; https://manual.joomla.org/docs/next/general-concepts/routing/build/ .

## C. Строгая маршрутизация и canonical — после smoke-теста реального материала

- `System → Plugins → System - SEF`: проверить существование/включение; установить политику URL без завершающего `/` (если опция доступна), кроме корня `/`. Для Joomla 6 часть строгих поведений уже может быть стандартной — не считать конкретные переключатели обязательными, ориентироваться на фактическую админку версии.
- **Strict Routing / Disallow non-SEF URLs**, если настройка присутствует, включать **только после** проверки реальных страниц материалов, товарной категории, меню, прямого не-SEF URL, 301/404, поиска, pagination, фильтров, авторизации и будущего checkout. Эта опция может ломать рабочие маршруты — нельзя включать без теста.
- `Site Domain` / canonical domain в плагине SEF **не указывать `minimarket.local` как будущий публичный домен**. На локальном сайте поле оставить пустым, публичный HTTP/HTTPS и www выбрать на этапе деплоя. Не переносить localhost-canonical на production.
- Canonical един для каждой карточки товара и индексируемой категории/SEO-лендинга. Нельзя полагаться только на SEF-псевдонимы. При альтернативных параметрах фильтра `robots noindex` + корректная canonical-политика; индексируются **только ручные SEO-лендинги** с собственным набором параметров и нормальным URL. Запрещать создание дублирующих параметрических SEF-лендингов. Формулировку `canonical` на пагинации уточнять под фактический контент; не вести все page N на page 1 автоматически.
- `index.php`-дубли, завершающий слеш, URL с другим Itemid/параметрами: проверить HTTP-редиректы, а не только наличие rel=canonical в HTML.
- Не мешать `Articles` и `Catalog`: A — встроенный com_content router, B — свой плоский роутер с ID.

Документация: https://guide.joomla.org/user-guide/seo/seo-seo-basics ; https://docs.joomla.org/Search_Engine_Friendly_URLs ; https://guide.joomla.org/help-pages-references/articles/articles-options .

## D. Минимальная проверка (после A и после создания одного тестового материала)

- Открыть главную, административную панель и меню категорий, убедиться в HTTP 200 без 500/404.
- Когда будет тестовый товар: открыть его из категории и через меню; сравнить конечный URL, canonical, Schema.org Product и отсутствие дублирующего Article; проверить прямой URL с `index.php`, слешом в конце и технический не-SEF URL: ожидаем выбранную единую каноническую схему, но не предполагать редирект там, где Joomla его пока не делает.
- Когда будет SEO-фильтр: проверить, что обычные GET-комбинации не превращаются в индексируемые дубли; ручные SEO-лендинги живут по уникальным маршрутам и отключение ведёт к 301 на категорию.
- Вариант A: Schema.org Product/Offer на материалах только выбранных товарных категорий; обычные Joomla articles = Article. Вариант B: плоские ID-маршруты; тот же Core/dataLayer.
- На локальной среде не обязательно настраивать публичную индексацию; перед PROD отдельно проверить `robots`, sitemap, HTTPS, canonical, 301 и доступность магазина.

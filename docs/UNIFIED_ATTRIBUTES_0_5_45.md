# MiniMarket 0.5.45 — универсальные характеристики: кандидат для приёмки

Дата: 04.11.2026. Исходная архитектура: [ATTRIBUTE_UNIFIED_MODEL_0_5_44.md](ATTRIBUTE_UNIFIED_MODEL_0_5_44.md).

## Что реализовано
- Независимые `input_type`, `value_source=manual|preset`, `is_multiple=0|1` для всех новых характеристик, кроме булева Да/Нет. **Число также может иметь несколько значений.** Например, 5, 10, 15 Вт.
- `legacy` сохраняет текущие старые механизмы ввода без автоматического переосмысления сохранённых значений.
- Один справочник с ID, названием, кодом, статусом, фото, HEX, типизированным содержимым. Для чисел содержимое — десятичное число; для HTML — очищаемая разметка; для файлов — проверенный путь Joomla Media. У цвета — кружок или кружок и текст.
- Готовые значения в товаре: одиночный выпадающий список или множественные флажки. Сохраняются стабильные ID, включая числовые значения.
- Ручные значения: одиночные поля по типу (включая HEX picker); для нескольких — кнопка «Добавить значение» и отдельные поля. На сервере проверяются кратность, уникальность, тип, диапазон и числовой шаг. Для HTML/документа множественный ручной ввод пока используется простое повторяемое поле (не отдельный WYSIWYG/Media picker для каждой строки) — это предмет браузерной доработки.
- Отдельная таблица `#__minimarket_product_attribute_free_values` позволяет сохранять несколько числовых значений и длинных текстов с порядком; старые таблицы `scalars`, `options`, `multi_values` не меняются.
- Публичная карточка выводит современные значения из справочника и ручные множественные значения; фильтры каталога как отдельная часть проекта ещё не реализованы.
- PHP/MySQL/ZIP CI и отдельная ручная браузерная приёмка Joomla 6.2.0.

## Миграция и сохранность
Миграция `admin/sql/updates/mysql/0.5.45.sql` **только добавляет** два поля в attributes, payload в attribute_values и новую таблицу ручных множественных значений. Existing products, ID, SKU, старые значения и связи не переписываются. Старые записи получают `value_source=legacy`. Переключение источника используемой характеристики заблокировано, если требуется перенос выбранных значений (исключение: безопасная операция legacy List/Color → preset при неизменных ID). Никакого автоматического стирания данных.

## Ручная проверка после CI
1. Резервная копия базы `minimarket`; обновить Joomla через `com_minimarket-0.5.45.zip`, не импортируя demo SQL.
2. Новая характеристика `Число`, `Ручной ввод`, `Несколько`, min=0, max=15, step=5; назначить категории. В товаре добавить 5, 10 и 15. Сохранить, открыть заново, проверить порядок и витрину. 3 и 20 должны отклоняться.
3. Характеристика `Число`, `Готовые значения`, `Несколько`; добавить 5 и 10 и отметить оба в товаре. Перезапустить редактор — ID/выбор сохраняются.
4. Повторить `Текст`, `Цвет`, `HTML`, `Файл`, одиночное и множественное заполнение. В цвете проверить HEX, превью и режим кружка.
5. Проверить старые `Возраст`, `Материал`, `Цвет` и существующие товары: их данные и URL/SKU/галереи не изменились. При попытке сменить источник занятой характеристики должна появиться ошибка, а не потеря данных.
6. Проверить типы редакторов на реальном Joomla 6.2.0, безопасность HTML/файлов и публикацию справочника. Отдельно пройти пункты 1–8 версии 0.5.44.

Сборка: `git pull --ff-only origin development`, затем `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1`, затем `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1`.

Артефакты в `dist` — **ровно два**: `com_minimarket-0.5.45.zip` и `minimarket_toys_rich_import.sql` (демоданные *не запускать* при обновлении). Ветка `development`; `main` и ядро Joomla не менять.

# MiniMarket 0.5.56 — глобальный тип магазина и расширенный импорт

Дата: **06.11.2026**. Ветка: **development**. Обновление поверх 0.5.55 без сброса данных.

## Тип магазина

- В настройках компонента (`Система → Компоненты → MiniMarket → Настройки`) добавлен **Тип магазина**: Физический / Цифровой, по умолчанию Физический.
- Удалён селектор формата из карточки товара. Комплект наследует общий тип точно так же.
- При сохранении товара `ProductTable` задаёт старому столбцу `delivery_type` значение глобальной настройки, не доверяя значению POST или сохранённому значению конкретного товара. Столбец оставлен без деструктивной миграции.
- Тип формата заказа будет читаться из этой настройки при создании корзины/оформлении заказов (эти разделы пока не реализованы). При переключении формата предполагается, что **весь ассортимент относится к выбранному типу**. Выдача цифровых файлов и управление доступом — позже.
- Технический `product_type=simple|bundle` остаётся отдельным признаком товара/комплекта. Никаких смешанных комплектов по формату больше нет — формат один для магазина.

## Импорт и экспорт

- В «Импорт / Экспорт» появился третий заполненный шаблон: **Полный демонстрационный каталог (с комплектами)**. Доступен прямо из админки в JSON/CSV/XLSX.
- Исходный JSON: [examples/import-rich-catalog-v1.json](../examples/import-rich-catalog-v1.json); его идентичная версия находится внутри установочного ZIP.
- Включает **11 категорий, 18 товаров, 5 комплектов**, в том числе вложенный комплект; 6 характеристик, 3 опции, назначения категориям, 3 группы связанных товаров. Включены примеры старой цены/флага «Скидка», фиксированной цены и процентной «Выгоды».
- Импорт принимает новый раздел `bundles` с идентификатором `key`, ценой, стратегией `price_mode=fixed|discount`, `discount_pct`, опциональной `old_price`, флагами `badge_sale`/`badge_benefit`, `items:[{product,quantity}]`. Состав разрешает обычный товар и вложенный комплект по ключу источника.
- Вся загрузка проходит через старый предпросмотр/подтверждение и транзакцию. `BundleItems::validate` проверяет отсутствие циклов, недопустимых SKU-компонентов, количества и чужих ссылок. При ошибке данные откатываются. Повторный импорт по одинаковому `source`/ключам обновляет те же записи, состав комплекта **заменяется содержимым поля `items`**.
- Экспорт показывает обычные комплекты и их состав, однако **отклоняет** комплект, указывающий на конкретный вариант SKU, вместо скрытой потери данных. Это всё ещё **не полный backup**.
- Обмен пока не переносит бренды, коллекции, значения характеристик каждого товара, SEO, медиа, видео и матрицы SKU. Для них нужен формат **v2** с round-trip.

## Проверка

1. Обновить ZIP 0.5.56 поверх 0.5.55. **Не** запускать демонстрационный SQL при обновлении.
2. Настройки: без сохранения по умолчанию «Физический»; выбрать «Цифровой», сохранить, снова открыть; вернуться к «Физический».
3. Товары / Комплекты: поля «Формат товара» больше нет; SKU, цены, комплектующие и флаги остались.
4. Импорт / Экспорт: выбрать новый расширенный шаблон JSON, проверить предпросмотр и применить **только к тестовому каталогу**; повторить для проверки отсутствия дублей. Для XLSX/CSV проверить круглую передачу комплектующих.
5. В комплекте с процентом проверить «Выгода», с фиксированной ценой — «Скидка».
6. Проверить, что ссылка на несуществующий компонент/циклический состав прерывает применение и данные не сохраняются.
7. Отдельно выполнить smoke Joomla 6.2; успешные PHP-тесты/CI не равнозначны тесту формы в браузере.

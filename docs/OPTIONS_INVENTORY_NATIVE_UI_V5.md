# MiniMarket V5 — общие опции, склад и единый интерфейс

**03.11.2026, после скриншотов Joomla 6.2.0.** Этот документ закрепляет принятый UX и порядок реализации. В 0.5.31 выполнены только первые точечные исправления; общие опции, складские политики и новый редактор SKU пока DESIGN_ONLY. Ни один описанный будущий этап не считается работающим без кода, миграций, CI и отдельной проверки в установленной Joomla.

## Что исправлено в 0.5.31

- Из выпадающего списка «Заполнение в товаре» физически удаляются неподходящие текущему типу пункты: для Текста не показывать ввод Числа; для Числа не показывать способы текстового ввода. Общий режим presets называется нейтрально «Выбор из заданных значений» и одинаково подходит числам и тексту. Раньше использовались hidden/disabled для option, отображение которых зависит от браузера. Серверный контракт AttributeSettings остался прежним.
- Таблицы «Характеристика → Категории» и «Категория → Характеристики» используют одинаковый Joomla table-striped и компактный select. Удалены искусственные отступы в ячейке обратной привязки; вложенность показывается префиксом «—» в названии. Лишнее «Нет» под строкой без наследования убрано.
- RU/EN подсказки для группы уточняют: одна группа исполнений на товар; новая группа привязывается к редактируемому товару, остальные товары добавляются вручную выбором той же группы. На витрине опубликованные участники автоматически перелинкованы. Изменения БД отсутствуют.

## Архитектура: информационные характеристики и опции заказа отдельно

**Характеристики** описывают товар: материал, мощность, характеристики, HTML, число, Да/Нет. Их таблица и назначения категориям уже существуют; они не формируют SKU.

**Опции** определяют продаваемое сочетание: размер, цвет, исполнение, комплектация и т.п. Новое меню «MiniMarket → Опции» должно содержать отдельные общие справочники, нативный список Joomla (checkbox, PublishedButton, title, SearchTools, сортировка), стандартную карточку и значения через Subform. В категории выбираются разрешённые опции с наследованием от предка. В товаре выбираются только нужные значения разрешённых опций. Привязка к категории НЕ создаёт все сочетания сама: матрица строится после выбора значений в товаре, а ненужные сочетания могут отсутствовать. Одна существующая комбинация = уникальный SKU / variant_id, без смены основного URL товара.

Проектируемые таблицы: `#__minimarket_options`, `#__minimarket_option_values`, `#__minimarket_category_options`. Связи локальных `variant_dimensions` и `variant_dimension_values` с глобальными записями добавляются *nullable* и в одной основной SKU-модели. Не создавать второй движок SKU и не дублировать SKU/stock. Не определять соответствие глобальных значений по названиям без явного выбора/ID. Изменение/удаление используемых значений должно быть безопасным. Миграции поднимают новые таблицы без изменения существующих SKU ID, артикулов, комбинаций, URL, цен, фото или остатков. Сохранять сами product-local options до явной безопасной привязки.

Порядок редактора: **Опции (справочник) → Категории (назначение) → Товар (выбор значений) → SKU (матрица)**. Глобальная опция имеет стабильный ID, уникальный код, название, порядок, статус. Значение имеет собственный ID, code, title, и при необходимости HEX/фото. Множественный выбор значений в товаре определяет допустимый набор; в заказе выбирается одна реальная комбинация. Опции со статусом «не опубликовано» не должны порождать новые продаваемые SKU, но редактирование существующих данных не уничтожает их.

## Учёт остатков

1. **Options магазина:** `inventory_enabled` Да/Нет, по умолчанию Да для сохранения текущего поведения. При Нет — весь магазин не проверяет остатки ни товара, ни SKU, но данные не обнуляются. В этом состоянии настройки остатков у категорий неактивны. Продавать можно только существующие опубликованные SKU/комбинации, даже если склад отключён.
2. **Категория:** `inventory_policy`: -1 наследовать / 0 не учитывать / 1 учитывать. Наследовать ближайшее явное правило предка; глобальный OFF всегда сильнее ON категории. При глобальном OFF поле визуально disabled, однако сохранённое правило категории не теряется. Не полагаться только на скрытие HTML: сервер должен принудительно игнорировать складские проверки.
3. **Товар:** при эффективном ON — существующее `option_stock_mode` (раздельный остаток каждого SKU по умолчанию, либо общий остаток товара). При OFF поля количеств не вводятся, отображение наличия не зависит от чисел, но предыдущие stock и mode остаются в БД. В будущем корзина/оформление повторно проверяет правила на сервере. Для фидов выключенный учёт не означает «остаток ноль».
4. Категорийное/глобальное изменение не переписывает сохранённые SKU, product_id, variant_id, URL, цены, остатки. Потребуются SQL upgrade и fresh-install, backup MySQL, тесты 0↔1, наследования и отсутствия потерь.

## Нативный компактный SKU-редактор

Текущий `admin/forms/product_variant.xml` встраивает фото, вложенные галереи, видео и описания в каждую строку `repeatable-table`, что приводит к горизонтальному скроллу и путанице. Целевая форма: одна компактная таблица **чекбокс | комбинация | SKU | цена | остаток при включённом складе | статус | редактировать**; фото, описания, видеоролики в отдельной карточке/панели деталей конкретного SKU с сохранением по тому же variant_id. Не делать вторую независимую JSON-модель, не терять сложные поля или ручное добавление позиции. Редактор значений опциона тоже компактный: название/HEX/превью, отдельная галерея в подробностях значения. Все списки и таблицы имеют одинаковые отступы, нативные компоненты Joomla, RU/EN, тёмную/светлую тему. На десктопе без горизонтальной прокрутки; на мобильном нужен адаптивный режим и доступность с клавиатуры.

## Группы исполнений и другие связи

Текущая `product_group_members` гарантирует **одну** группу исполнений на самостоятельный товар. Создание группы в карточке добавляет в неё текущий товар, а не автоматически все сходные товары. В других карточках выбирают существующую группу; опубликованные товары связаны на сайте. Разные URL/галереи/SEO каждого участника сохраняются. «С этим покупают», подборки, коллекции и комплекты будут другими M:N-связями; не смешивать их с группой исполнений. Если в будущем понадобится несколько групп одного типа на товар, отдельно проектировать UI и SEO перед сменой ограничения.

## Ручная приёмка 0.5.31

1. MiniMarket → Характеристики → создать Текст → открыть «Заполнение в товаре»: вариантов числового ввода нет. Сменить тип на Число: появляются варианты ввода числа, а текстовые presets исчезают. Сохранить и открыть снова.
2. Вкладка Категории характеристики: одна компактная таблица, ровные колонки, у вложенной категории префикс «—», нет ложного «Нет» под корнем; проверить выбор «Наследовать / использовать / обязательная / не использовать». Аналогично во вкладке Характеристики категории.
3. Карточка товара → Связанные товары: подсказки однозначно объясняют, что группа новая привязана текущему товару и остальные нужно привязывать по одному.
4. Сохранить старый товар без изменения SKU/остатков, проверить RU/EN, тёмную тему и Joomla 6.2.0. Это не приёмка V5-A—D.

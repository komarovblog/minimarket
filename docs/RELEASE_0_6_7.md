# MiniMarket 0.6.7 — карточки заказов, возвраты, повторные доставки, журнал

Работа в `development`, Joomla 6 / Atum. **Изменения схемы БД** — аддитивная миграция `admin/sql/updates/mysql/0.6.7.sql` через установку обновления компонента Joomla. Предварительно сохранить резервную копию базы! Не импортировать демонстрационный SQL для обновления.

## Категории и глобальная видимость

В редакторе категории вкладки **Характеристики / Опции** содержат только принадлежность к категории, обязательность и публикацию. Столбец «Показывать в карточке товара в списке» и управление им удалены из формы. Отображение в категории / карточке товара / обоих местах задаётся **глобально** в сущности Характеристика или Опция через `display_location`. Старые столбцы `show_in_list` сохранены в БД для обратной совместимости, но публичные листинги их больше не применяют. Категорийная иерархия/наследование участия по-прежнему работают.

## Модель заказа и логистика

- `#__minimarket_shipments`: вместо уникального `order_id` — обычный индекс; существующие доставки сохраняются, можно создать **несколько доставок на один заказ**. Каждая имеет `reason`: `initial`, `redelivery`, `replacement`, `other`. Контроллер не позволяет создавать более одной первичной доставки, но допускает повторные. Все изменения пишутся в журнал заказа.
- `#__minimarket_returns`: отдельный возврат с `order_id`, необязательным `shipment_id`, причиной (`defective`, `damaged`, `wrong_item`, `not_fit`, `other`), состоянием (`new`, `approved`, `received`, `rejected`, `closed`), решением (`pending`, `replacement`, `refund`, `no_action`), комментарием и автором/датами.
- `#__minimarket_return_items`: связь с сохранённым снимком позиции `order_item_id` и количеством. Контроллер проверяет принадлежность позиции к заказу и ограничение количества. Исходные цены/товары заказа не изменяются. Возврат можно создать без позиций и добавить их вручную, после сохранения.
- `#__minimarket_orders`: необязательные `payment_reference` и `payment_url` (только HTTPS), сохраняются вручную без изменения `payment_status`, не подменяют реальную интеграцию ЮKassa.
- Журнал `#__minimarket_order_events`: создание заказа, статусы заказа, ручной платёж, исполнение, выдача цифровых товаров, создание и изменение доставок, возвратов, операции корзины заказа. Для новых операций — атомарная запись с транзакцией, оператор и временная метка. Старые события не придумываются задним числом. Последние 500 событий отображаются в карточке (история в БД не обрезается).

## Интерфейс

- **Заказ:** сверху единые навигационные действия; сверху слева блоки «Статус заказа», «Оплата» и «Доставка», справа информация о заказе; ниже связанная таблица товаров (с переходом в товар), цифровое исполнение (если есть), возвраты и история. Доставка отображает **все** связанные записи, их основания и статус.
- **Доставка:** двусторонний переход в заказ; редактируемое основание; связанные возвраты, если появились. При создании из заказа показываются его данные, разрешено создать дополнительную доставку.
- **Возвраты:** меню непосредственно после доставок и перед отзывами, нативный плюс создания; новая карточка, список с чекбоксами, поиском, фильтром статуса/причины и массовыми действиями «Согласовать», «Принять», «Отклонить» с проверками ACL, POST/CSRF и переходов статусов. Решение `refund` **не** вызывает платёжный шлюз и само не переводит заказ в «оплачен/возвращён».
- **Отзывы:** появилась карточка существующего отзыва, отдельная ссылка из списка, настройка статуса (по ACL), нативные кнопки Save/Cancel над формой; массовая модерация сохранена.
- **Списки Заказы / Доставки / Возвраты / Отзывы:** существующие Joomla-compatible SearchTools, общая таблица `grid.checkall`+`grid.id`, toolbar над списком и компактный выбор видимости столбцов, локально сохраняемый в браузере. Никаких собственных цветов вне Atum.

## Контроль качества и установка

Статическая проверка `scripts/test-0-6-7-return-workflow.php` и отдельная безопасная проверка **реальной SQL-миграции** `scripts/test-0-6-7-migration-mysql84.php` на disposable MySQL 8.4; обе добавлены в GitHub Actions. Ожидаются также PHP 8.4/8.5, Windows ZIP и прежние регрессии.

Стандартная команда **одного** обновления компонента (скрипт самостоятельно выполняет git pull):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

На рабочем столе: `com_minimarket-0.6.7.zip` и отдельный необязательный демо SQL. ZIP ставится через «Система → Установка → Расширения Joomla», после установки Joomla применяет `0.6.7.sql`. **Demo SQL импортировать не нужно.** Не затрагиваются Joomla Core, шаблон Blank и модуль `mod_minimarket_toolbar` версии 1.0.0.

### Ручная браузерная приёмка

Проверить обе темы Joomla, RU/EN, desktop/mobile (не делать выводов о пиксельном дизайне только по CI). Проверить настройку глобальной видимости в характеристике, категорийное наследование, изменение всех статусов, создание заказа/доставки/повторной доставки/возврата и связей, журнал дат/автора, связывание не более купленного количества, оплату с HTTPS ссылкой, продуктовые ссылки, массовые операции и управление столбцами. Особенно проверить, что без действий в платёжном шлюзе не производится возврат средств.

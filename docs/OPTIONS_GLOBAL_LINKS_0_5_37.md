# MiniMarket 0.5.37 — глобальные ID опций в товарах, автоподстановка категории

Дата: 04.11.2026. Продолжение V7 / A1 после 0.5.36.

## Что сделано

**Прямая связь источников данных.** Для существующих таблиц локальных осей SKU добавлены nullable FK:
- `#__minimarket_variant_dimensions.source_option_id` → `#__minimarket_order_options.id`;
- `#__minimarket_variant_dimension_values.source_value_id` → `#__minimarket_order_option_values.id`.

Поле `code` локальной оси и `selection_json` SKU остаются прежними, потому что их изменение разрушило бы идентификаторы сохранённых сочетаний. Глобальная опция и её значение являются источником **названия**, ссылка указывается стабильным числовым ID. При переименовании в справочнике карточка товара покажет актуальный заголовок, не меняя SKU/сигнатуры. Физические изображения товара, SKU, остатки и описание не мигрируются и не удаляются. Обе новые связи допускают NULL для исторических локальных опций.

**Редактор товара.** На вкладке SKU при выборе категории отображаются глобальные опции (включая унаследованные) и их опубликованные значения; отдельной кнопки «Использовать опции категории» больше нет. Если товар ещё **не имеет локальных осей и сохранённых SKU**, Joomla автоматически создаёт редактируемые штатные подформы для опций и значений с **скрытыми глобальными source IDs**, затем показывает предпросмотр возможных сочетаний. При повторном сохранении IDs идут через `VariantMatrix::normalize`, серверную проверку категории и единую транзакцию `ProductLocalDimensions::replace`.

Когда у товара уже есть локальные опции или SKU, система **не перезаписывает** их при открытии или смене категории. Существующие локальные значения не привязываются автоматически по похожему названию/коду, чтобы не получить ложную связь. Для связанных глобальных опций значения title в редакторе доступны только для чтения — менять название следует в справочнике. Состав значений/комбинаций по-прежнему регулируется формой товара; база хранит source ID.

**Валидация.** Новые связи допустимы только для назначенных текущей категории опубликованных опций/значений, с учётом наследования. Нельзя подставить произвольный ID, смешать ID опции с значениями другой опции или заменить известный source ID уже сохранённой оси. Ранее привязанные значения можно сохранить даже если администратор потом отключил их в категории — история SKU не удаляется. FK MySQL запрещают удалять значения справочника, уже используемые в связанной товарной оси.

**MySQL.** 0.5.37.sql: только два ADD COLUMN + индексы + внешние ключи. Не выполняются UPDATE/DELETE/трансформации старых ID. Изменения добавлены в fresh-install SQL. Для обновления Joomla применит 0.5.37 при установке ZIP; руками через phpMyAdmin миграцию запускать не нужно.

## Почему это ещё не весь A2

- Товар использует **тот же прежний редактор физических SKU**. Комбинации сначала отмечаются в предпросмотре, затем становятся редактируемыми строками SKU; полноценная единая таблица активации строк с ценой/остатком будет следующим этапом.
- Артикул физического SKU пока обязателен: нельзя удалять его в форме, не изменив схему уникальности и проверку сервера.
- Глобальная опция может быть необязательной для категории, и пользователь вправе удалить её подформу до создания сочетаний. При этом обязанность предоставить требуемые значения на сервере для **каждого продукта** ещё не реализована.
- Обновления словаря синхронизируют названия, но изменения набора допустимых значений **не удаляют** сохранённые вариации. Добавленные позднее варианты для существующего товара нужно подключать отдельно. Автоматическая подстановка новых значений должна происходить без затрагивания старых SKU в следующем шаге.
- До проверки на реальной Joomla 6 это **исходный код и CI**, не подтверждённый browser smoke.

## Приёмка на локальной базе

1. Сделать backup БД `minimarket`. Обновить компонент через Joomla. Проверить, что сайт и карточки старых товаров работают, их SKU, фото и остатки совпадают.
2. В справочнике «Опции → Размер» указать значения S/M/L, в «Категории» назначить его категории игрушек.
3. Открыть **новый товар**, выбрать назначенную категорию. Опции появятся **автоматически**, без нажатия «Использовать». Указать название/основной SKU/цену, выбрать реальные сочетания из предпросмотра, сохранить.
4. Повторно открыть товар: опция и значения сохранили source ID, прежние коды SKU и `variant_id` не менялись.
5. Переименовать «Размер» → «Размер изделия», S → «Маленький». В редакторе товара отражается новый заголовок, SKU и подпись URL товара не меняются.
6. Проверить, что изменение категории старого товара с локальными вариантами **не стирает** матрицу. Проверить обязательные и необязательные опции, вложенность категорий, RU/EN и тёмную тему.
7. Проверить GitHub Actions (PHP 8.4/8.5, Windows ZIP, MySQL 8 upgrade). Отдельно пройти browser smoke, потому что PHP/MySQL unit tests не проверяют реальную инициализацию вложенных Joomla Subform.

## Принципы далее

Сохранять `development`; `main` и ядро Joomla не менять. Не создавать «старые SKU» и вторые идентификаторы; снимки базы и demo SQL/ZIP — отдельные тестовые данные, а не автоматическое содержимое при upgrade. При каждом создании нового раздела предусматривать импорт и пример данных. Следующая итерация A2 — **одна компактная матрица с активацией SKU, ценой и остатком прямо в строках**, с сохранением связанных изображений и ID, а затем необязательный артикул и складские правила.

# MiniMarket 0.5.13 — числовые варианты и нативные списки Joomla

**02.11.2026.** Принцип пользователя: «Число» должно допускать варианты заполнения в товаре через **повторяемое поле +/−/перетаскивание**, а админка MiniMarket должна максимально использовать **реальные элементы ядра Joomla 6**, как в Articles / Categories. Код проверяется PHP 8.4/8.5, MySQL 8, Windows ZIP; браузерный сценарий настоящей Joomla **не запускался** из GitHub Actions. [Документация Joomla о Subform](https://manual.joomla.org/docs/next/general-concepts/forms-fields/standard-fields/subform/), [о Search Tools](https://manual.joomla.org/docs/next/building-extensions/components/component-development-tutorial/step12-filter-form/).

## Числовая характеристика (не словарь List)

Для атрибута с **Type=Number**, **Product input=Choose preset number / Выбор заданного числа** под полем настройки появляется **нативная Joomla Subform** «Допустимые числа»: один ввод числа в каждой строке, Joomla Add/Remove/Move. Пример: 1000 / 1500 / 2000, перенос влияет на порядок dropdown. При сохранении значения проходят серверную валидацию, хранятся в старой колонке `number_options` CSV (`1000,1500,2000`) без новых таблиц и ID словаря. В товаре по-прежнему сохраняется **число** в `value_number`, не ID списка.

Старое заполненное CSV автоматически преобразуется в строки при повторном открытии формы и обратно при сохранении. Поскольку форма после обновления будет иметь только одно видимое поле вариантов, нельзя случайно редактировать дублирующиеся «CSV и строки». Номер компонента 0.5.13; **миграция БД не нужна** поверх 0.5.12.

Если выбран «Ввод числа», варианты остаются сохранёнными метаданными на случай обратного переключения режима, но не ограничивают ручной ввод. Если выбрать режим «из заданных чисел» при уже сохранённых у товаров других значениях, проверка 0.5.12 запретит сохранить эту настройку, пока товары не приведены к допустимым значениям. **Не удалять и не обнулять существующие числовые значения автоматически.**

## Списки Joomla

- **Товары:** `filter_products.xml` и настоящий `joomla.searchtools.default`, поиск по title/SKU/ID, фильтры категории и публикации, сортировка по ID/названию/цене/порядку, лимит 20/50/100 и нативные постраничные списки. Статус публикации выводится через Joomla `PublishedButton`; обычные bulk-checkboxes/toolbar сохранены.
- **Характеристики:** `filter_attributes.xml`, поиск по названию/коду/ID, фильтр публикации, сортировка заголовком и выбор количества строк, Joomla `PublishedButton` и массовые действия.
- **Категории:** `filter_categories.xml`, Joomla SearchTools для поиска и статуса, нативный `PublishedButton`. При этом дерево MiniMarket остаётся иерархическим, сохраняются сворачивание, вложенность, изображения, прямой и суммарный счётчики товаров. **Не разрезать ветку по страницам и не сортировать все категории глобально**: корни и дети должны оставаться рядом. Пагинацию дерева реализовать позже отдельно, после продуманной модели дерева.

Никаких кастомных цветных панелей/шрифтов поверх Joomla не добавлено. Joomla тему и версию 6.2 берём как источник интерфейса; карточки и фильтры должны наследовать её стиль. Стандартный Joomla dropdown Actions, 9/9 Columns, drag handles и другие подкомпоненты, где их нет, **не объявлять полностью совпадающими** до browser smoke; текущий выпуск — SearchTools, статус, сортировка для плоских списков, нативная подформа чисел.

## Установка и browser smoke

**До установки backup БД Joomla.** Ветка `development`, не трогать main, не удалять компонент, не менять ядро Joomla, не перезаписывать `.osp/project.ini`.

CMD:

```bat
cd /d C:\OSPanel\home\minimarket.local
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-numeric-preset-rows.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Expected `PACKAGE_OK: 0.5.13 (com_minimarket-0.5.13.zip)`. Joomla System → Install → Extensions, install `dist\com_minimarket-0.5.13.zip` OVER installed component.

1. MiniMarket → Attributes → открыть **Мощность**, Type=Number, Product input=**Выбор заданного числа**. Должны появиться строки с кнопкой «+», полем числа и перестановкой. Добавить 1000, 1500, 2000, изменить порядок, сохранить и открыть повторно. Должны сохраниться ровно эти числа и порядок.
2. В товаре тестовой категории проверить dropdown с соответствующими значениями; выбрать 1500, сохранить и переоткрыть. Должно остаться 1500 (value_number).
3. В Attributes → уже сохранённый Цвет List должен продолжать показывать прежние значения (без дублирования и потери ID). Товар TEST-001 — неизменные SKU, цена 1990.50, остаток 3, изображение/URL/состояние публикации.
4. MiniMarket → Products: проверить нативный поиск, Category, Published, сортировку Title/ID/Price, число строк. Отметить тестовый товар чекбоксом и убедиться, что старая панель массовых действий осталась; не нажимать Delete на реальных данных.
5. MiniMarket → Categories: убедиться, что «Тестовая категория» и «Вложенная» отображаются с правильным уровнем, работают раскрытие и счётчики товаров. Проверить SearchTools Search/Status. Сравнить визуально со скриншотами Articles: Categories. Переключение статуса проверить только на тестовой категории.
6. MiniMarket → Attributes: поиск/сортировка/публикация/постраничность, стиль по умолчанию Joomla. При отсутствии результатов корректная пустая таблица, без 404.
7. Отправить **скриншот** обновлённого списка и блока числовых значений, если что-то отличается. Живую Joomla пока проверить может только пользователь.

**Известные ограничения:** приложение ещё не имеет публичного фасетного фильтра, реальных SKU-вариантов и расширенных функций колонок JTable. 0.5.13 не добавляет новый способ каталожной фильтрации.

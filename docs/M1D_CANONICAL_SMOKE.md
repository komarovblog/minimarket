# MiniMarket 0.3.1 — canonical и защита от SEO-дублей: проверка

Дата: 2026-10-31. Только `komarovblog/minimarket`, ветка `development`. **Статус до установки: исходники опубликованы; локальный runtime тест ещё не выполнен.**

## Что изменено

- Исходный компонент повышен с 0.3.0 до **0.3.1**.
- Новый `Site/Helper/SeoHelper.php` в компоненте создаёт один абсолютный `<link rel="canonical" ...>` для `catalog`, `category` и `product` через **Joomla Route API**, с учётом активного SEF/menu prefix.
- Если до компонента в head уже была другая canonical-ссылка, компонент заменяет её на одну URL MiniMarket. **Действие стороннего SEO-плагина после Joomla dispatch надо проверить отдельно**: гарантировать отсутствие будущих дублей без теста нельзя.
- `System - SEF` Joomla 6 по-прежнему самостоятельно отвечает за опциональное строгое удаление `index.php` и завершающий слеш. В этом релизе **нет новых 301**, нет автоматических редиректов после смены alias, нет вмешательства в чужие Joomla страницы/меню.
- **Никаких изменений SQL**; товары/категории и их опубликованность не меняются. Корзина, Product Schema.org и GA4 dataLayer ещё не реализованы.

Официальный API: https://api.joomla.org/cms-6/classes/Joomla-CMS-Document-HtmlDocument.html (addHeadLink), https://api.joomla.org/cms-6/classes/Joomla-CMS-Router-Route.html (absolute URLs), https://guide.joomla.org/user-guide/seo/seo-seo-basics (System - SEF / index.php / trailing slash).

## Установка — только обновление компонента

1. У пользователя версия 0.3.0 установлена и проверена по подтверждению «Гтово». При желании сохранить закрытый локальный backup БД `minimarket`; ничего из БД не публиковать.
2. В Windows **PowerShell**, `C:\OSPanel\home\minimarket.local`, если `git status --short` не показывает неожиданных локальных изменений:
```powershell
Set-Location 'C:\OSPanel\home\minimarket.local'
git pull --ff-only origin development
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```
3. В Joomla → Система → Установка → Расширения → обновить **поверх** существующей версии файлом `C:\OSPanel\home\minimarket.local\dist\com_minimarket.zip`. **Не удалять компонент** и не копировать PHP-файлы вручную.

## Проверка (одна опубликованная тестовая категория и один товар)

1. Joomla Extension Manager: версия MiniMarket = **0.3.1**.
2. Открыть `/catalog`, затем опубликованную категорию `/catalog/<alias>-<id>` и товар `/catalog/<alias>-<id>`. На каждой странице через браузерное **Просмотреть исходный код страницы** найти `rel="canonical"`: должен быть один `<link>` с **абсолютным URL** этой же страницы (текущий домен, корректный `/catalog`, без `?view=`, `?id=`, `index.php`).
3. Открыть для тестового товара технический адрес `http://minimarket.local/index.php?option=com_minimarket&view=product&id=<REAL_ID>` (использовать ID уже созданного товара). Пока возможен HTTP 200, но `rel="canonical"` должен указывать на красивый SEO-адрес товара.
4. На обоих типах страниц убедиться, что заголовки/товары/цены/остатки отображаются как в 0.3.0, меню и админка не сломались. Обычная Joomla-страница, не относящаяся к MiniMarket, не должна получать новые canonical от нашего компонента.
5. Если доступно, проверить обычный SEF-плагин через «Система → Плагины → System - SEF»: опции строгой обработки `index.php`/хвостового слеша включать **по одной только после проверки**, что они не вызывают циклы редиректа и не ломают ссылки. `Site Domain` локально оставить пустым.
6. **Не тестировать переименование alias товара, полагаясь на 301:** такой redirect ещё не создан. **Не включать массовую strict routing по умолчанию.**

## Если ошибка

При ошибке установки, HTTP 500, пустой странице, двух `rel="canonical"` или неверном host/path — **остановиться**. Не удалять MiniMarket, Joomla core, SQL и не редактировать активный шаблон. Достаточно сообщить, на каком экране (каталог / категория / товар / технический URL) возникла проблема и текст ошибки Joomla/наблюдение в исходнике страницы. Секреты и логи — не копировать в чат.

## Дальше после подтверждения

- Устранение дублей от нескольких пунктов меню: выбрать один канонический каталоговый Itemid и проверить ссылки. Для истории смены slug нужна отдельная модель/таблица redirects (реализовать после обсуждения), а не случайное 404/301.
- SEO: Product+Offer Schema.org, валюту/наличие и dataLayer, только на корректных страницах; затем описание/фотографии/характеристики/оформление, SEO-фильтры и корзина.

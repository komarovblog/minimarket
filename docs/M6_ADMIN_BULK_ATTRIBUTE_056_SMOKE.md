# MiniMarket 0.5.6 — привязки категорий и массовые действия

**02.11.2026 · Репозиторий MiniMarket, development.** Выпуск **без SQL-миграций**: расширен существующий редактор характеристики и четыре существующих административных списка. GitHub PHP 8.4/8.5, MySQL 8, Windows ZIP: PASS (после фикса stub setColumnAlias). **Joomla runtime 0.5.6 NOT RUN до проверки пользователя.**

## Изменения

**Характеристика → Категории.** В карточке «Цвет» и любой другой характеристики появилась вкладка **Categories / Категории**. В ней показана реальная иерархия категорий, включая неопубликованные, и для каждой можно выбрать **Inherit / Enable / Exclude**. В колонке «From parent» указан источник унаследованной настройки по ID родителя. При сохранении меняются только прямые назначения **этой одной характеристики**; другие свойства в этих категориях не затрагиваются. В редакторе категории остаётся прежняя вкладка «Attributes / Характеристики». **Это две стороны одной таблицы** \`#__minimarket_category_attributes\`, а не дублирование данных. Для новой характеристики можно сразу выбрать категории при создании.

**Четыре списка Joomla:** категории, товары, характеристики, значения — стандартные \`cid[]\` чекбоксы, «Выбрать все», Toolbar **Publish / Unpublish / Delete**, колонка **Published / Опубликовано** с состоянием. Права Joomla \`core.edit.state\` и \`core.delete\` управляют доступностью действий. Статус записывается в существующее поле \`state\` благодаря Joomla Table \`setColumnAlias('published', 'state')\`.

**Ограничения удаления:** если у категории есть дочерние категории или товары, удалить её нельзя, даже если выбраны и дети; сначала нужно осознанно обработать связи. Характеристику нельзя удалять, пока она назначена хоть одной категории или имеет значения. Существующий товар может быть удалён с его **связями галереи**, но физические файлы Joomla Media не удаляются; это необратимое действие после подтверждения. Значения характеристик можно удалять пока они ни к чему не привязаны, затем будущие variant FK должны защищать используемые значения. Не удалять реальный TEST-001.

Этот выпуск **не** реализует значения атрибутов внутри редактора товаров, варианты SKU, фасеты и комплекты. Для будущих списков комплектов, фидов и т. п. обязателен тот же стандарт множественного выбора/публикации, с проверкой зависимостей.

## Одна установка

Сделать backup БД Joomla (хотя миграций нет, действия Delete могут быть необратимы). В Windows CMD:

```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-admin-bulk.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Ожидаемый вывод **PACKAGE_OK: 0.5.6 (com_minimarket-0.5.6.zip)**. Установить **\`dist\\com_minimarket-0.5.6.zip\`** через Joomla → System → Install → Extensions поверх текущего MiniMarket. Не удалять компонент и не запускать SQL вручную.

## Проверки браузера после установки

1. Открыть MiniMarket → Attributes → **Цвет / Color**. Перейти на вкладку **Categories**. Проверить, какие категории сейчас включают «Цвет», включая родительские; выбрать одну тестовую категорию и **Enable**, сохранить, открыть вновь.
2. Перейти MiniMarket → Categories → та же категория → вкладка **Attributes**: там у «Цвет» тоже **Enable**. Поставить **Inherit** в категории и сохранить; в редакторе «Цвет» после повторного открытия должно быть **Inherit**. Подтвердить синхронизацию двух направлений.
3. В категории/товаре/характеристиках/значениях проверить строковые чекбоксы и общую кнопку **Select all**; колонку **Published**; Toolbar Publish/Unpublish/Delete. Проверить RU и EN тексты в языке Joomla.
4. Выбрать **только созданную специально тестовую характеристику или значение**, нажать Publish, затем Unpublish: статус меняется; остальные строки не меняются.
5. Проверить Delete **только на тестовом неиспользуемом значении/свойстве** после подтверждения; связанная характеристика/категория должна защищаться от удаления, показывая понятную ошибку.
6. Убедиться, что у TEST-001 по-прежнему его SKU/цена/остаток/категория/изображения и URL, что в галерее ничего не удалилось.

**Не проводить Delete на реальных категориях, товарах, связанной характеристике или TEST-001 ради теста.** Если кнопки недоступны, проверить права Joomla, \`core.edit.state\`/\`core.delete\`. Если после установки обнаружена ошибка — короткий текст/скриншот, без паролей и SQL-дампов.

Реальные кнопки и сохранение в Joomla (не только статическое наличие файлов) подтвердить отдельным smoke.

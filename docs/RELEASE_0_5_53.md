# MiniMarket 0.5.53 — «Скидка», «Новинка» и «Популярное»

**Дата:** 05.11.2026. **Ветка:** `development`. Выпуск после 0.5.52. Сохранять все существующие товары, комплекты, SKU, изображения, цены, остатки, бренды/коллекции. Код Joomla не изменять.

## Поля товаров и комплектов

На вкладке **«Основное»** рядом с ценой добавлено необязательное поле **«Старая цена»**. На отдельной вкладке **«Метки»**:
- **«Скидка»**: checkbox показывается лишь когда старая цена заполнена и больше нуля; сервер разрешает её включить только при заполненной старой цене, превышающей цену продажи. Если флаг включён, публичная метка: **«Скидка −N%»** (RU) / **«Sale −N%»** (EN). N = математическое округление вверх от процента снижения цены в **целых копейках**. Пример: старая 1990, текущая 1490 → 26%, а не 25%. У комплекта скидка вычисляется от итоговой текущей цены, включая её скидку от суммы компонентов.
- **«Новинка»**: checkbox и необязательное число дней от 1 до 36500. Пустой срок означает бессрочную метку.
- **«Популярное»**: checkbox и такой же независимый срок. Пустой срок означает бессрочную метку.

**Момент начала действия** записывает сервер в UTC при переходе выключено → включено. Простое редактирование/сохранение товара **не** перезапускает таймер. Если снять флаг и сохранить, дата сбрасывается. При повторном включении с сохранением отсчёт начинается заново. Через N×24 часа метка автоматически скрывается при открытии страницы (никакой CRON не требуется). Пользовательские POST-поля с датами игнорируются.

**Публичный вывод:** одинаковый для каталога, категории и карточки товара/комплекта; несколько меток могут стоять одновременно. Старая цена (если больше фактической) выводится перечёркнутой независимо от решения показывать/не показывать сам значок «Скидка». Если динамическая цена комплекта достигнет старой или превысит её, неверная скидка и старая цена скрываются, при этом исходные настройки в БД остаются без удаления.

## База данных и обновление

Новая версия `src/com_minimarket/minimarket.xml = 0.5.53`.
Файл `admin/sql/updates/mysql/0.5.53.sql` — аддитивная миграция:
- `old_price DECIMAL(15,2) NULL`
- `badge_sale TINYINT NOT NULL DEFAULT 0`
- `badge_new TINYINT NOT NULL DEFAULT 0`
- `badge_new_days INT NULL`, `badge_new_since DATETIME NULL`
- `badge_popular TINYINT NOT NULL DEFAULT 0`
- `badge_popular_days INT NULL`, `badge_popular_since DATETIME NULL`.

При установке поверх 0.5.52 текущие цены остаются неизменными, все флаги по умолчанию выключены. Равносильная структура добавлена в `install.mysql.sql` для чистых установок MySQL 8.4. Данные сохраняются через Joomla ProductModel/Table, проверяются сервером. Все флаги работают у обычного товара и у комплекта.

## Отдельный SQL для демонстрации

Для пользовательской БД `minimarket` / `nnop3_` после установки 0.5.53: `sample-data/minimarket_product_badges_demo_0_5_53.sql`. SQL **не обязателен** для работы функционала и не запускается Joomla автоматически.

Примеры только с существующими тестовыми артикулами:
1. `TOY-1001` — старая цена 1990, текущая 1490, «Скидка −26%» и «Новинка» на 7 дней.
2. `TOY-1002` — «Популярное» на 30 дней.
3. `TOY-1003` — бессрочная «Новинка».
4. `TOY-1004` — бессрочное «Популярное».
5. `BUNDLE-1090` — фиксированная цена 4990, старая 6990, отображается вычисленная «Скидка −29%».

SQL меняет только строки с указанными ID/артикулами, когда все существующие флаги ещё выключены и старая цена пуста. Запуск безопасно повторяем, **не содержит DROP/DELETE/TRUNCATE/ALTER**, никогда не пересоздаёт каталог. Сроки начинают отсчитываться от фактического `UTC_TIMESTAMP()` выполнения SQL.

## Приёмка на Joomla 6.2 / MySQL 8.4

1. Сохранить полный резервный SQL-дамп базы. Установить **`com_minimarket-0.5.53.zip`** поверх 0.5.52.
2. Товар → вкладка «Основное»: оставить «Старая цена» пустой и проверить, что checkbox скидки скрыт. Ввести цену выше текущей, включить значок скидки и сохранить.
3. Установить «Новинка» на 7 дней, «Популярное» без срока. Сохранить и переоткрыть: флаги и даты должны сохраниться. Изменить описание и сохранить ещё раз — отсчёт **не перезапускается**.
4. Проверить на публичных страницах каталога, категории и товара, что названия переведены RU/EN и процент округлён вверх. Старую цену показывать перечёркнутой.
5. Для комплекта с динамической скидкой убедиться, что при изменении цены компонента расчёт процента старой цены изменяется автоматически; ни цена товара, ни SKU не перезаписываются.
6. Импортировать при необходимости **только** `minimarket_product_badges_demo_0_5_53.sql` в базе `minimarket`; ни старый полный каталог, ни демо-скрипты предыдущих релизов запускать не нужно.
7. Проверить скрытие метки по истечении срока (серверные тесты проверяют границу времени, а на реальном сайте проверка будет при каждом просмотре).
8. Убедиться в сохранности SKU-матриц, галерей, комплектов, связей, изображений и SEO.

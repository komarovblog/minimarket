# MiniMarket 0.5.78 — оформление заказов (первая очередь)

## Область изменений

- Физические товары: корзина → форма оформления заказа; имя и телефон обязательны, email и комментарий необязательны.
- На POST повторно проверяются SKU, варианты, цены, остатки обычных товаров и вложенных комплектов. Состав и стоимость из клиентского POST не принимаются.
- Таблицы `#__minimarket_orders`, `#__minimarket_order_items` сохраняют исторический снимок названия, SKU, количества, цены (в копейках). Запись целого заказа транзакционная.
- Одноразовый ключ формы + стандартный CSRF Joomla. После успеха корзина очищается, номер заказа показывается только из собственной сессии.
- Joomla → MiniMarket → Заказы и плитка на панели: список, состав, контакты, смена статусов Новый/Подтверждён/Выполнен/Отменён с ACL `core.edit.state`.
- Страницы checkout/order-complete: noindex,nofollow и Cache-Control: private, no-store. RU/EN.

## Ограничения

Заказ является **заявкой**, а не оплаченной покупкой. Сотрудник должен обработать его вручную. Пока нет платёжного шлюза, службы доставки, фискализации, email/SMS и автоматического резервирования или списания остатков. Для режимов цифровых товаров и доставки еды эта форма отключена.

## Установка

Обязательно полный бэкап БД и сайта. Установить `com_minimarket-0.5.78.zip` поверх текущего. Миграция `0.5.78.sql` выполняется установщиком Joomla автоматически и создаёт только две новые таблицы, не изменяет существующие товары/SKU.

В CMD для получения трёх файлов на рабочий стол:
```bat
cd /d C:\OSPanel\home\minimarket.local
git pull --ff-only origin development
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\release-to-desktop.ps1 -SkipPull
```

На Desktop окажутся ZIP компонента, отдельный ZIP модуля, необязательный SQL демоданных. Дополнительный SQL для работы заказов **не нужен**.

## Приёмка

1. Добавить доступные обычный товар, SKU с вариантами и комплект в корзину.
2. Оформить заказ по имени/телефону, проверить номер и очистку корзины.
3. В админке открыть заказ, проверить контакты, позиции, цены и общую сумму.
4. Изменить статус. Проверить, что складские остатки не уменьшились.
5. Повторить запрос с неверным CSRF/ключом, пустой корзиной и недостатком остатков: заказ не должен сохраняться.
6. Повторное открытие страницы подтверждения не должно создавать второй заказ.

Автотесты — `scripts/test-0-5-78-checkout.php`, `scripts/test-0-5-78-orders-mysql84.php`; далее реальная браузерная приёмка Joomla.

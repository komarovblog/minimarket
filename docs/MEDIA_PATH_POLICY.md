# MiniMarket — единое правило для изображений (обязательно для всех этапов)

**Принято 01.11.2026 по замечанию пользователя.** Применяется к категориям, товарам, комплектам, Open Graph, будущим галереям, изображениям вариантов и значениям атрибутов (например, цвет).

## Что хранить

В SQL и редакторах MiniMarket хранится **один относительный путь к файлу**, например:

```text
images/powered_by.png
```

Не сохранять и не показывать в поле MiniMarket служебный суффикс Joomla Media:

```text
#joomlaImage://local-images/powered_by.png?width=294&height=44
```

Это не второе фото и не часть пути; Joomla автоматически приписывает адаптер и размеры исходника. **В MiniMarket эта информация для ссылок на изображения не нужна.** Не сохранять width/height в строке пути, не плодить поля «исходная ширина/высота» в редакторах и не просить пользователя вводить их. Размеры для адаптивной вёрстки, srcset, миниатюр и предотвращения сдвига макета определяются **отдельно при выводе**, по фактическому файлу/превью и требованиям интерфейса, а не из suffix.

- **Joomla Media** остаётся штатным выбором и файловым менеджером. Не менять ядро, физический путь на диске, права на файлы или превью, которое делает Joomla.
- В редакторе после выбора показывать простой путь: механизм MiniMarket `media/js/clean-media.js` вызывает публичный `joomla-field-media.setValue(path)` (с запасной прямой записью) и синхронизирует поле. Проверить в реальном браузере.
- На сервере **всегда** использовать одну нормализацию `AdministratorServiceMediaPath::normalize` в точках сохранения. Клиентский скрипт не заменяет проверки на сервере.
- Пустое поле — пустой путь; допустим только `images/...` и известный Joomla-сервисный фрагмент. Не принимать внешние HTTP URLs, `..`, неизвестные хеши/параметры, управляющие символы.
- **Alt текст** хранить отдельно. Социальная обложка Open Graph — отдельная *ссылка на файл*, но того же чистого формата.
- Галерея в будущем содержит **одну ссылку на медиафайл** на запись связи + alt/порядок/область применения (общая/цвет/SKU). Не создавать для разных размеров дубли файлов или новых колонок width/height в пути.
- Если картинка выбрана без особых свойств, не формировать отдельный нестандартный URL для каждого SKU/размера.

## Исправление старых записей

Аддитивное обновление **0.5.2** не добавляет таблиц. Оно удаляет только `#joomlaImage://...` из 4 полей:

- `#__minimarket_categories.image`
- `#__minimarket_categories.og_image`
- `#__minimarket_products.image`
- `#__minimarket_products.og_image`

Остальное (ID, SKU, цены, остатки, названия, категории, статусы, файлы на диске) **не меняется**. SQL повторно применим к тестовым данным без повторных изменений. Действующие записи сохранять, сначала сделать backup БД, затем штатное обновление Joomla ZIP. Вручную SQL не запускать.

Публичный рендер уже извлекает путь без Joomla-фрагмента, чтобы остающиеся старые данные тоже показывались корректно. После нового сохранения запись нормализуется в самой БД.

## Приёмка и регрессии

- Тест ввода: `images/powered_by.png#joomlaImage://local-images/powered_by.png?width=294&height=44` → **`images/powered_by.png`** на экране и после Save + повторного открытия.
- Проверить четыре поля (категория/товар × основная/OG), очистку поля, отклонение некорректных URL.
- `scripts/test-product-editor.php`: проверки PHP-normalization для четырёх полей и безопасности.
- `scripts/test-category-schema.php`: MySQL CI только в одноразовой схеме, проверка миграции и сохранности торговых данных.
- `node --check src/com_minimarket/media/js/clean-media.js`: синтаксис клиентского скрипта, НЕ доказательство работы Joomla UI.
- `scripts/inspect-package.ps1`: проверка версии и состава ZIP. **Реальный Joomla smoke только после установки на OpenServer.**

## Реализация галереи 0.5.3 (SOURCE, Joomla smoke NOT RUN)

Фотографии простого товара представлены отдельными связями `#__minimarket_product_images` (`product_id`, `path`, `alt`, `sort_order`), без копий файлов Joomla и без `#joomlaImage://`. Одна основная обложка выбирается в прежнем поле `products.image`; дополнительные фото — Joomla repeatable Subform. Удаление строки удаляет связь, но не физический файл. Форму, сохранение, сортировку и публичный показ проверить по [M3_PRODUCT_GALLERY_053_SMOKE.md](M3_PRODUCT_GALLERY_053_SMOKE.md). Привязки цвет/SKU пока не реализованы.

## Архитектурная оговорка

Не путать **размер исходного изображения как файловый метаданный факт** и **размер отображения в шаблоне/списке**. Этот запрет относится к суффиксам и полям редактирования изображения, а не к технически нужным размерам адаптивных миниатюр или доступному HTML. Небольшие фиксированные визуальные превью в админском списке могут оставаться.

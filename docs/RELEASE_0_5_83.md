# MiniMarket 0.5.83 — расширение магазина и исправление замечаний после 0.5.82

**Дата:** 10.11.2026. **Ветка:** `development`. **Статус:** автоматические проверки PHP 8.4/8.5, MySQL и Windows ZIP пройдены; реальные экраны Joomla пользователя требуют приёмки.

## Что исправлено

- Меню MiniMarket: RU/EN ключи заказов, доставок, отзывов, SEO-фильтров и настроек. В манифесте явно регистрируются `com_minimarket.sys.ini` двух языков, чтобы Joomla могла переводить меню до первого открытия компонента. После установки может понадобиться обновить страницу администратора или очистить кеш меню.
- Список заказов: вместо неразрешённого `JOPTION_SELECT` используется собственный переведённый текст выбора фильтра. Настройка столбцов уподоблена системному выпадающему переключателю Joomla.
- Ручной заказ: результат выбора товаров читается **до** вспомогательного запроса остатков комплектов; это исправляет предупреждения об отсутствующих ключах `product_id`, `sku` и `title`, возникавшие из-за переиспользования объекта БД.
- Доставки: собственный административный список/очередь, не перенаправление на заказы. В блоке Управление явная SVG-иконка грузовика.
- Глобальные настройки: добавлены группировки по категориям, товарам в категории, карточке товара и системным атрибутам, параметры вывода изображения/анонса/полного описания категории, раздел отзывов и опциональные CSS-селекторы будущих offcanvas-панелей.
- Список товаров категории: галерея изображений на карточке и действие «Выбрать вариант» для покупок с вариантами; быстрый просмотр и обычная кнопка «В корзину» регулируются настройками.
- Видео товара: редактирование промо-видео отделено от стандартного списка видео.
- Отзывы: самостоятельная таблица, очередь модерации, ручное создание отзывов, настройки регистрации/модерации/фото/видео. Пользовательский сценарий и ACL требуют браузерной приёмки.
- SEO-фильтры: отдельная сущность и раздел в меню/инструментах, данные посадочной страницы, фильтры, собственный публичный путь, заголовки и метаданные, публикация.
- Добавлено две таблицы **только с префиксом `#__minimarket_`**: `#__minimarket_reviews` и `#__minimarket_seo_filters`. Старые заказы и товары не удаляются.

## Важное: экран «Система → Проверка базы данных»

В присланном скриншоте Joomla для компонента указана версия БД и манифеста **0.5.82**, но проверка ссылается на очень старые `0.5.12.sql`, `0.5.14.sql`, `0.5.15.sql` и `0.5.73.sql`. В 0.5.73 мы **намеренно отказались** от прежних `attributes.input_mode`, `attributes.text_options` и таблицы `product_attribute_multi_values`: они не должны возвращаться в каноническую схему. Проверка старых миграций на новом состоянии способна выдавать ложные нарушения. При этом сообщение `SQL syntax ... AND null = 'NO'` не объясняется самим скриншотом и требует отдельного выяснения.

**Не нажимать «Исправить» и не запускать старые SQL-скрипты повторно.** Сначала сохранить полный дамп БД и файлы, затем провести только чтение текущего состояния. Например, в phpMyAdmin, где префикс сайта `nnop3_`:

```sql
SELECT e.element, e.type, s.version_id
FROM nnop3_extensions AS e
LEFT JOIN nnop3_schemas AS s ON s.extension_id=e.extension_id
WHERE e.element='com_minimarket';

SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA=DATABASE()
  AND TABLE_NAME='nnop3_minimarket_attributes'
ORDER BY ORDINAL_POSITION;

SELECT TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA=DATABASE()
  AND TABLE_NAME IN (
    'nnop3_minimarket_product_attribute_multi_values',
    'nnop3_minimarket_product_attribute_options',
    'nnop3_minimarket_product_attribute_free_values',
    'nnop3_minimarket_reviews',
    'nnop3_minimarket_seo_filters'
  )
ORDER BY TABLE_NAME;
```

Если у сайта другой префикс, заменить `nnop3_` на реальный. Эти запросы **ничего не меняют**. До получения результатов нельзя утверждать, что база исправна или что все предупреждения ложные.

**О ядре Joomla:** расширение устанавливает/обновляет только свои `#__minimarket_*` бизнес-таблицы; метаданные установки Joomla (реестры расширений/версий схемы/админменю) штатно обновляются самой Joomla. Структура `#__users`, `#__content`, `#__categories` и других базовых таблиц Joomla не мигрируется кодом MiniMarket.

## Ограничения

- СДЭК, SMS, email-подтверждение, внешние ID и реальные платёжные провайдеры пока не интегрированы.
- Настройки offcanvas — точки подключения к шаблону, **не самостоятельные модули**; их разработка — отдельная задача.
- Для новых отзывов используются собственные записи; не импортировать публичные пользовательские отзывы автоматически без разрешения/модерации.
- Результат CI не гарантирует отсутствие ошибок в уже изменённой локальной БД Joomla. Перед установкой 0.5.83 — резервная копия, после установки — проверка миграции и страниц в браузере.

## Получение сборки на рабочий стол

В CMD, находясь в `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development && powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\release-to-desktop.ps1" -SkipPull
```

Скрипт создаёт `com_minimarket-0.5.83.zip`, отдельный `mod_minimarket_toolbar-0.5.83.zip` и необязательный SQL для галерей демоданных. **SQL не нужен для обычного обновления компонента.**

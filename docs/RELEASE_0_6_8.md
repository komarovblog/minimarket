# MiniMarket 0.6.8 — настройки подтверждения, заказ, пользователь и повторные доставки

**Ветка:** `development`, Joomla 6 / PHP 8.4–8.5 / MySQL 8.4. Это изменение UI и серверной валидации существующих функций; **новых таблиц/столбцов нет**. Уже существующая миграция 0.6.7 нужна при переходе с 0.6.6 и ниже. `mod_minimarket_toolbar` остаётся самостоятельной версией 1.0.0, переустановка не нужна.

## Изменения

1. **Настройки → Оформление заказа.** Скрытое поле `checkout_verification_method` заменено родным Joomla ListField «Способ подтверждения». Метод «Электронная почта (Joomla)» соответствует реально поддерживаемому обработчику OTP; активные установленные MiniMarket-плагины регистрации видны, но пока **не могут быть выбраны**, если у них нет действующей интеграции в checkout. Выбор неподдерживаемого метода продолжает отвергаться сервером через `CheckoutSettings::method()`. Никаких фиктивных SMS/MAX/ID-провайдеров.
2. **Карточка существующего заказа:** последовательные полные панели как в главной панели MiniMarket: «Информация о заказе» (внутри основной статус и редактирование), «Оплата» (метод/статус/ID/URL), «Доставка» (метод, все связанные Shipment, их отдельные состояния, кнопка новой доставки), «Товары», «Возвраты», «История действий». Сохраняются обе кнопки перехода к созданию доставки — сверху и в блоке. Основной статус `confirmed` в RU UI назван **«В работе»**; переходы контроллера и модель оплаты **не изменены** и остаются предметом отдельного согласования по Shop.
3. **История** поясняет, зачем нужна: дата/время, действие, прежнее/новое значение, оператор, связанные операции. Сотрудники отображаются по имёнам из Joomla, когда аккаунт существует; сырые значения в БД остаются неизменяемыми. Длинная история скрыта в раскрываемый элемент; статусы в ней переведены по RU/EN.
4. **Пользователь заказа:** для заказов авторизованных покупателей Joomla идентификатор уже автоматически сохранялся в OrderStorage. Теперь карточка показывает **реальный, сохранённый `user_id`**, имя и при праве `com_users` ссылку на пользователя. При ручном создании появился единый поиск/выбор учётной записи Joomla: серверный поиск имени/логина/email, не более 20 результатов, требуется 2 символа, только разблокированные, ACL+CSRF. POST `user_id` сервер повторно проверяет по ID до сохранения; контакты получателя сохраняются независимо и **не используются для угадывания владельца**. Привязка необязательна, режим гостевых заявок не отменён.
5. **Повторная доставка:** в реестре доставки можно найти и выбрать заказ, у которого уже есть Shipment — снято ошибочное ограничение `s.id IS NULL` в AJAX-поиске. Из заказа обе кнопки «Добавить доставку» открывают реальный редактор с заранее выбранным `order_id`; если есть предыдущая доставка, по умолчанию предложена причина «Повторная». Переход назад в заказ есть в редакторе, при сохранении проверяется статус заказа/CSRF/ACL/наличие ровно одной первичной доставки.

## Сознательно не меняется без отдельного решения

- В Shop ТЗ §§6.11–6.13 предусмотрены **4 основных статуса Order**, **3 Payment**, **7 Fulfillment** и строгие переходы с реальными доказательствами; у текущего MiniMarket действующая упрощённая модель и ручные действия. Смена лишь названия статуса не считается выполнением требований Shop.
- События ЮKassa/СДЭК, платежные попытки, подтверждённые RefundTransaction, удержание остатков SKU, полный обязательный CRM-аккаунт и автоматическое завершение заказа требуют отдельной миграции и регрессионных тестов. Ни одна из них не подменяется вымышленным подтверждением.
- Подробная таблица преимуществ и расхождений: [SHOP_TZ_GAP_REVIEW_2026_11_12.md](SHOP_TZ_GAP_REVIEW_2026_11_12.md). Источник Shop — [REQUIREMENTS_V2.md](https://github.com/komarovblog/shop/blob/development/docs/REQUIREMENTS_V2.md), в которой функциональная модель **проектная**, не доказанно работающий код.

## Установка

Перед обновлением сделайте резервную копию БД. Выпуск стандартной командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

Получится `com_minimarket-0.6.8.zip` (и необязательный накопительный демонстрационный SQL), отдельно SQL **не импортировать**. Манифест содержит `admin/sql/updates/mysql/0.6.8.sql` только с комментариями: изменений схемы нет; если установка идёт с 0.6.6, Joomla должна выполнить 0.6.7.

**Приёмка Joomla (не заменяется CI):** RU/EN и Atum Light/Dark; выбрать Email в настройках и сохранить, открыть заказ с пользователем и без, вручную создать заказ с выбранным существующим пользователем, убедиться что неверный/заблокированный `user_id` отвергается. Создать две доставки к одному курьерскому заказу (первая initial, повторная redelivery), переходы обеими кнопками, выбрать в общем списке заказ с уже созданной доставкой. Посмотреть порядок блоков, историю с отображением имени оператора и статусами. Проверить ACL редактора пользователей.

# MiniMarket 0.6.5 — меню страниц витрины и быстрые действия создания

**База:** 0.6.4, ветка `development`. Joomla 6, PHP 8.4/8.5, MySQL 8.4. Никаких изменений ядра Joomla, Blank, текущих сущностей и схемы БД. Верхний `mod_minimarket_toolbar` по-прежнему устанавливается единожды и не входит в обычную сборку компонента.

## 1. Пункты меню сайта Joomla

У компонента уже есть тип **Магазин** (`site/tmpl/catalog/default.xml`). Добавлен ещё один реально работающий тип **Корзина** (`site/tmpl/cart/default.xml`), с названием и описанием на русском и английском в административных системных языковых файлах. При создании пункта меню Joomla: «Меню → Создать → Тип пункта меню → MiniMarket → Корзина». В типе нет лишних настроек; карточки/количество/промокод/кнопка оформления отображаются существующей страницей корзины.

Маршрутизатор MiniMarket адаптирован к отдельному пункту меню корзины без изменения URL категорий и товаров:

- При наличии опубликованного пункта «Корзина» он используется как `Itemid` для `RouteHelper::cart()`, результатом является именно псевдоним пункта меню (например `/basket`), **без `/basket/cart`**.
- Если пункт меню корзины не создан, работает прежний путь `/shop/cart`. Действующие старые ссылки продолжают обрабатываться.
- Поддерживаются несколько пунктов корзины, явный допустимый `Itemid`; без него выбирается существующий с наименьшим ID, без создания скрытых пунктов меню.
- Канонические маршруты категории, товара, SEO-страницы и оформления заказа по-прежнему используют **основной пункт «Магазин»**. Сохраняется требование иметь опубликованный Shop item.

## 2. Предлагаемая структура меню сайта — последующие итерации

| Тип | Статус / правила |
|---|---|
| Магазин | Существующий: каталог и главная магазина |
| Корзина | Реализован 0.6.5 |
| Отдельная категория | Нужна безопасная форма выбора категории и интеграция с SEF без дублирования канонических адресов |
| Отдельный товар / комплект | Нужен выбор опубликованного товара и согласование адреса с SEO, без автогенерации пунктов для всех товаров |
| Оформление заказа | Реальная страница есть, но публичный тип меню сейчас не нужен. В будущем можно разрешить пункт скрытого меню для назначения модулей/макета; нельзя создавать из него отдельный публичный поток checkout |
| Личный кабинет | **Не реализован как страница MiniMarket**. Сейчас используем Joomla `com_users` для входа и профиля. Позже добавим отдельный аккаунт MiniMarket с заказами, адресами, цифровыми покупками и корректной проверкой прав доступа |
| Избранное, сравнение | Не реализованы, не выводить в селектор как рабочие пункты |

## 3. Административное левое меню MiniMarket

Добавлены штатные Joomla `menu-quicktask` с иконкой `plus`, текстом `JNEW` и **работающими** маршрутам создания для 7 разделов: **Связи товаров, Связи комплектов, Характеристики, Опции, Бренды, Коллекции, Фиды**. В сумме с существовавшими быстрыми действиями теперь **15 разделов с «+»**: Заказы, Доставки, Отзывы, Категории, Товары, Комплекты, Связи товаров, Связи комплектов, Характеристики, Опции, Бренды, Коллекции, Промокоды, SEO-фильтры и Фиды.

Не добавлен фиктивный «+» к разделам, которые не создают отдельную сущность через собственный редактор: Импорт / Экспорт, Способы доставки, Способы оплаты, Способы регистрации, Настройки. Создание нового **плагина** не следует путать с добавлением способа; интерфейс этих разделов настраивает уже доступные плагины.

## 4. Приёмка

Автоматические тесты:

- `scripts/test-0-6-5-menus.php` проверяет XML тип меню корзины, переводы RU/EN, все 15 `menu-quicktask`, отсутствие фиктивных плюсов и существование рабочей корзины.
- `scripts/test-router.php` дополнен случаями с отдельным пунктом Cart и без него, парсингом пустого хвоста, сохранением canonical Itemid Shop, различием между адресами /basket и /shop/cart.
- Стандартные проверки GitHub: PHP 8.4/8.5, MySQL fresh/upgrade, Windows ZIP и выпуск на рабочий стол.

Ручная проверка в Joomla после обычной установки `com_minimarket-0.6.5.zip`:

1. Проверить все семь новых плюсов в левом меню и создание записей, особенно «Связи комплектов» с типом bundle и «Фиды».
2. Создать опубликованный пункт сайта «Корзина» через нативный селектор MiniMarket, выбрать произвольный URL-псевдоним; проверить пустую корзину, товары, продолжение покупок, переход к checkout.
3. Проверить URL товаров и категорий до/после создания корзины; товары и SEO-страницы не должны поменять адрес.
4. Снять пункт корзины с публикации: ссылка должна снова работать через основной магазин.
5. RU/EN, тёмная и светлая темы. **Браузерная приёмка не заменяется GitHub CI.**

## Поставка

Одна команда для CMD и PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

На рабочем столе: `com_minimarket-0.6.5.zip` и необязательный накопительный `minimarket_mysql84_nnop3_update_0_6_5.sql`. SQL не требуется для обновления меню. Установленный `mod_minimarket_toolbar` не удалять и не переустанавливать.

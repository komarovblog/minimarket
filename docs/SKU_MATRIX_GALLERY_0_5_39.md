# MiniMarket 0.5.39 — прямая матрица сочетаний SKU и общая галерея с назначениями

Дата: 04.11.2026. Реализация следующего после A1 этапа редактора товара без горизонтальных таблиц и без промежуточных кнопок генерации SKU.

## Согласованное поведение

- В товаре остаётся блок «Опции категории»: справочники и значения принадлежат категориям.
- Ниже — **одна матрица**. По одной колонке на опцию: Цвет | Размер | Комплектация | …; затем **Артикул | Остаток | Активно**. Каждая строка — одно сочетание значений. Не нужно нажимать «Добавить SKU-позицию», «Создать сочетания SKU» и заполнять вторую форму.
- Новая неактивная строка с пустым SKU/нулевым количеством не создаёт физический вариант. Активный SKU с пустым артикулом допустим: идентичность — database `variant_id` + уникальное сочетание. Несколько NULL SKU в MySQL разрешены, непустые артикулы остаются уникальными.
- **У товара одна цена**. Цена содержится только в карточке товара, в редакторе SKU нет цены; при сохранении варианта его техническое поле `price` синхронизируется с ценой товара. На витрине выбранный вариант не меняет цену. Если нужна другая цена и самостоятельное SEO, это отдельный товар, связанный через «Связи товаров».
- Режим «общий остаток» скрывает количественную колонку матрицы, не стирая ранее сохранённые количества. Режим «по сочетаниям» показывает остаток каждого SKU.
- Отключённое сочетание (Активно = Нет) не публикуется на сайте. Сохранённые `variant_id` и связанные медиа не уничтожаются при отключении.

## Галерея товара

Для каждого изображения в **Товар → Изображения → Галерея**:

1. **Показывать фотографию**: «Везде (для всех SKU)» или «Только выбранным артикулам».
2. Если выбран ограниченный показ, список сочетаний SKU через компактный множественный список. Отображаются человекочитаемые артикул и значения опций; можно выбрать несколько.
3. Отдельно **«Главная фотография для SKU»**: можно назначить фото главным для одного или нескольких SKU. Для ограниченного изображения главное назначение должно быть подмножеством его видимости.
4. Файл изображения хранится один раз в Joomla Media. Связи между фотографиями и вариантами хранятся по `variant_id`, не по тексту артикула. Изменение SKU не обрывает фото.
5. На витрине сначала выбранная главная фотография SKU, затем остальные видимые ему фото и глобальная обложка товара. Скрытые для SKU фото не должны попадать в клиентский JSON этого SKU.
6. Наследованные старые SKU-фото/галереи сохраняются и используются как fallback, но их редактор отключён от основной SKU-матрицы. Будущее — единое редактирование всех медиа только через общую галерею.

## Техническая реализация

- Новый `SkumatrixField` + `media/js/sku-matrix.js`. Сервер получает **один JSON payload** по сочетаниям, больше не зависит от нативной кнопки `group-add`, которой у пользователя не было («Форма добавления SKU недоступна»).
- `ProductSkuMatrix::dimensions` использует наследуемые опции категории для нового товара и сохранённые локальные оси для существующего, не перезаписывая старые варианты на смене категории.
- `ProductSkuMatrix::normalize` получает из формы только SKU/состояние/остаток/выбор, а **старые медиа и дополнительные HTML/видео** восстанавливает из БД по существующему `variant_id`. Сервер проверяет полные сочетания и целостность данных; пропажа ранее существующего SKU из payload вызывает ошибку, не удаление. Операция сохраняется внутри одной транзакции `ProductModel`.
- Обновлён `ProductGallery`: глобальные фото/ограниченные фото/переопределения cover сохраняются после сохранения SKU в таблицу связей. Нет физического копирования фотографий.
- SQL `0.5.39.sql`: изменяет `product_variants.sku` на nullable, добавляет `product_images.visibility_mode` default 0, таблицу `product_image_variants(image_id,variant_id,is_cover)` с внешними ключами. **Существующие записи, цены, остатки, URL, ID и фото не изменяются автоматически**. Обновлён свежий install.mysql.sql.
- Новая версия 0.5.39. `scripts/build.ps1` сохраняет **два файла** рядом в `dist/`: `com_minimarket-0.5.39.zip`, `minimarket_toys_rich_import.sql`. Демо SQL импортируется отдельно через phpMyAdmin и ЗАМЕНЯЕТ данные MiniMarket только при ручном запуске, в установочный ZIP не входит.

## Приёмка на Joomla 6

1. **Backup БД**. Собрать ZIP, `inspect-package.ps1`, установить обновление Joomla. SQL миграция автоматически изменяет схему; демоданные не импортировать повторно.
2. Открыть новый товар, назначить категорию с «Цвет S/M/L» или другой опцией. Должны появиться строки сочетаний сразу в матрице. Выбрать активные, указать SKU/остаток и сохранить; повторно открыть, проверить значения.
3. Изменить цену **товара**. Переключение размеров/цветов на витрине не меняет цену.
4. Для галереи добавить 3 фото: одно «Везде», второе «Только Синий/S», третье «Только Красный/M», второе назначить главным для Синий/S. Сохранить, переименовать SKU, обновить — назначения не потерялись.
5. На сайте проверить, что при выборе Синий/S показывается второе фото первым и нет фото Красный/M; при смене SKU галерея корректно меняется, URL товара тот же.
6. Установить для Синий/M остаток 0, статус выключен; на витрине сочетание нельзя выбрать для заказа. Переключить режим остатка общий ↔ по сочетаниям; числа не сбрасываются.
7. Проверить существующий товар с сохранёнными SKU, изображениями, видео и описаниями: после открытия/сохранения `variant_id` и данные не изменились (кроме технического `price`, приведённого к цене товара).
8. Проверить RU/EN, узкий экран, отсутствие горизонтального скролла и тёмную тему. GitHub CI проверяет PHP 8.4/8.5, MySQL 8 и Windows сборку, но **не заменяет ручной browser smoke**.

Ядро Joomla и `main` не изменять.

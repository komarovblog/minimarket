# MiniMarket 0.5.32 — независимые товары и пересекающиеся группы

**Принято 03.11.2026. Каноническое решение для связанных товаров (заменяет ограничение 0.5.26 «одна группа на товар»).**

## Модель

- **Товар — всегда самостоятельная сущность:** собственный `product_id`, URL, SEO, категория, галерея, цена, информационные характеристики и набор SKU. Нет «альфа-товара», «родительской модели» или обязательной оболочки.
- **Группа — необязательное объединение товаров:** без URL, карточки товара, SKU, цены или остатков. Товар может быть в нуле, одной или нескольких группах. Пересечение групп разрешено, одинаковая пара (group_id, product_id) запрещена.
- Тип группы — `model` («Исполнения модели»), `similar` («Похожие товары»), `collection` («Коллекция»), `accessory` («Сопутствующие»). Тип — метаданные для расположения блока в шаблоне, а **не** признак SKU/варианта.
- **SKU — отдельная продаваемая позиция внутри одного товара.** Группа не объединяет склад и не меняет SKU комбинации. Цвет может быть собственным товаром с отдельным SEO либо опцией/SKU внутри товара — пользователь решает; группа не превращает один случай в другой.

### Схема

`#__minimarket_product_groups`: id, title (уникальное), type, state, sort_order. Неиндексируемый справочник связей, без публичного URL.

`#__minimarket_product_group_members`: **PRIMARY KEY(group_id, product_id)**, sort_order, отдельный индекс product_id для FK. Это M:N. Сохраняются прежние product_id/group_id/порядок при обновлении.

`#__minimarket_import_group_keys`: (source_key, external_group_key) → group_id. Это фундамент будущего импорта. Пока полноценного импорта НЕТ. Сопоставлять группы по внешнему стабильному ID + источнику, никогда не заменять товары/URL на «внутренние группы» и не угадывать группы по названию.

Миграция `0.5.32.sql` добавляет индекс product_id **перед** сменой PRIMARY KEY, оставляя валидными существующие FK. Группам, созданным до версии 0.5.32, присваивается тип similar, статус опубликован, порядок 0. Товары, фотографии, цены, SKU, URL и SEO не переписываются.

## Интерфейс Joomla

1. **MiniMarket → Товары:** каждый товар — ровно одна строка, без parent/child вложения по группам. Показать связанные группы рядом с категорией; количество строк не увеличивается при наличии нескольких групп.
2. **MiniMarket → Группы товаров:** нативный список Joomla (checkbox, статус публикации, название, тип, количество участников, ID, SearchTools). Новую группу можно создать здесь и выбрать сразу несколько существующих товаров.
3. **Карточка группы:** название, тип, публикация, порядок, список участников (нативный multiple select). Выбрать 3 товара, сохранить; они сразу будут показывать общую группу. Убрать участника = убрать только связь; товар не удаляется.
4. **Карточка товара → Связанные товары:** множественный выбор существующих групп. Можно дополнительно создать новую группу по названию, не отменяя прежние группы. Ниже — список всех текущих групп с прямыми ссылками на их редакторы и ссылками на товары-участники. Изменения отражаются после сохранения/перезагрузки страницы.
5. Группы можно скрыть с витрины через публикацию. Удаление группы с участниками намеренно блокируется: сначала снять связи. Никакого каскадного удаления товаров при удалении группы.
6. Штатные Joomla FormController/AdminController/AdminModel, Toolbar, PublishedButton, SearchTools, таблицы/формполя, RU/EN и тёмная тема. Без новых кастомных дизайн-систем или горизонтального скролла.

## Витрина

Показывать только **опубликованные группы** и **опубликованные товары** в опубликованных категориях. На странице товара блоки по каждой группе: название группы → остальные опубликованные участники со своими URL и фотографиями. Не показывать текущий товар внутри его собственных списков. Если группа содержит только текущий товар или остальные участники скрыты — не показывать пустой блок. Товар может повторно встретиться в разных группах, но только один раз внутри каждой группы. Никакой подмены URL или canonical товара.

## Приёмка на Joomla 6.2.0

1. **Перед установкой ZIP сделать резервную копию MySQL.** Установить версию 0.5.32 поверх 0.5.31, открыть Товары и Группы товаров. Старые товары, их ID, URL, изображения, SKU, остатки и выбранные опции должны остаться неизменны. Старые группы и связи сохранены.
2. Создать группу «Футболка Classic» тип «Исполнения модели». На вкладке Состав выбрать красную, синюю и чёрную футболки. Сохранить и открыть снова: в группе те же три товара.
3. Создать группу «Летняя коллекция», выбрать красную футболку и шорты. Проверить, что у красной футболки **две группы**, а у синей только Classic; в Товарах каждая футболка по-прежнему ровно одна строка.
4. На вкладке Связанные товары у красной футболки обе группы видны и можно перейти к их составу. Убрать одну группу из карточки красной футболки: сохраняется вторая группа, SKU/товар не меняются; из редактора группы пропадает только удалённая связь.
5. Создать дополнительную группу прямо из карточки красной футболки при уже выбранной другой группе. Проверить обе связи после сохранения, а новая группа создаётся лишь один раз и может быть открыта в общем списке.
6. На витрине опубликованные связанные товары сгруппированы по названию группы, ссылки ведут на **собственные** страницы. Скрыть группу: её блок исчезает; остальные группы остаются. Скрыть товар: он исчезает из блока, но в админке связь сохраняется.
7. Проверить удаление группы с участниками — отказ без удаления товаров. Убрать участников, затем удалить пустую группу. Проверить RU/EN, мобильную ширину, тёмную тему, кнопки Save/Save&Close.

**Автотесты:** `scripts/test-option-architecture.php`, `scripts/test-native-ui-consistency.php`, MySQL upgrade + fresh install в `scripts/test-category-schema.php`, PHP 8.4/8.5 lint и Windows ZIP через GitHub Actions. **CI ≠ Joomla browser smoke**. Результаты ручной проверки на Open Server сообщаются отдельно.

## Что не входит в 0.5.32

Импорт групп поставщика как фактическая операция, массовая сортировка участников, динамические автоподборки, рекомендации по поведению покупателей, комплекты/корзина — следующие задачи. Существующие атрибуты и локальные SKU-опции остаются отдельной системой; глобальные справочники опций (V5-A) — следующий этап.

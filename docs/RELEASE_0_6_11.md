# MiniMarket 0.6.11 — нативная админ-панель и независимые платежи

**Ветка:** development; PHP 8.4/8.5, MySQL 8.4, Joomla 6. **CI 6/6 PASS:** [GitHub Actions #43400791468](https://github.com/komarovblog/minimarket/actions/runs/43400791468), кодовый SHA `ce274bd293fddd8d88ba06dfdff03b19c0fa1574` (PHP 8.4/8.5, MySQL 8.4 fresh/upgrade/demo, Windows ZIP + standalone task ZIP). **Реальная браузерная проверка Joomla/Atum ещё требуется.** В этой версии изменена миграция и форма администрирования.

## 1. Навигация

Пять разделов, одна последовательность и один набор пунктов во всех трёх местах:
- **Управление:** Заказы, Доставки, Возвраты, Платежи.
- **Магазин:** Категории, Товары, Комплекты, Бренды, Коллекции, Связи товаров, Связи комплектов, Характеристики, Опции.
- **Маркетинг:** Отзывы, Промокоды, SEO-фильтры.
- **Инструменты:** Импорт / Экспорт, Фиды.
- **Настройки:** Способы доставки, Способы оплаты, Способы регистрации, Способы уведомлений, Настройки.

Обновлены `minimarket.xml` (native sidebar), `admin/presets/minimarket.xml` (Joomla dashboard module), `admin/tmpl/dashboard/default.php` (компонент) и белый список `AdminEntityLinks`. Дашборд и пресет продолжают использовать собственные средства Joomla, без изменений ядра. Если администратор ранее вручную копировал пункты в **пользовательское меню**, старые вручную созданные копии Joomla не меняются из-за обновления компонента; нужен осмотр именно используемого штатного модуля/пресета.

## 2. Заказы и вкладки

Удалены кастомная полоса кнопок срочности и постоянно видимый input «Причина отмены» из реестра. **«Причина отмены» относится к отмене заказа, не к поиску**, и сохраняется при действии отмены в самой карточке. Быстрые сценарии «Новые», «истекает за N/1 день», «просрочено», «неоплачено в резерве», «оплачено не получено» доступны одним нативным полем `filter_quick` в Joomla SearchTools, наряду с тремя независимыми фильтрами состояния заказа/оплаты/исполнения. Варианты исполнения охватывают все семь стадий и старые значения.

В списке оставлены основные девять колонок: чекбокс, номер заказа, дата, покупатель, статус заказа, оплата, исполнение, дата резерва/контроля, сумма. Лишние телефон/источник/способ получения не расширяют таблицу; детали доступны в заказе. Даты локализуются через Joomla, суммы не переносятся на три строки.

Карточки **Заказ, Доставка, Возврат, Платёж** показывают части данных на нативных Joomla UI tabs, как уже существующие карточки товара и категории. У заказа «Общее», «Товары», «Оплата», «Доставка», «Возвраты»; у доставки «Общее», «Возвраты»; у возврата «Общее», «Товары»; у платежа «Общее», «Операции оплаты». Формы действий остаются защищёнными ACL и CSRF.

## 3. Платежи — отдельный операционный реестр

`view=payments` — одна строка на платежное обязательство каждого **заказа** (включая неоплаченные), с суммой, датой, способом и финансовым состоянием. Это не дважды созданные фиктивные платежи. `view=payment&id=<order_id>` — карточка оплаты этого заказа с вкладкой настоящих подтверждённых операций.

Новая **добавочная** таблица `#__minimarket_payment_records` и миграция `0.6.11.sql`: одна строка для новой проверенной ручной отметки оплаты (order_id, сумма в копейках, валюта, метод, источник, идентификатор подтверждения, сотрудник, время), в одной SQL-транзакции со сменой статуса оплаты заказа. Повторная отметка уже оплаченного заказа не добавляет ещё одну платёжную запись. Историческим заказам автоматически не выдумывается новая банковская квитанция; отметка «Оплачено» остаётся, но журнал может быть пустым.

Это **не интеграция** ЮKassa, не ledger возвратов денег, не эквайринг банковского терминала, не поддержка частичных поступлений. Реальные внешние платёжные попытки и RefundTransaction требуют следующей отдельной итерации с проверкой provider-ID и идемпотентными webhook.

## 4. Резервы — только при создании заказа

0.6.10 резервирует физическое количество атомарно после оформления заказа, **не в корзине**. Для неоплаченного самовывоза таймер и напоминания; для оплаченного — дата проверки без автоматической отмены; для курьера — до физической передачи, без ложного SLA автоосвобождения. В этой итерации алгоритм остатков не переделывался, только упрощён интерфейс контроля.

## 5. Установка

Перед установкой — полный бэкап MySQL 8.4; в ZIP есть additive `0.6.11.sql`. Одна стандартная PowerShell команда синхронизирует development, собирает и доставляет на Рабочий стол:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

Артефакты: `com_minimarket-0.6.11.zip`, прежний отдельно устанавливаемый `plg_task_minimarketreserves-0.6.10.zip`, optional `minimarket_mysql84_nnop3_update_0_6_11.sql`. **Не импортировать** демо SQL при обновлении уже существующего каталога. `mod_minimarket_toolbar-1.0.0` не перегенерируется и не переустанавливается.

Проверки на локальном Joomla: RU/EN, светлая/тёмная Atum, наличие всех пунктов меню и карточек, отсутствие поля причины отмены в списке, нативные фильтры, переносы таблицы, все вкладки, новая оплаченная вручную операция и legacy уже оплаченный заказ, два одновременных заказа на последний SKU и отмена без двойного возврата остатков.

## 01.11.2026 — фотографии вариантов (концепция)

Решено использовать одну галерею товара с гибкой привязкой фотографий: общая галерея; фото по значению меняющей внешний вид характеристики (например, цвет) для всех размеров данного цвета; исключения — фото конкретного варианта/SKU. **Галерея меняется автоматически по выбранному реальному варианту, без отдельной обязательной галочки и без изменения URL/canonical.** Приоритет фото: точный вариант → цвет/визуальная характеристика → общая галерея. Фотографии не дублировать физически для размеров. Фильтр показывает фото подходящего совпавшего варианта. **Пока DESIGN_ONLY, не реализовано** — [PRODUCT_VARIANTS.md](PRODUCT_VARIANTS.md).

## Окончательная схема размещения и маршрутов

Один **обычный, опубликованный и явно настроенный** пункт меню Joomla **«MiniMarket — Магазин»**. Никаких скрытых пунктов, служебных menu anchors, невидимых Itemid, автоматического создания меню или правок ядра.

1. **Отдельный интернет-магазин:** владелец назначает пункт MiniMarket главной страницей `/`. Адреса: `/category/{alias}-{id}`, `/product/{alias}-{id}`, позже `/bundle/{alias}-{id}`, `/filter/{alias}-{id}`.
2. **Магазин как раздел сайта:** владелец размещает обычный пункт MiniMarket с алиасом `shop` по `/shop`. Адреса: `/shop/category/{alias}-{id}`, `/shop/product/{alias}-{id}`, позже `/shop/bundle/{alias}-{id}`, `/shop/filter/{alias}-{id}`. Значение `shop` задаётся алиасом пункта, а не жёстко вшито в код.
3. **Один выбранный Itemid** — публичная база для ссылок из всех модулей, категорий, карточек и поиска. Если пункт не назначен, требуется явная ошибка конфигурации, **не скрытый fallback**. Переключение `/` на `/shop` меняет адреса; это отдельная контролируемая SEO-миграция с 301/canonical.
4. Сам пункт имеет настройки выводимых блоков: категории (дерево/плитки), товары (все/новинки/популярные/выбранные), фильтры, сортировка, серверная пагинация. Категории и товары можно отключать: страница может состоять из модулей/баннеров Joomla. Эти параметры **ещё не разработаны**.
5. Дополнительные переиспользуемые модули `mod_minimarket_categories` и `mod_minimarket_products` можно размещать на **любой** странице, даже если сам магазин расположен по `/shop`. Данные, цены и ссылки берутся из общего компонента. Модули **пока не разработаны**.
6. Категории могут быть вложенными в БД, но URL плоские. Никакой корневой категории «Каталог» в БД. Крошки отображают торговую иерархию: `Главная → [Магазин] → Категория → Подкатегория → Товар`, а не буквальный URL.

## Среда и эксплуатационные правила

- Windows 11 / Open Server, `C:\OSPanel\home\minimarket.local`; Joomla 6.2.0, PHP 8.5, MySQL 8.0; живой сайт в `public_html`.
- Git хранит **только** исходники нашего расширения `src/com_minimarket`, скрипты и документацию; Joomla core, БД, пользовательские данные/секреты не публиковать.
- Локально изменённый `.osp/project.ini` — пользовательский, **не сбрасывать**. `main` не изменять; никакого Docker и ручного патчинга Joomla.
- Рабочий процесс: GitHub `development` → `git pull --ff-only` → `scripts/build.ps1` → `scripts/inspect-package.ps1` → штатный Joomla Extensions Installer → краткий smoke-тест. Windows/локальные логи не копировать в чат, чувствительные данные не отправлять в Git.
- Разрешённый перенос знаний в Symfony Shop — **только** зеркальный `docs/SHARED_ENGINEERING_KB.md`; ни код, ни бизнес-логика между магазинами не копируются.

- В выборе типа Joomla Menu Item были сырые `COM_MINIMARKET_CATALOG_MENU_TITLE/DESCRIPTION`, исправление добавлено в 0.3.3 (KB-0011). **Результат новой установки не подтверждён.**

## 01.11.2026 — версия 0.3.5: typed routing (runtime NOT RUN)

Код в `development`: Joomla Router MiniMarket теперь формирует `category/{alias}-{id}` и `product/{alias}-{id}` относительно единственного обычного опубликованного пункта меню, может работать когда пункт главная `/` или `/shop` (режимы ещё проверить). В `preprocess` чужой Itemid заменяется на Itemid магазина, при нуле или нескольких пунктах — ошибка, не скрытая маршрутизация. Старый `catalog/{alias}-{id}` при том же пункте меню пока обрабатывается legacy parser; canonical на новый typed URL, но **301 перенаправления ещё нет**, не считать SEO-переход завершённым. До публикации 301 нужен отдельный тест. Прототип Router проверен PHP 8.4 lint и mock DB/Menu сценариями; **не проверен** в реальной Joomla 6.2.0. Единственный следующий шаг — [M1E_TYPED_ROUTING_SMOKE.md](M1E_TYPED_ROUTING_SMOKE.md), ZIP 0.3.5 поверх 0.3.4 без изменений меню/SQL. Таблицы/варианты товаров не трогались.

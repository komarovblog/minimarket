# MiniMarket 0.5.38 — исправление админ-таблиц на всех списках

Дата: 04.11.2026. Причина: на экране Joomla 6.2 в «Товары» заголовок «Опубликовано» разбит вертикально на буквы, остальные колонки сжаты и пересекаются.

## Root cause
Начиная с 0.5.36 компонент загружает `media/css/admin-ui.css` в каждой административной странице. Слишком широкий селектор `#adminForm .table { table-layout: fixed; }`, а также `#adminForm .table th, td { overflow-wrap:anywhere; min-width:0; }` перезаписывал ожидаемое поведение **всех** нативных таблиц Joomla в списках. При `w-1` у статуса получалась узкая колонка, а `overflow-wrap:anywhere` разрешал перенос слова по каждой букве.

## Исправление

- В списках **Товары, Категории, Характеристики, Значения, Опции, Связи товаров** добавлен класс `mm-admin-list` и локализованные `data-label` для каждой ячейки. Вся структура Joomla `table table-striped`, `PublishedButton`, checkbox, SearchTools, сортировка и bulk действия **сохранена**.
- В CSS **удалён общий селектор `#adminForm .table`**. Для `.mm-admin-list` используется только естественная ширина `table-layout:auto`. Заголовки могут переноситься по словам, но не по буквам, статус имеет минимальную ширину. Длинные значения внутри ячеек переносятся.
- Для узкой ширины **самого списка** (container query 900px, а не viewport) строки отображаются адаптивными карточками, чтобы не создавать горизонтальной полосы. Каждая ячейка подписана локализованным `data-label`, а checkbox и `PublishedButton` продолжают работать.
- Только в компактных формах правил категорий/опций/характеристик разрешён `table-layout: fixed` на **`.mm-rules-table`**, не на списках.
- В списках товаров и категорий превью теперь отображается лишь когда файл существует в `JPATH_ROOT/images/...`. Отсутствующий файл больше не показывает длинный сломанный `alt`; отображается «—». SQL демонстрационных товаров продолжает ссылаться на `images/minimarket/sample.png`, но **никакие изображения и данные в БД не изменяются**.
- Меняется только frontend/CSS/шаблоны списков; миграции SQL не нужны. Версия компонента 0.5.38. Сохраняется правило двух отдельных файлов `dist/com_minimarket-0.5.38.zip` и `dist/minimarket_toys_rich_import.sql` после `scripts/build.ps1`.

## Проверка на реальной Joomla

1. Обновить компонент через Joomla и очистить кеш браузера `Ctrl+F5` для нового `admin-ui.css`.
2. На экране шириной примерно 1300px открыть **Товары**. В заголовке «Опубликовано» не должно быть вертикальных букв; статус, заголовок, SKU, цена, остаток, категории, группы и ID должны читаться без наложений.
3. Проверить списки **Категории, Характеристики, Опции, Связи товаров, Значения**. В заголовках слова должны переноситься только целиком.
4. Уменьшить рабочую ширину окна до примерно 900px или использовать узкий экран. Строки должны превратиться в подписанные карточки без горизонтальной прокрутки, чекбоксы/статусы/названия остаются рабочими.
5. Открыть формы редактирования категории и характеристики: двухколоночные таблицы назначений по-прежнему компактны. Проверить SKU и значения опций (подформы).
6. При отсутствии `images/minimarket/sample.png` в перечне товаров отображается «—»; при появлении файла будет корректная превью 48×48. Для содержимого с настоящими картинками ничего не изменилось.
7. Проверить, что bulk publish/unpublish и фильтры не сломались.
8. Результаты PHP 8.4/8.5, Windows ZIP и MySQL 8 в CI не являются заменой ручной проверки интерфейса Joomla.

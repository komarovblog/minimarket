# MiniMarket 0.5.8 — где настраивается список значений

**02.11.2026 · Реализация source, PHP/Windows/MySQL CI PASS, реальная Joomla NOT RUN.** Выпуск только для удобства редактирования характеристик и подсказок в товаре; **нет миграций БД и изменений SKU, цены, остатков, категорий, фото**.

## Как создать «Красный» и «Жёлтый»

1. MiniMarket → **Attributes** → открыть **Цвет** (`color`), убедиться, что тип **List**, «Distinguishes product variants» = Yes, «Use in filters» = Yes и Status = Published, сохранить.
2. На третьей вкладке **Values / Значения** нажать **Add value / Добавить значение**. Поле Attribute должно уже содержать **Цвет**. Создать **Красный** (`red`), Status = Published, сохранить.
3. Ещё раз открыть «Цвет» → Values, добавить **Жёлтый** (`yellow`), Status = Published. Список показывает уже созданные значения, их код и статус, а название является ссылкой на отдельный редактор Joomla.
4. У категории, в которой находится тестовый товар, характеристика «Цвет» должна быть Enable или наследоваться от родителя. В редакторе тестового товара открыть вкладку **Attributes** и выбрать Красный/Жёлтый. После Save + повторного открытия выбранное должно остаться.
5. Если товар по-прежнему не показывает варианты: проверить категорию товара, список значений у «Цвета» и то, что Joomla действительно обновлена до 0.5.8. В карточке товара у спискового атрибута есть ссылка **Edit values** и предупреждение об отсутствующих значениях.

**До выпуска 0.5.8:** в 0.5.7 уже была ссылка **Edit values** в отдельной колонке общего списка MiniMarket → Attributes → справа от характеристик типа List. Она открывает тот же общий справочник \`#__minimarket_attribute_values\`. Новая вкладка в 0.5.8 — лишь удобная навигация без копий значений.

**Важное разграничение:** Value type = List не содержит поле перечисления на странице самой формы до сохранения. В 0.5.8 значения отображаются в отдельной вкладке уже сохранённой характеристики; ссылки открывают обычный Joomla-редактор значения. Типы Text/Number/Yes-No не имеют справочника, у них значения вводятся непосредственно в товаре. У новой несохранённой List-характеристики Values покажет «Сначала сохраните характеристику».

## Установка (после успешного CI)

Сначала backup Joomla DB, компонент не удалять. Windows CMD в `C:\OSPanel\home\minimarket.local`:

```bat
git pull --ff-only origin development

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

## Что ещё не реализовано / план после согласования типов

Нужно разделить **data type** и **input control / cardinality**. Сейчас у List множественный выбор в товаре включается только флагом is_variant, что неуниверсально: мультивыбор нужен и для обычных свойств, не образующих SKU (напр. «Совместимые устройства»).

**Рекомендуемая модель:** общие типы: \`text\` (короткий текст), \`text_long\` (длинное описание), \`number\` (число, допустимые min/max/шаг/единица), \`boolean\` (да/нет/не заполнено), \`list\` (общие значения), \`date\` (дата) — два последних расширения не включены в 0.5.8. Для \`list\` независимые параметры: **single/multiple**, `is_variant` (только для обоснованных SKU-признаков), визуализация **dropdown/radio/checkbox/chips/color swatches/image swatches**; это способы показа общего ID-based dictionary, а не отдельные сущности. Фильтруемость и показ на карточке настраиваются отдельно. Единицы измерения и допустимые диапазоны — метаданные числового типа; «от–до» в фасетном фильтре — способ поиска, не тип хранения. Картинки цвета ссылаются на Joomla Media без копирования и служебных суффиксов. Бренды/коллекции и прочие сущности со своей бизнес-семантикой не надо подменять обычным свободным текстом.

**Не менять сейчас типы существующих данных или SQL, пока не согласована UX-матрица.** Настоящие SKU-комбинации и их собственные остатки — отдельный этап 7, не следствие выбора нескольких цветов в форме товара.

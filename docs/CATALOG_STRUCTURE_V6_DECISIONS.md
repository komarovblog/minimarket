# MiniMarket — архитектура каталога V6: 7 самостоятельных разделов

**Решение 03.11.2026.** Это главный архитектурный документ после обсуждения интерфейса Joomla 6.2.0 и скриншота `Связанные товары`. Перекрывает прежнюю V4/0.5.32 классификацию `model/similar/collection/accessory` внутри `product_groups`. Не считать будущие подсистемы реализованными: их статус указан отдельно.

## 1. Навигация MiniMarket

Административное меню: **Категории → Товары → Связи товаров → Бренды → Коллекции → Характеристики → Опции**. Стандартные настройки компонента — через Joomla Options. Дополнительные сущности (скидки, заказы, фиды, корзина) появятся по факту реализации; не создавать пустые экраны ради дорожной карты.

| Раздел | Что хранит | Есть собственный URL на сайте | Связь с SKU |
| --- | --- | --- | --- |
| Категории | Иерархия товаров, назначение характеристик и опций, правила рекомендаций | Да | Косвенная |
| Товары | Самостоятельная сущность, фото, карточка, SEO, SKU | Да | SKU принадлежит товару |
| Связи товаров | **Только ручные группы самостоятельных товаров**, пересекающиеся M:N | Нет | Никакой |
| Бренды | Справочник брендов с контентом и SEO | **Да, лендинг** | Нет |
| Коллекции | Справочник коллекций с контентом и SEO | **Да, лендинг** | Нет |
| Характеристики | Информационные свойства товара и фасетные фильтры | Нет самостоятельного лендинга по умолчанию | Не формируют SKU |
| Опции | Справочник выбора при заказе (размер, цвет, исполнение и др.) | Нет | Каждая реальная комбинация = собственный SKU |

**Один товар — один основной URL.** Каждый SKU сочетания его опций использует URL своего товара; связи не создают новых карточек товара. Бренд/коллекция — отдельный навигационный лендинг, а не товар и не одна из «групп».

## 2. Связи товаров: только ручное объединение

- Переименовать прежние «Группы товаров»/«Группа связанных товаров» в **«Связи товаров»**.
- В каждом товаре можно отметить **несколько** связей. В редакторе связи выбирают товары-участники; у связи нет основного/альфа-товара. Из одной карточки можно создать новую связь и не потерять остальные.
- Удаление связи не удаляет товар и его SKU. Состав связи виден и в редакторе связи, и в карточках всех её участников после сохранения. На сайте выводятся ссылки только на опубликованные товары опубликованных связей, с **собственными** URL, картинками и SEO.
- **Типы `model/similar/collection/accessory` НЕ используются** в логике и интерфейсе. Старую колонку `product_groups.type` оставить технически до безопасной миграции, чтобы не повредить существующие записи. Старые группы любого типа становятся обычными «Связями товаров»; существующие ID, названия, участники, порядок/публикация сохраняются. Никакой конвертации в бренды или коллекции по названию/типу автоматически.
- Привязка групп по будущему импорту: внешний стабильный `source_key + external_group_key`, внешние ссылки не угадывать по названию.

### Визуальная форма

На скриншоте Joomla 6.2.0 показан нативный `<select multiple size=7>` с огромным синим выделением — это неудобный браузерный элемент, не желаемый дизайн. В **0.5.33** заменить его на нативные Joomla `CheckboxesField` и в редакторе связи, и в карточке товара. Удалить подсказки о Ctrl/Shift. В карточке товара: компактная группа флажков со связями, затем поле «Создать новую связь», затем простая таблица «Название связи | Состав». В списке «Связи товаров»: название, публикация, количество товаров, ID — **без колонки типов**. Все UI-поля RU/EN, обычные отступы и стандартные Joomla формы.

При большом каталоге следующий UX-этап: поиск и подбор товаров с метками выбранных элементов вместо прокрутки сотен чекбоксов. Не вводить неподдерживаемые кастомные поля с потерей сохранения.

## 3. Похожие товары — правила категорий, а не связи

Редактор **категория → вкладка «Рекомендации» → Похожие товары**:

1. Источник кандидатов: **по умолчанию та же категория** (без ручных M:N связей); администратор может выбрать одну/несколько других категорий и при необходимости подкатегории.
2. Правила совпадения: отметить характеристики (например, мощность, тип подключения, форма) для сравнения с текущим товаром. **AND** между выбранными характеристиками. Для скалярных текстов/чисел/Да-Нет — точное нормализованное совпадение; для множественных — пересечение хотя бы по одному значению каждого выбранного атрибута. Не использовать описание HTML и не сравнивать только названия характеристик.
3. Если ни одна характеристика не выбрана — показывать кандидатов из заданных категорий без дополнительного сравнения. Исключать исходный товар, черновики и товары из неопубликованных категорий.
4. Управляемое количество, сортировка, отсутствие дублей; при недостатке совпадений **не расширять** фильтр тайно. Для каждой категории собственная настройка; наследование возможно по явному режиму `Наследовать` от родителя.
5. UI: «Источник товаров» → «Совпадающие характеристики» → «Количество и порядок»; рядом текстовый предпросмотр количества кандидатов на конкретном товаре на следующем этапе. Не показывать настраиваемые SQL-выражения в админке.

## 4. Сопутствующие товары — отдельные правила категорий

Редактор **категория → вкладка «Рекомендации» → Сопутствующие товары**:

- По умолчанию **не выводить ничего**, пока администратор не задаст правило, иначе появляются случайные/нерелевантные предложения.
- Выбираются одна/несколько категорий-источников (например, для топок — дымоходы, аксессуары, облицовки), при необходимости совместимость по конкретным характеристикам и исключения, лимит и порядок.
- Сопутствующие товары не становятся «Связями товаров», не превращаются в комплекты и не создают автоматически SKU. Покупка вместе, наборы и комплекты проектируются отдельно.
- Если категория ещё не имеет отдельного правила, может наследовать правило родителя через явно выбранный режим.

## 5. Бренды и коллекции — отдельные справочники с лендингами

- **Бренд**: ID, название, alias, лого, изображение обложки, краткое/полное описание, SEO/OG, публикация/порядок; на сайте отдельный SEO-лендинг с товарами этого бренда, фильтром/сортировкой, ссылками на бренд из товара. В товаре — одно значение `brand_id` или «Без бренда».
- **Коллекция**: ID, название, alias, обложка, описания, SEO/OG, публикация/порядок; на сайте отдельный SEO-лендинг с товарами этой коллекции. В товаре — **несколько** коллекций (M:N), чтобы товары могли входить в несколько серий. Не привязывать SEO лендинг к «Связям товаров».
- Бренды и коллекции должны иметь полноценные native Joomla списки/редакторы, ссылки в меню Joomla, роутер без дублирующих URL. Для каждого товара сохранять собственный URL/SEO.
- Не создавать одновременно второй произвольный текстовый атрибут «Бренд»/«Коллекция» с отдельными несинхронизированными значениями. На витрине можно **показывать бренд и коллекции как характеристики**, но источником истины являются только эти справочники.
- Старые ручные связи не преобразовывать в коллекции автоматически. Сначала явная миграция с подтверждённым соответствием ID, если она вообще понадобится.

## 6. Глобальные опции с привязкой к категориям

**MiniMarket → Опции** — такой же отдельный справочник, как информационные характеристики, но для выбора при покупке:

1. Создать опцию, например «Размер» → значения XS, S, M, L, XL (а также «Цвет» и др.). У каждого значения стабильный ID и сортировка. Список значений редактируется **один раз**, а не вводится вручную у каждого товара.
2. В категории → вкладка «Опции»: назначить опцию и указать один из режимов **Наследовать / Отключено / Необязательная / Обязательная**. Опции из родительской категории наследуются, но дочерняя может явно изменить правило.
3. В товаре → вкладка «Опции и SKU»: выбрать из разрешённых опций нужные для товара значения; отступ/вложенность минимальны. Категорийное назначение не должно создавать в товаре все значения без разбора.
4. **Обязательная опция**: посетитель обязан выбрать значение для заказа. **Необязательная**: допускается «Не выбрано»; это должно быть явно предусмотрено в SKU-матрице как отдельный корректный вариант, если товар можно купить без этой опции. Нельзя создавать скрытый фиктивный SKU. Неявная/неполная комбинация не допускается.
5. **Каждая фактически продаваемая комбинация** — уникальный SKU с ценой и, если учёт включён, остатком. Ненужные сочетания можно не создавать; при выборе несовместимые значения отключаются. Один URL товара, SKU в адресе не дублирует SEO-карточку.
6. Сохранять existing local `variant_dimensions`, `variant_dimension_values`, `product_variants` и их IDs до явной безопасной привязки на глобальные `option_id/value_id`. Не создавать параллельный конкурирующий SKU-движок или автосопоставление по названию.

**Редактор товара должен показывать процесс по порядку:**
«1. Опции и значения товара → 2. Сформировать реальные сочетания → 3. SKU, цена, наличие»; подробные фото, HTML, видео отдельных SKU редактируются в деталях SKU, не в широкой таблице. На этапе **0.5.33** добавлена только поясняющая нативная Joomla Note с текущим ручным процессом; отдельный общий справочник **ещё не реализован**.

## 7. Качество админки

- Единая нативная Joomla 6.2.0 верстка и формы (тёмная/светлая темы), одинаковые размеры обычных полей и `table table-striped` без искусственной высоты строк и ненужных цветных блоков.
- Флажки — для множественного выбора, единый выпадающий список — для перечислений; в больших справочниках — поисковый подбор, не огромный `select multiple`.
- Не помещать вложенные галереи/HTML/видео в каждую строку матрицы SKU; без горизонтального скролла на обычном десктопе. Показывать пользователю только поля, относящиеся к текущему шагу, условиям и типу данных.
- Реальное сохранение и редактирование через стандартную модель Joomla, RU/EN. Текст подсказок короткий и объясняет действие, а не внутренние названия SQL.
- Пустые разделы объясняют, что создать/выбрать; без забытых заглушек и ложных статусов «всё готово».

## 8. Приоритетная реализация

- **0.5.33 (минимальный UX):** переименовать группы в «Связи товаров» во всём пользовательском admin UI, удалить типы из формы/списка, заменить большие HTML select-multiple на Joomla Checkboxes, добавить понятный порядок настройки опций; данные/БД не менять, RU/EN и тесты.
- **V6-A:** общий справочник опций и значений, категории с обязательностью/необязательностью, новый компактный редактор опций и SKU с совместимостью существующих SKU.
- **V6-B:** категория → правила похожих и сопутствующих, автоматический подбор только опубликованных товаров, тесты AND-условий, наследование, отсутствие дублей.
- **V6-C:** справочники брендов и коллекций, поля товара, SEO-лендинги и маршруты.
- **V6-D:** глобальный/категорийный учёт остатков, master/detail карточка SKU, проверка availability в заказе, затем импорт/экспорт, фильтры, фиды, корзина.
- Перед любым SQL upgrade на реальной `minimarket` сделать backup. Только ветка `development`; ядро Joomla не менять. PHP/MySQL/ZIP CI + отдельная **ручная** проверка Joomla, особенно после установки.

## Приёмка 0.5.33

Открыть Joomla → MiniMarket → Товары → редактировать → **Связи товаров**. Вместо синего высокого списка должны быть компактные флажки, доступен одновременный выбор нескольких связей. При сохранении обе связи остаются и состав каждой виден ниже. В главном меню — «Связи товаров», редактор/список без выбора «Похожие, Сопутствующие, Коллекции, Исполнения». В редактировании связи — штатные флажки для товаров-участников; прежние данные сохранены. Вкладка опций теперь объясняет **реальную последовательность** текущего создания SKU и не заявляет о пока не реализованных глобальных опциях. RU/EN и тёмная тема обязательны.

# MiniMarket V7 — согласованные правила и дорожная карта реализации

**03.11.2026. Главный действующий документ.** Основание: проверка версии 0.5.33 в Joomla 6.2.0, screenshots of «Товары в связи» с PHP Warning и широкой матрицей SKU. Этот документ заменяет устаревшие решения V4/V5/V6 там, где они противоречат изложенному ниже. Рабочая ветка только `development`; ядро Joomla и `main` не меняем. **Не отмечать функциональность ГОТОВО до кодовой реализации, CI и браузерной проверки.**

## Структура панели MiniMarket

1. **Категории** — дерево, контент, изображение, SEO, информационные характеристики, назначение опций, правила похожих и сопутствующих.
2. **Товары** — каждый товар отдельный (без «альфа-товара»), собственные URL, галерея, SEO и список продаваемых SKU.
3. **Связи товаров** — вручную созданные группы самостоятельных товаров, пересечения M:N допустимы. Никаких типов «похожие», «сопутствующие», «коллекция»; только перелинковка и состав. Список товаров не становится иерархией групп.
4. **Бренды** — отдельный справочник с изображениями, описанием, SEO, лендингом и опубликованными товарами данного бренда.
5. **Коллекции** — отдельный справочник с изображениями, описанием, SEO, лендингом, товары могут входить в несколько коллекций.
6. **Характеристики** — информационные параметры и фильтрация; не создают SKU.
7. **Опции** — общий справочник опций заказа, повторно используемый во многих категориях; задаёт значения (например, Размер → S/M/L), но не является характеристикой или связью товаров.

Опции, бренды, коллекции, правила рекомендаций должны стать **реальными** разделами/формами и работать, а не быть только строками меню с неработающими действиями.

## Опции и SKU: целевой пользовательский процесс

1. В разделе **Опции** один раз создаём «Размер» и значения S, M, L, XL. Коды/ID значений стабильны, публикация и порядок редактируются в нативной компактной форме Joomla. При необходимости возможны цвета с HEX/фото без второй сущности.
2. В **Категории → Опции** назначаем глобальную опцию и правило: Наследовать / Не использовать / Необязательно / Обязательно. Дочерняя категория может изменить правило родителя. Обязательность означает, что покупатель не может оформить товар без выбора разрешённого значения. Необязательность требует явно допустимой «без выбора» комбинации; не пытаться автоматически продавать несуществующий SKU.
3. В **Товар → Опции заказа** выбираем из опций категории только значения, реально предлагаемые для этого товара. Нельзя каждый раз заново создавать словарь значений в карточке.
4. В том же разделе строится **компактная матрица пересечений выбранных значений** (размер × цвет × другие опции), одна строка на возможную комбинацию. Столбцы: активировать / значения / SKU (может быть пустым) / цена (по умолчанию цена товара, при необходимости переопределяем) / остаток (только при учёте по сочетаниям) / подробности. **Не все комбинации обязаны существовать**.
5. Артикул конкретной комбинации **необязателен**. Уникальность требуется только для непустых SKU; внутренний variant_id и выбор комбинации остаются уникальными. Для пустого SKU хранить NULL в MySQL при уникальном индексе; никогда не создавать одинаковые фиктивные артикулы. Для синхронизации с поставщиком использовать внешний ID, а не отсутствие SKU.
6. Общий запас: у товара один остаток; у каждой строки матрицы отдельного поля количества нет, сохранённые старые остатки не обнуляются. Раздельный запас: у каждого активного сочетания свой остаток. Режим выключения складского учёта — глобально, с возможными политиками категорий (следующая фаза).
7. Дополнительные медиа/HTML/видео варианта открываются через «Подробности» в отдельной секции, а не разворачиваются десятками столбцов таблицы. При переключении значения на сайте недоступные комбинации и значения должны отключаться. Один URL товара, вариант — SKU внутри него.
8. Сохранение требует серверной проверки полного валидного сочетания, уникальных непустых SKU, правильных остатков и публикации; кнопки браузера сами по себе не являются защитой. Переход от существующих product-local `variant_dimensions` к общим option_id/value_id только с сохранением вариантов, цены, остатков, фото, SEO и variant_id. **Без параллельного второго движка SKU и без автосопоставления по одинаковым названиям.**

## Правила рекомендаций в категории

**Похожие:** по умолчанию другие опубликованные товары той же категории; можно указать одну или несколько категорий и нужные совпадающие характеристики. По выбранным характеристикам действует AND; для множественных значений требуется пересечение по каждому выбранному атрибуту. Предел количества, сортировка, наследование и отсутствие дублей.

**Сопутствующие:** по умолчанию пусто; администратор указывает категории-источники (например, Топки → Дымоходы/Аксессуары) и при необходимости правила совместимости по характеристикам. Не связывать это с ручными «Связями товаров». Источником являются опубликованные товары/категории; ручное удаление SKU не должно менять правила.

Интерфейс категории на вкладке «Рекомендации»: два последовательных блока с полями «Категории-источники», «Совпадение характеристик», «Количество/порядок». Не использовать непонятные скрытые настройки.

## Бренды и коллекции

Бренд: отдельный справочник, один бренд на товар (или нет), лендинг с описанием, лого/обложкой, SEO/OG, списком опубликованных товаров, фильтрами и ссылкой из карточки. Коллекция: отдельный справочник с аналогичным лендингом, несколько коллекций для одного товара. Ссылки должны использовать маршрутизатор Joomla и не конфликтовать с URL товаров и категорий. Для существующих данных не выводить «магические» бренды из строкового атрибута. Витрина может отображать бренд/коллекции как свойства, но источник истины — справочник.

## Конкретные проблемы 0.5.33 и меры

- `Warning: Undefined property: stdClass::$checked` из Joomla `layouts/joomla/form/field/checkboxes.php`: два кастомных поля добавляют `HTMLHelper::_('select.option')` без `checked`. Присваивать `checked` каждой опции по фактически выбранным ID. Проверить сохранение/редактирование связей без предупреждений и в тёмной теме.
- Не оставлять огромный синий `select multiple`; UI связей с нативными чекбоксами/поисковым выбором, понятными заголовками и адекватной высотой. Если сотни товаров — добавить поиск, а не сотни строк на одном экране.
- Текущая вкладка SKU перегружена вложенными таблицами и горизонтальным скроллом. Перепроектировать вокруг реальной матрицы активных сочетаний. **Нельзя скрыть поля цен/остатков, не сохранив данные и валидацию**.
- Каждая форма Joomla — штатные Toolbar, SearchTools, компактные поля и таблицы, RU/EN, светлая/тёмная тема, единая иерархия заголовков, понятные пустые состояния. Название вкладки в редакторе связи — «Товары в связи» (это корректно); сама связь может быть названа произвольно.

## Реализация по этапам — обязательный порядок

| Этап | Содержание | Критерий завершения |
| --- | --- | --- |
| **A0 / 0.5.34** | Исправление CheckboxesField; общий справочник Опции/Значения и назначение категориям (режим + наследование), SQL upgrade и fresh-install, RU/EN, тесты. | Можно создать «Размер S/M/L», сохранить и назначить обязательной в двух категориях. Нет PHP Warning. |
| **A1** | В товаре использовать только разрешённые справочником опции и значения. Безопасное связывание существующих локальных опций с ID глобальных. | В двух товарах один и тот же справочник, без повторного ручного создания списков. Старые SKU/ID/фото сохранены. |
| **A2** | Новая матрица SKU (активация комбинации, необязательный SKU, цена, режим остатка, подробности). Миграция `sku NULL` + серверные правила, компактная верстка. | Активные и неактивные сочетания корректны, нет горизонтальной прокрутки, пустой SKU законен. |
| **B** | Рекомендации похожих и сопутствующих по настройкам категории с наследованием, AND и серверной выборкой. | Категория Топки: похожие из выбранных категорий и по совпадающим параметрам; сопутствующие из заданных категорий. |
| **C** | Бренды и коллекции (CRUD, привязка к товару, лендинги, SEO, маршруты). | Клик по бренду/коллекции ведёт на самостоятельный лендинг и показывает связанные товары. |
| **D** | Глобальное и категорное включение складского учёта, проверка заказов, импорт/фиды. | Остатки не стираются при выключении; единая серверная проверка, экспорт/импорт по стабильным ID. |

**Статус на момент составления:** V6 имеет только товар/категория/характеристики/ручные связи и старый локальный редактор SKU. Справочник опций, A1/A2/B/C/D не считаются готовыми. После A0 потребуется ручной smoke локальной Joomla. Не ставить новую версию без успешного CI и резервной копии MySQL при SQL upgrade.

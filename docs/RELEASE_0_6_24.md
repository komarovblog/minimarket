# MiniMarket 0.6.24 — персональная очередь, приоритет и связи обращений

**Направления:** C06 (внутренние очереди/уведомления), C09 (обращения и поддержка), интеграция с C03 (CRM). Joomla 6, PHP 8.4/8.5, MySQL 8.4; только `development`. Не создавать новую сущность уведомлений, когда её источник — уже существующая заявка.

## Что работает

1. **Управление → Очередь задач**: четыре прежних источника (ожидающие оплаты заказы, проблемные доставки, открытые обращения и незавершённые возвраты) продолжают показывать ВСЕ незакрытые задачи. У каждой строки можно поставить личную отметку «Прочитано» или вернуть «Не прочитано». Это не закрывает проблему и не скрывает её из очереди; общий счётчик реальных задач не меняется.
2. Личная отметка хранится в `#__minimarket_queue_reads` по ключу `(user_id,source_kind,source_id)`; доступ только к собственной отметке текущего сотрудника Joomla. На каждой операции сервер проверяет `core.manage`, POST+CSRF, существующую нерешённую исходную запись, актуальный отпечаток её статуса/времени/последнего события и актуальный пользовательский ID. Устаревшая форма не может отметить новое событие прочитанным. Изменение приоритета/новое внутреннее сообщение/новый факт доставки снова делает задачу непрочитанной. При событиях в одну секунду учитывается ID последнего фактического сообщения/события.
3. **Обращения**: добавлен приоритет `normal/high` (по умолчанию обычный, старые обращения сохраняются), фильтр по приоритету, высокий приоритет выводится первым в очереди. При создании можно связать обращение с конкретным `Shipment` и/или `Return`, но только если эти записи реально принадлежат выбранному заказу. Проверка только серверная с блокировками. Никаких автоматических возвратов денег или складских остатков.
4. **Контекстные переходы:** создать обращение можно прямо из карточек заказа, доставки, возврата и покупателя. Соответствующие идентификаторы передаются формой и затем серверно перепроверяются; новые дублирующие разделы не создаются. К ранее привязанным доставке и возврату есть обратные переходы из карточки обращения. CRM показывает приоритет и статус обращения.
5. Нативный Joomla/Atum и Bootstrap 5, оба языка RU/EN, без собственных цветов и нового плагина.

## Границы

- Это **внутренние** отметки менеджеров, а НЕ отправленные покупателю уведомления. Настройки уведомлений и действующий `NotificationSender` не менялись.
- Клиентской переписки, SMS, Telegram/MAX, автоматической отправки ответов по почте и гарантированной доставки сообщений **нет**. Создание внутренней записи не объявляется исходящим письмом.
- Нельзя угадать покупателя по имени, email или телефону; сохраняется привязка только к верифицированному `Joomla user_id`.
- `read` не означает `resolved`. После закрытия исходного объекта он исчезает из рабочего списка по его бизнес-статусу, а не по личной отметке.
- В выводе очереди по каждой категории максимум 100 текущих записей; полный список открывается в соответствующем разделе. Число проблем считается из исходных таблиц, а не из отметок.

## Локальная браузерная приёмка

Перед установкой — резервная копия БД. Стандартная команда:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\OSPanel\home\minimarket.local\scripts\release-to-desktop.ps1"
```

В Joomla обновить компонент ZIP `com_minimarket-0.6.24.zip`. Joomla применяет SQL-миграцию автоматически, ручной импорт демонстрационного SQL **не нужен**. Независимый модуль тулбара остаётся как есть.

Сценарий: два сотрудника с `core.manage` открывают очередь, один отмечает запись прочитанной (у второго она остаётся непрочитанной), затем в исходной карточке меняется статус/появляется сообщение и личная отметка сбрасывается. Из заказа/доставки/возврата/покупателя создать обращение с подставленными ID; попытку привязать чужую доставку сервер должен отклонить. Проверить RU/EN, светлую/тёмную Atum, мобильную ширину, права пользователя без `core.create`, историю внутренних сообщений и прежний checkout. Только после реальной проверки статус «принято».

**Выход:** реализовано + интегрировано + автотесты PASS; браузерная приёмка ожидается.

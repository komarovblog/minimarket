# MiniMarket 0.5.80 — возвращение checkout без регистрации

**Дата:** 10.11.2026. **Ветка:** `development`.

## Назначение

По решению пользователя сначала доводим до финального вида оформление, корзину, доставку, оплату и управление заказами без реальной регистрации/авторизации. SMS и ID-провайдеры подключаются **после** согласования UX. Запрет гостевого оформления из 0.5.79 был преждевременным.

## Что изменено

- Неавторизованный посетитель снова может заполнить форму и создать **заказ-заявку** с `user_id=0`; пользователю Joomla заказ связывается с его `user_id`.
- Форма доступна независимо от входа. Контакты заполняются вручную: имя и телефон обязательны, email и комментарий — нет. Проверки CSRF, nonce, корзины, серверной цены/SKU/остатков, SQL-транзакции и одноразового checkout key сохранены.
- Подтверждение заказа проверяется через сессию, где запрос был успешно отправлен. Для анонимного заказа `user_id=0` подтверждение видно только анонимной исходной сессии; для входящего пользователя дополнительно проверяется owner user_id. Нельзя получить сведения другого заказа по URL.
- Нет фальшивого SMS, фиктивной регистрации, активации через код, автоматического создания Joomla account и попыток оплаты.
- Сервисы PhoneIdentity/PhoneOtp и аддитивные таблицы 0.5.79 оставлены в коде как **неподключённые** заготовки будущего этапа. 0.5.80 — без новой структуры БД, миграция `0.5.80.sql` — безопасный marker `SELECT 1`.
- Три отдельных доставочных файла: `com_minimarket-0.5.80.zip`, `mod_minimarket_toolbar-0.5.80.zip`, необязательный `minimarket_demo_gallery_filters_0_5_80.sql`. Последний **не импортировать** ради обновления интерфейса.

## Что пока нельзя считать готовым

- Выбор способа получения/адресов/ПВЗ и расчёт доставки; выбор способа оплаты и ЮKassa; реальная регистрация/SMS/ID; уведомления и личный кабинет. Это следующие продуктовые шаги.
- Исторические `user_id=0` и новые контактные заявки пока не переходят автоматически на будущий аккаунт. Понадобится отдельная безопасная политика привязки после подтверждения личности. Нельзя связывать по одному совпадению телефона/email.
- Заказ — неоплаченная заявка. Остаток не резервируется и не списывается.

## Проверки и установка

CI: `scripts/test-0-5-78-checkout.php` включает хранение guest/order snapshots; `scripts/test-0-5-79-auth.php` проверяет криптографическую основу без её использования в checkout; `scripts/test-0-5-80-checkout-phase.php` проверяет доступность формы и закрытость подтверждения заказа. Дополнительно PHP, MySQL 8.0/8.4 и Windows ZIP. GitHub CI не заменяет браузерный smoke.

После резервной копии на тестовой Joomla 6 проверить пустую и заполненную корзины, заказ без авторизации, заказ Joomla-пользователя, чужой session/order ID, невозможность повторного создания и сохранение цен/остатков.

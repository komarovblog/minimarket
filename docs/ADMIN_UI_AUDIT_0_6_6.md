# MiniMarket 0.6.6 — ревизия админ-интерфейса Joomla 6

**Эталон:** штатный Joomla / Atum, список категорий и материалов. Никаких изменений ядра, шаблона Atum или Blank. Отдельные кнопки, стили и формы должны использовать существующие Joomla/Bootstrap классы (`ToolbarHelper`, `joomla.searchtools.default`, `form-select`, `table table-striped`, `btn`), стандартные CSS-переменные текущей темы. **Проверка по исходникам и автоматические регрессии ≠ приёмка реальных экранов в браузере.**

## Зафиксированный единый контракт

- **Списки:** панель действий сверху, SearchTools с фильтрами/сортировкой, обязательная колонка `grid.checkall` + `grid.id` для выбора строк, табличная разметка Bootstrap и ограниченная `table-responsive mm-native-list-viewport`, пагинация. Массовые кнопки должны соответствовать реальному серверному действию, быть защищены ACL, POST и Joomla CSRF. Внешний вид — от Atum, без произвольной палитры.
- **Редакторы FormController:** Joomla toolbar `apply/save/cancel` над формой, `adminForm`, `uitab` и `renderFieldset`; основной раздел «Основное». Нельзя дублировать в теле кнопки с тем же действием, но другими цветами.
- **Нестандартные редакторы:** сохраняют свои реальные POST endpoint и политику прав доступа, но визуальная панель `btn-toolbar` над формой едина: сохранение зелёной кнопкой, отмена нейтральной `btn-outline-secondary`, красный только для удаления. Вкладки — родные Joomla.
- **Специальные таблицы:** SKU-матрица и списки выбора значений не превращаются в административные CRUD-списки. Для них действуют отдельные адаптивные ограничения; цветовая гамма всё равно наследуется от Joomla.

## Исправления 0.6.6 по замечаниям

1. **Редактор категории → Отображение:** добавлен отдельный синий инфоблок **«Сетка товаров»** перед параметрами расположения/числа карточек. «Сетка подкатегорий» остаётся отдельным; обе группы с независимым наследованием и сеткой XS–XXL.
2. **Редактор категории → Характеристики / Опции:** устранено противоречие старых CSS-ширин четырёхколоночных таблиц. Ширины по столбцам 32/30/20/18%; таблица ограничена своим скролл-контейнером, даже когда окно узкое. Поля «Использование в списке» стали native select «Показывать/Скрывать» вместо чекбоксов (прежнее хранение `v<ID>` не меняется). Колонка состояния не превращается в вертикальный текст.
3. **Создание заказа:** строка товара/артикула, категории, количества и «Удалить» выровнена; кнопка удаления небольшая `outline-danger` с родной иконкой и `aria-label`, а не большой красный прямоугольник выше поля. JS-клон строк использует тот же шаблон. Дублирующие кнопки сохранения внизу удалены — действие сверху едино.
4. **Редакторы отзывов, доставок, зон, фидов, SEO, промокодов, способов оплаты/доставки, настроек плагина:** сохранение/отмена перенесены или нормализованы в верхнюю панель действий. Опасный красный применяется только для удаления.
5. **Фиды и зоны:** добавлены полноценно работающие массовые операции для отмеченных строк, с ограничением числа ID, проверкой POST/CSRF/ACL, серверным списком целых положительных ID. У зон массового удаления нет.
6. **Способы:** общий список получил выбор строк и действие «Изменить». Редактор открывается по проверенному `scope` и одному выбранному встроенному способу либо реально установленному MiniMarket-плагину, не по произвольному URL.
7. **Верхний административный модуль:** самостоятельная версия `mod_minimarket_toolbar` **1.0.0**. При изменении компонента модуль не переустанавливается и не генерируется повторно. Для него существует **отдельная команда однократной сборки** `scripts/build-toolbar-package.ps1`. Изменён только номер манифеста пакета, интерфейс кнопки и разрешения прежние.

## Приёмка на локальной Joomla (обязательно)

- Проверить RU/EN, тёмную/светлую темы и ширину окна 375/768/1024/1440 px. У таблиц назначения категории проверить перенос текста, выпадающие Show/Hide и сохранение после reload. Для таблицы при 375px допускается **локальная** горизонтальная прокрутка, но не глобальная прокрутка страницы.
- Пройти каждый список: выделить один и несколько элементов, массовая публикация (где предусмотрено), снять выделение, поиск, фильтры, сортировка и страницы списка. Проверить отсутствие кнопок без реального действия.
- В списках способов выбрать одну строку и «Изменить», убедиться в правильном экране. Выбор нескольких должен отвергаться; массовые изменения настроек плагинов не поддерживаются.
- В фидах проверить один и несколько ID, batch publish/unpublish и удаление **на тестовых данных**, сохранение XML.
- В заказах создать две строки, проверить позицию удаления на desktop/mobile, удалить одну и сохранить заказ.
- В модуле после обновления компонента проверить верхнюю ссылку. ZIP 1.0.0 установить один раз как обычное обновление существующего модуля, сохранить его позицию в статусной панели Joomla.

## Что не следует считать проверенным без браузера

Автотесты не подтверждают реальную пиксельную геометрию Atum и чужие CSS-переопределения администратора. При несовпадении скриншота с контрактом исправлять конкретный селектор в коде, не создавать новую палитру или общие глобальные CSS-хуки. Модуль 1.0.0 не создаётся при стандартном выпуске ZIP компонента.

# MiniMarket 0.3.10 — один основной пункт меню в настройках компонента

**Дата:** 01.11.2026. **Статус:** исходники `development`; GitHub CI PHP/Windows проверен отдельно, локальная Joomla/OpenServer **RUNTIME NOT RUN**.

## Согласованный контракт

- В **Компоненты → MiniMarket → Настройки → Общие** ровно одно поле **«Основной пункт меню для ссылок»**; значения **«Автоматически»** (по умолчанию) или один опубликованный обычный Joomla пункт `MiniMarket → Магазин`, например `Главная (/)` или `Каталог (/catalog)`.
- Нет галочек `shop_primary_route` в настройках отдельных пунктов меню; не требуется собственный Joomla-плагин и пакет `pkg_minimarket.zip`. Официальный артефакт установки теперь **один компонентный `com_minimarket.zip`**.
- Можно создать сколько угодно открытых пунктов MiniMarket. У каждого собственные URL и настройки `show_categories`, `show_products`, сортировки и количество товаров. Глобальный выбор влияет **только на автоматически создаваемые ссылки и canonical категорий и товаров**, не на URL собственных страниц магазина.
- «Автоматически» → опубликованный пункт MiniMarket, назначенный главной, иначе опубликованный пункт MiniMarket с наименьшим ID. Если явно выбранный пункт удалён или снят с публикации, безопасно срабатывает тот же fallback; пункт другого компонента, скрытый/неопубликованный/alias не принимается.
- Исторические флаги `shop_primary_route`, оставшиеся в JSON некоторых старых пунктов Joomla, **игнорируются** и не удаляются из пользовательской БД. При переходе со старого выбранного `/catalog` на автоматический `/` URL категорий/товаров могут измениться, поэтому после обновления вручную выбрать желаемый базовый пункт из одного списка. Не вводить 301 редиректов без отдельного SEO согласования.
- Joomla Menu Item Alias — обычная навигационная ссылка на другой пункт, не самостоятельный основной пункт MiniMarket; его нет в выпадающем списке.
- Никаких изменений структуры БД, товаров, категорий, Joomla core или пользовательского `.osp/project.ini`.

## Один набор локальных команд

Из **CMD** в `C:\OSPanel\home\minimarket.local`:

```bat
git status --short
git pull --ff-only origin development
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-router.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-shopmenu.php
"C:\OSPanel\modules\PHP-8.5\php.exe" scripts\test-catalog.php
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\inspect-package.ps1
```

Должны появиться `ROUTER_TEST_OK`, `SHOPMENU_TEST_OK`, `CATALOG_TEST_OK` и **`PACKAGE_OK: 0.3.10`**. Запуск на GitHub CI не заменяет локальную проверку. При любом FAIL прекратить установку, сообщить короткий текст ошибки. Известный изменённый `.osp/project.ini` не перезаписывать, не делать `git reset --hard`/очистку.

После PASS использовать **Система → Установка → Расширения** Joomla и **`dist/com_minimarket.zip`** поверх 0.3.8/ранее установленного компонента. **Не устанавливать `pkg_minimarket.zip`**; эта схема отменена, и старый файл может лежать локально от прошлых сборок. Компонент, существующие пункты меню и данные не удалять.

## Smoke в установленной Joomla 6.2

1. Убедиться, что главная MiniMarket `/` и второй обычный пункт «Каталог» `/catalog` одновременно опубликованы и открываются. Ничего специально не пересоздавать.
2. В **Компоненты → MiniMarket → Настройки → Общие** должна быть одна выпадающая настройка «Основной пункт меню для ссылок». Варианты **«Автоматически»**, **«Главная»**, **«Каталог»** с путём и ID. В форме **самого пункта меню** переключателя больше нет; независимые настройки категорий и товаров сохранены.
3. Выбрать «Автоматически», сохранить. Ссылки товара и категории при MiniMarket на главной должны быть `/product/testovyj-tovar-1` и `/category/testovaa-kategoria-1`.
4. Выбрать в **общих настройках** «Каталог» (`/catalog`), сохранить. Ссылки из каталога/главной на товар/категорию и их `rel=canonical` должны стать `/catalog/product/testovyj-tovar-1` и `/catalog/category/testovaa-kategoria-1`.
5. Выбрать обратно «Главная», сохранить. Ссылки должны снова стать `/product/...` и `/category/...`; `/catalog` и `/` остаются доступными каждый со своим canonical.
6. Проверить, что `show_categories`, `show_products`, сортировка, пагинация работают независимо для двух пунктов, а товар `TEST-001` сохранил цену `1990.50`, остаток `2`, обычное сохранение категории/товара по-прежнему работает.
7. Не создавать фальшивых товаров и не удалять пункты ради теста fallback. Mock-тест `scripts/test-router.php` покрывает случай отсутствующего выбранного Itemid, а реальный сценарий можно испытать позже без риска для работающего сайта.

**Важно:** до Joomla runtime нельзя утверждать, что новый тип Joomla поля Options уже работает в реальной админке. Если вместо поля ошибка «Unknown field type Shopmenu» или похожая — сообщить её, не менять Joomla core или вручную таблицу `#__extensions`.

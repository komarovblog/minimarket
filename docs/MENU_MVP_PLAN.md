## Решение по объёму

**Не строить заранее всю панель опций.** Новинки, популярные, ручные подборки и фильтры по характеристикам — **не параметры страницы, а отдельные модули Joomla**, после появления соответствующих данных и проверенной логики. Разрабатываем пункт меню и добавляем параметры только тогда, когда соответствующая функция уже реализована и её можно проверить в Joomla. Запрещены настройки-пустышки, сложная универсальная схема конфигурации, скрытые/автоматические пункты меню и самостоятельное дублирование настроек модулей.

### Этап 0 — устранить уже известный дефект, независимо от нового роутера
- В `development` уже есть 0.3.3: исправлены `COM_MINIMARKET_CATALOG_MENU_TITLE/DESCRIPTION` в административных `*.sys.ini`.
- Не объявлять исправление VERIFIED, пока не выполнен Windows `build/inspect`, штатный Joomla upgrade и проверка, что в выборе типа пункта меню видны нормальные подписи. Существующий `/catalog` на локальной Joomla сохраняем до тестов новой схемы.

### Этап 1 — минимальный обычный пункт меню «MiniMarket — Магазин»
- На основе существующего site `catalog` view (внутреннее `view=catalog` можно сохранить ради совместимости) дать пользователю понятное имя типа пункта **«Магазин»**, без дополнительного вида/компонента.
- Joomla уже предоставляет **название, alias, публикацию, назначение главной, доступ, язык и привязку модулей** — не повторять эти поля в настройках MiniMarket.
- **Единственный собственный параметр для первого этапа:** `show_categories` («Показывать категории» = Да по умолчанию). Он реально управляет существующей выдачей опубликованных категорий; при «Нет» сама страница работает, но содержимое можно собрать модулями Joomla. Никакой неработающей настройки «Показывать товары» до создания общего списка товаров.
- Администратор создаёт **один обычный опубликованный пункт**, который либо назначает главной `/` отдельного ИМ, либо размещает как раздел `/shop` на другом сайте. Никакого скрытого/служебного меню, автопубликации, правок ядра или `.htaccess`.
- Сохранять настройки штатным `<fields name="params">` меню Joomla. При отсутствии обычного пункта магазина в конфигурации — понятное сообщение администратору; **не создавать fallback Itemid**.
- В этой точке не вводить отдельную глобальную опцию «основной Itemid», пока действует контракт **одного** опубликованного пункта MiniMarket. Если позже понадобятся несколько видимых пунктов, отдельным решением добавить явный выбор канонического, но сейчас не усложнять.

### Этап 2 — независимые корректные маршруты категорий/товаров
- Реализовать маршруты `/category/{alias}-{id}`, `/product/{alias}-{id}` если пункт магазина главная, и `/shop/category/{alias}-{id}`, `/shop/product/{alias}-{id}` если обычный пункт находится по `/shop`.
- Joomla SEF через штатные `Itemid`, `preprocess/build/parse`, единый `RouteHelper`, `SeoHelper`; ссылки из любой страницы, модуля и карточки ведут на **единственный обычный пункт**.
- Критерии PASS на Joomla: оба сценария, клик и прямой ввод URL, published/unpublished (404), корректный absolute canonical, отсутствие чужого Itemid, отсутствие дублей; админский CRUD не ломается. Старые `/catalog/{alias}-{id}` на локальном стенде обрабатываются безопасно — 301 с однозначным сопоставлением либо документированный переход до публичного релиза. Не менять старое меню до готового тестового пакета.
- При перемещении самого магазина `/` ↔ `/shop` адреса изменятся. Это отдельная миграция с проверкой 301/canonical, не настройка «безопасно переключить в один клик».

### Этап 3 — общая выдача товаров и только тогда параметры её отображения
- Реализовать выборку всех опубликованных товаров с серверной пагинацией, исключить товары неопубликованных категорий.
- Добавить в `params` пункта меню **«Показывать товары»** (Да/Нет), **число товаров на странице** и **сортировку** (с проверенными вариантами). Не добавлять популярность/новинки/ручную подборку/фасетные фильтры как меню-настройки: это отдельные модули, реализуемые позже.
- Если оба переключателя «Категории» и «Товары» выключены, view пустой, но допускает обычные назначенные Joomla Modules/баннеры; никакой скрытой торговой выдачи.

### Этап 4 — независимые модули
- `mod_minimarket_categories`: дерево/плитки и сквозное раскрывающееся меню.
- `mod_minimarket_products`: обычный список всех товаров либо по категории (с потомками), лимиты/пагинация.
- `mod_minimarket_popular`: **отдельный модуль популярных товаров** после определения источника популярности (например, число заказов).
- `mod_minimarket_new`: **отдельный модуль новинок** после определения даты появления и окна «новый».
- `mod_minimarket_selection`: **отдельный модуль ручной подборки** с явным списком товаров/порядком.
- `mod_minimarket_filters`: **отдельный модуль фильтров по характеристикам**, только после появления характеристик/фасетного поиска, с учётом текущей категории и безопасного canonical/noindex.
- Каждый вид блока создаётся отдельным штатным модулем Joomla; все они разделяют сервисы каталога, цены, наличие, выборки и RouteHelper. Параметры конкретного модуля относятся к модулю, параметры базовой страницы — к пункту меню; **никаких переключателей «популярные/новинки/подборка/фильтры» в параметрах пункта «Магазин»**.
- Модули могут отображаться на любых страницах и использовать ту же базу URL выбранного обычного пункта MiniMarket.

### Этап 5 — позже, вместе с реальными сущностями
- Дерево категорий, характеристики, фильтры и SEO-лендинги, комплекты, корзина, checkout/доставка/оплата, источники популярности, SEO/schema/dataLayer.
- Настройки меню/модулей вводить *только с реализованной функцией*, с обратной совместимостью и понятными значениями по умолчанию.

## Не делаем сейчас
- Большой экран параметров с неработающими полями; универсальный конфигуратор блоков, drag-and-drop конструктор, новые БД/миграции «на будущее».
- Скрытые/технические пункты меню или автоматическую публикацию пунктов. Никаких «магических» fallback URL.
- Не обещаем готовность по одному коммиту: 0.3.3 — i18n patch (runtime NOT RUN); **0.3.4 — код минимального меню/show_categories опубликован, но Windows/Joomla runtime NOT RUN**; роутер, общая выдача товаров и отдельные модули НЕ реализованы.

## Сохранность и тестирование
В `development` — маленькие логические изменения. При каждом обновлении: GitHub → `git pull --ff-only` → `scripts/build.ps1` → `scripts/inspect-package.ps1` → стандартная установка ZIP поверх текущей → реальный smoke. `main`, Joomla core, `.osp/project.ini`, старые категории/товары, база и `.env` не меняются.

Официальные механизмы Joomla: [menu item params](https://manual.joomla.org/docs/next/general-concepts/menus-menuitems/), [SEF router](https://manual.joomla.org/docs/next/general-concepts/routing/build/), [menu layout](https://manual.joomla.org/docs/next/building-extensions/components/component-development-tutorial/step02-menuitem/).

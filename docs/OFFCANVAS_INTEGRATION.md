# MiniMarket — контракт offcanvas-панелей для будущего Joomla-шаблона

**Статус:** решение по интерфейсу, без активного перехвата ссылок. Четыре параметра в «Общие → Команды интерфейса» уже сохраняются, но пока не выполняют переходы.

## Принцип

- Шаблон Joomla (включая отдельный проект лёгкого шаблона) создаёт фактические панели Bootstrap 5: `#offcanvas-cart`, `#offcanvas-filters`, `#offcanvas-account`, `#offcanvas-menu`. MiniMarket не меняет ядро Joomla и не создаёт скрытые offcanvas без шаблона.
- Фильтры, корзина и регистрация — **отдельные устанавливаемые модули** (как текущая отдельная верхняя панель), чтобы размещать их в обычных позициях Joomla. Модули пока **не реализованы**.
- Глобальные параметры MiniMarket `offcanvas_cart_target`, `offcanvas_filters_target`, `offcanvas_account_target`, `offcanvas_menu_target` — только ссылки на уже существующие id, не HTML и не произвольный JavaScript.
- Когда подключим, пользовательский клик по ссылке сначала проверит: id валиден (строго `#[A-Za-z][A-Za-z0-9_-]{0,63}`), элемент существует, доступен `bootstrap.Offcanvas` и модуль действительно установлен. Только после успешной проверки будет вызван `bootstrap.Offcanvas.getOrCreateInstance(target).show()`. В остальных случаях останется обычная рабочая ссылка `/cart`, `/category` или ссылка на страницу входа.
- Нельзя показывать кнопки регистрации, пока не подключён реальный способ входа. Временное гостевое оформление работает независимо от будущего offcanvas.
- Модули корзины и фильтров должны читать актуальное серверное состояние и поддерживать AJAX обновления; не дублировать внутреннюю реализацию каталога или цены в шаблоне.
- В будущем возможно несколько панелей одного типа на разных страницах, но текущий контракт намеренно ограничен одним ID на команду.

**Перед реализацией** согласовать позиции модулей в шаблоне, поведение на мобильном и события открытие/закрытие. До этого пользовательские ссылки не менять на `href="#..."` без работающей панели.

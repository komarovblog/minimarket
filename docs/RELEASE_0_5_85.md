# MiniMarket 0.5.85 — админка и промокоды (11.11.2026)

## Сделано
- Промокоды: схема 0.5.85 добавляет процентную или фиксированную скидку, сроки в UTC, минимум корзины, общий и персональный лимит, область применения (весь каталог/категории/товары), разрешение сочетания скидок и счётчик использований.
- Промокоды: создание и редактирование с серверной валидацией, проверкой существования целевых ID, нативные вкладки и верхние кнопки, ссылка из списка в редактор.
- SEO-страницы: создание и редактирование на вкладках «Основное / Фильтры / SEO», WYSIWYG-редактор Joomla для вступления и описания, серверная очистка HTML, выбор опубликованных значений характеристик вместо ручного ввода mmf; старые значения других типов фильтров при редактировании сохраняются.
- Исправлены маршруты формы создания заказа и отзыва; интеграции показывают только реально установленные плагины, ссылки на их настройки; при создании доставки есть поиск и фильтр дат (по загруженным записям).
- Группы глобальных настроек больше не сворачиваются; доработан контейнер таблиц для масштабирования.
- Встроенный механизм 0.5.84 архивации устаревших SQL-файлов теперь допускает версии новее 0.5.83. Иные несовпадения схемы НЕ исправляются автоматически.
- Версия компонента и самостоятельного модуля 0.5.85; новая аддитивная миграция и полный комплект накопительного демо-SQL для сборки.

## Границы и обязательная проверка
- Это **не завершённая настройка скидок**: checkout не применяет промокоды, used_count не увеличивается. Включать применение до транзакционного учёта и защиты от повторного списания запрещено.
- SEO-подбор сейчас охватывает опубликованные словарные значения характеристик. Следующие задачи: системные и числовые фильтры, опции SKU, медиаполе Joomla/OG, предпросмотр и более строгая проверка совместимости выбора с категорией.
- Доставка: текущий курьерский тариф — город/цена/порог бесплатной доставки. Зоны по региону/индексам, вес/габариты, CDEK API и общий реестр тарифных плагинов не завершены.
- **Не нажимать «Исправить» в проверке БД Joomla без резервной копии и отдельной проверки SQL.** Предыдущий SQL syntax error около `AND 'null' = 'NO'` не подтверждён исправленным.
- В связанной среде невозможно запустить локальный `minimarket.local`, проверить установку SQL, CRUD и изменение масштаба браузера: эти проверки остаются обязательными перед приёмкой.

## Порядок установки на локальную Joomla
1. Создать полную копию БД и текущего кода MiniMarket.
2. В PowerShell из корня репозитория:
   ```powershell
   git pull --ff-only origin development
   .\scripts\release-to-desktop.ps1 -SkipPull
   ```
3. Установить `com_minimarket-0.5.85.zip` через Joomla → Система → Установка → Расширения. Не импортировать SQL миграции вручную после успешной установки компонента.
4. Проверить `#__schemas` для com_minimarket, структуру `#__minimarket_promo_codes`, редактор промокода (создание, редактирование, повторяющийся код, неправильные сроки, категория/товар), SEO-редактор и создание заказа/отзыва.
5. Проверить светлую/тёмную тему, RU/EN и масштаб 90%, 100%, 125%, 150%. Отдельно проверить корректность Joomla Maintenance: Database; если снова ошибка — снять точный SQL и не продолжать автоисправление.

Демо SQL `minimarket_mysql84_nnop3_update_0_5_85.sql` не меняет актуальные правила промокодов и нужен только для тестового каталога; он не требуется для обновления компонента.

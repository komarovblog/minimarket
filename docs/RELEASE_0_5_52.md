# MiniMarket 0.5.52 — комплекты, цены, поиск, левое меню Joomla

Дата 05.11.2026. Рабочая ветка `development`. Это продолжение 0.5.51 без пересоздания каталога и без изменений ядра Joomla.

## Принятые решения по структуре

1. **Отдельный раздел «Комплекты» в админке**, при этом совместная основа `#__minimarket_products` с `product_type='bundle'`, общие поля товара/категория/URL/SEO/изображения. Состав остаётся в `#__minimarket_bundle_items`. У комплектов собственный базовый артикул. В списке товаров теперь только обычные товары, в списке комплектов только комплекты.
2. **Отдельные «Связи товаров» и «Связи комплектов»** как отдельные списки и сохранение: используем существующую таблицу именованных групп `#__minimarket_product_groups`, где `type='bundle'` отличает связи комплектов, остальные типы — связи товаров. Состав комплекта и связи комплектов — **не одно и то же**. Валидатор состава разрешает вложенность комплектов (до 8 уровней) без циклов; валидатор связей допускает только участников правильного типа.
3. **Цены комплектов:** новая безопасная миграция `0.5.52.sql` добавляет `bundle_price_mode='fixed'|'discount'` и `bundle_discount_pct` (0–100% с 2 десятичными знаками). По умолчанию у всех существующих товаров/комплектов `fixed`; поле `products.price` сохраняется. При fixed берём собственную цену, при discount считаем цену компонентов с учётом количества и **итоговых** цен вложенных комплектов, применяем процентную скидку и округляем результат до копеек. Изменение цен исходных товаров динамически меняет скидочные комплекты. Списание/резервирование и фиксация цены в заказе — будущий этап корзины.
4. **Поисковое добавление:** коллекции в карточке — компактные выбранные позиции и кнопка «+ Добавить в коллекцию», поиск по названию/alias; состав комплекта — кнопка «+ Добавить товар или SKU», поиск по названию/артикулу и категории, выбор конкретного SKU с количеством. При удалении позиции она только исключается из состава/назначения при сохранении родительской карточки, не удаляя товар/коллекцию. Серверные GET endpoints с ACL, CSRF, лимитом 25 результатов; вывод текстом, без unsafe HTML. Интерфейс RU/EN.
5. **Левое меню Joomla 6:** штатный манифест компонента `minimarket.xml`, иконка корзины (`img="class:cart"`), нативные Joomla `menu-quicktask` и 6 `type="separator"`, без вмешательства в ядро. Порядок: Категории (+) → Товары (+), Комплекты (+) → Связи товаров, Связи комплектов → Характеристики, Опции → Бренды → Коллекции → Экспорт/Импорт. У каждой ссылки есть реальный MVC-путь.

## Защита данных

- **Только аддитивная миграция**, никаких DROP/DELETE, варианты SKU, stock и галерея не изменяются; базовые и связующие сущности сохраняются.
- Список групп разделён по типу; сервер не позволяет привязать обычный товар в «Связи комплектов» и наоборот.
- Для комплекта с сохранённым составом нельзя молча переключиться на обычный товар и стереть компоненты.
- Цены считаются только для отображения; базовое значение `products.price` не переписывается.
- Взаимозависимые вложенные комплекты при сохранении проверяются на циклы.

## Данные для проверки

Опциональный отдельный `sample-data/minimarket_bundle_prices_demo_0_5_52.sql` для базы `minimarket`, префикс `nnop3_`: показывает фиксированную цену комплекта 1090, скидку 10% у 1091 и скидку 15% у вложенного 1092. SQL применяет настройки **только** к исходным демо-SKU `BUNDLE-1090/1091/1092` при неизменённых прежних настройках. Повторно исполним, без удаления/пересоздания каталога. Для нового UI и меню отдельный SQL **не нужен**, он нужен только для готовых примеров двух режимов цены.

## Приёмка

1. Создать резервную копию MySQL базы. Установить `com_minimarket-0.5.52.zip` поверх 0.5.51. Автоматическая миграция добавит два поля цены; **старый SQL каталога не запускать**.
2. Проверить левое меню: иконка MiniMarket, шесть разделителей, «+» возле категорий, товаров, комплектов, каждую ссылку и создание соответствующей сущности; важно проверить и после перезагрузки панели администратора Joomla.
3. В карточке обычного товара выбрать «Бренд и коллекции», нажать «Добавить в коллекцию», найти по названию, добавить две, сохранить, переоткрыть и снять одну без потери другой. Начальный список всех флажков должен исчезнуть.
4. В карточке комплекта — вкладка «Состав комплекта»: найти товар по имени, вариант по SKU, отфильтровать по категории, добавить и задать количество; сохранить и переоткрыть. Проверить, что старые комплекты 1090–1092 сохранили свой состав.
5. В списке «Комплекты» должны быть именно комплекты, а в «Товары» — обычные товары. Вкладка «Связи комплектов» должна позволять создать именованную связь с **только комплектами**, а «Связи товаров» — только обычными товарами.
6. Попробовать скидку 10%: итог должен изменяться при изменении цены исходного товара. Вложенный комплект должен учитывать итоговую цену внутреннего комплекта. Фиксированная цена остаётся постоянной.
7. При необходимости импортировать **только** `minimarket_bundle_prices_demo_0_5_52.sql` как пример. Никаких новых таблиц или сброса данных не требуется.
8. Проверить сохранность SKU, матрицы, фотографий и категорий. Если меню не обновилось после установки, проверить кэш админки и установленное расширение; не удалять Joomla.

**Ограничения:** не выполняли браузерное тестирование непосредственно на `minimarket.local`; требуется приёмка пользователя. Возможности оформления заказов/резерва остатков, полного импорт/экспорта и публичного редизайна будут следующими этапами.

# MiniMarket 0.4.2 — одна приёмка на существующей Joomla

Дата: 01.11.2026. GitHub development, CI PASS; локальная Joomla 0.4.2 ещё НЕ проверена.

## Подготовка

1. Сделать резервную копию базы данных Joomla средствами phpMyAdmin. Не удалять компонент или Joomla.
2. В CMD открыть C:\OSPanel\home\minimarket.local и выполнить git status --short. Не сбрасывать изменённый .osp/project.ini.
3. Выполнить git pull --ff-only origin development.
4. Запустить проверки: php scripts/test-router.php; php scripts/test-catalog.php; php scripts/test-category-tree.php; php scripts/test-admin-category-tree.php; php scripts/test-admin-options.php. Использовать C:\OSPanel\modules\PHP-8.5\php.exe вместо php, если он не в PATH.
5. Выполнить powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1, затем такой же вызов для .\scripts\inspect-package.ps1. Ожидается PACKAGE_OK: 0.4.2. Не выполнять scripts/test-category-schema.php на пользовательской БД — он только для одноразовой CI-схемы!
6. В Joomla Система → Установка → Расширения загрузить единственный ZIP dist/com_minimarket.zip поверх существующего com_minimarket. Миграции применяются штатным установщиком. Не выполнять ALTER TABLE вручную.

## Проверка в Joomla

1. MiniMarket → Категории: построить тестовую иерархию из 3 уровней. В списке проверить отступы, раскрытие, название, миниатюры изображения (включая пустые), порядок, статус и ID.
2. Проверить прямое и суммарное количество товаров на примере родителя и двух дочерних категорий. Поиск по самому нижнему узлу должен оставить его предков для контекста. Фильтр неопубликованных записей не должен менять состояние ни одной категории.
3. Редактор: вкладки Основное, Описания, Отображение, SEO и соцсети, Публикация. Оба описания являются визуальными Joomla Editor. В тестовой категории вставить жирный текст и список в оба поля, выбрать Media и alt; сохранить и открыть снова.
4. Убедиться, что описание выводится на публичной странице с форматированием. URL категории остаётся плоским /category/alias-id, без имён родителей.
5. Попробовать сменить родителя тестовой категории; в списке доступны иерархические уровни, но запрещены сам объект и его потомки. Проверить сохранение и отсутствие циклов.
6. Установить для тестовой категории SEO title, meta description, robots noindex,follow, OG title, description и image. Проверить HTML head на публичной странице: title, description, robots, OG, один canonical. Очистить отдельные поля и убедиться в применении fallback, без копирования fallback в БД.
7. Проверить флаги «Показать подкатегории/товары» со значениями Наследовать/Да/Нет и Options. Скрытый блок не должен показывать ложное сообщение о пустоте.
8. Снять с публикации только тестовую родительскую категорию: её потомки исчезают с витрины, но сохраняются в админке. Вернуть тестовые записи к исходному состоянию.
9. Проверить действующий товар TEST-001: ID, SKU, цена, остаток и URL не изменились. Основной пункт меню Shop, каталог и canonical остаются рабочими.
10. При ошибке сообщить номер проверки, URL, краткий симптом или скриншот; не удалять записи/компонент и не исправлять БД вручную.

**PASS:** сохраняются все поля редактора, дерево/фильтры/миниатюры и счётчики корректны, публичные SEO/OG и маршруты корректны, старый товар не затронут. Только после ручного PASS обновлять ROADMAP как выполненный. Следующий этап — товары.

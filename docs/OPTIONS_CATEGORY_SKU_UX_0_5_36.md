# MiniMarket 0.5.36 — опции и категории как характеристики, компактные формы

**04.11.2026. Промежуточная реализация после снимка широкого скролла в карточке опции.** Основной курс V7 сохраняется: **Опции (справочник) → Категории (назначения) → Товар (выбор значений) → Матрица SKU**. Не путать текущий выпуск с завершённой A1/A2 интеграцией; автоматическая двусторонняя синхронизация идентификаторов глобальных значений со SKU ещё требует отдельной миграции и проверки.

## Что исправлено в 0.5.36

1. В карточке опции добавлена вкладка **«Категории»**, идентичная обратной привязке характеристик. Все категории показаны с вложенностью; для каждой — `Наследовать / Не использовать / Необязательно / Обязательно`. Изменения сохраняются в **той же таблице `#__minimarket_category_order_options`**, что и на вкладке «Опции» карточки категории, а не в новой таблице. Сохранение опции, значений и назначений происходит в одной транзакции. Сохраняются назначения других опций.
2. **Значения опции**: вместо длинной горизонтальной repeatable-table — нативный `joomla.form.field.subform.repeatable` и адаптивные компактные строки. Данные `value_id/code/title/HEX/status` не меняются, порядок определяется штатным перемещением.
3. В **Товар → Опции заказа** выводится отдельный блок **«Опции категории»**: названия, значения и обязательность с наследованием от родительских категорий. Если категория ещё не сохранена, показывается инструкция; динамически загружать опции из несохранённой новой категории на этой стадии нельзя.
4. Кнопка **«Использовать опции категории»** доступна, если в товаре ещё нет ни одной локальной оси SKU, опций не больше 4, произведение числа значений не больше 200. Она заполняет **те же существующие native Joomla Subform оси и значения** и показывает таблицу возможных сочетаний. Пользователь отмечает реальные комбинации и добавляет SKU через существующую проверенную логику. Это **одноразовое явное копирование справочника**, а не незаметная синхронизация/перезапись: уже существующие локальные опции и SKU **не трогаются**. При смене категории сначала сохранить товар.
5. Редактор SKU больше не использует широкую repeatable-table: строки переведены на `repeatable` и адаптивное отображение. Видимые основные поля: сочетание, SKU, цена, остаток (при раздельном учёте), статус; фото, галерея, описания, видео скрыты за действующей кнопкой «Подробности SKU». Скрытые поля не отключаются, не удаляются из DOM и остаются в том же POST/транзакции. Матрица предпросмотра по-прежнему состоит из отметки и названия сочетания.
6. Аналогично вкладка характеристик категории и обратная вкладка характеристики используют единые компактные правила верстки. Компонентный CSS загружается на всех административных страницах MiniMarket через DisplayController; **ядро Joomla не меняется**.
7. **SQL не менялся**: версия 0.5.36 — UX/форма/сервис, миграции нет. Existing product ID, SKU, картинки, цены, остатки остаются на месте. Новая ссылка на категорию не превращается в SKU автоматически.

## Что остаётся для полной реализации A1/A2

- Стабильная связь каждой оси/значения товара с исходным `order_option_id/order_option_value_id`, а не локальная копия кода/названия. Изменения справочника после копирования **не синхронизируются автоматически** — сделать аддитивные FK и детерминированную миграцию с реальной проверкой конфликтов и существующих комбинаций.
- Выбор ограниченного набора значений из общего справочника внутри товара **без ручного редактирования локальной копии**; актуализация при смене категории, контроль обязательных опций на сервере, необязательное «не выбрано» без фиктивного SKU.
- Матрица с явной активацией каждой комбинации и редактируемыми SKU/ценой/остатком **в одной компактной таблице**, без промежуточного второго шага генерации. Для уже существующих SKU нельзя терять фото и variant_id.
- Пустой артикул SKU (NULL и уникальность непустых), режим общего остатка без количеств в строках матрицы; это отдельно влияет на БД и серверную валидацию, не включено в 0.5.36.
- Ручная проверка всех сущностей на реальной Joomla 6.2.0, особенно в мобильной и тёмной теме. CSS-проверка CI не заменяет browser smoke.

## Приёмка 0.5.36 в локальной Joomla

1. Открыть **Опции → Размер → Категории**; выбрать обязательную для «Конструкторы», необязательную для «Мягкие игрушки», сохранить, повторно открыть: правила на месте. В обеих категориях на вкладке Опции виден тот же результат. Изменить в категории: обратная вкладка опции показывает обновление.
2. Открыть **Опции → Размер → Значения**; поля S/M/L/код/HEX/статус без горизонтальной полосы. Переставить строки, сохранить и снова открыть: ID, значение, статус сохранены.
3. Открыть товар из категории с опциями: в «Опции заказа» видны назначенные значения, обязательность. На товаре **без ранее заданных осей** нажать «Использовать опции категории» и выбрать нужные сочетания — SKU создаются в старом серверном механизме, URL товара тот же.
4. На товаре с ранее заданными осями кнопка копирования не перезаписывает значения; убедиться, что ID, фото, цены, остатки и SKU сохранены. Не удалять оси ради повторного копирования, если в них сохранены SKU.
5. Проверить строки SKU: без горизонтальной прокрутки, фото/галереи/видео открываются в «Подробности SKU», сохраняются после закрытия и повторного открытия. Отображение отдельного остатка зависит от переключателя «общий / по сочетаниям».
6. Открыть Категории, Характеристики, Связи товаров, списки: нет принудительного горизонтального скролла на обычном десктопе, поля и таблицы не выходят за доступную ширину. RU/EN и тёмная тема.
7. Приёмка считается завершённой **только после** повторной установки, ручного smoke и проверки GitHub Actions (PHP 8.4/8.5, MySQL 8, Windows ZIP). До неё версия не считается проверенной в браузере.

# MiniMarket 0.6.23 — документы заказа и основа фискальных операций (C11, этап 1)

**Ветка:** `development`. **База:** Joomla 6, PHP 8.4–8.5, MySQL 8.4. **Реальная фискализация НЕ подключена.** Не объявлять эти документы законными фискальными чеками или подтверждением оплаты.

## Реализовано

- **Управление → Документы**: рабочий список с поиском, сортировкой и переходами на заказ и документ. Три точки входа: Joomla submenu, preset меню компонента и карточка главной панели с реальным количеством.
- **Заказ → Документы**: администратор с `core.admin` может создать один неизменяемый внутренний счёт по заказу. Повторный POST идемпотентен: возвращает ранее созданный документ и не создаёт второй. Отменённые и удалённые заказы без документа не допускаются.
- Снимок документа содержит **исходные строки заказа**, артикулы, количества, цены, скидку, доставку и общую сумму в копейках, плюс контактные данные заказа. Нельзя брать изменившиеся цены/названия из каталога. Проверяется целостность `sum(line_cents) = items_total_cents` и `total = items_total - discount + delivery_fee`. JSON хранится с SHA-256 и проверяется при чтении. Данные после создания не редактируются; нет перепечатки задним числом.
- Карточка документа внутри защищённой администратора Joomla отображает строки и итог, поддерживает системную печать браузера, везде сообщает **«не фискальный чек / не налоговый документ»**. Экспорта PDF, публичной отправки покупателю и юридических реквизитов продавца пока нет.
- **Настройки → Фискализация**: защищённый `core.admin` read-only реестр операций (продажа/возврат, связанный Order/Payment/Return, внешний источник, статус, ошибка, повторное событие). Пока при отсутствии кассового адаптера он пустой и это явно показано. **Нельзя вручную помечать чек выданным**.
- Новые таблицы `order_documents`, `fiscal_operations`, `fiscal_operation_events`; уникальные ключи для документов, provider-requests и событий; FK на источники; без перезаписи исторических денег, заказов, резервов и остатков. `admin/sql/updates/mysql/0.6.23.sql` и fresh install согласованы.
- RU/EN и штатные Joomla/Atum элементы, без собственной цветовой схемы. Повторяется архитектура текущих меню.

## Границы и риски

1. Это **первый шаг C11**, а не фискальный чек. Нет подключённого оператора фискальных данных, налогового режима, юридических реквизитов, ставок НДС, форматов и подписей.
2. Следующая бизнес-итерация по C11 возможна **после выбора страны/юрисдикции и реального кассового провайдера**. Тогда нужно проектировать и тестировать sale/refund checks, webhooks, ошибки, retries, операции только по подтверждённым платежам/возвратам, FK-согласованность Order/Payment/Return и налоговые поля.
3. Операторские права: создание коммерческого документа `core.admin`; просмотр `core.manage`; фискальный журнал `core.admin`. Это закрытые данные покупателей.
4. Версия 0.6.23 **не** создаёт чеки автоматически при создании/оплате заказа. **Не** изменяет статус заказа, платежа, возврата, доставку, склад, резерв.
5. При изменённых вручную старых денежных суммах генерация коммерческого документа может быть остановлена на контроле несогласованных итогов. Это намеренная защита, не повод исправлять исторический заказ автоматически.

## Что видно на панели

- В верхней строке MiniMarket справа от заголовка размещены жёлтая кнопка **Уведомления** и красный badge нерешённых действий; рядом остаётся штатная синяя кнопка открытия каталога. Кнопки «Очередь задач» и «Уведомления» исчезли из карточек управления.
- Количество берётся из **текущих статусов** существующих сущностей: новый заказ (`status=new`), платёж в обработке уже принятого заказа, новая/проблемная/просроченная доставка, новый возврат, новое обращение, ошибка фискализации. Нет записей ради нажатия/просмотра.
- Внутри «Уведомления» две отдельные области: **Требует внимания** с переходами к источнику и **История событий** за 30 дней с личным read/unread. Просмотр события не закрывает действие. После перевода заказа из `new` в `confirmed`/дальше он больше не фигурирует как новый; другие незавершённые проблемы продолжают отображаться независимо.
- Старый `view=workqueue` и таблицы personal read сохранены только для совместимости, но переходы из всех трёх меню убраны.

## Шесть групп настроек

| Раздел | Куда ведёт | Технический view |
|---|---|---|
| Настройки доставки | Реальные способы, их настройки и точки | `deliverymethods` |

Порядок совпадает в dashboard, Joomla submenu и component preset.

## Настройка событий и шаблонов

- Для каждого события и аудитории (покупатель/администратор) есть переключатели разрешённых каналов и доступ к шаблонам **Почта / Telegram / MAX / Личный кабинет**. Кнопка «Выключить» снимает отмеченные каналы для события; эффект сохраняется только по **Сохранить**. Основная email/плагин-матрица остаётся в Joomla component params; дубликата таблицы правил нет.
- Выбор способа уведомления доступен ссылкой из раздела; в карточке способа больше нет второй редакторской копии матрицы событий. Сохранение email-enabled не стирает ранее выбранные разрешённые события.
- Текст шаблонов plain-text с прежним перечнем переменных; `channel_code` в существующей таблице уже поддерживает до 16 символов. **Email** может публиковаться, и его клиентские сервисные шаблоны остаются под `NotificationSender`, `allowedEvents` и preference пользователя. **Telegram, MAX, личный кабинет** можно редактировать только как **черновики** (`state=0` принудительно проверяется сервером). Публикация, отправка, подключение каналов и личный кабинет пока **НЕ реализованы**.
- Маркетинговые цепочки по-прежнему draft без получателя/consent/scheduler. Новый интерфейс не начинает отправку.
